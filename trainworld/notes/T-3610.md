# T-3610 and T-3612 (agent saveread, 2026-11-17)

## T-3610: one unreadable save hid every save

Fix (worktree tw/saveread, `workers/saveFile.ts`): `listSlots` and `listBackups` read each record in a transaction of
its own (`readApart`, tried twice), so a record the browser cannot read aborts only itself. Cancelling the error event
was not used: it would leave every other read in the same transaction depending on the browser honouring it.
A slot that cannot be read lists as `{ key, name: "Saved game", at: 0, day: 0, damaged: true, unreadable: true, cloud }`:
the existing damaged line shows ("This save is damaged."), its backups and account copy are grouped under it as for
any damaged game, and it sorts last. `SlotFacts` hides the time and day for it. `stampAll` (cloud.ts) skips it, since
there is no record to stamp (stampOrigins would abort every stamp in its one transaction). An unreadable backup is
left out of `listBackups`. Sync records are read the same way (unreadable reads as none).
Opening the unreadable game still goes through `readStored`, which retries and throws StorageReadError (load failure
screen with the storage reason), as before.

Not done: the card says "No undamaged copy of this game is left" when the only backup has not been checked; the
backup is still offered under "1 other version".

Proof: scratch script (scratchpad/saveread/unreadable.mjs): two slots plus backups in a throwaway profile; the page's
`IDBObjectStore.prototype.get` made to fail (fake request error event) for `slot-bad`. Start menu lists both games,
no "could not be read" message, one damaged line, the damaged game's backup offered. Before the change the same
failure took out the whole list. Strings: none new (reuses `clockWorker.saveDamaged`).

## T-3612: iOS version in feedback

`browserOf` appends " (iOS X.Y)" from the "OS 16_5 like Mac OS X" part of the UA. Samples: iOS Chrome "Chrome 120 (iOS 16.5)",
iOS Firefox "Firefox 121 (iOS 17.2)", iOS Safari "Safari 16.4 (iOS 16.4.1)", iPad Chrome "Chrome 110 (iOS 15.7)",
in-app browser (no browser token) falls back to the UA text, which already carries the OS; desktop Chrome, Mac Safari,
Android Chrome unchanged. An iPad on a desktop UA (Macintosh) carries no iOS version in the UA, so none is shown.
