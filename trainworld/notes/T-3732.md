# T-3732 Quick stop edits in the line panel

Agent panelstops, 2026-11-18, tree `panelstops`.

## Cause

`ui/inspector/LineInspector.tsx`: `stopEdit` and `moveStop` returned at once while a module flag said one was out, so a
quick second click did nothing. `setStops`, `removeStop`, `takeOut` and `addGaps` built the list from the rendered
`l.stops` at the click, and `dropStop`/`endLineAt`/drag used row indices, so a second edit sent before the first
landed counted from the old list.

## Fix

Every panel stop edit goes through `sendStops`, which joins `queueStopEdit` (T-3731's queue, shared with the map's
clicks, so panel and map edits keep their order and undo/save/leave wait for them). A click captures its stops as
station plus visit number (`StopRef`) and the op is built when it is sent, from the line's stops then. A stop gone by
then makes the edit a no-op. Undo steps are unchanged: one per edit.

## Measured (real NYC save, line 1 of 49 stops, 6 row remove buttons clicked in one go, `scratchpad/panelstops/probe.js`)

| | lost of 6 |
|---|---|
| before | 5 (normal), 5 (slow-sim stand-in, 200 `stopTiers` reads queued) |
| after | 0 (normal), 0 (slow), 0 (dot clicks, slow) |

After, three undos took back one stop each (+1, +1, +1). Drag (`moveStop`), Shift-click end and Add were converted the
same way but not probed by pointer; typecheck passes.
