# T-2486 Compress .bin files to cut download size

Agent binzip, 2026-11-20, tree `.tw-trees/binzip`. Built and proved locally; nothing uploaded or published.

## 1. Measured

- **Live site** (plain GETs to `data.anita.garden/trainworld/2026-11-19/`, all encodings accepted): `nyc.bin` 200,
  `application/octet-stream`, 7,605,084 bytes, no `Content-Encoding`; a Range read is a 206 of raw bytes;
  `market-drives.bin` 14,652,440 bytes raw. Cloudflare does not compress `octet-stream`, and R2 compresses nothing.
  JSON is already gzipped (`Content-Encoding: gzip`, deploy.py).
- **Who reads a `.bin`**: whole: `demandClient.downloadPack` (every zone pack the demand pool opens),
  `fetchMarketDrives` (market-drives.bin). By Range: the clock worker (water rows, street-speed arrays), `walks.ts`
  (walk grid), the diagram worker (water). Range-read arrays are 30% of all `.bin` bytes (1.29 of 4.36 GB), so leaving
  them raw would forfeit a third of the saving.
- **Ratios** (sample of city packs): gzip -9 0.54 (nyc, tyo, phl), 0.55 (lon), 0.43 (mic); brotli 11 0.49 to 0.51
  (0.31 for mic) but 25-45 s a file and no `DecompressionStream` for it. **gzip per array = gzip whole file** (0.54
  both on nyc), which decided the format.
- **Over the registry's 4,765 zones** (data/packs today): 4,343 MB raw -> 2,492 MB packed (0.57).
  `market-drives.bin` 17.0 -> 10.0 MB (0.59). On R2 that is about 43% off each version's `.bin`; R2's own total
  was not listed (live `nyc.bin` is byte for byte the local one; T-2472's 2.2 GB is from 2026-11-03).

## 2. What was built

- **Format** (`tools/packzip.py`): a zone `.bin` becomes one gzip member per array, back to back; the header
  (`<id>.json`) gains `bin_gz: {size, parts: [[raw offset, file offset, length], ...]}`. Members start at 0 and at each
  array's offset, padding included, so they inflate to the raw file byte for byte. `arrays` keep the raw offsets.
  A pack is refused when non-zero bytes lie outside every array or an `offset` key outside `arrays` points into the
  file (none did). `market-drives.bin` is gzipped whole (only read whole; raw starts `TWD1`).
  `packzip.py check` inflates every pack and compares it and its header with the source: all 4,765 passed.
- **App**: `workers/packZip.ts` (index, inflate). `downloadPack` inflates a packed `.bin` after the T-484 header
  check, so workers, sim and the load-size estimates see the raw layout (no Rust change). `rangeFetch.ts` reads the
  pack's header itself (memoized per worker, from the browser cache), maps a raw span onto the members covering it,
  fetches those bytes (T-2499's 200/206 handling kept), inflates and slices; callers unchanged, so `clock.worker.ts`
  was not touched. `diagram.worker.ts` now uses `fetchRange` instead of its own Range fetch. `fetchMarketDrives`
  inflates on the gzip magic. A header without `bin_gz` takes the old path, so data/packs, 8800 and any old pack load
  as before.
- **Publish** (`tools/deploy.py`): `stage_bins` runs `packzip pack` then `check` on the build's packs into
  `artifacts/trainworld/publish/<version>/bin/` (about 2.5 GB, a few minutes on 4 processes, `--jobs`); the top-level
  `.bin` go up from there, the rest raw as before, and `stage_gz` gzips the packed headers in place of the build's.
  No new headers, bucket or layout on R2. `--verify` gains "a .bin is packed" (its first two bytes are gzip's).
  data/packs stays raw: nocar, enrich_*, merge_cells and pack_gravity read and append `.bin` by raw offset.

## 3. Proof (own Vite 6156, `TW_PACKS` = a packed copy in scratch, other files hard-linked read-only)

| Run | Raw packs | Packed packs |
|---|---|---|
| New game, New York, one 3 km line: trips/day, rail trips/day, cash | 885,517,165 / 222,497 / 8,806.94 | identical |
| New game: `.bin` downloaded (demand pool's byte count) | nyc 7,605,084 | nyc 4,127,478 (-3.5 MB, 46%) |
| Real save (109 lines) final: trips/day, rail trips/day | 895,752,175 / 12,558,064 | identical |
| Real save: zone `.bin` downloaded (nyc, hfd, lck, nhv) | 11.65 MB | 6.24 MB |
| market-drives.bin served / read | 17.0 MB, TWD1 | 9.98 MB gzip, read back 16.97 MB TWD1 |

Range check (scratch `probe-range.js`): every array of nyc, phl, tyo and lon read through `fetchRange`, plus a
span across two members and an odd span inside one, equals the same bytes of the whole read: 174 reads, 0 bad.
The same spans read through `fetchRange` inside the clock worker (Playwright `page.workers()`) hash the same as on the
page: water_row, pop, jobs, zone, zone_cells9, walk_row. Inflating nyc whole on the main thread (`unpackBin`, 42
members): 44-108 ms. The packed real-save run had 2 cores against the raw run's 3, so its load time is not compared.
Staging: deploy.py's `stage_bins` + `stage_gz` run on a 3-zone folder with STAGE in scratch (`stage_test.py`): the
gzipped `nyc.json` has `bin_gz`, `nyc.market.json` is the build's, staged `nyc.bin` and `market-drives.bin` start
`1f8b`, and the two rclone filters, tried with `rclone lsf` on local folders, send only top-level `.bin` from the
stage and none from the build. A real `--dry-run` was not run.
Typecheck clean. Smoke not run (no sim, save or demand rule changed; the orchestrator's batch smoke covers it,
though smoke on 8800 runs raw packs; the packed path is proved only by the runs above).

## 3b. Fixes after the check (notes/T-2486-check.md)

- **Packed `.bin` under a header without `bin_gz`** (two uploads mixed) hung the load. Now `downloadPack` throws
  ("New York could not load", the reason in the feedback diagnosis), and `rangeFetch` reads a raw-header pack's first
  two bytes once per worker and refuses a gzip one, so the clock worker fails the ground (construct says
  TerrainMissing) instead of feeding the sim garbage (it had panicked in cost.rs). A real save in that state still
  waits on its ground, as for any failed water mask. Proved on a scratch folder with only nyc.bin packed; raw packs
  re-checked (174 Range reads, 0 bad). A raw `.bin` never starts with the gzip bytes (none of 4,771 do).
- **deploy.py --resume** into a version whose served headers (nyc and about 8 others from the build) lack `bin_gz`
  is refused; a version with no headers yet resumes.
- **--verify** also checks that nyc.json has `bin_gz`, market-drives.bin starts with the gzip bytes, and water_row
  read by Range through its members equals the same bytes of the whole file inflated. Proved against a local R2
  stand-in (Range, gzip JSON) in `scratchpad/binzip/verify_test.py`: all pass on a packed version, all fail on a raw one.

## 4. Left

- **Market files by region** (not built). The drives table is one global TWD1 file indexed by place; a line in the
  US needs pairs touching US places, 1.36 MB (8%) of 17 MB; China the most, 3.5 MB (21%). India 17%. A split changes
  the format, the sim's reader and how the market is composed (and `market-rows.json`, 11 MB raw, 2.7 gz, bundled
  with the app, would want the same), a design call beside the demand work: a follow-up task. The drives table that
  ships next is today's 17.0 MB, packed to 10.0 MB, against 14.65 MB downloaded now: the first line's one-time cost
  drops by about 4.7 MB (plus the 2.7 MB rows, unchanged).
- **Open-source copy**: its dev server proxies `/packs/` from the R2 version in `data-version.txt`, so it works as
  long as the sync writes that file with the version published beside the code; old code pointed at a packed
  version (TW_DATA_VERSION by hand) would read the gzip as raw.
- **Exercised only when published**: 8800 and smoke serve raw packs. A standing check that serves a packed copy
  (`packzip.py pack` into a temp folder + `TW_PACKS`) would catch a future Range reader that bypasses `fetchRange`;
  not added (no bug has happened yet). Any new Range reader must use `fetchRange`.
- **Disk**: the publish stage grows by about 2.5 GB per version (`publish/<version>/bin`), on a disk 96% full;
  the older stages can go with the `gz/` ones.
- The scratch packed copy was deleted; `packzip.py pack <data/packs> <dir>` remakes it in about 8 minutes on 4 cores.
