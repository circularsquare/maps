# T-4029 population view stuck after a load

Report (Twitter 11-21): after loading with the population circles on, turning them off leaves them on screen.
The view is the demand bubbles (Homes / Destinations / Total; map/demandOverlay.ts, its own WebGL canvas).

Cause: `DemandOverlay.draw()` returned at once when the WebGL context was lost (or there was no camera yet), before
the "nothing to draw" branch that empties and hides the canvas. A load is when the browser drops contexts (memory),
so bubbles turned off while the context was lost left the canvas sized and visible; a browser that keeps a lost
canvas's last frame (the Safari case of T-956) keeps showing the circles. Only restore() would have blanked it.

Repro (play.mjs, t3470-big240.save, Homes on, WEBGL_lose_context on the demand canvas, then None):
before: canvas 1098 px wide, visible, after turning off while lost. After: 0 px, hidden at once.
A plain load plus off, quick on/off at several delays, and the zoomed-out overview all blanked fine before the fix,
so this is the only path found (Chrome headless shows a lost canvas as clear, so the picture itself can't be shown).

Fix: draw() works out what is to be drawn first and blanks without touching GL; only drawing needs cam and a live context.
Other sparse overlays (fitSparse users) are 2D canvases and blank without a context, so none had the pattern.
No in-game strings changed.
