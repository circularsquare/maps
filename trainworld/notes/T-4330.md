# T-4330: Select tool modes

Anita's pad, 11-25: "add the 'select lots of demand bubbles' feature to the actual select tool instead of just having it on
shift+drag... a top menu to the select tool like the top menu for the station tool ... blueprints then track if theres no
blueprint (current setting), or just track (new) or demand bubbles. the blueprints then track button can be like a blue track
icon. the track button can just be a gray track icon. the demand bubble can be the little purple demand bubble icon."

## What was built (tree selectmodes)

- `game/ui.ts` `selectMode` ("blueprint" | "track" | "demand"), remembered in the browser with the build settings.
- `ui/ToolBar.tsx` `SelectBar`: a `.tool-bar.select-bar` with the station bar's kind group look (`group tb-kind`, icon buttons,
  hover = label, the click mode's colour on its top edge). `MapToolBar` shows it for the Select tool. Picking a mode drops the
  pick it would not make (`onlyOneKind` again; all of it for bubbles) and turns the bubbles on as last shown when off
  (`DemandSelector.tsx` `showBubbles`, only once demand is ready).
- Built track only: `game/blueprintPick.ts` `onlyOneKind` keeps only constructed pieces while the Select tool is on in that mode.
  Every pick funnels through it (box `within`, `unionPicked` for Shift, `under` for a click, the double click's run), so one
  change covers all of them. `blueprintBox.ts` `under` now skips a hit the mode empties, so a blueprint station drawn over
  constructed track still lets the click reach the track (before, the first hit was taken even when empty).
- Demand bubbles: `blueprintBox.ts` leaves the left button and a finger alone in this mode (no preventDefault, so the bubbles'
  mousedown runs; right and middle drags still pan); `commuterView.ts` `boxes()` accepts the Select tool in this mode and starts
  the box at once (no long press, no ring: `ring` now says "armed by a long press" instead of reusing `!add`); `main.ts`
  routes a click to `pickBubble` (the bubble under it, Shift adds, none clears) and shows the pointer cursor over a bubble.
- The selection bar gets `.under-bar` while the Select tool is on and sits 6 px under the Select bar (margin, so every
  breakpoint's `top` still applies; on a phone it goes over the bar, and the tool notes and level choices over both).

## What can go wrong, and what a player could hit

- Leaving the tool: Esc leaves it as in the station tool (`tools.key`); a bubble selection stays, the next Esc clears it.
- Bubbles hidden or zoomed out to the overview: a drag in demand mode draws nothing (as Shift+drag while plain selecting).
- Pre-existing, not changed: `nodeDrag.ts` enables MapLibre's drag pan on every mouseup, whatever the tool, so the Select
  tool's "drag pan off" does not hold after the first click. The tool's box still works because its pointerdown is
  preventDefault-ed; in demand mode the bubble box disables the pan on its own press. Harmless today; noted only.
- Plain selecting is untouched: `builtOnly` and the bubble routing check `tool === "blueprint"`.

## Game run (new NYC game on :6192, one built 3-station line, one blueprint piece 400 m south)

- Default mode, box over both: "Selected: Blueprint: 1 track".
- Built track only: the blueprint pick dropped at the switch; the same box: "Selected: Built: 1 station" (the box held the
  middle station only); a click on the blueprint track: no pick; back to the default, the same click: "Blueprint: 1 track".
- Demand bubbles: the built pick dropped; bubbles turned on (were off); a box drag: a commuters selection of 10 areas; a click
  on a bubble: commuters, 1 area; Esc left the tool and the Select bar went with it.
- Plain selecting, Shift+drag over the same box: commuters, 10 areas (unchanged).
- Bars: station bar and Select bar both at page top 118, height 38, centred on x 851 (UI scale 0.9); the selection bar 6 px under.
  Screenshot: artifacts/trainworld/review/select-modes.png (Built track only on, a built pick in the selection bar under it).
- Phone, 390x844 touch: the Select bar on the map's bottom edge (page y 452-497), the selection bar 6 px over it (401-446),
  the tool notes 5 px over that (365-396). The first look found the selection bar 220 px tall: the narrow-map rule
  `.blueprint-bar.under-bar { top: 148px }` outranked the phone rule's `top: auto`; the phone rule now sets it too.
- About 4 minutes of game checks in all; no benchmarks.
