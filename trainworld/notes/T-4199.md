## The New York extra download and solve (stage 3)

Cause, from the code and stage 2's run records (runs/rq-c2-head-nyc-1.json): perf_bench (and a player) opens a save
while a game runs. `stationsAhead` starts the load's focus pool and opens the save's zones and markets ahead of its
network; the pool gets the zone in view's pack from the main pool's `post`. With the corridor file the markets were
open before the save's network arrived (7.1 s against 8.2 s after the import), so `flush`'s "a pack opened since the
newest solve" sent the **last game's** network again (0 stations, 4 zones, 9 markets, done in 0.5 s). Its final ran
`endFocus` (`final && s === this.cur`), ending the load's focus pool. The save's network then started a new pool
(one more worker: worker code, WASM, attractions) whose `focusSoon` downloaded New York again (13 MB) and sent its
focus solve after the whole solve. Without the file the markets opened after the network, so the race never showed.

Master has the same bug whenever the packs open first. Shown on 8800 (d56bb9594) with the network held back 15 s
(artifacts/trainworld/t4199/delay-import.js, a new game in New York, then the real save imported): a solve of the old
network at 22.0 s (the markets' open), New York downloaded again by the focus pool at 33.8 s, its focus solve at 41.5 s,
7.7 s after the whole one. The tree, same probe: no solve before the network, no download (the pool opened New York at
12.0 s from the shared pack), the focus solve 4 ms after the whole one. Cousins covered by the same guard: a replaced
worker's `solveAgain` and the quiet refresh during a load. T-4220's side jobs already wait for `gameLoadArmed()`
(`asideWanted`); nothing they rely on changed.

## Review fixes (agent corrfix, 11-25, tree corrfix, not committed)

Review: artifacts/trainworld/gemini/batch23/review-T-4199.md. Each finding checked against the code.

1. Stale fareBits (medium): confirmed. tools/corridor_file.mjs under --strict now fails on a stale fareBits.json, and
   --need-drives fails when there are no drives. pipeline/freeze.py build requires the freeze's packs/market-drives.bin,
   runs the script with both flags, checks its exit code and that the file is newer than the build's start, then checks
   a copy of exactly that file is in the build's assets and records its sha256 and keys in frozen.json "corridors".
   world_run.py's @corridors uses both flags too; a failure stays a report problem, now worded "MARKET CORRIDOR FILE NOT
   MADE ... fix it before a publish" and printed as a PROBLEM line. The same flags cover finding 2 (script failure, stale
   tree file kept, no drives).
   Publish check: tools/deploy.py preflight refuses a build on a freeze whose frozen.json has no corridors entry or
   whose assets hold no file with that sha. It cannot say whether the shipped WASM accepts the file: that needs the WASM's
   source key and the freeze's world, i.e. running the dist's demand WASM over marketWorld(rows) in Node (what
   corridor_file.mjs does on the tree's WASM, which freeze.py build uses). Doing it in preflight would need a script that
   loads the dist's hashed WASM and the freeze's rows (about 15 s); not done, the build's own strict run is the check.
2. Respawn during a load's wait (low-medium): confirmed (workerDied's "panicked" counted the entry kept while solveAgain
   sent nothing; restartStuck refused). Entries get `held` when solveAgain finds a game load armed; while armed, a held
   entry counts toward neither the second-panic rule nor restartStuck's refusal (demandClient.ts respawnTrusted). Once the
   network arrives (not armed) the entry counts as before until its solve's done. MAX_RESPAWNS still counts every panic.
3. fetchCorridorFile (low): now patientFetch with 3 retries (0.5, 1.5, 4 s), 404 is none at once, a final failure is
   still null (the file is optional, so no load fails over it). parse (corridor_file.rs): checked arithmetic on the
   length, so a garbled count is a refusal (unreadable) on 32-bit wasm; header slot 68..72 (was zero) holds a checksum of
   the body (hash64 folded to 32 bits), so a flipped bit anywhere in the body is refused. Costs one pass over 424 KB.
4. t4199.rs: new test a_file_of_other_drives_or_another_build_is_not_used (file made with no drives read with some,
   made with drives read with other or none, same drives used, other source key refused and dropped); the refused
   test now also covers a flipped body bit (unreadable), counts that wrap 32 bits, and the sample-differs case with
   its checksum made again.
6 (toolchain not in key): not changed; every demand wasm build remakes the file and the 1024 samples would catch a
   powf or exp_m1 change.
