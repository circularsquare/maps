# T-029 local saves

Done 2026-10-09 by the gameplay agent (batch 4). The game saves itself in the browser and comes
back where it was on the next visit; the settings pane (gear) has "Save to a file", "Load a file"
and "New game".

## What is in a save

The player's inputs only (SPEC 11): the track model's network save (`TrackApi.save()`, format
TWT2: nodes, stations, edges with their PIs, lines with stops, path and schedule, constructed
flags), plus a JSON header with the city, the game clock, cash, cars owned, the fare curve and
the last 30 days of the money ledger (T-028). Everything else (geometry, profiles, capacity,
demand) is recomputed on load.

File layout (`app/src/workers/saveFile.ts`), gzip-compressed as a whole:

    "TWG1" | u32 LE header length | JSON header | TWT2 network bytes

Nothing in it depends on wall time, so the same game saves to the same bytes. The file name is
`anitabuilder-<city>-day-<n>.save`. Header `format` is 1; a reader refuses a newer format with a
reason, and a save for another city.

## Where it runs

All of it in the clock worker, which owns the network: `api.save()` and the header are taken in
one synchronous step (so an edit arriving mid-save cannot tear it), then compressed with
`CompressionStream` and written to IndexedDB (database `anitabuilder`, store `saves`, key
`autosave`) from the worker. The main thread only sends messages (`flush`, `export`, `import`,
`newGame`) and, for an export, turns the bytes into a download.

**Cadence**: at once after any edit that paid for something (construct, trains, a paid platform
or flyover); otherwise once a minute of wall time if anything changed (an edit, a fare change, a
game hour settled); and when the page is hidden or closed (`visibilitychange`, `pagehide`).

**Start**: the worker reads the autosave before its first state; if there is one, it loads it and
tells the main thread the clock (`loaded`), else a new game: day 1 07:00, $6B, empty city.
`?new=1` starts a new game without reading the autosave (the next autosave replaces it). A save
that cannot be read is kept aside under `unreadable-<time>` and the player is told.

**Loading** (autosave, file, new game) replaces the track world (undo history gone), sets cash,
cars, fares, ledger and clock, sends the new state and a new demand snapshot at once (no
debounce). Track ids are renumbered by a save, so the main thread clears the selection and any
tool in progress.

## Checks

Headless Chrome on Anita's desktop, driving the app through the same edit ops the tools send
(`scratchpad` driver, not kept): a 5 km double-track line at -1 with 4 stations, constructed,
schedule 20/10/3, fares $2.25 + $0.12/km, a blueprint stretch at +1, then 2.4 game hours at the
top speed so fares and running costs settle.

- Reload (autosave): stations (name, position, level, platform, constructed), edges (length,
  tracks, levels, cost, constructed), lines (name, colour, stops, schedule, status, round trips,
  trains), cash to 1e-6, cars, fares, ledger and clock all equal.
- Export, reload, export again: the decompressed files are byte-identical.
- New game, then import the first export: equal again.
- Size: 413 bytes compressed (458 raw) for that game. T-040 measured the network part at 20 KB
  compressed for 2,000 route-km, 104 KB for 10,000.
- Worker time per autosave (encode + gzip, then IndexedDB; reported in the `saved` message as
  `encodeMs`, `totalMs`): 0.7-3.4 ms encoding, 0.9-3.9 ms in all over five saves of that game; no
  long task on the main thread while saving.
