## Network layers

- **Line width**: riders an hour on a stretch = (run 0's load + run 1's load on it) / period
  hours, the period in force on the clock (`LineDemand.loads[period]`). Width = 0.45 + 1.75 x
  sqrt(min(1, r / 30,000)) line widths (`widthFor`). A line demand has no fitting answer for
  (not running, or its stops changed since the solve) stays at width 1.
- **Side by side at those widths**: T-062 gives each line on an edge a slot. `networkFromState`
  now also stores per line stroke segment the slot, the number of lines on the edge, the sign that
  maps slot order to "left of the segment's direction", and the run-0 stop stretch it is on
  (counted while walking the line's path: a path entry ending at the next stop advances it). On
  the main thread the offset of a line is the widths of the slots right of it plus half its own,
  less half the bundle; with all widths 1 that is T-062's offset exactly. The new offsets are
  written into `net.lines.offset` and `net.sampleOff` (pick.ts and `tripAt` read them), the
  originals kept in a WeakMap per network. `sampleStroke` maps each 50 m train sample to a stroke
  segment of the same path entry, so trains take the same offsets.
- **Station size**: the shader's radius x (1 + 1.6 sqrt(min(1, riders / 150,000))), riders the
  day's boardings plus alightings from `DemandView.stations`; the bundle span uses the widest
  bundle's width at the node (sum of widths) instead of its line count.
- **Train gauge**: per train sample, the gauge of run 0's and run 1's average train on that
  stretch (loads / (tph x hours), against 44 seats and 160 at crush per car, as T-083). Gauge =
  0.5 x aboard / seats up to the seats, then 0.5 + 0.5 x the standing share up to crush, 2 when
  over full (red rim). The shader reads the sample ahead of the train for run 0 and behind for run
  1 (its way), so a train at a stop shows the stretch it leaves on. The fill grows from the back
  of the train: dark line shade (as before) over `mix(line colour, white, 0.6)`.
- **Rebuilt** on a new network, world, demand result, period, or a switch, at most once per task
  (an edit sets the world and then the network; the build waits for both in a microtask).
  Main thread, real New York save (117,701 line stroke segments, 90,178 samples, 1,756
  stations): **3.9-6 ms** (10-13 ms before working per run of segments sharing an edge and line).
  `setLayers` uploads in place (bufferSubData, texSubImage2D), under 1 ms.

## Commuter dot map

- **Data**: `cellModes()` for the solve shown, home or work end. Asked on a solve's first
  estimate and again when `demandUpdating` turns false (round 3); the crowding rounds between
  are skipped. The demand client cached `cellModes` per solve, so the refined ask returned the
  first estimate's answer; it now caches per solve and round (one line, demand agent's file).
- **Carry** (memory `feedback_dot_allocation_spatial_carry`): cells sorted once by a 2^16 Hilbert
  index of their position; each mode keeps a running total and drops a dot in the current cell
  every time it passes 5 commuters. Levels: a dot whose index in its mode is a multiple of 4^L is
  in level L (L = 0..4: 5, 20, 80, 320, 1,280 a dot), which is the same carry at 4^L x 5 with a
  phase offset. The buffer holds the coarsest level first, so level L draws the first
  `drawn[L]` dots.
- **Mass check** (real New York save, home end, commuters in a box vs dots x value; `s7` probe):

  | box | mode | commuters | level 0 (5) | level 3 (320) |
  |---|---|---|---|---|
  | Manhattan | train / walk / drive | 385,231 / 38,154 / 261,209 | 382,435 / 37,890 / 259,050 | 382,720 / 38,720 / 258,240 |
  | Staten Island | train (5%) / walk / drive | 12,017 / 6,149 / 222,419 | 12,155 / 6,180 / 222,695 | 11,520 / 6,400 / 223,040 |
  | east Suffolk | train (5%) / walk (5%) / drive | 6,581 / 6,035 / 119,291 | 6,585 / 6,050 / 119,140 | 6,400 / 6,400 / 119,040 |
  | north Westchester | train / walk (4%) / drive | 10,791 / 3,164 / 69,350 | 10,815 / 3,150 / 69,325 | 10,560 / 2,880 / 69,120 |
  | Newark area | train / walk / drive | 74,020 / 9,022 / 183,746 | 73,620 / 8,975 / 183,285 | 73,920 / 9,600 / 183,040 |

  Minority modes come out within 1% at level 0 and within one coarse dot at level 3 (box edges
  cut cells' discs, so a box is not exact either way).
- **Placement**: dots spread uniformly over a disc of 200 m around the cell centre (an H3
  resolution 9 hexagon's corner radius) by mulberry32 seeded with the cell index, the cell's dots
  shuffled first so no mode is always drawn last where dots pile up. A sunflower spiral per cell
  was tried first and showed each cell as a rosette up close.
- **Which level**: `round((12.5 - zoom) / 1.4)`: 5 a dot from zoom 11.8 in, 20 to 10.4, 80 to 9,
  then 320. Quadrupling every zoom level (constant density on screen) left the city view at zoom
  9.8 with 320 a dot, too sparse under the lines. Dot size 1.6 px at zoom 9 to 3.4 px at 16.
- **Drawing**: a canvas of its own under the network overlay (`canvas.overlay.demand`), drawn
  from `Overlay.afterMapFrame` (MapLibre's frames, same matrix, T-015) and once after its data
  changes; never by the clock. Dots are chunks of 4,096 consecutive dots within a level, with a
  box each from the worker; only chunks whose box meets the view (padded 400 local units) are
  drawn, consecutive ones in one call.

## A station's commuters

`stationRiders(id, 20)` on selection and on each new demand result for it; marks rebuilt from it
(no new query) when the player picks the other end. Near end: the station's cells as discs, area
proportional to riders (183 m equal-area radius at the busiest, at least 2.5 px). Far end: up to
20 gravity zones as rings, radius up to half a zone (1 km) by sqrt of riders. Places in the
inspector: each far zone named by the nearest station within 3 km of its centre (zones sharing a
name merged), else "12 km northeast" from the selected station; the top 8 listed.
