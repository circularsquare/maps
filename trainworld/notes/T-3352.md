## 1. Where single track is refused today

Nothing in the sim's model needs these two kinds to be double. Each refusal is a flat rule, put in when the kind
was added, and none has a reason that is still true.

### Rebuild (Select bar)

`sim/src/track/wasm/rebuild.rs`:
- `single_refusal` (396-402): `HighSpeed` ("unless Regular is made too") and `Tram` reasons. These are the two
  T-3321 kept, T-3339 left in place.
- `double_ok` (380): double goes single only if the plan's type is Regular.
- `single_ok` (374): single goes double only if Regular and not one-way. So a single high-speed or tram piece can
  never be doubled.
- `kind_ok` (367): a piece can change type only if it is double (or `single_ok`), so a single Regular piece cannot
  become high-speed or tram, and a single high-speed leg cannot become Regular.
App: `Blueprint.tsx` / `game/blueprintPick.ts` count `ones`/`twos` only for non-tram track, and `canBeHsr` wants
`tracks === 2`, so the Select bar's type buttons and the count icons skip single high-speed and any tram.

## 2. What "manual flyovers" means

A flying junction built by hand today with regular track, no auto flyover: the player draws one-way single track for
each of the two directions of the branch, at different levels so they cross without a flat crossing (levels 8 m
apart cross freely, ramps 200 m, wiki `levels-and-tunnels`, doc 6.1 "Levels"), joins each single end to the double
track's own track with the track tool's Single track snap (T-3137 joins; the end takes the track nearer the
pointer), and sets "One way" in the Track inspector (T-3094, `set_edge_oneway`; the switch is on the single
piece's inspector, `TrackInspector.tsx` 66). The automatic version (T-3092, T-3169, T-3170) does exactly this
with a fixed layout, and only when the route is a plain double branch with room.

For a high-speed junction by hand the player needs, in order:
1. Draw single track while High speed is picked (draw, snap to join one track of a high-speed double, ghost at
   lane 0), so tool and sim stop forcing it to regular or double.
2. The track inspector's One way switch on a high-speed single piece: `TrackInspector.tsx` 66 hides it for
   `e.hsr` and any tram kind. The sim side already allows it (`oneway_plan` only wants `tracks == 1`, `set_edge`
   allows one-way high-speed).
3. Single high-speed legs at 320 km/h and 50 m least radius: kind-based, already true for the auto legs
   (`HSR_MIN_RADIUS` 50, `V_HSR`); nothing to add. Capacity: a one-way single section already takes double track's
   per-direction rule (`70 s + v/0.6`).
4. A price that is not regular's (see decision 1).
Two-way single high-speed is not needed for flyovers but is the same rule (the draw tool has no one-way mode, a new
piece is two-way until set), so it is allowed too; a high-speed single line then runs under the single-track rule
(run time + 240 s margin).

## 3. Tram

- **Stops**: a tram stop is a station with a 20-80 m platform on the tram track (kind from the edge, `stationOnTram`,
  `StationUpgrades` shows only Waiting room). On single tram a stop is a single-track station: one shared platform,
  priced `SINGLE_TRACK_STATION` (0.6x), no passing tracks (the upgrade is already hidden for tram). Nothing in the
  station code reads tram as double except `StationUpgrades`' `double` test, which only matters for rail.
  Turnaround: a loop line or a terminus works the same on single as on single rail.
- **Looks of a single-track station**: today a two-way single station is drawn as a passing loop (T-3212,
  `terminalBays.ts` `singleSplitEnds`, which also skips tram). T-3332 is changing that look to a choice; tram should
  take whatever T-3332 does for "no passing loop", and tram stops should default to the no-loop form.
- **Street running**: a street tram route follows a street (`trace_kind`, 18 m curves, 60 km/h). Single street tram
  would be one track on the street's centre line instead of the pair the fit now draws beside it (`tram_ends`,
  `draw.rs` `route_op_plain`'s tram lead-in code is kind-based, not track-count-based; one check item). Street cap,
  curves and the 0.1x ground price scale are untouched.
- **Passing**: single tram follows the rail rule exactly (section with run time + 240 s margin, one platform shared
  by both directions, joins at junctions when beside a double). Tram's own section rule `60 s + v/0.6` is for
  double and one-way single only, as for rail. A flat crossing with a train route: the tram yields
  (`capacity.rs` 696), unchanged; crossing marks pack "tram tracks 0 to 2" (`map/markData.ts` 23-26), so a
  single tram crossing needs a 1-track value (check item).
- **Buses**: none. Buses are a separate network over streets (`bus` module, `line_bus`); the only code shared with
  trams is the street graph the snap reads, which is read-only. Single tram track never touches bus routes.
- **Still true**: tram and rail never join (`TrackFamily`), a tram line is told by its first stop's kind, `fast`
  lines refused on tram, no crossovers on tram, no flyover offers on tram (draw.rs `with_flyovers` skips family != 0
  and `tracks != 2` already). These stay.

## 5. For Anita (recommended answers)
