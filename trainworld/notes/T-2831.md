# T-2831: what to trim from the workflow (audit, 2026-11-09, agent trimaudit)

Read-only audit. Nothing was changed except this file.

**How the costs were measured.** I read every Claude Code transcript on this machine that touches trainworld and
attributed each model call to what it did. Tokens are weighted the way `checks/token_usage.py` weights them (cache
read 0.1, cache write 1.25, output 5). Baseline: **since 2026-11-01, 487 transcripts used 1,970M weighted tokens, about
250M a day**; the median subagent makes 109 calls and uses 2.7M. One tool call costs about 20-35k because it re-reads the
context. Figures saved are for those 8 days unless stated, and are estimates. Scripts: my scratch folder
(`scan_transcripts.py`, `scan2.py`, `scan3.py`, `stale_checks.py`).

Limits of the data: a check run from a `.cmd` or with a relative path is not counted as run, so "not run" means "not
seen run". The 5-day-old cleanup surveys (notes/T-2361.md, T-2362.md) already tidied a lot, and most of `checks/` shows
a November git date only because of that move, so I went by runs, not git dates.

## Where the tokens actually go (since 11-01)

| What | Weighted | Share |
|---|---|---|
| Waiting: log tails 108M, sleep and poll loops 60M, process checks 26M, Wait-Process 4M | 197M | 10% |
| Re-caching after long idles ("wakes") | 135M | 7% |
| Core ledger calls (1,007 claim, 660 list, 558 release) | 68M | 3.5% |
| `CLAUDE.md` read by 307 of 465 agents, carried through each one | 36M | 1.9% |
| Handoff file edits (835 of them, in 22 orchestrator sessions) | about 23M | 1.2%, but 9% of orchestrator tokens |
| Smoke, all of it (tokens) | about 25M | 1.3% |

Smoke is cheap in tokens; what it costs is minutes. The doc-size worries were mostly wrong: **DECISIONS.md and
ARCHIVE.md cost 1M in 8 days** despite 260k tokens on disk, because agents grep them. TASKS.md was read whole 3 times.

## 1. Clear cuts

Ranked by what they save. None touches an Anita rule.

1. **Stop claiming cores by hand for anything that goes through `launchChrome`.** Saves about 25-40M (1.5-2%).
   Files: `CLAUDE.md` "CPU", `maps/CLAUDE.md` "Sharing CPU cores". T-2630 made `checks/cores.mjs` claim from the ledger
   by itself, but agents still claim first (`python cores.py claim 4 ...; node smoke.mjs`), so the same run is booked
   twice, about 7 cores for 3-4 of real work, which can starve the next claim. Of 1,261 claims since 11-03, 419 were
   followed by smoke or a check. Rule becomes: checks claim for themselves, set `TW_CORES_WANT` for more; hand claims
   are for pipeline, Rust and scripts that launch their own browser. Also `cores.py list` before a claim is unneeded,
   the claim prints what you got. Lost: nothing.

2. **Smoke: skip the Node checks when pointed at 8800.** Saves about 90 s on each of the two 8800 passes, every
   round. File: `checks/smoke.mjs` line 278. The Node checks read the working tree, not the build under test, so on
   8800 they repeat the dev pass exactly and can say nothing about the build. Three 8800 FAILs came from this part: t2005 on
   11-03 and t1053 on 11-04 and 11-05 ("the main tree's registry mid-worldfix, not the build", handoff). Lost: nothing.

3. **Smoke: `t1380-complexes` with 5 seeds instead of 30.** Saves about 45 s on every run (median run 176 s, Node
   checks are about 90 of that, this one 53). 0 failures in 387 runs. It stays in smoke; the full 30 seeds remain the
   script's default for whoever edits `complexBuilder`. Smoke's Node checks can also run two at a time for another
   15 s or so. Lost: a small chance of a rare seed catching something. `CLAUDE.md` still says smoke takes "about half
   a minute": it is 3 minutes.

4. **Dark smoke only before a publish, not every round.** Saves about 3 minutes and two orchestrator calls a round.
   `CLAUDE.md` "Before a commit" step 4. In 202 dark runs ever, 12 failed, and none of those looks theme-related
   (network errors, Node checks, a start menu timeout, one code error). It only checks for errors, never how dark looks. The T-377
   incident justifies the 8800 pass in light, which stays. Lost: a dark-only shader error would surface at publish
   instead of the same day.

5. **Cut `notes/handoff.md` to its working part.** 335 lines (10.9k tokens) against the handoff skill's "under about
   60". 280 lines are "Earlier Claude handoff" history already in git and ARCHIVE. At 10.9k it costs a long orchestrator
   about 1k weighted on every call, and 100 reads since 11-01. Move it to `notes/archive/`. Lost: nothing, git has it.

6. **Commit the orchestrator's build scripts.** `snapbuild.cmd`, `snapbuild-frozen.cmd`, `keep_hunks.py`,
   `mark_taking.py` live in an old session's scratch folder ("snapbuild.cmd in cd5c271d scratch", handoff line 16) and
   each new orchestrator copies them by hand. T-2362 flagged this on 11-04. Put them in `checks/`. Cost now is small; the
   risk is a temp folder being cleaned and 8800 not building. 47 builds since 11-01, 3.7 minutes each.

7. **Make `checks/dev-nowatch.mjs` pick up edits on a page load**, so agents stop restarting it. Saves about 15-25M
   (1%). 1,068 commands starting or stopping it in 8 days from 465 agents, plus background-task stops. One-file change: clear Vite's module
   cache on each HTML request; HMR stays off, so nothing reloads mid-check. Needs a quick test on this Vite version.
   Lost: nothing; a reload may see another agent's half edit, as a restart can today.

8. **Delete dead rules from `CLAUDE.md`.** Small tokens, but every agent reads them.
   - "Every city task ends with a retrospective ... the orchestrator records each task's tokens": 33 `token_usage.py`
     runs ever, 3 since 11-02, and the world is built. Keep the script, drop the duty (also in
     `docs/adding-a-country.md` 10, `adding-a-city-by-hand.md` 12).
   - "Each milestone ends with a doc tidy task": `doc_lint.py` replaced it (T-2362).
   - "Read this, then SPEC.md, then TASKS.md": agents already don't (3 whole reads of TASKS). Say "grep TASKS.md".

9. **`doc_lint.py`: stop reporting long entries by default.** 152 of its 188 findings today are `long-entry` and
   `long-task`, burying the 36 that matter (dead links, tasks whose blockers are done). The 40-word cap isn't being
   followed and costs nothing when files are grepped. Keep them behind a flag, and drop the cap from `CLAUDE.md`.

10. **Prune `checks/`.** Near zero tokens, but it's what you asked about and makes the folder usable.
    - `checks/old/`: 62 of 78 scripts have never been seen run. Delete those (git keeps them) and their `old/` lines in
      code-map (82 mentions). Six use selectors the app no longer has (t348-lag, t743, t1276, t1414, t1476, t1554), so
      code-map's "they still work" is untrue. Move `old/t2125-edit-note` back up: run 14 times since 11-01.
    - Top level, task-bound, last seen run by 10-30, to `old/`: t161, t263, t285, t486, t675, t724, t745, t871, t884,
      t1198, t1201, t1407, t1419, t1464, t1517, t1530, t1533, t1544, t1626, t1777, t1812-symbol, t1812-shots, t1813,
      t1854. The two with real history are t486 and t1201 (30+ runs each); leave those if in doubt.
    - Keep: t125 (the Rust frame test compares against it), the t066/t149/t301/t325/t409 worker family, `world_field_check.py`.
    - Verify when next touched: `t988-cloud` uses `.save-backup`, which is gone from the app.

## 2. For discussion

**A. Waiting on long jobs (10%, the biggest single line).** `CLAUDE.md` says never poll, but agents do, about 10 calls
each. The rule is partly wrong on the numbers: a poll costs 0.1x of the context and a wake costs 1.25x, so polling
every 4-5 minutes is cheaper than one wake for waits up to about an hour. What is really wasted is tailing logs
mid-job and short sleeps. Recommend rewriting the rule: under 4 minutes, one foreground call; longer, background and
at most one light check per 4-5 minutes; never read the log until it ends. Might save 50-70M (3%). Lost: slightly later
notice of a job gone wrong.

**B. What every agent starts with: 54k tokens at its first call (median), before it reads anything.** Each 1k removed
saves about 12k weighted per agent, 5.6M per 8 days. Candidates: the list of about 30 AWS and other skills and the
connector tools (my estimate 5k+; AWS work goes through `tools/aws/*.py`, which needs none of it), the memory index
(4.5k, mostly other projects), and the "User-facing text" section of the global CLAUDE.md (about 2k, needed only by
agents writing player text). Recommend turning off the AWS and Stripe plugins for maps sessions, and moving the text
guide to a file text-writing agents read. Saves 20-50M (1-2.5%). **Your files and your setup, so your call.** Lost: AWS
skills on hand in the rare AWS session; a risk that a text agent forgets to read the guide.

**C. Opus for 90% of tokens** (1,769M of 1,970M; Sonnet 201M), though you said on 11-09 to use Sonnet for
straightforward work. The biggest lever on your usage limit, and not a cut. Recommend the orchestrator default to Sonnet
for briefs with known files and an easy check, per your global tier notes. Lost: some Sonnet rounds that get redone.

**D. Spec docs for every small UI change.** The `ui-*` docs are 140k tokens and were edited about 680 times in 8 days.
Agents read them mostly in order to edit them (ui-panels: 47 agents read and edited, 20 read only; only
`localization.md` is mainly a reference). All docs together are about 3% of tokens. Recommend: a small UI tweak
(label, spacing, colour) updates a doc only if a rule changed. Your "the spec says what is true now" rule stays for rules
and behaviour. Lost: docs get less exact on small UI facts; code is the reference there. Your rule, so your call.

**E. Smoke twice before a landing.** A tree agent runs smoke, then the orchestrator runs it again on the same
files before `land` (since 11-01: agents 134 runs, the orchestrator about 73 on dev or trees and 79 on 8800). Recommend the orchestrator skips it when the agent's smoke was on
the final state, and runs one smoke on master after a batch lands. Saves about 3 minutes per landing. Lost: the failure
is found after landing, and needs a revert or fix.

**F. Handoff edit habit** (9% of orchestrator tokens, 38 edits a session). You asked for it to be current so a takeover
can happen any time, and that works. Recommend one edit per event that changes the plan, folded in with the other
bookkeeping of that turn, not one per message. Saves maybe a third (8M).

**G. "One simple Bash command per call."** Your rule, to avoid prompts, and each extra call costs 20-35k. Claude Code's
docs now say each part of a chained command is checked on its own, but reports conflict on whether that works. Worth
one test in a real session: `git status && git diff --stat`. If it doesn't prompt, read-only chains could be allowed.
Savings unknown until tested.

**H. T-2377 and T-2378 (CLAUDE.md cut, DECISIONS and ARCHIVE split).** Both still open. T-2378 is not worth doing:
those files cost almost nothing as they are; I'd abandon it. T-2377 would save about 12M (0.6%) and is worth doing at a
quiet moment, showing you the result as planned.

## 3. Looked wasteful, earns its keep

- **8800 smoke in light.** A production build copies only listed pack files (T-377: packs missing from the build,
  demand never finished, while dev passed). The 53-error FAIL on 11-04 was production-only too; I couldn't tell from the transcript what it was.
- **Both `cargo test` runs after a sim change.** Two tests broke unseen without the feature flag (T-2250). 1 minute.
- **Worktrees.** 23M, against agents breaking each other's demand loading (2026-10-22).
- **Browser part of smoke.** `no console errors` failed 44 times, `start menu` 12, `demand final` 8. Some were
  network or load trouble, but several were real bugs (`profileS is not defined`, `lean_loads`, the periods mismatch).
- **The tiny Node checks** (t133, t144-146, t1053, t2021, t2022, t2552): 0.1-1 s each.
- **File counts.** 392 notes and 417 entries in `notes/` cost nothing; agents open them by id.
- **Reading player text before release, and region names exempt.** Your rule; I found no sign of a large token cost,
  and it started after a bad string got through ("grey fills a platform", 2026-10-29).
