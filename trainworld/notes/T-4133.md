# T-4133 Edits move only the trains they can change (agent trainmove, 2026-11-24)

## What changed

- `Service::note_changes` (sim/src/track/service.rs) works a running train out again only when its line could have
  moved it: the line was noted during the edit (`Service::changed` since `before_edit`: rebuilt, rescheduled, its
  profiles recomputed, the net changed under it, or its variants moved by `timing::retime`, bounded in T-4132, which
  notes the lines it moved) or its pattern or trip lengths moved (the era test, still run for every line). That list
  is the one the clock worker already reads lines again by (T-1382), so nothing new decides "what an edit touched".
  A settle notes every line it scheduled, most unmoved, so the list alone is often every line: each train in the
  snapshot also carries a key of what moving it reads (`train_key`: its profile's phases and length, its run's path
  and offsets), and a train whose profile and run after the edit give the same key stands where it was.
- `before_edit` collects what it did (every line's pattern and trip lengths, every train running at the edit) plus
  that key, worked out once per line, run, slot and variant. It stays whole: it runs before the edit, when what the
  edit will touch is not known. Bounding it would need a guess at what an edit reaches (settles, spacing, retime
  clusters) or a snapshot kept between edits, which holds only while the clock is paused. Natively it is about 5 ms an
  edit on the Asia save at 07:00 (about 2,450 trains running): 2.2 ms the trips walk, the rest each train's place
  (the bisection for trains standing at a platform is most of it). Not filed: the orchestrator's call.
- What the full walk did and the bounded one does not: work an unchanged train out again from where it stood, which
  rounds its shift (the bisection in `time_reaching`) by at most 5.5e-10 s and moves its entry to the end of its
  line's shift list (read by lookup, so the order means nothing; a save lists them in another order). No train is
  placed otherwise.
- Check mode, native only (`sim/src/track/service/check.rs`, T-4132's pattern): `TW_TRAINS_CHECK=1` runs the full walk on
  a copy of the service beside every bounded one and panics where any line's eras differ, its shifts hold other
  trains, or a shift differs by more than 1e-6 s (rounding below that is counted); `TW_TRAINS_CHECK=skip` leaves the
  first line with a train to move out of the bounded walk, so the check must fail; `TW_TRAINS=full` walks every
  train (master's rule) to time both in one binary. `edit_fuzz` prints per-op figures with `TW_TRAINS_STATS=1` (op,
  apply ms, before_edit ms, note_changes ms, trains running, trains walked) and the totals at the end ("trains stats").
- docs/track-and-service.md "Trains join and leave at the ends": one clause on which trains are worked out again.

## Memory

Nothing kept between edits. While an edit applies: 8 bytes more per running train in `Before` (about 20 KB on Asia at
07:00) and the keys of the profiles running trains use (about 600 x 16 bytes), freed when the edit ends. Against the
10 MB budget: 0 MB kept, under 0.1 MB while an edit applies.

## Found on the way

- **Master's production build does not start.** Every build of master since T-4147 stage 1 (2171510df) that I opened
  (perf_bench's `trainmove-base` = 2b730e8a, `busland-base` = fbe22879, `trainmove-head`) stops at "Demand could not
  load": the clock worker throws "Cannot read properties of undefined (reading 'lineWord')". Cause: an import cycle,
  workers/clockWord.ts imports `* as lines` from clockWordLines.ts, which imports `lineEdges` from clockWord.ts, and
  clockWord.ts reads `lines` while its module starts (`const KINDS = [..., kind(lines, "lineWord"), ...]`); Vite's dev
  server is fine, the bundle is not. Building `KINDS` when it is used (a function) fixes it in the bundle (tried in a
  perf build only, not kept: not my file). This breaks perf_bench for everyone (the boot times out; other agents'
  compares at 03:58, 04:14 and 05:00 failed the same way) and would break a publish.
