# T-3318 place names (feedback 2026-11-12)

## 1. Changshu in Chinese
Cause: Changshu is a zone (`cau`, kind zone, Changshu + Taicang). `tPlace` only had Wikidata labels for the 451
registry cities; all 3,531 zones showed their Latin name in ja and zh. Same for every zone, not one place.
Fix: `tools/place_names.mjs --zones` writes `app/src/i18n/place-names-zones.json` (same Wikidata matching as cities);
`i18n/places.ts` loads it lazily the first time a ja/zh name is asked for. Search by the local name works through
`cityMatch`, which already reads `tPlace`.
Also: 19 cities (Morocco, Egypt, Algeria, Tunisia, Israel, Palestine) had no entry; `--redo` added them.

## 2. Hyogo shows as Osaka
No screenshot in the thread. Cause found: the registry city `osa` is Keihanshin (Kyoto, Osaka, Hyogo, Nara). English
shows "Kansai" (zone-names.json) but the Wikidata match was Osaka city, so ja/zh showed 大阪 for the whole metro,
Kobe and Himeji included. `dor` (shown "Ruhr") had the same fault: it showed Dortmund.
Fix: `HAND_LABELS` in place_names.mjs: osa = 関西 / 关西 / 關西, dor = ルール地方 / 鲁尔区 / 魯爾區.
If the player meant something else (a flag, a map label), the thread gives no more.

## 3. Senzan Line skips Toshogu
Fact: real order from Sendai is Sendai, Toshogu, Kita-Sendai, Kitayama... (OSM relation 12467357 and the player agree).
OSM relation 12467356 (Sendai to Yamagata local) and 5262910 (rapid) leave Toshogu out; the opposite-direction
relations have it. `realnet.build_lines` kept the busier pattern and dropped the other as a "variant", and the
day filter timed reverse trips later so the Toshogu-less one won by a few trips.
Fix: `pipeline/realnet.py build_lines`: a pattern takes the trip counts of patterns with its ends and a subset of its
stops when ordering; equal totals go to the longer. Check: `net sdj` into scratch gave both Senzan lines
Sendai, Toshogu, Kita-Sendai... (scratchpad names/net_sdj.py). Other cities change only where two patterns share
ends and 80% of stops.
Rebuild (orchestrator; writes data/work and data/packs/real/sdj.save, small city, est 10-15 min):
    cd trainworld
    ..\venv\Scripts\python.exe pipeline\realnet.py net sdj
    ..\venv\Scripts\python.exe pipeline\realnet.py geom sdj
    ..\venv\Scripts\python.exe pipeline\realnet.py route sdj
    ..\venv\Scripts\python.exe pipeline\realcorridors.py sdj
    (realsave bin, --shared, then) ..\venv\Scripts\python.exe pipeline\realnet.py gamesave sdj
    ..\venv\Scripts\python.exe pipeline\realnet.py ship sdj
The exact middle steps are as `realauto.py build` runs them (`realsave --dir OUT --city sdj --out OUT --shared --slow`);
check how sdj.save was last made (T-3233 frame) before running.

## T-3324 filter (2026-11-12)
`tools/place_names_check.py`: China and Taiwan zh labels must read (pypinyin, heteronyms tried, ethnic-autonomous suffixes
and trailing Xian/Qu/Shi/City ignored) as the name the game shows (zone-names.json name, else the registry's). Dropped
entries become `{"q": null}` (ja too, same item). Results: zones 506 -> 488 kept after the shown-name rule; China 483 of
638 zones keep a name, Taiwan 5 of 9, cities 89 of 89 (luo 漯河 set by hand: pypinyin has no "luo" for 漯). 19 hand-checked non-pinyin names in KEEP.
Dropped examples: Cao -> 曹国, Jincheng Township -> 福建省, Lin'an -> 杭州, Longjiang -> 齐齐哈尔; 8 more where the shown name
(Penghu, Fushun County, Lu County, Hsinchu, Zhangye, Yunyang) differs from the registry name the match used.
Spot check of 12 random China zones (seed 77): all read as the shown name (Kuqa 龟兹, Songyuan 松原, Dandong 丹东, Yulin 榆林...).
pypinyin installed with `pip install --target <scratchpad>/pp pypinyin` (3.9 MB, not in the venv).
Japanese labels not checked (36 of 38 Japan zones have one).
