## What profit is

`dayProfit(inc, m)` (game/profitEstimate.ts), on the weekday's income (`incomeByDay[0]`): the weekday's fares minus
running cost a day (`runningADay`, the clock's weekday running per period) minus the network's upkeep (track, stations,
buses), US$. It is the edit note's "profit per weekday" figure (editNote.ts `figuresOf` now calls the same function)
and the Money panel's Fares, Running trains and Upkeep rows; new trains, construction and the loan stay out, as
Cities' `net` leaves them out. DECISIONS 2026-11-20.

- One world board (`profit`), no city or country boards: the page has no per-region weekday profit.
- A loss is sent and stored (signed), but only a profit above 0 has a row, as a 0 score has none. Changing that later
  is a server change only.
- Ties share a rank, by name, as on the points boards. Each person's row is their best game's profit.

## Client (tree)

- `game/account.ts` `figures()` adds `profit` (rounded, clamped to ±1e14, left out when not finite) from the same whole
  final as the points (T-3639), so the same guards hold (sandbox, copy and modded latch, published build, T-3707). It
  is in the change signature, so a profit-only change sends; so is the config's `trainworldProfit`, so a game sent to
  a server that dropped `profit` (publish before deploy) is sent again once the server keeps it.
- `fetchBoards` remembers a board asked for while another is fetching and fetches it next (Profit clicked as the
  panel opens was dropped before; checked in the not-joined screenshots).
- `ui/Leaderboard.tsx`: a Points / Profit `Segmented` above the picker, shown only when `/noritetsu/config` says
  `trainworldProfit` (so the published game against today's server shows nothing new). Profit hides the picker; Points
  goes back to the points board last shown. Rows show `money()` (the viewer's currency), hover the exact figure and the
  rule line. `.lb-kind` 8 px under it, as `.lb-find`.
- An old server ignores the extra field (plain `json.Unmarshal`), so sending it always is safe.

## Server (shonei-server)

`twGame.Profit *float64` and `twScoreRequest.Profit *float64` (absent differs from 0); range ±1e14 (400 past it);
`indexGames` keeps the best profit of the games that have one; `value("profit")` and `boardKeys` list it above 0;
`handleBoard` accepts the key; config `trainworldProfit`. No new route. Test `TestTwProfitBoard`: ranking by profit
against points, a loss stored and unlisted, a send without profit taking the game off, 0 unlisted, ±2e14 refused, a
sandbox latch taking it off, a reload reading it back. `go test ./...` passes.
