# T-4284 stage 5: what the page still went over whole after an edit (agent pagestage5b, 2026-11-28)

**For Anita.** After an edit the page now does a few more things only for what the edit changed: the busiest-station
figure behind the achievements reads only the stations the edit touched, the lists of stations and lines by id are kept
while those lists stay the same (they were made again for every state), the map the pointer picks on keeps each edit's
new pieces in a small grid of their own instead of laying every piece added since the last full build again, and a
state's money, world and panels are set in one go, so whatever reads two of them works once per state, not once per
signal (the track hover tag did 4-5 times). Fare income makes its per-line money with less churn. Nothing you see
changes except timing. On New York the page's take of a placed station was 7-11 ms without the network, against 12 at
stage 4; the machine was busy (the bench run is stamped noisy), so that is an indication, not a figure. Your Asia save
was not measured in this stage (its budget is one New York bench run).

## The cause, in the code

What a station placed or removed still made the page go over whole, after stage 4, T-4300 (complexes) and T-4314 (reach,
trains' fill):

1. **The take set its signals one at a time** (workers/clockClient.ts `takeStateNow`): `setMoneyState` (two signals),
   `worldIsRows`, `rightHand`, `world`, then `pendingTaken`. Outside a batch each write runs its effects at once, so
   an effect reading two of them ran twice a state, the first time on the new money and the last world (the
   achievements' post, which reads the money and the figures on the world; the guide; the ripple). The track hover's
   effect queued a tag update per run (4-5 calls, 3.9 ms on Asia at stage 4); the previous run gave it one microtask.
2. **The world's lookups were keyed by `save`** (game/world.ts `lookup`), which `toWorld` makes anew for every state:
   `stationsById`, `stationsByNum`, `linesById`, `linesByNum`, `listedLines`, `linesAtMap` (every stop of every
   line), `lineIndicesAt` were made again for every state, an edit's or not, by whichever reader came first.
3. **The busiest station** (game/achievements.ts `demandFiguresOf`): every station of the view, four map lookups each
   (the world's station, its complex, the complex's slot, a station of its own), on every world whose stations or
   running lines changed.
4. **The pick grids** (map/cellIndex.ts `carry`): a carried grid kept one grid of every item added since its base was
   built and made it again at each edit, renumbering every one of those items: the more edits since the base, the
   costlier (up to an eighth of the set, about 12,500 segments on New York, before a whole rebuild).
5. **Fare income** (game/money.ts): by the base pool rule (T-2104) any line's passenger-km moving re-shares every
   line's base fares, so every line's money is made again on each kind of day, with closures and four arrays per
   line; `baseTrips` also copied its map twice per call.

## What changed

- **One flush per state**: `takeStateNow` sets the money, rows flag, hand, world, tools' world and pending panels in one
  `batch`; effects run once, on the state as a whole, before `onState` hands the renderer its network (as before).
- **Lookups per list** (world.ts): keyed by the list each reads (`save.stations` or `save.lines`), which `toWorld` keeps
  as the same object while none of its records changed.
- **Busiest station by change** (achievements.ts `stationRowsOf`): one row per station of the view in the view's order
  (boardings, changes, in the world or not, name, complex as a group of the rows' own), kept while the view is the
  same; the stations the world's diff and `complexChanges` name are read again. The pass left is over typed arrays, in
  the same order with the same tie rule, so the figures are the same to the bit.
- **Pick grids** (cellIndex.ts `PatchedIndex`): the items added at each edit go in a small grid of their own, numbered
  as at that edit, with the runs since composed onto it; past 8 such grids they are merged into one. A carry costs the
  runs and that edit's new items.
- **Fare income**: `ownMoney` without closures (the same sums in the same order); `baseTrips` returns its kept map.
- **edit_bench** (tools/edit_bench.mjs): waits for the load's clock hold as well as the final (`held: true`); see below.
- docs/architecture.md: the pick grids' carry.

## Not taken from Gemini's patch

  would end those copies (about 1 ms an edit on Asia by stage 4's figures), but every reader of `w.nodes` would then
  iterate a stand-in Map through generators, and any code that sets or clones one breaks. Left (below).
- `baseTrips` returning the last shares when no line's part changed: when no part changes the shares come out equal

- `sameShape` by the diff (about 30 us), the `PerLine` dirty map, the composed carry of grids never asked for (the
  per-edit grids do it).

## Left

  hover (3.9), the complexes and dot groups (2.5 and 1.0, T-4300), the reach (2.3-4.2, T-4314), the busiest station's
  lookups and the pick grids' re-laying are gone or cut.

  passenger-km moves (the base pool, T-2104), on each kind of day: a pass of arithmetic over every line. Keeping it to
  the edited lines would need the pool re-shared later (a lie, Anita's call); not worth it at a few ms.
- **Whole map copies each world**: the nodes map (`laidNodes`, for the state's world and the tools' click world; 9,215
  on Asia), `stopsOf`'s two maps, the click map's edge points, `stationsById` on a station edit. A persistent map would
  end them (see "Not taken").
- **The snap edge grid** (map/snapIndex.ts `layEdges`): its laid-over part is made again over every edge touched since
  its base at each edit, the pattern fixed here for the pick grids: T-4576.
- The demand figures' built zones (a zone lookup per station) and `corridorSums`' key (the places sorted) still go over
  every station and place when the stations change.
