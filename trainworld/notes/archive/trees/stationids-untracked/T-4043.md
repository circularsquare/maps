## Plan (agreed with the advisor, not built)

**Storage**
1. Stations get their own id space: `Network::stations` indexed by a `StationId` (a newtype like `TrackId`, so the
   compiler finds node/id mixups), with alloc, claim and a free list (as nodes, edges, lines in net/store.rs), plus
   `node_station: Vec<u32>` (stop node -> station id, NONE). Ids are dense and **never equal to node ids by rule**:
   with identity on old saves, a node passed where an id is meant still works and no test sees it. Test any scheme
   against "split off the node the station was first placed at: what is the rest's id?".
2. **Keep the node-keyed accessors** (`platform_len(n)`, `is_station(n)`, `station_name(n)`, `station_built(n)` and
   the rest in net/stations.rs): they mean "the station at stop node n" and change only inside stations.rs. That
   leaves about 700 call sites alone (platform_len 179 in 57 files, line_stops 228 in 53, station_data 57,
   set_station 90), and perdir.rs, legs.rs, snapshot.rs and addtrack's files untouched.
3. **Stops and rows stay stop nodes**: line stops, `picks`, `ones`, `only`, demand rows (`demand_stations`, one row
   per stop node, as 06-demand says) and platform ids (`2n`, `2n + 1`, node-local) keep naming stop nodes. Only
   `Platform::station` becomes the real station id. No column added to `demand_stations`. This boundary is the main
   thing Join inherits.
4. **Undo**: `Op::Station { node, data }` stays node-keyed; `StationData` gains `id: Option<StationId>` (None: the
   node keeps its station, else a fresh id; Some: join or recreate that id, claiming it). `station_data(n)` returns
   the concrete id, so every inverse restores the same id. Check that history replays inverses with the concrete id,
   never the original "new" op. A station record is freed when its last stop node leaves. Setting a shared record
   through one node must touch every node of the station (`touch.stations`, `names_changed`), since labels are by node.
5. **Spread audit** (the quiet failure): every `StationData { .., ..old }` or `station_data(a)` applied to a
   *different* node would now silently join two nodes into one station. Sites to check: wasm/draw.rs ~1235 (twin /
   one-track copy), rebuild.rs ~617, split and move paths, `convert_frame` (save.rs ~1169), quad twin placement
   (`station_beside`), crossings.rs renames. About 25 full `StationData { .. }` literals need the new field (list:
   `grep -rn "StationData {" sim/src`).
6. Complexes (complexes.rs): union every stop node of one station into one complex (identity on old saves).

**Save**
- With one stop node per station, write exactly today's bytes, so the re-saved-bytes gate keeps its power.
- Extra stop nodes of a station go where an older reader counts them unread. Found: TWT7 `read_body` station flags
  count bits from 3 as unknown (save.rs ~1959), but a flag that adds a field changes the layout, so an older reader
  would misparse rather than refuse. Two choices: a trailing block (say `LSJ1`: per joined stop node its node index
  and the node index of its station's first node), written only when a station has two stop nodes; an older build
  then sees bytes left over and refuses (`save_unread` > 0 -> `SAVE_NEWER`, clock.worker.ts:307). Or body level 5
  with the station's other nodes in the station section. The block was leaning; before writing after `LBN1`, check
  what `bare_end` (`rposition(b"LBN1")`, save.rs ~2216) assumes. Either way update `BLOCKS`, `LEVEL` (and the
  app's `SAVE_LEVEL`) if bumped, and `pipeline/readsave.py`.
- Leave the node-indexed blocks (`LNK1`, `LOR1`, `LFR3`, `LFZ1`, `LSN1`, `LBT1`, `LBD1`) as they are: each stop node
  writes its station's shared fields, which load back onto the one record. Old saves: each station entry becomes
  its own station, ids assigned in node order.
