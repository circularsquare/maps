# T-2227: does the road-crossing count make placing track laggier?

Anita, 2026-11-03: "does checking for road crossing smake track placement a bit laggier? it does fel laggier than before."

Measured with `checks/t2227-roads-lag.mjs` on my Vite (6191), one demand worker, the machine loaded by
other agents (15 of 15 cores claimed for part of it). `?perfOff=roads` stops the road tiles reaching
the track model, so nothing is counted. Logs and JSON: `artifacts/trainworld/t2226/` (`before.log`,
`tiles.log`, `after.log`).

## Before (runs interleaved on, off; medians over runs)

| case | ghost cold p50 / p95 / worst | ghost warm p50 / p95 | click to redraw |
|---|---|---|---|
| new game, roads on (3 runs) | 2.5 / 6.8 / 16-96 ms | 2.3 / 3.3 | 62 ms |
| new game, roads off (3) | 2.3 / 3.1 / 13-14 | 2.2 / 2.8 | 62 ms |
| real save, roads on (2) | 6.1 / 26.7 / 52-90 | 5.5 / 6.9 (one run 19.5 / 92, noise) | 339 ms |
| real save, roads off (2) | 6.4 / 54.9 / 20-113 | 5.4 / 6.8 (one run 11 / 55, noise) | 271 ms |

Frame gaps were 17 ms at p95 in every case: the main thread never felt it. Warm (tiles already in),
no difference. The cost is all on the first pass over a place, when tiles land on the clock worker,
which the ghost's previews wait behind. Placement on the real save varied 210-360 ms with roads on or
off; the 40-70 ms gap is within the spread between runs of one case.

Per tile on the clock worker (`tiles.log`): MVT decode 2-22 ms, install (`add_road_tile`) 0.1-1.8 ms
on a new game and 1.5-12 ms on the real save (`Network::rework_ground` tests every edge's pieces).

## Fix

`map/roadTiles.ts` `decodeRoads` read every layer's keys and values as strings (building, place and
POI layers too) before looking at the layer's name, with a new `TextDecoder` for each. It now skips
any layer but `transportation` on its name. Same lines and weights to the element on eight New York
tiles, both `keep`s; 6x faster in Node (31.5 to 5.5 ms for the set). Bus routes (T-1465) use the same reader.

## After

Decode 0.1-2.8 ms a tile in the worker. New game cold ghost p95 4.7 and 2.8 ms over two runs (roads
off 2.8), worst 15 ms (off 15). Real save cold p95 15.6 and 11.6 (off 6.9), worst 40-49, the rest
being the install's 2-11 ms a tile: T-2230. Placement unchanged within noise (real save 266 ms on,
241 off; new game 65 and 61).

## Seen on the way

The fifth placement (a segment at -73.855, 40.672, Ozone Park) took 1.8-2.7 s on the real save with
roads on or off, nearly all of it the worker's state buffers (`networkFromState`, `s.ms[1]`
1.4-2.5 s): not roads; reported to the orchestrator for its own task.
