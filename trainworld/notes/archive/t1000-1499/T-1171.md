# T-1171: planned lines priced on every clock state

## Before

Every state the clock worker built ran `blueprint_cost_items` (a trial construction of the whole
blueprint, for the cars to buy) and, per planned line, `line_build_cost` (another trial) and
`line_train_cost` (`cars_needed` over every line), whether or not any panel showed them.

Measured in Node on the track WASM (scratch `quote-bench.mjs`: the real New York save, 12 planned
lines drawn as 6 km blueprint pieces with a station at each end):

| per state | ms |
|---|---|
| `blueprint_cost_items` | 172 |
| `line_build_cost` + `line_train_cost`, all 12 planned lines | 1,124 (93 a line) |
| `costs()` (total and built, kept) | 0.1 |

So about 1.3 s of the worker on every edit of a game with 12 planned lines on this network (T-1156
measured 8-10 ms a line on its China save; the per-line trial grows with the service it settles).

## After

A state carries neither: `ClockLine.buildCost/trainCost` and `ClockState.blueprintItems` are gone.
Two clock queries, `blueprintQuote` and `lineCost { line }`, answer them; `game/quotes.ts` asks only
for what a shown panel needs (the Build tab's total, breakdown and disabled cost; a planned line's
Construct button, `ui/inspector/ConstructButton.tsx`), one answer per world version shared between
panels, asked 250 ms after the last world change so a run of clicks pays for one trial. The C key
asks the quote at once. A state's quote cost is now 0 ms; the Build tab pays one
`blueprint_cost_items` (172 ms above) once edits pause, a line panel one line's trial (93 ms).

Checks: `t1382-rows` PASS (rows equal a full read); `t1270-terrain` PASS (its quote rows now asked by
query; Construct charges the quote); a scratch page check (a planned line in a new game: the panel's
"Construct for $287M" equals the `lineCost` answer and the blueprint quote's total).

Trade-off (DECISIONS.md 2026-10-27): the quote shown can be up to about 300 ms behind the last edit.
