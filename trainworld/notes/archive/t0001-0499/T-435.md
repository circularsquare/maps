# T-435: the market's zone pair loop

2026-10-15. `IntercityApi::pass_on`, the loop over market zone pairs (each pair's home access
stations times its far-end access stations).

## What the loop does on the real save

Real New York save (T-007-real-nyc.save's network, `data/work/realnet/nyc_real_track.json`, the
seven Northeast market packs it reaches), one pass: 379,120 zone pairs, 7.40M access station pairs,
7.06M (95%) with a finite rail cost, 680 zone pairs with none. Skipping pairs with no finite cost
was already there (the `is_finite` check before the exp), so that half of the proposal had nothing
left to win.

## Change

- one `terms` buffer reused across zone pairs (was a new `Vec` a zone pair, 379k allocations a
  pass);
- terms keep (from station, to station) instead of a flat index, so the scatter does no `/` and `%`;
- the skim row sliced once per home station;
- exp in f32 (the argument was already f32, clamped to +-80, so it cannot overflow).

The first three are result-identical (checked bit for bit: seg, boardings, summaries). The f32 exp
moves figures by float rounding only.

## Measured

Native release, one worker solving all five periods with T-434's per-period stop, T-434's probe
(scratch bin `t435.rs`, timer around the loop). Box shared with another agent's builds, so solve
times move +-1 s between runs.

| | Before | Same results, no f32 | After (with f32 exp) |
|---|---:|---:|---:|
| Market pair loop, whole solve (ms) | 2,393 / 2,570 / 3,163 | 1,794 / 1,822 | 1,477 / 1,660 / 1,588 |
| Per pass, period 0 free flow (ms) | 145 | | about 90 |
| Whole solve (s) | 25.0 / 26.3 / 26.1 | 25.3 / 25.4 | 24.8 / 26.3 / 26.0 |

The loop is about 38% faster (median 2,570 to 1,588 ms), about 1 s of a 25-26 s solve (4%), which
is inside the solve's run-to-run noise here. Rounds run by period unchanged (3, 3, 3, 2, 1).
