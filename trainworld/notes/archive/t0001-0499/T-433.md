# T-433: the everyday layer's assignment in one pass

2026-10-15. `sim/src/demand/everyday.rs` only.

## What changed

- A purpose's pairs fill the one station-pair matrix as before; at the purpose's end its trips are
  packed into columns by destination (origins ascending, only the rows written are scanned), and
  the matrix is reused. Then `assign_lanes` walks each destination's strategy once with a lane per
  purpose (`[f32; 8]`), each lane doing `kernel::DestWalk`'s arithmetic in its order. Before, the
  kernel assigned each purpose separately: six walks of every strategy, six strided reads and six
  clears of the S x S matrix.
- Loads are identical to the bit. The transfers note an arrival's riders summed over the lanes, so
  they differ from the purpose-by-purpose count by float rounding (DECISIONS.md).
- `lanes_match_the_kernel_assignment` (and `purpose_parts_add_up_to_loads_and_cell_modes`) turn on
  `check_lanes`, which assigns each purpose alone with the kernel inside every pass and compares
  every load to the bit and the transfers to 1e-5. `assign_lanes` copies `DestWalk`: a change
  there must be made in both, and the test catches a miss.
- The pair loop in `F8` lanes (T-036's way, eight directions at a time, terms padded with zeros)
  was built, gave identical results, and was 15-20% slower than the scalar loop, so it was taken
  out. A direction has 25 access-pair terms on average (24M terms a New York pass), each a random
  read of the station table and a write of the matrix; timing with the spread or the sum removed
  put the spread at about 40% of the loop, the sum 30%, the logit and drive arithmetic (what lanes
  speed up) under 30%. Caching the station values from the sum for the spread did not help either.
