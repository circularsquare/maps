## T-670, line editing
1. **One edit mode for bullet and name.** "we can double click the bullet to edit the bullet and the
   pencil to edit the name. lets have both of these enter the same 'edit' mode where we can edit both
   the bullet stuff and the name." Double click on the bullet and the pencil open one editor holding
   the name (`NameEdit.tsx`), the symbol and the colour. Settle the layout yourself; one Done or click
   away closes it.
2. **Edit stops higher.** "for a line, put the 'edit stops' panel higher...": while a line is selected
   the stops editor sits near the top of its inspector instead of below the daily figures. Judge
   the order against what the panel shows (CLAUDE.md: panels show what can change).
3. **New line from a lineless track.** "if we select a track with no line running on it its likely
   cuz we want to make a new line to assign it there. so maybe lets put an instance of new line button
   here": the track inspector (`others.tsx`) shows a New line button when no line runs on the
   selected track; it does what the Lines tab's new line does (`game/lineActions.ts`), starting on
   this track if that flow allows, else plain. Icon button with a hover.
4. **Hotkeys** for new line, edit stops and construct blueprints. Look at what `keys.ts`, `tools.ts`
   and `main.ts` already bind; pick free single letters that sit well together (N for new line is
   the obvious one), never fire while a text field is focused (T-183), and put the key in each
   button's hover. List them in the report.
5. **City column.** "in the lines view if we have the whole world selected and we have built stuff in
   multiple cities lets show a 'city' column next to the line names" (`tabs.tsx`, the Lines list).
   Only when the region filter is the whole world and lines span two or more cities; a line's city is
   where its first stop is (as local time does, SPEC 3). Use the names the Cities tab uses.

## T-672, the colour picker
"color picker is laggy, dragging it around freezes the game as we rerender. also looks quite clunky,
can reference languagedots for colorpicker ui." Today it is the browser's `<input type="color">`
(line ~433) with `onChange` into `setLineColour`.
- **Find the freeze first.** A drag fires the colour edit on every move, and each one is a clock
  worker edit, a network rebuild and a demand re-solve. The fix is that the drag only changes the
  preview (the chip, the line drawn on the map if that is cheap) and the edit is sent once on
  release, plus at most one every ~100 ms if the live line on the map matters. Measure with the real
  save before and after; report the numbers.
- **Look.** Replace the native input with our own small picker in the style of `languagedots/index.html`
  (read its picker: markup, behaviour, CSS) in our tokens (`ui/style.css`, light and dark): a hue and
  a saturation/lightness area, the preset swatches, a hex field. No CSS transitions (CLAUDE.md).
  Put it in `widgets.tsx` or its own file; other colour spots (themes in Settings?) may reuse it.
