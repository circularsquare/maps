# T-994 Local demand bubbles gone (not reproduced, 2026-10-23)

Anita, 2026-10-23 on 8800: "I'm not seeing local demand bubbles at all now, only intercity."
8800 was the 9292979 build (dist built 00:38).

## What was tried, all on 8800 unless noted, headless Chrome on the same RX 6600

Every case drew the local bubbles (`twViews.overlay.showBubbles`, `bubbles[level].count`,
`discsDrawn` > 0, screenshots in `artifacts/trainworld/t994*.png`):

- `?new=1` bare games in New York, Paris, Beijing; light and dark; Homes and Destinations.
- The real save imported, before and after its solve; clock paused and running; the track tool on.
- Start menu: a start on the world map then a zoom into New York; a start in New York.
- A saved game continued from its slot: the open fit lands at zoom 7.76 (the overview, zone bubbles
  only); zooming in by jump or by wheel brings the local bubbles; None, Destinations, Homes and a
  colouring switch keep them and do not move the camera.
- The reload from the demand cache: version 0 (the cached view) builds no bubbles (`cellModes` has
  no cells for it), and they come with the fresh solve, about 6-10 s on the real save. A game whose
  fresh solve takes minutes shows only the overview's zone bubbles until it lands.
- Lines in New York and Philadelphia, overview then each city; a line in New York only, then bare
  Philadelphia; a line in Hangzhou and in Paris on a world-map start.
- Phone size (412x915, DPR 2.625, touch); stored settings weekend day, Mode mix, detail 2.
- A bubble selection: near, far (588 discs) and inter-region discs all drawn.

The commits named in the brief were read for anything on the bubbles' path: the T-976 shader band
(local bubbles have edge 0, so they skip it), the T-976 overview dots, T-979 (trip queries only),
T-953 context loss, T-950 watchdog, T-951 CSS. None touches `display.commuters`, `cityOverview`
at city zoom, `cellModes` or the bubble upload.

## Open

Needs from Anita: desktop or phone, which game (city, how many zones built), the zoom, whether a
selection was on, and a screenshot. If on the Pixel: the disc shader's plain path (local bubbles,
edge 0) differs from the split path the zone bubbles take (edge 3 and up), so a GPU that gets the
first wrong would show exactly "only intercity".

Smoke now turns Homes on in the bare new game and on the real save and fails if no local disc
draws (`homesDrawn` in checks/smoke.mjs); before, smoke never turned Homes on (it is off by
default), so it could not see this.
