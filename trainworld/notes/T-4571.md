# T-4571 A gate can freeze app/ mid-landing

Cause: agent-tree finish merges the tree (app/ changes at once) and rebuilds the main tree's WASM about 8 minutes later (step 3).
A gate chunk starting in between (world_run.py freeze_app) copies app/ with the new demand.worker.ts but the old WASM.

Two fixes in the Goal: build the tree's WASM before the merge, or make freeze_app wait. Picked the wait.
The WASM is untracked, so the main tree's copy has to be rebuilt after the merge either way (and after a rebase the tree's
build is not the merged code), so building first removes nothing. A lock file is a few lines and covers plain `land` too.

Change:
- checks/agent-tree.mjs: holdLanding() writes data/work/landing.lock ({pid, since}) before landTree in `finish` (not --dry-run) and `land`;
  releaseLanding() after the WASM step, in finish's failure handler, and on process exit. Steps, messages and --dry-run unchanged.
- pipeline/world_run.py: freeze_app calls wait_for_landing(): waits (5 s polls) while the lock exists, owner pid is alive and it is under 45 min old.
  If a landing fails mid-way the lock is released by the failure handler, so a half-landed app/ is copied then (same as before the fix).

Not covered: sync-track (rebuilds WASM after merging master into tw/track; that checkout is not what a gate serves).
Checked: node --check, finish --dry-run output identical, world_run.py parses. No landing, no game run.
