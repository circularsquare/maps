# T-3450 Shiga shows as 志賀 in Japanese

## Cause

`tools/place_names.mjs` matched a zone to the Wikidata item with the most sitelinks whose English label or alias is the
zone's name, within 60 km of its centre. Japan's prefectures are labelled "Shiga Prefecture", not "Shiga", so the only
exact "Shiga" near the zone was Q2278690, the old town of Shiga (志賀町, Shiga District, merged into Ōtsu in 2006), 23 km
from the centre. With 5 sitelinks it went to the fallback search, which does see "Shiga Prefecture" (7 km away, 98
links) but ranked an exact name above sitelinks, so the dead town won. Distance could not catch it: it is a near
namesake of the wrong kind, not a far one. Iwate (岩手町) and Kamikawa (上川町) went the same way.

The audit (all 3,640 matches, coordinates, classes, P131 parents) found a bigger second cause: an entry is never matched
again once made, so a zone renamed later in `zone-names.json` kept the label of its old name (Kingsport showed
サリヴァン郡, Annecy オート＝サヴォワ県, Pingdingshan 郏县, East Jerusalem ラマッラー), and the match also accepted the
registry's raw name, so even a fresh match could name the county the English no longer shows. Smaller: a museum or camp
filed under settlements (Oświęcim matched the Auschwitz camp), and former countries (Crna Gora: Kingdom of Montenegro,
Kuqa: Kucha). No match was more than 60 km off.

## Fix

Rules in `tools/place_names_rules.mjs`, used by the tool and by `checks/place_names_match.mjs`:
- matched by the shown name; the registry's own name only when it is a spelling of it (edit distance 2);
- an item still existing beats a dissolved one; museums and concentration camps are never candidates;
- an existing entry whose item has no English name fitting the shown name is matched again on every run;
- a new match inside a unit named for the place (P131 chain), not that unit's seat (P36), whose label is a town's
  (町村镇鎮乡鄉郷) or, in JP/CN/TW/HK/MO/KR, a different hanzi spelling than the unit's, is swapped for the unit;
  a former country is dropped;
- near: within 60 km of the centre or inside the zone's box (towns and states that name a zone lie off its centre).

The check (about 10 minutes, Wikidata SPARQL, cached a week in %TEMP%) fails on: far, name, not a place, historical,
namesake. Not in smoke (network).

## Result

96 zones and 2 cities changed (old -> new, ja / zh-Hans); 62 new registry zones were matched in the same run. Full list
at the end; the prominent ones:
Shiga 志賀町 -> 滋賀県; Iwate 岩手町 -> 岩手県; Kamikawa 上川町 -> 上川総合振興局; Delhi ニューデリー -> デリー;
East Jerusalem ラマッラー -> 東エルサレム / 东耶路撒冷; Montenegro モンテネグロ王国 -> モンテネグロ; Maine カンバーランド郡 -> メイン州;
Vermont チッテンデン郡 -> バーモント州; Pingdingshan 郏县 -> 平顶山; Zhangye 甘州区 -> 张掖; Wuzhou 长洲区 -> 梧州;
Suizhou 随县 -> 随州; Chaling 攸县 -> 茶陵县; Oświęcim アウシュヴィッツ＝ビルケナウ強制収容所 -> オシフィエンチム;
Liberec, Botoșani, Samokov (was ソフィア), Livorno (was ピサ), Annecy and seven other French prefecture towns, 20 US
county zones now named for their town, Tierra del Fuego, Krabi, Tak.
Now Latin (no item fits the shown name near the zone): Kuqa, El Arish, Westerwald, Villa Carlos Paz, La Hormiga,
Latrobe Valley, Gia Nghia, Vi Thanh, Ha Tinh, Sahibganj, four Philippine island zones. Small places, left to the rule
(Anita 2026-11-16: hand-check only prominent cases).

Checks: place_names_check.py (pinyin) 89 + 487 kept, 0 dropped; place_names_match.mjs: 3,681 matches checked, 0 wrong (about 12 minutes uncached).
