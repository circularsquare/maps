# T-067 ? Player fares affect demand

Implemented 2026-10-10. The clock worker includes the current fare and actual forward/reverse track kilometres between stops in its demand snapshot. Fare edits schedule the same debounced snapshot as service edits. Demand's deduplication key includes fare and distances, so a price-only change starts a new version and supersedes an older solve.

The US value of time is $20/hour (3 perceived minutes per dollar), a gameplay judgement. The base is added once to a complete trip's rail generalised cost, outside the boarding/transfer graph; changing trains therefore does not charge the base again. The per-km charge is added to each ride edge using actual track length, so route searches as well as mode choice see distance pricing. Crowding multiplies riding minutes and leaves fare minutes unchanged. Existing income calculation continues to use the same actual line lengths and fare curve, with the existing 100x economy applied only to money.

The live default remains $1.50 plus $0.10/km. A legacy/test snapshot without a fare retains the previous flat 6 perceived minutes ($2 at this value of time); a snapshot without segment lengths uses station-to-station straight-line kilometres. No save format changes.
