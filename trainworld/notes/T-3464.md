# T-3464 Freight and abandoned rail in All

## What exists
- pipeline/real_extra.py: reads an OSM file (pbf, or .osm for a test), writes <cc>_extra.pmtiles (layer track, k = freight or abandoned) and keeps extra.json (regions that have a file) beside it. Imports noritetsu/build_tiles.py for the tile maths (read only; no noritetsu file changed).
- app/src/map/realNetwork.ts: when the setting is All and not snapping, adds each region's extra archive under its passenger layer (two layers: freight solid, abandoned dashed; MapLibre cannot vary a dash per feature). Reads `<base>data/extra.json` first; no file or no listing means nothing is drawn, so shipping the app before the rebuild is safe. `?realExtra=<url prefix>` points manifest and archives elsewhere (tests).
- Colours in game/shadeTable.ts (realFreight, realAbandoned), both themes.

## Full rebuild (overnight batch, not run)
noritetsu keeps no .pbf (deleted after extraction), and abandoned rail was never extracted, so this needs fresh Geofabrik extracts for the 118 regions (a new download, which noritetsu's HANDOFF says is Anita's say-so). Per region cc, one at a time:
    download <cc>'s pbf to a scratch folder
    python trainworld/pipeline/real_extra.py --region <cc> --pbf <file> --outdir noritetsu/dist/data
    delete the pbf
Regions cut from a bigger file (hk, sg, the gb/fr Channel Tunnel halves, ie vs Northern Ireland, cn, ru) take --bbox=w,s,e,n of the region's outline. Then upload noritetsu/dist/data/*_extra.pmtiles and extra.json to R2 beside the passenger files (noritetsu's own deploy; the app finds them through the same base).
Estimate (extrapolated from one dense test area, so rough): 2 cores, a pass over each pbf is the cost, about 1.5 to 3 hours of reading plus the downloads (tens of GB in all); output about 150 to 400 MB against 260 MB for the passenger tiles. A one-region check first: python real_extra.py on Germany or the US file, compare size and look.
