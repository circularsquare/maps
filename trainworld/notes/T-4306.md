# T-4306 Lines rows under the pointer

Cause: the rows in LinesTab (lines, group Fragments) and StationsTab had no keys, so Preact matched rows to elements by position. When the list sorted again, the element in a position got another line's props. A press began on an element; its click handler (closure over the line at render) then opened whichever line the element held at click time.

Fix: key each row (`l:<id>` / `g:<n>` Fragment in LinesTab, first member in StationsTab) so elements move with their lines. A moved element loses the click (the click lands on the list), so LinesTab pointerDown's end handler opens the line the press began on when no drag happened and the release was inside the list (pick(id), groups too).

Run (new game NYC, 4 lines, Vite 6180): tagged row elements follow their lines when sorting riders up/down; pressed a row, sorted again with the button held (rows reverse), released: the pressed line opened. Before the key and press fix the same sequence opened nothing/the old selection. Typecheck clean. Stations tab: keys only; its own pointerDown still has the lost-click case when the element moves (not changed).
