# T-4374: closing a loop refused with "at least two different stations"

Agent loopfix, 2026-11-27, tree `tw/loopfix`. Player thread 1795784564-e03329a7 (0.4.7, 42 lines, Mac Chrome): "not
letting me loop line, saying 'a line needs at least 2 different stations' despite it having multiple stations". No
save, no diagnostics. The same player's other thread (fares per mode) says they run several modes.

## Reading: where the message can come from

The text is `issues.lineStops`, the app's words for `Issue::LineStops`. It is shown only by edits that are not
quiet; bus and ferry tool edits are quiet (they say "The bus/ferry line could not be added ..."), and a bus line's
check never gives LineStops. So the player's refusal was a train or tram line edit. LineStops came from five
branches of `Network::check_route` (validate.rs): a stop that is no station; fewer than two stops with a path;
two equal stops in a row; a path that does not start at the first stop or end at the last; stops not along the
path in order (with no reversal). ferry.rs used it for every port problem too.

Every way the game makes or changes a loop, followed from the click to the check:

- Right click on the first or last stop ("close" tier, `stop_tiers` / `close_path`): tools.ts sends `setStops`
  with the first stop again at the end; `set_stops` -> `edited_stops` (adjacent repeats dropped, routed hop by
  hop through every stop, a closed list's path made to stop at every pass, `every_pass`). The stops then lie along
  the path in order, first at its start, last at its end, all stations: none of the five branches can fire. A
  shape `close_path` offered that routes differently in the edit gives LinePath or NoWayBack, never LineStops.
- Right click on the stop before a loop of track ("turn", `turn_end`): `turned` routes the new stops hop by hop and
  refuses repeats in a row; `every_pass` again; `branch_end` (T-3141) only rotates a circle's stops and path
  together. Same result.
- Open loop, the ring opened at a stop, a stop taken out of a loop (map click, panel row, panel dot), passed
  stations added (G, panel): all through `edited_stops`. Same result.
- Brief's suspects: (1) first and last stop equal and adjacent: only a one-stop line closed, which `close_path` never
  offers, and `distinct_stops` drops it anyway; (2) a linked station or complex: tiers are per station node, and a
  complex mate is only used for a run's own platform (`way_stops`), which refuses with LinePath; (3) a different
  platform of the first station: `close_path` then needs a reversal and the hover says "Trains would have to reverse
  to close a loop"; (4) a line already stopping twice at a station: open lines never do (`best_slot` refuses a
  repeat), and loops route as above.

So no loop edit in the code reaches LineStops. The one player-reachable producer found is **deleting a station a line
stops at** (`pieces_ops` in wasm/links.rs): the line's stops lose the station, and where its reroute failed the
old path was kept with the new stops, so a removed end left the path ending at the deleted station ("first or
last stop off the path", LineStops). T-4098's notes saw it: deleting a terminus past a one-way loop was refused
"LineStops". The same code also ignored T-3050: deleting a loop's first station opened the loop (stops [B, C, D]),
where taking that stop out of the line closes it again on its new first stop. A player who deleted a station while
reshaping a loop line could meet either. Which exact action this player took can't be told from the report.

## Fix

- sim/src/track/net.rs, validate.rs: LineStops is now only "fewer than two stops and a path to run". New issues:
  `StopTwice { line, node }` (the same station twice in a row), `StopNotStation { line, node }` (a stop that is no
  station, or a ferry line's that is no port), `StopsOffPath { line }` (stops not along the path in order, or a
  path not starting at the first stop and ending at the last). A refusal now names which.
- sim/src/track/ferry.rs: the same split for ferry lines (a route not calling at its ports is StopsOffPath).
- sim/src/track/wasm/links.rs: removing a station takes the stop out as a stop edit does (`edited_stops`, made
  `pub(super)` in lines.rs): a loop that loses its first stop closes again on its new first stop (T-3050), loops stop
  at every pass, one-way stations go where the track puts them. If that route adds a reversal or doesn't run, the old
  path is kept where it still runs the stops left, or where the removal takes the line's track too (left broken, as
  before). Otherwise the line is left alone and the station's removal is refused by `set_station` as
  `StationInUse` ("A line stops here. Take the station out of that line first."), its real cause.
- app/src/game/issues.ts: StopTwice and StopNotStation have their own words; StopsOffPath says LinePath's.
- docs/track-and-service.md "Lines": the removal rule. DECISIONS.md (main tree, Lines): the entry.
