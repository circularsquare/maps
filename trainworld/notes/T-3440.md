# T-3440 sharing a large network fails

Cause: shonei-server's drawing check (trainworld_community.go, check()) refused a network over a count cap (lines 1024, colours 256, stations 20,000, path points 1M, pills and passages 40,000) with a plain 400 bad-drawing. The game shows that as "couldn't send", with no hint it was the size. Byte limits (512 KB gzipped, 4 MB unpacked) already gave 413 too-big and the existing text "This network is too big to share."

Fix (shonei-server commit 372a8ce, not deployed): every count cap now answers 413 too-big (same existing message); caps doubled (lines 2048, colours 2048, stations 40,000, points 2M, pills and passages 80,000, upload 1 MB gzipped, 8 MB unpacked). The game's own limits in app/src/diagram/shared.ts (MAX_GZIP, MAX_RAW) match. Go tests pass (go test, Tw/Community).

Not measured: no real huge save was drawn, so which cap the player hit is unknown; the new caps are a guess at 2x headroom. The viewer has no size limit when painting, so very big drawings may paint slowly. Deploy needed on the server for the fix to reach players (Anita's word); the game change ships with the next publish.
