Anita's TODO 2026-11-12: "when people submit feedback allow them to attach a screenshot or up to 4 by pasting or attaching".

## What the existing shot was

The server's `screenshotPng` (one PNG, base64) comes from the Unity game's feedback panel. anitabuilder's form has never sent it (nothing under `trainworld/` mentions `screenshotPng`). So there is no automatic capture to keep; the field stays on the server and is untouched. The 4 pictures are a separate list that reuses the same storage folder, byte total, budget and removal.

## Stage 1, done (shonei-server, not deployed)

- `POST /trainworld/feedback` (threads on) takes `images: [{"type", "data"}]`, up to 4, new thread only. `type` is `image/webp`, `image/jpeg` or `image/png`; the bytes are checked to be that type; each at most 1.5 MB decoded; one bad one refuses the post.
- Errors, all `{code, error}`: 400 `too-many-images`, 400 `bad-image`, 413 `image-too-big` (a body past 9.5 MB gives 413 with no code), 507 `full` (pictures past half the store budget), plus the old 409 `too-many`, 429.
- `/noritetsu/config` has `trainworldFeedbackImages`: 4 with threads on, 0 off, absent on an older server. The form shows the picture control only when it is above 0.
- Inbox: `GET .../thread/<id>` has `images: [{n, type, bytes}]`; `GET .../thread/<id>/image/<n>` returns the bytes.
- `trainworld/tools/ops/feedback.py <id> --shot` saves the old shot (`<id>.png`) and every picture (`<id>-<n>.<ext>`) into `artifacts/trainworld/feedback/`; without `--shot` it says how many.
- The feedback inbox page (`trainworld/tools/feedback-inbox/`) is not changed. It does not show pictures yet; not asked for, say if wanted (small: thumbnails from `images`, fetched with the admin key).

## Stage 2, the form (not started; do not touch `app/` until told)

Files: `app/src/ui/FeedbackPanel.tsx` (the new-feedback form, around the `useState` block at line 95 and the `<form>` at 117), `app/src/game/account.ts` (`sendFeedback`, line 145), `app/src/i18n/messages/en.json` (`feedbackPanel.*`), `app/src/ui/style.css` or `account.css` for the thumbnails. New small module `app/src/game/feedbackImages.ts` for the encoding.

Form state: `images: {id, blob, url, type}[]` (max 4), `useState`. A thumbnail row under the textarea.

Adding pictures, three routes into one `addFiles(files: File[])`:
- paste: `onPaste` on the form (not only the textarea, so focus on the name field works); take `clipboardData.files` items whose type starts with `image/`; if it has any, `preventDefault` only when there is no text in the clipboard, so pasting text still works.
- file picker: a button wrapping `<input type="file" accept="image/png,image/jpeg,image/webp" multiple hidden>`.
- drop: `onDrop`/`onDragOver` on the form, same `addFiles` (cheap to add; the decision list did not name it, drop it if unwanted).

`addFiles`: ignore non-images, take only as many as fit in 4, show `tooManyImages` if some were left out. For each: `createImageBitmap(file)` (falls back to an `<img>` decode), scale so the long edge is at most 1920 (never up), draw on a canvas, `canvas.toBlob(cb, "image/webp", 0.85)`. If the blob's type comes back as `image/png` (Safari ignores webp), re-encode with `image/jpeg` at 0.85. A photo with transparency: fill white first for JPEG. If the result is over 1.5 MB, retry at quality 0.7, then 0.55, then fail with `imageTooBig`. Animated GIF is not accepted (picker and paste filter to the three types; GIF paste is dropped).

Thumbnails: 64 px squares from `URL.createObjectURL(blob)`, each with a small remove button (an x, `aria-label` "Remove picture"); revoke the URL on remove and on unmount. Counter "2/4" beside the attach button; the button is disabled at 4.

Send: `sendFeedback` gets `images?: Blob[]`; each becomes `{type: blob.type, data: base64}` (via `FileReader.readAsDataURL`, strip the prefix). Only sent when `accountConfig.trainworldFeedbackImages > 0`; hide the attach control otherwise (and ignore paste). Replies (`sendReply`) are unchanged and take no pictures.

Errors: `api()` gives an `ApiError` with the server's `code`; map `too-many-images`, `bad-image`, `image-too-big` (and a 413 without code) to the strings below, via the same `reason` slot the form uses ("{reason} Your message is still here."). On success clear the images and revoke their URLs.

Checks for stage 2: typecheck; headless: paste an image through a synthetic `ClipboardEvent`, pick two files, remove one, send against a local shonei-server with `SHONEI_FEEDBACK_THREADS=1`, read the thread with `feedback.py --shot`; a 5th picture is refused; a 6000 px screenshot comes out at 1920 px and under 1.5 MB.

## Strings (decided by the orchestrator, 2026-11-12; new, exactly as shown)

| key | text |
|---|---|
| `feedbackPanel.attach` | Attach screenshots |
| `feedbackPanel.imageCount` | {n}/4 |
| `feedbackPanel.imageRemove` | Remove screenshot (screen reader label) |
| `feedbackPanel.imageAlt` | Screenshot {n} (screen reader label) |
| `feedbackPanel.tooManyImages` | Only 4 screenshots fit. The rest were left out. |
| `feedbackPanel.badImage` | That file isn't an image the game can send. Use PNG, JPEG or WebP. |
| `feedbackPanel.imageTooBig` | That screenshot is too big, even after shrinking it. Try a smaller one. |

The 507 `full` case reuses the existing `feedbackPanel.full` ("Feedback is full right now. Try again later."). Drag and drop is in. The inbox page (`tools/feedback-inbox/`) also gets small thumbnails that open the full image (stage 2).
