# T-3038: how many players have each achievement

Anita, 2026-11-10: "could we start tracking how many people have got each achievement? and display that?
would that be okay / privacy okay". Built, with T-3037's hidden achievements (notes/T-3037.md).

## What the game already sends

shonei-server `/trainworld/ping` once a minute while a game is open: a per-page-load id, a second random
browser id kept in localStorage (`trainworld.browser`, the same across visits), the start city, sandbox, build
and browser language. The server keeps the browser id as a hash with its first and last day, forgets it after
395 days, and never keeps the IP. Nothing is sent with `?notrack`, on localhost or from an automated browser.
`app/public/privacy.html` says all of this under "Play counts".

## Design

- **Sent**: `POST /trainworld/achieved {"b": <the browser id>, "ids": ["orient", "cities:2"]}`, no session, only
  keys the browser has not sent before (remembered in localStorage `trainworld.achSent`), after a 4 s pause so a
  jump over several tiers is one post. Same quiet rules as the ping (`quiet()` in `game/playtime.ts`). A sandbox
  earns none and so sends none.
- **Counted**: `achievements.json` beside `playtime.json`: a count per achievement id, and per browser a hash of
  its id (salted differently from the plays file, so the two cannot be joined), the day it last wrote and the
  ids it sent, so a browser counts once. No IP, account, name or time of day. A browser unseen for 395 days is
  forgotten (the counts stay); at most 200,000 browsers and 300 distinct ids; 64 ids a post.
- **Shown**: `GET /trainworld/achievements` (public, cached 5 minutes) is `{"players", "counts"}`; `players` is
  the browsers the plays file knows. The achievements view's hover on every listed step (tiers, firsts, hidden
  ones once earned) ends with "12% of players have this" ("<1%" under one percent). Nothing shows until the
  server has answered with at least 20 players, or against a server without the routes
  (`/noritetsu/config` `trainworldAchievements`); the counts are asked for when the view opens, at most every 10
  minutes.
- **Privacy answer**: fine, because it adds only an achievement name to an id the game already sends and the
  server already hashes; it is never tied to an account; the privacy page has a paragraph for it. It stays
  within what the plays ping already does, so no new consent; `?notrack` turns it off with the pings.
- **Known gaps**: the share is browsers with the achievement over browsers the plays file knows, so a browser
  that earned one and was then forgotten (13 months idle) still counts in the numerator; the first load after
  this ships sends every achievement the open game already has; someone who clears site data counts again.
  Nobody can be identified from counts, and a count is not a way to guess one person's achievements.
