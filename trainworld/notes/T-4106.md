# T-4106: the install note on phones

Anita, 11-23: "i think we can still do the install as app banner. people can dismiss it... and we should just remember
that they have dismissed it". Decided by her: phones, after 2 hours of play, dismissed forever, logged-out players told
the app's saves are separate. Why install at all: notes/T-4086.md (no more memory; on iOS an installed app keeps its saves
past Safari's 7-day clearing).

## What it does

`app/src/ui/InstallBanner.tsx`, mounted from `main.ts` only on a phone or tablet outside an installed app.

- **When**: `playedSeconds` from `game/hoursPlayed.ts` reaches 7,200. That count is kept in localStorage
  (`trainworld.played`) and adds up every visit in this browser: a second counts while a game is open (not the start
  menu) and the tab is visible. So 2 hours is total play in this browser, across sessions and saves. The installed app
  starts its own count, but the note never shows there.
- **Where**: the bottom of the map, the device note's look (`.no-market-note`), raised to 40 px so it clears the
  map's attribution button. Taps go through the words; only the buttons take them.
- **How long**: up a minute each visit, then gone until the next visit; the x closes it for good
  (`trainworld.install-banner` = 1 in localStorage). On Android, Chrome's own install question, answered either way,
  also closes it for good, as does the `appinstalled` event.
- **Never**: on a computer; in an installed app (`display-mode` standalone, fullscreen or minimal-ui, or iOS
  `navigator.standalone`); in Facebook's, Instagram's or LINE's browser or an Android web view (none can install);
  while a yes or no question, a load failure or a stopped notice is up (demand, figures, model, new version); while the
  device note or the retry note is up (same place); while the tutorial card is fully out. The card folds to one step
  only on a phone held upright, so the note shows beside the folded card there, and is hidden while the card is
  opened or on a phone on its side (CSS `:has(.guide)` in style.css).
- **Per platform**:
  - iOS Safari: the 7-day sentence, then Share and Add to Home Screen.
  - Other iOS browsers (Chrome, Firefox, Edge, Opera): the steps only, since the 7-day clearing is Safari's.
  - Android with Chrome's install prompt (`beforeinstallprompt`, kept from page start): one sentence and an Install
    button that opens Chrome's question.
  - Android without one (Firefox, or Chrome before it decides): the menu steps.
  - iOS and not signed in: "The app has its own saves.", plus "Sign in first to have your games in both." where
    accounts are on. Not on Android, where an installed app shares Chrome's storage.

## Checked

Scratch script `ib.mjs` (scratch folder installbanner/), Chromium with Playwright's iPhone 14 and Pixel 7 profiles, all
passed: none under 2 hours; waits for the device note; iOS Safari signed out shows the separate note and the sign-in
sentence; signed in, steps only; not over the folded card, hidden while it is opened and on a phone on its side with
the card up, shown on its side once the card is closed; hidden under a question and a stopped notice, back after; the x
hides it and it stays away after a reload; none in an installed iOS app; Chrome on iOS gets no Safari sentence; Android
gets the menu steps with no prompt, the Install button with one, and Install opens the prompt and closes the note for
good; none on a desktop. No page errors. Headless Chrome fired its own `beforeinstallprompt` on localhost with no
service worker, so Android Chrome players should see the Install button.

Android Install, Android Install signed in. The best: artifacts/trainworld/review/installbanner.png.
