# T-3134 and T-3135: single track's ghost, and single track joined to one side of double track

Agent singletrack, 2026-11-10. Stage 1 (causes and design). Stage 1b (notes/T-3137.md) recommends building the
joins and the way below on lanes with a move table at nodes; stage A here stands as is. Flyover code read in `maps/.tw-trees/flyover2`
(T-3120/T-3121), the rest in the main tree.

Anita's words are on the TASKS.md lines; screenshots `artifacts/trainworld/t3134-anita-single-ghost-double.png`,
`t3135-anita-single-branch-centre.png`.

## Causes

### 1. The single track ghost draws as double (T-3134)

`app/src/map/tools.ts`, `TrackTool.showPreview` (line ~1123) draws the route ghost with
`strokesFromPreview(a.pts, ..., a.marks, 255, ...)`: lane 255 is double track, always. Commit d9fe0752
(2026-10-19) had `trackCount.peek() === 1 ? 0 : 255`; 2a467811 the same day hid single track (T-733) and
hard-coded 255. When single track came back to the track bar (`singleTrack` in `game/ui.ts`), nobody put the
lane back. Built track draws right because each edge carries `tracks`.

The same mistake in other places (fix them all at once):
- `tools.ts` ~949: segments placed early and held (T-2404) are drawn with 255.
- `realSnap.ts` 369/379/390: the real-network snap's local ghost, 255 (the request does carry `single`).
- `network.ts` `previewStrokes` (node drag `nodeDrag.ts`, `blueprintBox.ts`): every part 255, so dragging a node
  on single track shows double.
- A flyover preview (`draw.rs` `preview_route`): the plain leg (the route J to J3, single) and the crossing leg
  are drawn as double, since the whole answer is one lane. Only `edgeEdit.ts` gets it right (`d?.tracks`).

The general fix: the worker's preview answer says per segment whether it is single (`lanes`), from the sim,
which knows every piece's track count; the app stops guessing. Stage A.

### 2a. The flat-junction badge on a single branch (T-3135)

`sim/src/track/capacity.rs` `junction_crosses` (the badge; `preview_route` in `wasm/draw.rs` marks a new
junction with it) lists every move the node's ports and `Network::dir_ok` allow. `track_pos` puts a single
track port "in between" its rank's two positions (rank + 0.5), so a two-way single branch takes moves from both
tracks of the double: one of them always crosses the other direction's main track. The branch is two-way because
nothing says otherwise: `EdgeData.oneway` is 0 unless the player sets it (T-3094). The badge is truthful for
the model as it stands; the model is what is missing (no notion of which track the single joins, and no
direction from it). The test that pins today's behaviour is `flyover_tests.rs`
`t3103_badge_only_where_moves_cross` ("a two-way single branch off double track crosses too").

### 2b. It comes out of the centre line

Every edge ends at its node's centre. The map moves a single track's end onto one of the double's two tracks
only in `app/src/map/network.ts` `legShifts` / `shiftedEnds` (T-3117, T-3120), and only for **one-way** single
track (`if (e.tracks !== 1 || !e.oneWay) return`), guessing the side as "away from the nearest other track
leaving the node its way". That is why the auto flyovers' legs look joined to one side and a drawn single
branch does not. The drawing tool's snap (`tools.ts` `snap`, `endOf`) puts the point on the edge's centre line,
and the ring sits there; nothing records which track the pointer was over.

## Design

### The join: which track a single track meets

A single-track piece's end at a node that has double track gets a **join side**: the double's track it meets.
Stored per edge end on `EdgeData` as `join: [u8; 2]` (end a, end b): 0 none (centre, as today and as old saves
have it), 1 the track to the left looking out from the node along this piece, 2 the one to the right.

Why "looking out along this piece": it survives what changes around it. The node's heading is the lowest port
code's direction and flips when ports come and go; the double's pieces at the node are split, joined and
renumbered. The single piece's own outward direction does not change unless the piece is reversed (then swap
the two entries, no sign change). To use it at the node: the side relative to the node heading is
`join_out * (port side == 1 ? 1 : -1)` (side 1 leaves within 90 degrees of the heading, so its left is the
heading's left).

Rules:
- Set only on single track of the regular kind (high-speed and tram track are always double), only when the
  node has double track on the other side of it (a junction). At a node where the single meets double end to
  end (2 ports, the T-658 taper) there is no join: both tracks feed the single, as now.
- Splits keep each outer end's join on its half; new middle ends get 0. Joins at plain joints are always 0, so
  joining two pieces (`net.rs` join at plain joints) needs no new check beyond "the inner ends are 0".
- A piece that stops being single (kind change, tracks set to 2) clears its joins, as `oneway` is cleared
  (`net.rs` ~1420).
- A join whose node later stops qualifying (the double beside it deleted) stays stored and is ignored.
- Saves: edge flag bits 13-14 (end a) and 15-16 (end b). Older builds count them as unknown bits (`tb >> 13`)
  and load the save with joins dropped, as they do any newer flag. Old saves have 0: centre, two-way, as today.

### Placing: snapping, the ghost, the click

- **Pointer side.** When the track tool has Single track picked and the snap target is double track (an edge, or a
  node with double track), the snap records the pointer's side of the centre line (`besideAt` already computes
  this sign the same way). It counts only while the double is drawn as two tracks at the current zoom (the
  renderer's lane threshold); zoomed out the side is "auto".
- **Snap ring** moves 2 m (`HALF_GAP_M`) to that side, so it sits on the track that will be joined. Auto: the
  ring stays in the middle.
- **To the sim**: a new `TrackApi::set_route_join(p: &[f64])` (ax, ay, bx, by in local units, NaN for auto),
  used by the next `preview_route` / `add_route` only, like `set_route_beside`. The sim works out the side from
  the point against the double's centre line at the join (the split point for an edge end, the node heading for
  a node end) and converts it to `join_out` once the route's lead-in direction is known (`route_op_as`, after
  `lead_in` / `nearer_dir`). Auto picks the side toward the route's next point: the near track, which never
  crosses the other (see "Direction"). `branch_end` (a route from a station's node, T-1155) uses the same
  rule at its junction 20 m past the platform.
- **Preview answer** gains, from the sim: `lanes` per segment (stage A), `joins` (the two ends' `join_out`, so the
  ghost can draw its ends off centre) and `way` per segment (0, or along / against the drawing), so the ghost
  shows chevrons where the new track would run one way. The ghost's ends are moved with the same
  `shiftedEnds` the built track uses (one function, so ghost and built track agree).
- **Merging into** double track at a route's end works the same: the end's pointer side picks the track.
- **Cost**: unchanged. A junction is priced as one whichever track the single meets (`cost.rs`
  `junction_cost`); a single turnout being cheaper than a double junction is real but not worth a rule.

### Direction: inferred, with `oneway` as the player's override

Two values per piece:
- `oneway` (stored, the player's): 0 not set, 1 a to b, 2 b to a, and new **3 both ways, pinned** (value 3 is
  read as 0 by today's load, so the bits are free; stage D).
- the **way** (derived, never saved): `oneway` where set, else the way inferred for the piece's run. Everything
  that today reads `edge_oneway` for behaviour reads the way instead: `Network::dir_ok` (route search,
  `check_line`, `back_path_of`), `back_lines` (its "any one-way track" shortcut), `capacity::directed`,
  `junction_crosses` (through `dir_ok`), and `oneway_edges` (chevrons, the hover's "One way", `legShifts`). The
  inspector and `edge_oneway` read the stored value.

**Which way a join sends trains.** Trains keep to their running side, so each track of a double runs one way
along the node heading: the right-hand track along it with right-hand running (`Network::right_hand`), the left
against it; flipped for left-hand running. A move through a node goes from side 0 to side 1 (along the heading)
or back. A single port on side 1 joined to the track that runs along the heading takes trains from the far side
into the single: away from the node. Joined to the other track: towards it. In short:
`away = (port side == 1) == (joined track runs along the heading)`, then a to b or b to a by which end of the
piece is at the node. This is Anita's "branches off the right side, trains going up; merges into the top side,
sends its trains leftward".

**A run** is a chain of single-track pieces through nodes with exactly two ends that are both single track
(plain joints, and stations on single track). Its two ends each give a vote:
- a **join** at a junction with double track on the node's other side: its way (above);
- a **bare track end** (no station): nothing;
- **anything else says both ways**: a station anywhere on the run (trains turn at stations, T-3107), the run
  meeting double track end to end (taper), a junction with other single track, a join of 0 (centre, old saves),
  a crossover.

The run's inferred way: one way when there is no "both" vote and every join vote agrees (at least one);
otherwise both ways. Pieces whose `oneway` is set keep their own and do not vote (T-3101 is the tool for
setting a whole run).

What a player gets, without touching the switch:
- **A manual flyover** (Anita's example): each leg joined at both ends to the track running its way; one way,
  no move crosses at either junction, so no badge; capacity by the directed rule.
- **A stub to nowhere** being drawn: one way from its join, no badge in the ghost.
- **A single-track branch line** with a station on it, or carrying on into two-way track: both ways. Its trains
  come back and must cross the other main track, so that one move is flat and the badge shows. This is how
  real single-lead junctions work (references below); a flyover is the fix in game as in life.
- **Inconsistent joins** (both ends send trains in): both ways, flat moves at both junctions, the two-way
  capacity: it works badly, as Anita expects.
- **Joined to the far track** (pointer over the track away from the branch's side): the single's way crosses the
  near track at the node, so the badge shows. The rank-based `track_pos` already classifies this correctly; no
  change there.

**Capacity** (T-3112): a run that is one way, inferred or set, takes the directed rule (`edge_section_s` + v /
`SIGNAL_BRAKE`, per direction); a two-way run keeps run time + `SINGLE_TRACK_MARGIN_S` (240 s). No new rule.
No cheap trick comes of it: two-way service on one-way single track needs two pieces, 1.2x double's price.

**Routing**: `dir_ok` on the way. A line whose return run runs against a one-way piece takes its own way back
(`back_path_of`, T-3094) as now.

**Edits later**: the way is recomputed in `Network::apply` after `derive_node`, for every run touching a touched
node (a walk along single track from each such node; cheap), and on load for all. Pieces whose way changed join
the touched edges, so their lines are rechecked. A route edit that changes a run's way moves the lines that ran
against it through their same stops, in the same edit, as `oneway_plan` does (that code generalises: a list of
pieces and their new ways instead of one piece). A line with no other way is left broken (the existing broken-line
alert), not refused: drawing track should not be blocked by a line, and Anita accepts that such setups "just
don't work well". Deleting the double beside a join turns that vote into "both" (taper) or nothing (bare end),
and the run follows. Reshaping or dragging keeps joins.

**The inspector switch** (stage D): "Run trains one way" shows the way (on for inferred one-way too).
Turning it off on an inferred one-way piece stores 3 (pinned both ways); turning it on stores the inferred way
if there is one, else a to b; "Reverse direction" stores the opposite. Setting a piece's way also moves the join
at each of its ends that has one to the track running the new way, so the drawing matches where trains come
from (the switch is "a way to enforce usage", so the join follows it rather than contradicting it).

**Auto flyovers** (`wasm/flyover.rs` `lay_flyover`): set each leg's joins at J and J3 to the track running the
leg's way (at J the plain leg meets the track on the branch's side and the crossing leg the far one; at J3 each
meets whichever of the route's tracks runs its way, worked out by the rule above rather than by position) and
keep their explicit `oneway` as now. A test checks the inferred way of each leg equals the
flag it is given, which proves the vote rule against the hand-built case.

**Drawing built track**: `legShifts` takes the sign from the stored join when there is one (any single piece,
one way or not); the old guess stays as the fallback for one-way legs with join 0 (flyovers built before this).
A far-track join is drawn as the plain 2 m shift easing back over the turnout length, crossing the near track;
`shiftedEnds`' near-track keeping applies only to near-side joins. The snapshot sends joins as pairs (edge, a
and b packed), like `oneway_edges`, so the stride-10 `edges_info` readers stay as they are.

## Decisions made (agent's calls)

- The join is stored per single-track edge end, relative to the piece's own outward direction, not per node and
  not inferred from geometry: the player can pick the far track (a real flat junction), and the stored value
  survives node heading flips, splits and renumbering.
- Pointer side counts only while the double is drawn as two tracks; zoomed out, auto picks the near track (never
  a crossing).
- The way is derived per run from its end votes, recomputed on every edit, never saved; the player's `oneway`
  overrides per piece; explicit pieces do not vote.
- A station anywhere on a run, a taper, a fork of single track or an old centre join makes it two-way; a bare
  track end gives no vote.
- Forks of single track do not pass a way through (a later task could propagate across them; not filed).
- A route edit that changes a run's way reroutes lines through their stops and never refuses; a line with no
  way goes broken.
- Price unchanged.
- Auto flyovers keep their explicit flags and gain joins.
- `oneway` 3 = pinned both ways, so a player can undo an inferred one-way stretch (a single-track link between two
  mains joined consistently would otherwise have no way to run both ways).
- Setting a piece's way moves its end joins to match.

## For Anita (changes what the game is)

- **A single-track branch line stays two-way, and its junction keeps the flat badge.** Her message reads as
  "a single track off the right side is one way". Taken literally, a branch to a terminus would let trains in
  and never out. My rule: single track runs one way by itself only where it is a plain link whose joins agree
  (a manual flyover, a stub being drawn); once a station is on it (or it meets other single track or the end of
  double track) trains run both ways, and those coming back cross the other main track flat, so the badge
  shows there. That is how real single-track branches off double track work. The alternative is one-way
  everywhere a side join exists, with terminus branches unusable unless joined to both tracks.
