# T-728, T-729, T-731: new game menu, cities opened by a click, sandbox real networks (design)

Approved by Anita 2026-10-19 with every recommendation. Stages 1, 2, 3 and 5 are built (T-728,
T-729, T-731; the rules now live in docs/ui-panels.md "Saved games", docs/architecture.md 11,
docs/zones.md 6 and docs/ui-demand-views.md "Cities not opened"); stages 4 and 6 are T-730 and T-750.
T-729's pan measure is at the end of this note. Her words:
"new game: open a menu where we can choose between normal mode and sandbox mode; optionally specify a
city to start in (offer a short list of 5 cities, and ability to type in a city or select on map);
rather than autoloading demand for cities that we haven't selected, lets show a gray bubble on the
intercity level (still sized like how we currently size the per-city bubbles, just grey instead of
red), that lightens a little when you hover it, and clicking it loads the city. (would be nice if we
could get this lightening to happen for normal demand bubbles and line segments and stations too
actually, to get the game feeling a bit more responsive). i think we should save the cities that have
been clicked and from then on forever auto load them when we pan over them, as we currently do."
"ability to load in whole city network in sandbox mode."
Later, not designed here but left room for: a campaign that unlocks cities, and easy, medium and hard
starting cities.

## The short version

- **Two modes, chosen once per game.** Normal is today's game. Sandbox is the same game with money
  that never runs out: nothing is refused for cash, and the top bar shows "Sandbox" where the cash
  was. Demand, fares, running costs, points and stars are worked out exactly as in normal, so the
  Lines and Money tabs still say which lines earn. Construction is instant in both (there is no build
  time today). Only sandbox offers a city's real network.
- **New game opens a small sheet** on the start menu: Normal or Sandbox, then where to start: five
  suggested cities (New York, London, Paris, Tokyo, Toronto), a box to type any city or region the
  game has, or nothing, which starts on the world map. The button says what it will do: "Start in
  Tokyo" or "Start on the map". In sandbox, a city with a real network shows a "Real network" box.
  Every New game makes a new save slot (T-743).
- **A city you have not opened is a grey bubble.** It is sized as the zoomed-out city bubbles are now,
  drawn at every zoom, lighter while the pointer is on it, and a click opens it: its demand loads and
  it turns into the usual coloured bubbles. Each save keeps the list of cities it has opened, and
  those load on pan as every city does today. Building a station within reach of a grey city opens
  it too, since its riders are needed. Nothing else loads, so panning across the world downloads and
  solves nothing it was not asked to.
- **No demand number changes.** A city with no station in reach already gives every line zero riders
  (T-149), and longer trips only pair zones a station serves (T-409), so the list only decides what is
  shown and loaded for viewing.
- **Hover lightening** everywhere (T-730): one "hovered thing" per drawn layer, lightened in the
  shader or in the bubble's colour; T-741 (lighting up an entry of the resting hover's list) uses the
  same hook.
- **Real networks in sandbox** (T-731): seven cities already have one built by `realnet.py` (New
  York, London, Paris, Tokyo, Seoul, Toronto, Sendai), 7-80 KB each. First stage: a sandbox new game
  can start from one. Later stages: add one to a running game, and more cities from OSM.

## The new game sheet (T-728)

The start menu's New game, and the saves panel's New game in a running game, open the same sheet.
Sketch (light theme, the start menu's card):

```
+------------------------------------------------+
|  New game                                      |
|                                                |
|  [ Normal ]  [ Sandbox ]          <- one lit   |
|                                                |
|  Start in                                      |
|  ( New York ) ( London ) ( Paris )             |
|  ( Tokyo )    ( Toronto )                      |
|  [ Find a city or region...               ]    |
|     Osaka                      Japan  <- list  |
|     Okayama                    Japan           |
|                                                |
|  [x] Real network      <- sandbox, 7 cities    |
|                                                |
|  [ Start in Tokyo ]                 Back       |
+------------------------------------------------+
```

- **Mode**: two buttons, Normal lit to begin with. A hover on each states the difference in one line
  (hover text is allowed; no note on the card).
- **The five suggestions**: New York, London, Paris, Tokyo, Toronto. Why these: they are the cities the
  demand model was fitted and checked on (T-509's calibration set), so they play best; all five
  have a real network for sandbox; and they span sizes (Tokyo and New York about 70M trips a day,
  London 43M, Paris 37M, Toronto 20M) and three continents. Seoul and Sendai are the same quality
  and could swap in. When easy, medium and hard starts come, this row becomes those (Toronto or
  Sendai easy, London medium, Tokyo hard, say), so the slot is kept as a short fixed list in code
  (`START_CITIES`), not derived from data.
- **Typing a name**: searches the registry's 110 zones by name (68 cities and 42 regions such as
  Worcester County or Aomori), ignoring case and accents and matching any word ("hague" finds
  "Rotterdam [The Hague]"). No download: the registry is already in the page. The list shows up to
  eight matches, biggest first, each with its country (registry entries have no country yet; the
  pipeline adds a `country` code, a small change in `zone_boxes.py` or the registry writer). A name the game does not have shows no rows.
  Searching places inside cities (Brooklyn, Shibuya) needs each zone's place list and is left out;
  the in-game search already does that once playing.
- **Picking on the map**: leave the city empty and start. The game opens on the world map
  (zoom about 2, centred to show the Americas, Europe and East Asia) with every city a grey bubble;
  a click opens one. So "select on map" is the grey bubbles themselves, not a separate picker. The
  map is already drawn behind the menu (T-677), so this costs nothing extra.
- **Start**: the menu goes, the camera goes to the city's registry `center` and `zoom`, the city is
  the save's first opened city, and it opens bare as New York does now (T-351: card gone in about
  2.7 s). `startDemand(HOME_CITY, ...)` in `main.ts` already takes a city; the camera and
  `viewedZone`'s first value need the start city instead of New York's coordinates.
- **The new slot** (T-743, being built now): New game always makes a new slot. The slot is named after
  the start: "Tokyo", "Tokyo sandbox", "World" for a map start, with " 2" and on if taken. The saves
  card shows a small sandbox mark.
- **In a running game**, the saves panel's New game opens this sheet over the map; Start replaces
  the game in view with the new one in its new slot. The old game is safe in its slot (T-743).
- **URL switches**: `?new=1` stays a normal game in New York with only New York opened. A check that
  pans over other zones adds `&opened=all` (every zone opened, as today), so `t325-bare-check.mjs`
  and the like keep working. Optional `&mode=sandbox` and `&city=tyo`.

## Normal and sandbox

| | Normal | Sandbox |
|---|---|---|
| Starting cash | $3B | none shown |
| An edit costing more than the cash | refused | allowed |
| Top bar cash | the cash | "Sandbox" (hover: spent to date, fares less running costs) |
| Construction | instant (no build time exists) | instant |
| Demand, fares, running cost | as now | the same |
| Money tab, line money, history | as now | the same; the cash row is the money spent |
| Points and stars | as now | worked out and shown; a later campaign counts normal games only |
| Real network at start | no | offered for cities that have one |

- **Inside the clock worker** the cash is kept as now (so the ledgers and line money are unchanged) and
  only the "not enough cash" refusals are skipped when the mode is sandbox; the cash may go below
  zero, and the top bar does not show it.
- **Switching later**: a normal game can be turned into a sandbox from Settings (asked once, cannot
  be undone); a sandbox never becomes normal, so a campaign's or a hard start's achievements cannot
  be had for free. Recommendation, in the questions.
- **What the save records** (header fields, `workers/saveFile.ts`; old saves read as normal):
  - `mode`: `"normal"` or `"sandbox"`.
  - `start`: the start city's zone id, or none for a map start (for the saves card, and later for
    easy, medium and hard).
  - `opened`: the zone ids opened in this game, in the order they were opened (T-729).
  - The slot summary (`SlotSummary`) gets `mode` so the start menu shows the mark without opening the
    save.
- **Room for the campaign**: each zone is in one of three states for a game: locked, not opened,
  opened. Today nothing is locked. A campaign would lock zones and unlock them by points or stars;
  a locked zone draws grey without the hover lightening and says what unlocks it.

## Cities not yet opened (T-729)

### What loads today
- The **viewed zone** (the one holding the view's centre, or within 40 km of it) is opened. With no
  station in reach it opens **bare**, in the auxiliary worker only (T-325): 0.7-1.5 s to open, its
  bubbles from a no-rail pass. Up to **four nearby zones** with their outline on screen open bare too
  (`nearbyZones`). Packs close 60 s after nobody needs them, or at once past two such (T-301).
- Every zone a **built station reaches** (within 4.5 km) opens in every solving worker and joins the
  solves; a zone's **market pack** opens once it is viewed or reached or a station lies within 30 km of
  its box (T-396).
- **Zoomed out** (zoom 8.5 and below) every zone is one bubble: an opened zone's own figures, else the
  pipeline's `localTrips` in registry.json (all driving, hence red; T-602 would add a walk split so
  it shows some green, T-651).
- The cost of panning: in the 13-step pan measured for T-325, the auxiliary worker grew from 76 MB to
  477 MB from bare zones alone (WASM memory never shrinks), and each bare zone is a download and a
  0.7-1.5 s opening.

### What changes
- **Each game keeps `opened`**, a list of zone ids. The viewed zone and the nearby zones are opened
  only if they are on it (`viewedSet` and `nearbyZones` in `workers/demandClient.ts` filter by it).
  A zone not on it is treated for loading exactly like dead space is now (T-318): nothing is fetched,
  no card, the clock is not held. Its name still shows in the top bar, with "–" for the split.
- **Reach still opens zones**: a station built within reach of a zone adds it to `opened` and opens it
  as today. The market pack rule (30 km) is untouched, since a solve needs it. So the list can only
  stop a zone opening for viewing, never for a solve.
- **A grey bubble** is drawn for every zone not on the list, at every zoom: at its registry centre,
  sized by `localTrips` with the zoomed-out bubbles' scale (`TRIPS_PER_PX2`, which grows with zoom), in
  a neutral grey from `shades.ts` (one for light, one for dark). Zoomed in over a grey city there are no
  neighbourhood bubbles, only the one grey bubble and the zone outline. Its hover tag: the name, "45M
  trips a day within Lagos" and "Click to open". (The trips line is a fact the pipeline has; no mode
  bar, since nothing is solved.)
- **Hover** lightens it (below). **A click** adds the zone to `opened` and opens it bare as a pan does
  now; while it loads it shows the existing loading bar (`zoneLoading.ts`, T-343), then turns into the
  coloured bubbles. The camera does not move; zooming in is the player's. A grey bubble under the
  pointer takes the click before the track or a station.
- **From then on** that zone opens on pan as today, in this game, for good. Nothing closes it from
  the list (there is no "forget this city"; it could be added if wanted).
- **Old saves** (no `opened` in the header) start with the zones their stations reach plus the zone
  in view when they open. Anita's serious game would show Philadelphia or Boston grey if it has no
  station there, one click each.
- **New York's start** opens New York only; Philadelphia, Hartford and the rest of the Northeast show
  grey until clicked.

### What a not-yet-opened city contributes to the opened ones
Nothing changes. A zone no station reaches already carries no rider on any line: its people walk or
drive (T-149, checked to the bit). Commutes between zones and the world market's longer trips build
pairs only between zones a station serves (T-409); trips from an opened city to a grey one keep
their place in the registry rows and show in a selected zone's partner bubbles as now (grey cities
appear there as partners, coloured as any partner, since a partner bubble is about the pair). Once a
line reaches a grey city its station opens it, so its riders are counted from the first solve.

### T-602 and T-651
The grey bubble makes T-651 ("zones not opened look fully red") moot for zones never opened. A zone on
the list but not yet opened in this session (after a reload, off screen) still draws from
`localTrips` when zoomed out, so T-602's walk split still matters for those, at lower priority (P3).

## Hover lightening (T-730, with T-741)
Built 2026-10-19; the rules are docs/ui-map.md "Hover tags on the network". Built as a uniform per
disc set (the hovered instance) rather than a buffer rewrite; mixes 30%, station rims 60%.
- **Bubbles** (grey, zoomed-out city bubbles, neighbourhood bubbles): the hover already finds the disc
  (`discAt` in `demandHover.ts`); the overlay rewrites that one disc's colour mixed 20% toward white
  and back when the pointer leaves. A one-disc buffer update, no redraw of the rest.
- **Lines and stations**: `renderer.ts` gets a hovered line id and station id as uniforms; the
  fragment shader mixes a matching piece toward white. Track pieces hovered without a line light that
  edge. The hover already knows what is under the pointer (`trackHover.ts`, `networkTips.ts`).
- **T-741** sets the same ids from the resting hover's list, so pointing at "Line 4" in the list
  lights Line 4 on the map. One hook for both.
- Dark theme: the same mix toward white reads as "brighter" there; check by eye.

## Real networks in sandbox (T-731)

### What exists
- `pipeline/realnet.py net <city>` turns a city's sources into a network (GTFS, the operators'
  timetables, or OSM route relations with rough frequencies by kind of line); `geom` fits track to the
  GTFS shapes (straight hops where there are none); the `realsave` bin builds the track model's
  network; `gamesave` wraps it as a save file. This made `T-007-real-nyc.save`.
- Built saves now, in `data/work/realnet/` (2026-10-16): New York 75 KB (109 lines), Paris 80 KB, London
  64 KB, Tokyo 54 KB, Seoul 31 KB, Toronto 30 KB, Sendai 7 KB.
- They are demand tests, not showcases: each line has its own double track at its own level, so
  shared trunks are drawn as tracks lying over each other; New York's has 411 curves too tight, 180
  crossings and 200 platform crossings, which the game does not check on load. Their lines run, their
  demand works, and the real New York save is the smoke test's.
- `T-269`: realnet's operator count is wrong; it does not affect a save.
- **noritetsu's data** (T-682 stage 1, the Real network reference layer): world track geometry by
  region (N02 for Japan, FRA, RINF, OSM), no services or timetables. It is the source for T-727's
  "snap and follow" track, not for whole networks with lines.

### How it would be offered
1. **At the start (first stage)**: in the sheet, sandbox with a start city that has a real network
   shows "Real network" (ticked by default). The new game opens that city's save in its new slot as
   sandbox: camera on the city, the city opened, clock at day 1 07:00. The seven saves ship beside the
   packs (`packs/real/<id>.save`, about 350 KB in all). Small: the file load path exists (Load a
   file reads the same format).
2. **Into a running sandbox (later)**: Settings > Real network gets "Build <city>'s network" for the
   viewed city. This needs a merge in the track model (append another network's nodes, edges,
   stations and lines into the current one, renumbering) and a rule for overlap with the player's
   own track (stack it, as the saves do). Medium, Rust.
3. **More cities (later)**: realnet's OSM adapter already works without timetables (Sendai). A
   pipeline step could make a rough real network for any registry city from OSM route relations,
   minutes a city, as part of `world_run.py`. Japan from N02 is T-737's stress test.
4. **Cleaner networks (later, optional)**: merge shared trunks so lines share track, and fit curves to
   the game's limits. This is the same fitting problem as T-727; worth doing once, there.

## Stages and rough sizes

| Stage | What | Size |
|---|---|---|
| 1 (T-728a) | `mode` in the save and slot summary; sandbox skips cash refusals; top bar "Sandbox"; saves card mark | small, 1-2 agent hours |
| 2 (T-728b) | The new game sheet: mode, five cities, search, map start; start city to camera and `startDemand`; slot name; the saves panel's New game uses it; URL switches | medium, 3-4 hours; startup is the delicate code (T-149, T-172, T-347, T-677) |
| 3 (T-729) | `opened` in the save; loading filtered by it; grey bubbles at every zoom, hover and click; old saves' list; `&opened=all` for checks; smoke updated | medium, 4-6 hours |
| 4 (T-730, T-741) | Hover lightening on bubbles, lines, stations; the resting list lighting things up | medium, 3-4 hours (shader work) |
| 5 (T-731a) | Sandbox start from a real network: ship the seven saves, the "Real network" box | small, 1-2 hours |
| 6 (T-731b, c) | Merge a real network into a running game; OSM real networks for more cities | medium to large each; after Anita has played 1-5 |

Stages 1, 2 and 5 can be one agent in a row; 3 and 4 are separate agents (3 touches
`demandClient.ts` and `intercityView.ts`, 4 `renderer.ts` and `demandOverlay.ts`).

## T-729's pan measure (2026-10-19)

`checks/t301-pan.mjs` on a `?new=1` New York game (three solving workers and the aux worker, Homes on,
zoom 10.5, Washington to Toronto and back, 5 s a stop, REST=15000), `&opened=all` (as before T-729)
against the default (New York opened only). Outputs: `artifacts/trainworld/t729/pan-{before,after}.json`.

| | before (every zone opened) | after (New York only) |
|---|---|---|
| pack and market loads | 56 (14 zones and their markets) | 4 (New York and its market) |
| most packs open at once | 5 | 1 |
| peak WASM memory, solving workers | 102 / 98 MB (market packs) | 17 / 17 MB |
| peak WASM memory, aux worker | 53 MB | 36 MB |

save now is the downloads, the market packs in every solving worker (about 85 MB each) and the
0.7-1.5 s openings. Start memory was 17 / 15 / 15 / 36 MB in both.
