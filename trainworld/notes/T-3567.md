# T-3567 Fare multiple per line (with T-3566, the line panel's money chart)

Agent lineprofit, 2026-11-17, tree `.tw-trees/lineprofit` (branch tw/lineprofit).

## What was built

- **T-3566**: the line panel's money chart is the Money tab's chart (`FareCostBars` in ui/MoneyHistory.tsx, shared by
  both): each day a blue fares bar and a red running cost bar side by side, the last 30 whole days in 30 slots (a
  young line's few days at the right), heading "Revenue and expenses" with the coloured words, the scale's top at
  the right. Moved to the panel's very bottom. The clock keeps 31 days a line now (`LINE_DAYS`, was 8), so a save
  grows by about 20 bytes a line a day kept (109 lines: about 50 KB more JSON before compression).
- **T-3567**: `Fares.lines` (line id -> multiple, 0 to 3 in hundredths, only lines off 1), edit op `fareLine`, the row
  "Fare multiple" (stepper by 0.05, typed on a click, undo button back to 1.00x) right above the chart in a rail or
  tram line's panel, and at the bottom of a bus or ferry line's panel (which has no chart).

The chart's heading changed meaning, so it is a new key, `lineMoney.title` "{revenue} and {expenses}" (the
Money tab's coloured words), and the old `lineMoney.heading` went from en, context and every language's messages and
sources; the new keys (`lineMoney.title`, `lineMoney.fare*`) await translation.

## Where the factor enters (and the one caveat)

`lineFareMul` (game/fareCurve.ts) is the one per-line fare factor: high-speed, bus, ferry. The line's own multiple is
multiplied in there, so it reaches demand through `fareW` (`set_fare_mul`, route choice, mode choice, the market,
the curve's extra) and income through money.ts, regionMoney.ts and stretchMoney.ts with no new path and no sim change.
It lives in `Fares`, not on the sim's line, because income prices riders at the fares they were solved with
(`solvedFares`, T-2266) and the value has to travel with them.

**Caveat**: like the high-speed multiple, it scales only the fare above the base. The base is paid once a trip in
the kernel's mode choice (`p.fare_min`), not on any line, so a per-line base would be a change to every solve path
(route search, mode choice SIMD, everyday, intercity). On the real save line 14 the base is about 61% of its fare a
ride, so 1.2 raises the fare a ride 6.6% and 0 leaves the base.

Twins: a quad-track twin (T-3333) takes its line's multiple (`setLineFare` sets both; `tidyLineFares` re-derives
twins and drops deleted lines each time the network is sent to demand).

## Measured on the real save (T-007-real-nyc.save), weekday, line 14

| multiple | riders/day | revenue/day | fare a ride | rail trips/day | network revenue |
|---|---|---|---|---|---|
| 1.00 | 1,010,584 | $150.64M | $1.491 | 12,368,755 | 0 |
| 0.50 | 1,145,897 (+13.4%) | $137.21M (-8.9%) | $1.197 | +0.15% | -1.00% |
| 1.20 | 973,667 (-3.7%) | $154.79M (+2.8%) | $1.590 | -0.07% | +0.28% |
| 3.00 | 612,898 (-39.4%) | $127.26M (-15.5%) | $2.076 | -0.47% | +1.11% |

Revenue is at the game's 100x economy; fare a ride = revenue / 100 / riders. At 3x the lost riders mostly move to
parallel lines (+329k riders elsewhere). With every line at 1.00 the figures are bit-identical to master (rail trips,
every line's riders and revenue), and setting line 14 back to 1.00 returns them to the bit.

## Repro for the checker

From the tree root, with a Vite on the tree (`node trainworld/checks/dev-nowatch.mjs 6144`):

    node trainworld/checks/t3567-line-fare.mjs http://localhost:6144/ 14

It types 1.2, 5 (held to 3), 0 and presses the undo button through the real panel, checks the fare a ride and
riders move each way, that 1.00 again is bit-identical, and that an exported save carries 1.2 and opens with it.
Places worth trying to break: a line deleted with a multiple then a new line built (its number should not inherit
it), a line with quad-track pairs on (both halves should charge it), a bus and a ferry line, typing text or a
negative number, an old save (no `lines`).
