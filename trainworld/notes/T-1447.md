# T-1447: copy a selection into another saved game, as blueprint

Agent copysel, 2026-11-28. Her words (11-27): select with the Select tool, a Copy button that "opens up a modified
version of the save menu that lets you copy it into any other save you have, as a blueprint", so "you still have to
construct it with money"; hover "copy selection into another save as a blueprint".

## What a selection holds, and what copies

- The Select tool's pick (`BpPicked`): track pieces and stations, all blueprint or all built (T-829). Both copy, and
  arrive as blueprint: not built, no build day. A disabled blueprint piece stays disabled; built track arrives on.
- With each piece its shape (corners, radii, levels), kind, single or double, one way, joins, speed limit and ramp;
  with each station its name (and whether the player typed it), own name, platform, one-track side, upgrades (built
  with the station, so in the blueprint's price), a port's berth, a BRT station's heading.
- **Lines** whose every stop is a picked station and whose whole path is on picked track, with their trains, schedule,
  cars, kind settings, one-way and boarding-only stops, colour, name and symbol. Only running lines need cars
  (`cars_needed`), so a pasted line costs nothing until its track is built; Construct buys its trains as for any line.
- Station links and kept-apart pairs whose two stations both copy.
- **Not copied**: bus and ferry lines (no pick holds them), line groups, line notes and schematic places, fare zones
  (the target's fare areas are its own), station buildings, kept bus stops, settled rates, build days, money. `sep`
  (an imported real network's grade separation among its own pieces) is cleared: copied track crosses by the usual
  rule, so a real network copied out of a sandbox gets flat crossings where its levels did not keep lines apart.
- **The clip** is made by the track model: the picked records go through the ordinary checked edit into an empty track
  model, which the save writer then writes (TWT6 network bytes). A record the checks refuse there (a station whose
  platform runs onto track outside the pick) is left out, and the copy says how many.

## How the target takes it: a pending blueprint, applied at its next load (chosen)

- "Copy here" stores `clip:<origin>:<time>` in the saves' IndexedDB store: the source game's name, the save level and
  the clip's bytes. When a game of that origin next opens in this browser in a tab that holds its slot (autosave on),
  the page sends one edit, `pasteClip`, adding the clip as blueprint: one undoable step through the checks, water
  mask and terrain drawing uses. The pasted pieces become the pick (the selection bar shows them), the map moves to
  them, and the notice says `Blueprint added from "Tokyo".` The clip is deleted once a slot write holding the paste
  has gone through; a page closed before that pastes it again at the next load (the edit was not saved either).
- **Not written into the target's slot from this page**: that needs a second track model holding the target's network
  and the water masks under the clip, which only a loaded game has; it writes a slot this tab does not own (the
  one-writer lock, `edit` marks, backups and the account's sync record would all have to be faked); and the paste
  could not be undone. Pending costs nothing until the game opens, and goes through code that already writes saves.
- **The same place on the map**: the world is one frame, so a clip copied in Tokyo lands in Tokyo. The Select tool's
  drag moves it from there.

## Ids and names

Fresh ids in the target from the track model; no source id survives. Station names come as they are (a name the
player did not type follows the target's place names as any new station's does). Line names, symbols and colours
come as they are; a name or symbol the target already uses is stepped as Copy line steps it ("Line 3" to "Line 3b").

## Save levels

The clip keeps the level it was written at and is read with `save::decode_at` at that level, so a clip from an older
build reads as an old save does. A target at an older level is brought up by its own load first; the paste runs in
this build. A clip above this build's level, with a newer network magic, or with bytes `save_unread` finds left over
stays waiting, untouched ("A blueprint copied on a newer game version is waiting. Reload the page to update."). Bytes
that do not decode are dropped ("A copied blueprint could not be read.").

## Water and another region's zones

- The paste is an edit like drawing: ground-level track over water, a crossing the model refuses, a platform that does
  not fit, a line the target cannot run are refused by name, left out, and the rest tried again (at most 32 rounds):
  "3 pieces could not be added." Track copied onto the same track (into another version of the game) is refused as
  overlap, so nothing doubles. Terrain and road prices follow their blocks as they land, as for drawn blueprint, and
  Construct waits for them as always.
- Blueprint shows its realms only; once built it opens zones and pays into each region's ledger like any track.

## Cloud-saved games

The copy panel lists every card but the one being played, account-only games included: their Open downloads them into
a slot of the same origin, which takes the clip at that load. Clips stay in this browser and are never uploaded; once
pasted, the blueprint is part of the game and goes up with its next upload like any change. A game opened first on
another device does not have it (the panel's line says "in this browser"). The card's bin, deleting the whole game,
deletes its clips.

## The track rework (tw/track, release 1)

A clip is network bytes and a level, read by `save::decode_at`, the decoder every save uses. On tw/track that decoder
reads TWT4 to TWT6 as the old model and returns the new one (`read_old_body`), so a clip waiting across the update
converts as an old save does, and clips made after it are TWT7. The Rust that turns records into ops
(`sim/src/track/wasm/copy.rs`) names nodes, edges and stations, which the rework changes: the merge ports it, held by
its round-trip tests (a pick copied into an empty world and pasted into another; lines inside kept, lines leaving
dropped; overlap refused; built made blueprint; `sep` cleared).
