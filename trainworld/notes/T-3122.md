# T-3122 Stop order for lines with loops

Agent stoporder, tree `.tw-trees/stoporder`, 2026-11-10. Anita's words: TASKS.md T-3122 line. Save:
`artifacts/trainworld/t3099-anita-amsterdam.save` (Line 1: a stem Johan van Hasseltweg .. Hobbemakade, a north loop
with Pluvierstraat, a south loop with Amstelkade .. Apollobuurt).

## Why it went wrong

Replayed on the save in a Rust scratch test (clicks as `insert_stop` + `set_stops`, optional right-click turns):

- **Clicks alone** give an open U: `[Pluvierstraat, JvH, ..., Hobbemakade, Amstelkade, ..., Apollobuurt]`, reversing at
  Pluvierstraat and Apollobuurt, both of them partway round a loop. Nothing turned an end that already stands on a loop.
- **With right-click turns taken as soon as offered**, the result depended on order: north to south gave
  `[JvH, Pluvierstraat, Bankwerkerij, ..., Apollobuurt, JvH]`, a circle whose way back runs express down the whole stem
  (0 stations both ways); "ends first" left Hobbemakade one way (8 both ways); only "loops first" came out right. The
  cause: stops added to a loop line went in once (`best_slot`), and the second pass was added only by `second_visit`,
  for the clicked station only and only when the path stayed the same. Any loop made while the stem was short, or
  closed from the far end, kept its later stops on one pass.
- **The save itself** had Johan van Hasseltweg stopped one way only (north loop: Bankwerkerij, JvH passed, Pluvierstraat,
  JvH).
- **The dots**: `oneWayStops` took a stop's direction from the stops either side of it. On a loop with one station
  (Pluvierstraat between JvH and JvH) both are the same station, so the direction was zero, the half fill and the
  chevron were dropped, and the north loop drew a full dot while the south loop drew half dots; the stop list read the
  loop rows from `turnedLine` and drew both loops one way. That is the mismatch she saw.

## The rule (decided; DECISIONS.md)

1. **A loop stops at every pass** (`every_pass`, `wasm.rs`): after every stop edit of a loop line, each pass of its path
   over a station it stops at is a stop, unless it would stand straight before or after a stop at the same station.
   This is Anita's rule with "stations between" read as **stops** between: a loop whose station the line passes but
   does not stop at still makes two stops in a row at the terminal, which is one stop with a pointless lap. Passes the
   same way count too (a figure-of-eight), since stopping is never worse there. Open lines are left alone: they run both
   ways already, and a pass twice in one run is a T-797 reversal, an accident the U-turn icon flags. Saves load
   normalised (Line 1 gains JvH's second stop).
2. **(Undone by T-3140, 2026-11-10: only the right click turns an end.)** **A click turns an end on a loop** (`add_stop`, `auto_turn`): when a click puts a station at an end, each end whose
   stop lies past the point a loop rejoins the path (the line already runs onto the loop and reverses on it) is turned
   round the loop as T-3021's right click would, the line one way. An end before a loop with no stop of its line stays
   the right click's. Not when that end was already on a loop before the click (she opened it), nor hand-ordered, bus or
   ferry lines. A balloon's stem also grows past its turning stop (`best_slot` tries `[S] + stops + [S]`), so a loop
   turned early keeps working as the stem is clicked.
   A ring is not affected: its loop rejoins at the first stop, not past it, so a ring clicked round stays open until
   the right click closes it (both ways, as T-798).
3. **One source of truth for which way** (`TrackApi::line_stop_ways` -> `LineStats.oneWayAt`): a one-way rail line
   serves a station one way when its run passes it only heading one way (the side its trains leave the node by); a
   turn there, or passes both ways, is both ways. So a terminal with a stationless loop (stopped once) is a full dot.
   The heading is the track's at the station (`node_heading`), not the neighbouring stops. Read by the editing markers'
   half fill and chevrons (`stopMarkers.ts`), the hover chevrons (`networkTips.ts`), and the stop list's half dots
   (`LineInspector.tsx`, any line, turned or not). `oneWayStops` is gone. A one-way ring now shows half dots on every
   stop (it is served one way); before, nothing did.

A case the plain rule would get wrong, found on the way: the turned circle from the north end (express way back) is
only fixed because rule 1 looks at every station, not only the one clicked.

## Out-of-scope effects

- Removing one visit of a repeated station in the stop list (the cross or the dot on a plain row of a loop) now takes
  every visit, as the map click does (`removeStop`, `dotClick` in `LineInspector.tsx`); a single visit would come back.
- `drop_stop` on a loop keeps the path and is not normalised; the app no longer sends it for a repeated station.
- Stop tiers (`stop_tiers`) do not run `auto_turn` for each station (one bounded search per station would be costly on
  big saves): a station whose click turns an end still shows the tier of the plain insertion (marker size only).
- Buses are untouched (their loop-back already stops both ways, T-3063).

## Outside references

- Amsterdam's trams are single-ended and turn on balloon loops (keerlussen) at their termini; stem stops are served
  both ways and the loop's stops one way, which is the service Anita described.
- GTFS writes such a trip as the stem stops twice (out and back) and the loop's once; NIMBY Rails and Transport Fever 2
  make the player list every visit (notes/T-2988.md section 3). The game derives the list instead.
