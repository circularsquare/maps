## The save guard

**What a tw/track save did in today's game.** The rework's saves get a new network magic, `TWT7` (07-saves.md). Today's
build took any magic but TWT5/TWT6 for the old equirectangular frame, the frame conversion gave nothing, and
`TrackApi.load` failed, which the clock worker reads as `SAVE_DAMAGED`. On the slot opened at start that marks the
slot damaged (`markDamaged`, never uploaded again), rescues an older backup as its good copy (`rescueGood`), keeps an
`unreadable-` aside copy, and the card says "This save is damaged." A player opening a game the new release saved
(another device, a stale tab) would see a healthy game called damaged.

**Now** (magic only; no level raise, no header change, so every save up to level 36 loads as before):
- `isNewerTrackFormat` (workers/saveFile.ts) and `save::is_newer_magic` (sim): `TWT` followed by a digit or letter
  above `6`. The sim's decode refuses it with its own error (`save::NEWER_FORMAT`), for tools and `readsave`-style
  readers.
- `openSave` (clock.worker.ts) throws `SAVE_NEWER` (the key `clockWorker.newer`) before anything reads the network.
  `loadFailKey` maps it to itself, so the open paths that use it (slot at start, account copy pulled in play, a
  failed new slot) show the same line, and a file or backup passes the key itself (two paths run in the probe: the
  slot at start and a file opened in a game; the rest by reading); the slot path skips the aside copy, and nothing marks it damaged (not
  `SAVE_DAMAGED`). The page goes to the start menu, as any failed open does (T-3773).
- `checkSave` calls such bytes "other" (kept as they are, never damaged, never a good copy), so the account and
  backup checks leave them alone.
- The cousin: a newer header `format` threw the raw English "This save is from a newer version of the game.", which
  the slot path showed as "loadText.failed" and the file picker as "not a save". It now throws the same key.
- The shared-save check already refused TWT7 as "version" (`/^TWT[4-6]$/`, game/sharedSave.ts).

**Server (shonei-server)**: needs nothing for this. `trainworld_savecheck.go` already answers any TWT7 network with
`twVerdictNew` (its test "a newer network"). When tw/track merges into master, the server's check must learn to walk
TWT7 (and `twSaveLevel` the rework's levels) to verify those saves rather than only store them.

**Levels on tw/track** (for the branch): 07-saves.md planned 35 (LBN1), 36 (TWT7 body), 37; master is at 36 already
(LBT1 35, LBQ1 36), so the rework's levels move up by at least two, and each merge of master into tw/track must
renumber past master's. A tw/track TWT6 save with a block master lacks (stage 2a's LBN1) needs no guard: an unknown
block already plays read-only (T-1826).

**Proof** (scratch `guardcheck.mjs`, the Amsterdam test save with its network magic swapped to TWT7): see "Checks".

Player text: none new. The line shown is `clockWorker.newer`, reused word for word: "This game was saved on a newer
game version. Reload the page to update." It now also shows where before "This save is damaged." (a slot),
"This save is from a newer version of the game." (a file with a newer header format) or the generic load failure
appeared.

## T-1183: the fixed-rate path

What fixedrate2, T-3929 and T-3931 left (notes/T-1183.md): capacity's rounded delays, the parked over-full fleet
test, and `LineData.trains` as an Option. Done here:
- `capacity::solve_one`: delays are always continuous; the rounding to whole seconds and the drop of holds under
  2 s (`HOLD_MIN_S`, still the profiles' threshold) applied only to resources whose every user had no trains.
- `switching_to_headways_on_overfull_track_keeps_every_train` (wasm/tests/fleet_tests.rs) removed: its over-full
  track came only from a fixed-rate line, a state count and headway lines cannot reach (the fill holds them to
  full). Its rule, the switch keeping the trains (T-752), is still asserted in the test before it.
- The Option stays as the load-time state only (DECISIONS 2026-11-21, T-1183): a line known by its rate alone (a
  TWT4 save's frequency line, `realsave`'s and bench's lines as built) between its decode or build and
  `allocate_unallocated` in the same load. Nothing runs a line by rate after that, and old saves with frequency
  lines keep loading. `rate_line` stays as that test's input (`a_frequency_line_is_given_trains_on_load`), and the
  writer still writes what a line has.
- Parity: `lanes_parity` fingerprints (every path, capacity resource with solved figures, lines' figures) are byte
  identical before and after on real NYC, Northeast, London's start, Amsterdam test, Vienna, the 2,647-station save
  and NA 383. That shows counted lines are unchanged; whether any of these saves holds a frequency line (the only
  case the rounding touched) was not checked, so whether a legacy load's first counts move is not measured.
- What stays of the path: the Option, `rate_line` (its one builder of a rate line in the tests; no other
  `line_data(.., None)`), the writer's flag-0 branch, the `is_some` branches that treat an unallocated line apart
  (capacity's lone train, `off_at`, the settle's filter), and the rate-built lines of `realsave` and bench's synth.
  Removing those needs the load to allocate without a first derive on rates, or dropping frequency-line saves:
  a call for whoever next touches loading.
