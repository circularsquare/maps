# T-3427: Recalculate trips while paused

Agent recalc, 2026-11-16, worktree .tw-trees/recalc (branch tw/recalc), not committed.

Anita (2026-11-16): "a bunch of people requested an editing mode where it doesnt try to recalc while we're editing.
this should be a toggleable thing i guess. perhaps ilke "recalculate trips while game is paused". default on."

## What was built

- Settings, Performance: "Recalculate trips while paused", on by default, remembered with the other Settings
  (`display.recalcWhilePaused`).
- Off and paused: the clock worker's network snapshots stop in `DemandClient.submitNetwork` (`pauseHolds`); the
  newest is kept. Play (or the setting back on) sends it, so one solve covers every edit made meanwhile. Edits
  still apply, draw and cost as usual (the clock worker is untouched). Never held: a game's own load
  (`gameLoadArmed`), a network demand reads the same as the one in hand, demand that failed.
- `demandHeld` (game/demand.ts) while a network waits. lineFigures doesn't settle pending lines or forget edits
  while it is set; editNote treats it as "demand still updating" (so the note comes after play, and its
  give-up clock restarts then).
- Status tag while held: "Trips recalculate when you unpause", hover "Recalculate trips while paused is off in
  Settings", no bar.

## Calls

- Stale lines: keep the existing "calculating..." label and their last figures; the status tag is the one marker.
- Money: lines keep earning at the riders they were solved with (as during any solve); paused, nothing is paid anyway.
- Save while held: the save has the edits; the demand cache beside it is the older network's, so loading it solves
  afresh. No solve is forced on save.
- Cheap local figures: the edit note's profit estimate (profitEstimate.ts) and the Money tab's fare estimate are
  main-thread and still run.

## Checks
