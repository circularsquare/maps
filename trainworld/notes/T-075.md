# T-075: avoid duplicate overlay draws

The clock's RAF callback skips its draw when MapLibre has already queued a frame. MapLibre's
custom layer draws the network with the current camera in that frame. When the map is idle,
the clock continues to draw trains normally. Paused/state-change invalidation still wakes a
draw, or the queued map frame supplies it. This adopts the existing candidate, with
`perfOff=noDouble` as the old-behavior measurement switch.

Fresh check after T-074: six alternating headless Chrome runs, 500 synthetic lines / 10,000
trains, 2.5 s camera ease at zoom 12. Old behavior: 309-310 draws, 118-119/s. Guard: 156-157
draws, 60/s. Map frames stay 152-153. Including the debug lag probe, measured overlay drawing
work is 41.8-48.1 ms without the guard and 20.9-21.2 ms with it over 2.6 s. All six runs have
zero off-camera frames and zero pixel lag, no WebGL or page errors. This is a reduction in
overlay work; total browser/GPU CPU was not measured and should not be described as halved.

TypeScript and production build pass. `t075-check.mjs` and `T-075-check.json` reproduce the check.
