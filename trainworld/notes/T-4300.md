## For Anita

- After an edit the clock worker used to work out every station's complex again and fold every station's name by them,
  three times over (for the state's rows, for the map the tools click on, and for the drawn network), and the page did the
  same twice more. Each complex was numbered by its place in the list, so one new complex renumbered all the ones after it.
  Now a complex is numbered by its first station's node number, so a complex nothing touched keeps its number, and every
  one of those steps redoes only the complexes the edit's stations were or are in.
- On your Asia save, in Node, the worker's part went from about 27 ms an edit to about 0.6 ms (table below), and the page's
  complexes and dot groups from about 4 ms to about 0.2 ms. That is a few percent of an edit's wait there: the whole state in
  Node went from about 268 to 206 ms (noisy, many other steps).
- Nothing you see changes: names, hubs, complexes and the demand figures are the same as before (demand gets the same numbers).

## The cause, in the code

`ComplexBuilder` (game/complexBuilder.ts) reworked only the touched complexes, but then renumbered every complex by its
first station in list order (`renumber`, a pass and a new map over every station), so the numbers of every complex after a
new or vanished one moved. Every reader took that numbering and so went over every station again:

- `StateRows.foldNames`: a geometry object per station row, the links, `withBuildingLinks` (every building's members
  worked out over every station, since the station list was a new array each call), the builder, `complexGroups` and the
  fold over every station; 9 ms.
- `complexOfNodes` (the drawn network, `line_related`, the schematic): the same builder fed another list (ports in), so
  the two lists made it rework the ports each time, and a new array filled over every station; 4.5 ms.
- `patchNames` (the map patch at the word, T-4271): the last read's stations with the touched ones swapped in, the same
  shared builder with a third list; 10.5 ms, on the click's own path.
- `shownBuildings` (an unnamed building shows its first member's complex's name): every building's members over every
  station whenever the rows list was a new array, that is every read; 3 ms.
- The page's `complexes` and `dotGroups` (game/complexView.ts): the builder's pass over every station and the renumbering,
  and `withBuildingLinks` again; about 2 ms each in Node (T-4150 stage 4 measured 2.5 and 1.0 in the page).

## What changed

- **Numbering** (game/complexes.ts, complexBuilder.ts): stations are taken in node order (their ids are node numbers) and a
  complex's number is its first station's node number, in `buildComplexes` (the reference) too, so a whole rebuild and the
  kept complexes compare exactly, numbers included. `Complexes.members` is a map by number (it was an array by index).
- **The builder** (game/complexBuilder.ts): `update` takes every station and finds what changed, as before; `patch` takes
  only the stations that may have changed (each as it is now, null when gone). Either reworks the complexes those stations
  were or are in, those at the ends of a link made or undone or a pair separated or let go, and those of a station
  building whose members or outline changed, and patches its own maps in place: a new handle for each change, the same
  handle when nothing changed, and a log of the last 64 changes so `complexChanges(from, to)` says which stations moved
  across several steps (it said one step only). A member list is replaced, never changed. Station buildings are inside
  the builder now (membership kept per station: an outline new or moved is tested against every station, a station new or
  moved against the outlines), so no caller works out building links over every station. `buildingFirst(id)` gives an
  unnamed building's first member. `complexesDiffer` is the check against a whole build.
- **Worker, the names** (workers/stateRows.ts): `StateRows` keeps its own builder over the station rows (ports out, as
  the names always were). A read gives it the rows the read changed and the stations a patch gave from the model since;
  the names are folded again only for the complexes `complexChanges` names and for stations whose rows changed (a rename
  moves its complex's name source), and the node list is patched by those ids (`patchList`). A read that walks (a load,
  `?patch=walk`, repricing), the first read, or an unknown change folds whole (`foldAll`). `headOf`, `complexSize`,
  `complexName` and `oldApart` are kept per complex the same way. `patchNames` gives the touched stations to the same
  builder and names only the complexes changed since the read.
- **Worker, every node's complex** (workers/clockDemand.ts `complexOfNodes`): its own builder (ports in, as the page and
  the network have them) follows the rows by the row log's ids since the read it last took (`changedSince`), and the
  stations touched since the last read are taken from the model (given again from the rows once a read has them). The
  array is a new one per change, the last one copied with the changed stations laid in, as the network build holds the
  old one across its pieces. `complexInputs`: the links, separated pairs and building outlines, each the same object
  while the model's numbers for it are the same.
- **Snapshot** (`buildSnapshot`): its builder as before (every built station), the numbers made 0, 1, ... by first station,
  so demand gets exactly what it got (workers/demandClient.ts numbers a station of none past the station count).
- **Buildings' names** (`shownBuildings`): the first member from the names' builder, as the last read left it.
- **Page** (game/complexView.ts): the complexes and dot groups kept from the world each last read, given the stations
  `worldDiff` names; the buildings to the builder directly.
- **Readers** of the numbers, now keys: diagram/view.ts, map/networkTips.ts, map/stationCircles.ts, map/labelNames.ts,
  map/busLayer.ts, map/joinButtons.ts and game/busLinks.ts `brtJoins` (members iterated), map/rendererParts.ts
  `StationGroups`, ui/StationsTab.tsx (the count is `members.size`), game/achievements.ts (the corridors' union by a
  map, keys of stations of none negative; the busiest station by a local slot per complex: both took the numbers as
  array indexes and `members.length` as the count). The Rust readers (`line_related`, demand's `demand_groups`) and
  the network, facilities and schematic compare numbers for equality only: no change.

### What names each input (why no read of every station is needed)

| what the complexes read | what names its change |
|---|---|
| a station's place, heading, platform length, platform line | the read's changed rows (a row whose geometry moves is another object; a platform line moved by track beside it through T-4113's carry); between edits and their read, the touched nodes (`peek_touched`), given again at the next read (`cxLive`, `nodeLive`); on the page `worldDiff`'s stations |
| a station new or gone | the same |
| the player's links | `station_links`, compared by value each call; the builder diffs the pairs |
| the pairs separated (T-4048) | `station_apart` (`apartNow`) |
| station building outlines | `buildings_info`, compared by value |
| the frame | its kind: another builds whole |
| a load, a new game, `?patch=walk`, repricing, a read that left regions (`behind`), a row log gap | whole: `reset`, a walk, the log's whole entry, `behind` (as before) |
