# T-436: start crowding rounds from the previous solve

2026-11-16, agent perf. Measured, not shipped: the figures drift far past what a player would notice, and an undo
does not bring them back.

## What was measured

Native release build, one core per run, commutes and the everyday purposes solved together as the workers do (no
market, no capacity cap; both left out on both sides). Cold is today's solve: free flow, then up to three crowding
rounds with T-434's per-period stop. Warm starts each period's first pass priced on the previous solve's final
loads (mapped onto the new network's route nodes by line and place in the line; a removed line's loads dropped, a
returning line's start empty), then runs k MSA rounds. The experiment's code is kept here: `T-436/solve_from.patch`
(a `solve_from(q, at)` on `DemandApi` and `EverydayApi`) and `T-436/t436.rs` (the test that drove it; it went in
`sim/src/demand/api/` with `mod t436;`).

Networks: the real New York network (`nyc_real_track.json`, 109 lines, the save's complexes; the network
T-007-real-nyc.save is built from) and real Tokyo (`tyo_real_track.json`, 133 lines, 1,940 stations). Edits: (1)
trains an hour halved on the busiest line (New York subway 1, Tokyo Keihin-Tohoku), (2) the 5th busiest line
removed (New York subway 4, Tokyo Marunouchi), then (2) undone, then (1) undone. Each warm solve starts from the
one before it; each is compared with a cold solve of the same network. Lines counted: 1,000+ boardings a day.
Line figures are boardings a day and passenger km a day (fares are a base plus per km, so these two carry the
money).

Threshold used: no line moves more than 2% against the cold solve, and undoing every edit returns the figures
the network had before.

## Results

| | New York, k=1 | New York, k=2 | Tokyo, k=1 |
|---|---|---|---|
| cold solve | 62-64 s, 18 passes | same | 123-127 s, 17 passes |
| warm solve | 31-37 s, 9-10 passes (-45%) | 47-56 s, 13-14 passes (-20%) | 74-89 s, 9-10 passes (-35%) |
| warm re-solve of an unchanged network vs cold: lines over 2% / 5%, largest | 55 / 25 of 101, +68% (NJT HBLR) | 54 / 20, +23% | 22 / 9 of 128, +15% (Arakawa) |
| after edit 2 vs cold | 70 / 38, +28% | 50 / 21, +35% | 21 / 8, +29% (Ueno-Tokyo) |
| both edits undone vs cold base | 65 / 34, +56% | 53 / 27, +29% | 26 / 10, +40% |
| edit 2 undone vs warm before edit 2 (same network) | 64 / 35, -26% | 46 / 18, -14% | 26 / 9, +27% |
| rail trips, any warm vs cold | within 0.34% | within 0.06% | within 0.12% |

The edits' own effect, for scale (cold vs cold): halving the 1's trains moves 13 lines over 2% (the 1 itself
-38%); removing the 4 moves 22 lines over 2% (largest +16%). Tokyo: 16 and 22 lines. The warm solve's drift is as
large as the edit's own effect, or larger, on lines the edit never touched.

## Why

A cold solve's figures are the average of four passes, one of them at free flow. They are not the equilibrium
(T-434: New York's round 3 is 20 lines over 2% from round 12) and only a cold start reproduces them. A warm start
never includes the free-flow pass and averages one to three passes taken near equilibrium, where a single pass
still rings (T-434: a raw pass moves loads 3.6-7% from those it was priced on at rounds 3-4). Its figures then
depend on the edit history, and the gap to the cold figures is of the order of the cold solve's own distance from
equilibrium, many times the 2% threshold. Two more rounds (k=2) halve the worst lines but leave about half the
lines over 2% and save only 20%. Carrying the old loads into the average instead of only into the prices would
damp the ringing but put the old network's riders into the new figures (an edit would show a fraction of its
effect), so it was not tried.

The same history dependence would also show on reload: a loaded game solves cold, so figures would jump on every
load of a save played with warm solves.

## If revisited

Only with a different solve: one converged far enough that cold and warm agree (T-434's tolerance would need 4-6
rounds on New York, more work than today), or one that keeps a per-network result to return to on undo (the
demand cache, T-328, already returns the stored final for a network it has seen, but not for a network
reached by edits).
