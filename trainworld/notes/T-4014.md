# T-4014 Builds refuse, and never overwrite, a newer save

Agent newerlevel, 2026-11-21, tree `.tw-trees/newerlevel` (cut at ac49304b, fast-forwarded to master 2b7ed10a once
busways landed at level 37, so the tree is level 37), Vite 6224. Advisor consulted before the design (it pointed at
my own baseline: the level-37 slot did open in T-1826's read-only mode, so the fix is turning that mode into a
refusal; and at the server as the only place that is atomic and reaches v0.4.5). Scratch: scratchpad/newerlevel.

## What changed

**Load** (one check): `isNewerSave(header, track)` in workers/saveFile.ts, run by `decodeSave`, so every read of a
save goes through it (slot at start, a slot card, Open a file / Load from file, a backup, an account copy pulled in
or in play, the file picker's own check, the save check). Newer means: header `format` above `SAVE_FORMAT`, a level
above `SAVE_LEVEL` or an unknown header field in a save with a level (`headerUnread`), or a network magic past TWT6
(T-3948's `isNewerTrackFormat`, now inside it). The clock worker adds `TrackApi.save_unread > 0` (unknown blocks, flag
bits) before any conversion, no longer exempting `fresh` loads, and its save check calls such bytes "other". All
throw `SAVE_NEWER`, which T-3948's paths already handle: start menu, the card's line "This game was saved on a newer
game version. Reload the page to update.", slot byte for byte, no damaged mark, no `unreadable-` copy, no good copy
rescued. A Community share above this level (or TWT7+) is refused as "version" in `sharedSave.ts`.
- `SAVE_LEVEL` (38) is the app's copy of save.rs `LEVEL`; `the_app_knows_this_level` (save.rs tests) fails until both
  match, and the clock worker logs an error if the WASM it loaded says another level (a stale build).
- T-1826's read-only mode is gone: `saves.newer`, `newerFile`, `keepAsLoaded`, the "newer" write block, the
  protocol's `newer`, Download-as-loaded, and the two hovers `savesPanel.saveNewer` / `savesPanel.downloadNewer`
  (removed from every message file). The quiet "last game did not load" console error is skipped for a newer save.
- docs: architecture.md "Saves from a newer build" (rewritten) and the new "Never over a newer account copy";
  ui-panels.md; SPEC 11; T-3444-design/07-saves.md "What plays read-only".

**Upload**: every PUT sends `level: SAVE_LEVEL` in its meta and in its facts (the facts come back in any server's
list). In workers/cloud.ts, `listGames` remembers games whose copy a newer build sent (`newerThere`, page memory
only, so a reloaded newer build starts clean), and `upload`, the one function that sends a save, refuses those
before sending (any path: save by hand, the settle's forced upload, the "elsewhere" retry; the "moved" retry lists
first). A 409 `newer` from the server does the same. Upload result "newer" is not retried (no `upFailed`); the sync
record's `error` is `WHY_NEWER`, shown through `whyText` as the reused newer line on the card's red line and the
account mark's hover. A fork (new id) still goes up.

**Player text**: no new string. Reused word for word: "This game was saved on a newer game version. Reload the page
to update." (`clockWorker.newer`), now also the card's red line and the account mark's hover when the account holds a
newer copy. Removed with the read-only mode: `savesPanel.saveNewer` ("This game was saved on a newer game version.
Reload the page to update.", Save's hover) and `savesPanel.downloadNewer` ("Download as a file, as saved on the newer
game version"). No changelog item (a safety net).

**Hazard for other trees**: a change that raises save.rs `LEVEL` must raise `SAVE_LEVEL` too, or that build refuses
the saves it writes. `the_app_knows_this_level` (agent_cargo test) and the clock worker's console error (smoke's "no
console errors") catch it.

**Server** (shonei-server f16278a, committed, not pushed or deployed): in `storeGameLocked`, before the elsewhere /
moved rules and whatever `force` says, a PUT whose sender level (meta `level`, else its save's header level) is below
the current rev's level is 409 `{"code":"newer","level","rev"}`, nothing written, no quarantine. Each rev records
`level` (listed); a rev stored before this is judged by its file's header once. A newer build may upload an
older-level slot (one it settles without opening): it can read what it replaces. Cost: each existing game's first
PUT after the deploy runs one full check of its stored rev under `gamesMu` (as `findIntactLocked` already does). Test
`TestTwOlderBuildNeverWritesOverNewer`; `TestTwPinnedCopyOutlivesRotation`'s last intact save now comes from the newer
build. docs/trainworld-api.md "Revs, writers and the three 409s", CLAUDE.md.
- The full suite has two failures not from this: `TestTwSaveCheckFollowsTheGame` (master's save.rs is level 37 since
  busways; the server's check must learn kind 4 and level 37, the handoff's "server learns save level 37+") and
  `TestSetEmailThrottlesRepeatSends` (flaky: passes 3 of 3 alone).

## What builds without this do (said plainly)

From reading v0.4.5's code (b0899150), not a run:
- **v0.4.5 (live, level 34)** opens any save of level 35 or above in T-1826's read-only mode: it plays, nothing
  autosaves or uploads it, the top bar says the newer line; but **Make a copy** writes a level-34 copy without what it
  could not read (busways as rail, BRT stations' blocks dropped) into a new slot, which then uploads as a new account
  game. It never writes over the newer slot or account copy that way.
- **v0.4.5's uploads** of its own games: until the server change is deployed, its forced uploads (a save by hand, the
  settle after a clock-only move on the account) can replace a newer build's account copy (the replaced copy becomes
  an account backup). After the deploy the server refuses them; v0.4.5 does not know the code and shows "Not on your
  account yet: The server could not be reached.", trying again about once a minute while the game runs.
- So the deploy should go before the first release whose level is above what live builds read (this one, 37).
  Builds with this fix refuse level 38+ and TWT7 on load and upload even without the deploy (from the facts' level).
- buswaychk's "opens silently" was not reproduced: on this tree before the fix the level-37 slot opened read-only
  with the newer line in the top bar. Its `m_a.save` (level 36) may be a game built on master rather than the level-37
  file exported back; not checked.
