# T-3430 lines vanish past a zoom level on a Chromebook (bugs3, 2026-11-16)

Fixed (reproduced on software GL, not on the player's device). Reports: 1794785375-4f5ebe4d (Acer R753T Chromebook, two screenshots) and
1794509588-9140c806 (phone, T-3368 found nothing on desktop).

Her screenshot at zoom ~15.4 shows no track or lines outside the station boxes, only the short stretch drawn through each box. The
boxes (and so the "track through the boxes" layer) start at zoom 14 (STATION_BOX_ZOOM), which is the zoom at which it breaks.

Cause: StrokeCache (map/strokeCache.ts) drew its two layers (the whole network, then the track through the boxes) one after the other
into the same multisampled colour renderbuffer, resolving each to its own texture. On some GL drivers the first layer's resolve is lost once the
second layer is drawn into the shared buffer, so layer 0 comes out empty. Below zoom 14 there is only layer 0, so nothing breaks.

Repro: checks scratch script (scratchpad bugs3/zoomrepro.mjs): new game, one built line, Chrome with --use-angle=swiftshader (MAX_SAMPLES 4),
zoom 15.5: before, no line at all; with ?perfOff=strokeCache, line drawn; after the fix, line drawn. The d3d11 desktop was never affected.

Fix: each layer has its own multisampled colour renderbuffer (depth/stencil still shared), so a layer is resolved before the next is drawn into
different memory. One extra MSAA colour buffer per cached view (about 4 MB at 1366x768, 4x).

Not done: a framebuffer completeness check on the cache (it would only help a driver that reports failure, which this one did not).
If a device still loses lines, ?perfOff=strokeCache is the quick test.
