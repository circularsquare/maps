# T-4534 Patched rows check still trips on edge cost (agent edgecost2, 2026-11-27)

Follow-up to T-4506 (notes/T-4506.md). Outcome: fixed, app only (two small changes in the clock worker).

## Cause, from the code

- The road feed (workers/roadFeed.ts) puts each road tile into the track model as soon as it lands: `add_road_tile`
  re-prices the edges it crosses at once (sim net/edit.rs `add_roads`). Its `landed` callback, which calls
  `patchOutside` (clockGround.ts `roadFeed`), runs 30 ms after the last tile of a burst, and every tile restarts that
  timer. So while tiles keep landing less than 30 ms apart the whole burst is one open window.
- A state read that begins inside the window reads the new price and clears `patchedSince` (stateRows.ts `begin`).
  When the burst ends, `patchOutside` sees nothing patched and sends nothing. The page then compares the edit's patch
  (the price before the tile) with the state (the price after): "the patched rows differ from the state's: edges N:
  cost".
- In fresh ground the ghost and the blueprint fetch many tiles at once (6 at a time), so the window is wide while an
  area's ground is loading: T-4368's first route in a new NYC game near Pittsburgh, and smoke on 11-27 (Tokyo, "edges 2:
  cost"). T-4506's run did not open it because its held state was read after the burst had ended.
- The other ground paths have no window. Terrain blocks, zone masks and the world's water are installed and
  `patchOutside` runs in the same task (`ensureBlocks`, `ensureMasks`, `worldWaterIntoModel`). `set_terrain_index`
  prices nothing, `drop_terrain` is refused under live track, and street speeds re-time buses but price no edge. The
  state read is synchronous from `begin` to the edge rows (clockMain.ts `buildState`). Rows a follow-up built before an
  edit came (clockFollowUp.ts `standAside`) were read after their own `begin`, so ground landing since is in neither
  the patches nor those rows.

## The fix

1. clockMain.ts `buildState` calls `patchOutside(a)` right before `stateRows.begin`. What has to hold is about the
   read: what the page holds patched must match what the read gives, or be marked missing. So the test runs where the
   read clears `patchedSince`. That covers the road burst and any later ground path whose patch comes late or never.
2. clockPatch.ts `patchOutside`: the price test compares the edges the last patch laid (`laidCost`'s keys), not every
   edge touched since the read. Edges re-priced by roads go into the touched list through `drain_priced`, which
   `kept_now` runs from `peek_changed_lines` (inside `mapPatch`, after it has read the touched list) and from
   `node_flags_of`. Those edges were never laid, had no laid price, and so always failed the test, sending a patch for
   nothing. With the read running the test, that would have meant a patch before every state that followed any road
   re-pricing.

- Cost: one `edges_info_of` over the laid edges per state read. A patch goes only when a laid edge's price moved with
  no patch since, at an edit patch's cost (worker 7-11 ms, page 1-30 ms by save size, notes/T-4214.md).
- docs/architecture.md (the tools' map paragraph) says that each state read makes the same test.
- Kept: the road feed's 30 ms burst timer. Calling `patchOutside` for each tile would send a patch per tile over new
  track; the read's test closes the window instead.

## Game run (App logic budget: 1 run)

Vite 6147, a new NYC game in sandbox, play.mjs. The probe (`probe.js` in the agent's scratchpad) recorded the worker's
messages and wrapped the page's `checkPatched`.

- Setup: the camera to east Pittsburgh (40.445 N, 79.88 W, zoom 12), with the view's ground in (pending 0 after 0.6 s).
  An 8 km ground-level segment was placed the way the track tool places it (early, its state held), then one ghost 40 m
  beside it. A Playwright route let the ghost's 5 road tiles through 16-25 ms apart, starting 160 ms after the first was
  asked, so the burst was still landing when the held state was read (REST_MS, 220 ms after the ghost's answer).
- Messages (ms from the start; edge 0's price): 72 applied+patch 692.2; 365 preview; tiles landed 558-636; 603
  outside+patch 922.2 (the read's test); 620 state 922.2; 700 state 1322.2 (the burst's end, all 5 tiles); 704 roads.
  No outside came at the burst's end, because the read had already cleared what the page held patched.
- The check on the 620 state: last patch 922.2, state 922.2, no T-4214 error. Without the read's test the last patch
  would have been the edit's 692.2 against the state's 922.2, which is the reported error.
- Not run in the game: the price test's change on its own (read from the code).
