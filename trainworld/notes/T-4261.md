# T-4261: Gemini agents can run play.mjs games

Cause 1 (games): agy puts each session in a Windows job object and ends what a tool call started when the call ends, so play.mjs start's detached game process and the agent's own Vite died after the call. (Earlier runs that "worked" ran start, edits and do inside single calls.)
Cause 2 (grep, and play.mjs do): the allow rule's argument class SAFE excludes | ( ) { } ; & < > $. `git grep -n "a\|b"` has a |; `-e "\.fill("` and `"pack("` have (. All were refused as "user denied permission" (lanecap and packfix steps.txt). The same would refuse most `play.mjs do '...(...)'` calls, which is why agents fell back to `do --file`.

Done:
- gemini_agent.py: `--game <city|file.save>` (off by default). The runner, outside agy's job, starts the tree's dev-nowatch.mjs Vite on a free port in 6100-6199 (no state file, nothing listening on 127.0.0.1 or ::1) and `play.mjs start <game> --port P --cores 1 --idle <timeout>`, before the session; the prompt tells the agent (use do|sim|edits|reload, not start/stop/serve). In the finally it runs `play.mjs stop --port P` then `taskkill /F /T /PID <vite pid>`; port and vite pid are in state.json, so `gemini_agent.py stop` also cleans up after killing the runner. A game that fails to open leaves the run going with a prompt line saying so. Not covered: the runner killed some other way leaves the Vite until reboot and the game until its --idle (= --timeout minutes).
- Chose this over making play.mjs's own start survive the job: the job kills every child, so play.mjs would need a breakaway the job may forbid, and nothing would stop the game reliably at the end.
- agy_session.py: new ARG = SAFE plus "..." (no $ or backtick) and '...' strings, as PowerShell reads them; git read rules use it, and gemini_agent adds a play.mjs-only rule with it. Not allowed still: bare | ; & < > ( ) { } $ backtick, and any command outside the old list. Tested with re.fullmatch on 14 strings (pipes after or inside broken quotes, $(...), redirection, backtick all refused).
- Prompt: one line on how to grep for alternatives (several -e, or -E "a|b").
- Env TW_MAPS_ROOT: points MAPS (trees, runs, venv, cores.py) at the main root; needed because a worktree copy of gemini_agent.py otherwise resolves MAPS to the worktree. Everything else is read from the worktree's own tools folder; the report inbox (reports.py) goes to the worktree's trainworld/notes, so it is not in the orchestrator's inbox for the trial.
- Docs: orchestrator.md Gemini paragraph and line 41; gemini_agent.py top comment.
