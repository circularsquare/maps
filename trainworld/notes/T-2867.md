# T-2867: Firefox out of memory on a 16 GB machine (2026-11-09, agent firefox2)

Player's report: "worker 4: RuntimeError: unreachable executed (out of memory: 57318568 bytes could not be allocated), 184 MB of WASM memory". Firefox, 16 GB, New York.

## Cause: a 32-bit browser's address space

32-bit Firefox 159.0.1 (Mozilla's win32 installer, headless, its own profile) on the real New York save, the game as it stood:

| Pool | Result |
|---|---|
| Default on this 16-thread machine (2 solving workers + aux + focus pool) | Fails at 312 MB of WASM, the same 57,318,568 bytes as the player |
| `?demandWorkers=5` (what "Use more cores" gives on 16 threads; the player's "worker 4" needs that setting) | Worker 1 at 129 MB, 28 MB refused |
| `?demandWorkers=1` | Final, 12,218,770 rail trips (the figure 64-bit Firefox and Chrome give), 367 MB + 65 MB |

Sure it is this for the error's shape (same allocation, same message). That the player's browser was 32-bit is inferred; the report does not say. "worker 4" means the player had "Use more cores" on, or an equivalent.

Why so little: SpiderMonkey keeps 32-bit memories below 2 GB and, with no declared maximum (the demand module declares none), a grow moves the whole memory, so old and new must both fit in one piece of a 4 GB space. Measured with bare workers, 32 MB steps, each memory touched:

- 1 worker: fails at 688 MB. 6 workers: 272-304 MB each, 1,760 MB in all.
- Declared maximum: 1 worker reaches 1,008 MB; 2 workers 432 + 880 (T-2868).

## Telling a 32-bit browser

The user agent cannot: this 32-bit build says `Windows NT 10.0; Win64; x64` in both `navigator.userAgent` and `oscpu`. `new ArrayBuffer(0, { maxByteLength: 2 ** 32 })` throws at once in 32-bit Firefox and returns in 3 ms in 64-bit (`addressLimited`, workers/deviceMemory.ts).

## After the fix, real 32-bit Firefox, real save, 4 cores

| Run | Solving workers | Final | Rail trips/day | Solver WASM |
|---|---|---|---|---|
| As a player gets it (detected) | 1 + aux | 263 s from load | 12,218,770 | 367 MB |
| Same, intercity trips off | 1 + aux | 279 s | 12,175,750 | 193 MB |

The market costs 174 MB in a solving worker on New York's real save, and 0.35% of its rail trips. Six workers reach 272-304 MB each here, so at 193 MB each intercity off would have let this player's six fit; with the market they could not.

## What changed

See the entry in ARCHIVE.md. A forced five-worker pool in real 32-bit Firefox fell 5 to 2 to 1 and then ran out at 318 MB: the workers already stopped had left the address space in pieces, so a detected 32-bit browser starts at one worker rather than relying on the fallback. The fallback is for machines the check cannot see (a commit limit, a full page file).
