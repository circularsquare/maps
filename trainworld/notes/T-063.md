# T-063 network updates from the clock worker

Done 2026-10-09 by the gameplay agent (batch 4) for networks up to ~2,000 route-km; the
10,000 km case is follow-up T-070. Not per tile: measuring first showed the cost was elsewhere.

## What was slow

A 2,000 km synthetic network (T-040's `bench::synth`: 486 edges, 472 stations, 60 lines,
20 KB save) loaded into the app through a save file (`cargo test --release --lib
write_bench_save -- --ignored` with `TW_BENCH_SAVE` and `TW_BENCH_KM` writes the track bytes;
wrapped as TWG1 in the page). Changing one line's trains an hour, headless Chrome on Anita's
desktop:

| | before | after |
|---|---|---|
| edit round trip (post to answer) | 203-251 ms | 26-36 ms |
| main thread per state message | 160-193 ms | 3-6 ms |
| clock worker: state, then render buffers | (in the round trip) | 4-9 ms + 10-19 ms |

A CPU profile put 85% of the main thread in `StationLabels`: every edit recreated all 472 DOM
labels and the invisible shadow layer's GeoJSON, then measured each label's width between writes
(`offsetWidth` after each `transform`), and `Overlay.toScreen` read `canvas.clientWidth` per call,
so every label forced a layout. The rest was building the renderer's stroke arrays with
`number[]` pushes on the main thread.

## What changed

- `StationLabels.set` keeps labels and the shadow layer when no station changed (name, position,
  constructed, heading, lines through it); `place` measures all new labels before moving any.
- `Overlay.toScreen` uses the canvas size kept from the last resize.
- The clock worker builds the renderer's buffers (`networkFromState`, map/network.ts, now with
  typed arrays that grow by doubling) and sends them in the state (`ClockState.net`, transferred);
  the main thread only uploads them.
- The worker keeps each edge's drawn polyline and each line's 50 m samples in local units between
  edits and redoes only those the edit dirtied (`dirty_edges`, `dirty_lines`); a load clears them.

## 10,000 km (2,408 edges, 2,340 stations, 300 lines)

Load from a file 0.71 s (worker). An edit: round trip 130-214 ms, main thread 23-36 ms per state
(GPU uploads of every buffer, the world view, effects) plus deserialising the whole state object;
worker 13-33 ms for the state and 60-100 ms for the buffers. Not a freeze, but one or two dropped
frames an edit. T-070: send what an edit changed (edges, nodes, lines by id) instead of the whole
state, keep stroke buffers per edge in the worker, and upload sub-ranges on the main thread.
