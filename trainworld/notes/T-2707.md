# T-2707: the boarding account's memory on all of Japan

T-2699 left the account at ~1.07 GB of the clock worker's WASM memory on all of Japan with three kinds
of day (made-up riders; ~98 MB before riders). Done 2026-11-07, agent boardmem, main tree.

## What it was

The arrival masks (T-842b), as guessed. `Boarding::mem_bytes` (new, benches only; `TrackApi::boarding_mem`,
not exported) counts the heap each structure holds; `boarding_bench` prints it after its rounds.
`t737-japan-trains.save` (807 lines, 9,529 stops), three kinds of day, native bytes:

| structure | before | after |
|---|---|---|
| mask segments (`Mask::t`, `s`) | 559.3 MB | 185.2 MB |
| mask running sums (`Masked::pre`) | 275.3 MB | 38.7 MB |
| load, q_after, gone | 39.1 | 39.1 |
| order, order_t | 39.1 | 39.1 |
| left_h, wait_h, hour_load | 16.0 | 16.0 |
| arrivals, riders, accounts, deps, stop_open, ride_km | 21.6 | 21.6 |
| masks kept (the per-line list) | | 0.2 |
| **all** | **950.4 MB** | **340.0 MB** |

A mask has a segment per 60 s of the tolerance ramp (`span::stop_mask`, `STEP_S`) before every
departure more than 30 min after the one before, so a stop with hourly trains has ~600 segments; three
f64 a segment, at ~19,000 platforms, times three kinds of day. The segments depend on the service only;
the running sums depend on the day's riders.

## Changes (`sim/src/track/boarding.rs`)

- `Masked::m` is an `Arc<Mask>`. `Boarding::masks` keeps each line's masks per run with the service
  key they were made for (`line_masks`); every kind of day's account, and the warm rerun and a circle's
  second pass, use the same ones. A line whose service key changes gets new masks; a line with no
  account on any day drops its own once a full scan finds everything up to date; `clear` drops all.
- `Masked::pre` keeps one running sum in `PRE_EVERY` (8); `Arrivals::cum` adds the segments between
  in the same order as the sum was built, so every figure is the same to the bit.
- The service key (`Boarding::key`) now hashes `net.line_auto` too: the lattice's headway waits
  (T-2607) read it, and the shared masks must not outlive a change to it. Before, a change to it alone
  left the account stale until the riders changed.
- `simulate` keeps its signature (tests); `simulate_with` takes the masks.

## Measured

Native `boarding_bench` (same machine, one after the other): three kinds of day p50 5.07 -> 4.06 ms;
later rounds p50 4.85 -> 3.7 ms. Building a line's masks once instead of three to six times outweighs
`cum`'s extra segment sums.

WASM, T-2699's Node bench (`wasmbench.mjs`) on the app's `wasm` profile build, master built to a
scratch folder and run alternately with this one:

| | memory | three kinds of day p50 / p95 / max | later rounds p50 |
|---|---|---|---|
| master, two runs | 1,056 MB | 5.24-5.53 / 13.3-13.7 / 44 ms | 5.4-6.5 ms |
| this, three runs | 412 MB | 4.23-5.08 / 11.1-12.2 / 27-36 ms | 4.0-4.8 ms |

Memory before riders is 97 MB in both, so the account goes from ~960 MB to ~315 MB of WASM memory.

Figures: the native `TW_DUMP` before and after are byte-identical (and identical to T-2716's).
