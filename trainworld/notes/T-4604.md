# T-4604: zone pair click-through ignores bus stops

Found 11-28 (agent ldexplain, from moonraker's report; see long-distance-explainer-2026-11-28.md).

Cause: map/tripView.ts exploreMarket asked game/marketRule.ts stationNear with world.save.stations. Plain bus stops are
not in save.stations (game/world.ts stopsOf adds them to stopsById), so a bus-only network had no "station" near either
place and the explorer answered from the market rows with no transit ("There are no stations near either place").

Fix: exploreMarket passes every stop, [...stopsById(w).values()] (stations and bus stops). stationNear's comment and
docs/ui-inspectors.md say stop. No string changed.

Other places that ask "is there a stop near here" and read only save.stations (listed, not changed):
- game/places.ts nearestStation / stationNameNear: name the station near a point (TroubleList, Marey chart, LineInspector). A bus
  stop is never named there; those are display names, left alone.
- game/worldTotals.ts builtCities and ui/inspector/CityInspector.tsx / CityDetails.tsx / Cities.tsx / AllCitiesView.tsx: a city
  counts as built only with a built station, so a bus-only city is "not built" in the Cities tab, top bar totals and city panel.
  This is the biggest cousin; whether a bus-only city counts as open is a spec question (SPEC "open"), left for Anita.
- game/realms.ts built realms: from stations only.
- map/intercityView.ts unbuilt dots use the clock's opened set, not stations.

Not in scope: the zoomed-out hover counts and the "intercity" wording.

Checks: typecheck passes. Game run not done: the core ledger was full (14 of 14) and the Duluth game never got its 2 cores.
The fix is one predicate input; not seen running.
