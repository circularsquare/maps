# T-051 app wasm size

Done 2026-10-09 by the performance agent (batch 4).

## What changed

The app builds two wasm modules from the one crate instead of one (`app/package.json`):

| Module | Built with | Loaded by | Out dir |
|---|---|---|---|
| track | default features (`track-api`: `TrackApi`) | the clock worker | `app/src/wasm/track/` |
| demand | `--no-default-features --features demand` (`DemandApi`) | each demand worker | `app/src/wasm/demand/` |

- New Cargo feature `track-api` (default on) gates `track::wasm` (`TrackApi`); `track-bench` now
  implies it. With LTO, a module carries only the code its exports reach, so the demand module
  has no track model (it uses `track::params` constants only) and the track module has no demand
  kernel or `serde_json`.
- New Cargo profile `wasm` (release plus `codegen-units = 1`), used by both wasm builds through
  `wasm-pack --profile wasm`. Native builds and `cargo test --release` keep `release`.
- `npm run wasm` runs `wasm:track` then `wasm:demand`. The two worker imports changed by one line
  each (`../wasm/track/sim`, `../wasm/demand/sim`); the old combined `src/wasm/sim*` files were
  deleted.

## Sizes

All from the same source at 09:05 (the track model grows as batch 4 adds to it; later builds are
a little bigger). Raw / gzip -9 of `sim_bg.wasm`; wasm-pack runs wasm-opt `-O` on all of them.

| Variant | Raw | Gzipped |
|---|---|---|
| one module, track + demand, opt 3 (before) | 677.6 kB | 243.6 kB |
| same without wasm-opt | 862.4 kB | 261.0 kB |
| track only, opt 3 | 431.4 kB | 163.9 kB |
| track only, opt 3, 1 codegen unit (**shipped**) | 412.4 kB | 157.2 kB |
| track only, opt s | 360.7 kB | 146.9 kB |
| track only, opt z | 305.7 kB | 122.8 kB |
| track only, opt z, 1 codegen unit | 298.6 kB | 120.4 kB |
| demand only, opt 3 | 205.2 kB | 81.2 kB |
| demand only, opt 3, 1 codegen unit (**shipped**) | 193.7 kB | 78.5 kB |
| demand only, opt s | 164.9 kB | 71.7 kB |

So: the clock worker downloads and compiles 157 kB gzipped instead of 244, each demand worker
79 instead of 244, and the two together are 236 against 244 (nothing is downloaded twice).
The build in `dist/` at the end of this task: track 428.6 kB (165.8), demand 193.7 kB (79.3).

## Why opt-level 3 for both

- **Demand**: the pair loop is the recompute (SPEC 4.4), so it stays at 3.
- **Track**: the clock worker runs every edit and every drawing preview (a trial edit per mouse
  move). WASM track bench, 2,068 km (`track_bench` in Node, median of 21):

  | opt-level | PI on the busiest edge | 1-line edge | schedule | load a save |
  |---|---|---|---|---|
  | 3 | 2.40 ms | 0.45 ms | 0.41 ms | 18.4 ms |
  | s | 2.93 ms | 0.52 ms | 0.53 ms | 20.1 ms |
  | z | 4.33 ms | 0.92 ms | 0.82 ms | 33.3 ms |

  s saves 17 kB gzipped for edits 1.2x slower, z 41 kB for 1.8x. SPEC 1 puts never freezing and
  CPU before download size, and at 10,000 km the busiest edit is already ~20 ms, so 3.

## Not done

- **`serde_json`** is now only in the demand module: about 15-20 kB raw there (twiggy: the `Value`
  deserializer 6.5 kB plus parsing and float code). Dropping it means parsing the pack header in
  JS and handing `DemandApi` the numbers (T-060, demand agent's files).
- **`TrackApi.issues()`** (Debug text of every issue) is unused by the app (it reads
  `issue_kinds`) and pulls in `Debug` formatting; float formatting (`flt2dec`, ~11 kB) stays for
  `issue_kinds`' money text anyway. Worth removing with the next `wasm.rs` edit; a few kB.
- The track module is spread thin: no function over 17 kB, and the many monomorphised sorts
  (2-6 kB each) are the largest group. Nothing big left to cut without opt-level s or z.
- The T-001 `Sim` skeleton export in `lib.rs` is still in both modules (small).
