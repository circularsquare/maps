# T-3940: a warning before a big load on Safari (agent safariwarn, 2026-11-23)

## What changed (tree tw/safariwarn)

- **Signal** (`workers/deviceMemory.ts` `tabLimited`): a phone or tablet by `mobileDevice()` (user agent iPhone, iPad,
  iPod, Android, Mobi; or a Mac user agent with `navigator.maxTouchPoints > 1`, which is iPadOS Safari's desktop mode)
  whose browser has no `navigator.deviceMemory`. That is every iPhone and iPad browser (all WebKit, including Chrome
  and the Google app there) and Firefox on Android. A Mac (Mac user agent, 0 touch points) and desktop Firefox are not
  included. iPhone and iPad are not told apart: both have crash reports (iPad 10th gen T-4071 group 1, the 2360x1460
  report), and their tab limits overlap.
- **Threshold** (`game/memoryEstimate.ts` `bigForTab`, `overBudget`): 1,600 stations or more. From T-3781's emulated
  iPhone runs (tab peak, production build): shipped Tokyo start 1,454 stations 1,362 MB; A 2,090 stations 1,270; B
  1,646 stations 1,628-1,705; C about 1,659 stations 1,653; D 1,156 stations 1,254. iOS kills a tab at about 1.4-2 GB.
  Every crashed game with a known count is 1,646 or more; the shipped real starts (Tokyo 1,454, Osaka and Berlin of a
  similar track size) stay under, so a player who just started one is not nagged. Stations predict the peak badly (A
  has the most and peaks lowest: only 2 of its 7 zones held fine); fine zones matter more, but no crash save's zone
  ids were kept, so no zone rule was fitted. The desktop GB estimate (1.64 + 0.8 per 1,000 stations) reads about 1.7x a
  phone's tab, so it is not compared with anything on phones; the card still shows it (now red past 1,600).
- **Warning**: the existing callout (`ui/MemoryWarn.tsx`), on the start menu card and the saves panel's Open, with the
  phone sentence in place of the GB one. Buttons wrap now (the third did not fit at 390 px).
- **After a died load**: T-2545's sessionStorage flag already marks a load that never finished. Added: the died load's
  slot goes to localStorage (`tw-died-slot`, kept until that slot loads with its trips, so a closed tab keeps it), and
  whether the load was light (`light` in the mark). The out of memory screen gets Open without calculating trips when
  the slot is known and the died load was not already light: it opens `?slot=<key>&trips=off&paused=1`, the light load
  of T-3851 (no demand worker, no city pack; money frozen while open), which already worked for a slot saved from a
  viewed network and now takes a slot from the URL (`choiceFromUrl`). On the start menu the died slot asks first with
  "This game ran out of memory the last time it loaded." and the same three buttons. T-3933's retry with fewer workers
  skips a died light load (no workers ran, and its retry would open the game with trips). The failure screen no
  longer repeats its sentence as the small reason line when the two are the same (the died screen showed it twice).

## Strings (en)

- new `savesPanel.memoryWarnPhone`: "This game is big for a phone or tablet and may run out of memory while loading."
- new `savesPanel.memoryWarnDied`: "This game ran out of memory the last time it loaded."
- new `common.openWithoutTrips`: "Open without calculating trips"
- reused: "Open anyway", "Cancel", "Try again", "Ran out of memory. Close other apps and tabs, then try again.",
  "This game's trips aren't calculated.", "Calculate trips".
