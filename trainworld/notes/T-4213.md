# T-4213 Benchmarks enforce the measuring budget (agent benchgate, 2026-11-24)

Anita 11-24: "we've said something along these lines 'from now on we will do fewer tests' like several times now. lets make sure we actually come up with something followable."

## What it does

tools/bench_gate.mjs (shared by perf_bench and edit_bench). A tree is a checkout under .tw-trees/<name>/.

In a tree, one plain line and exit 2 for: --runs above 1; a third invocation (count in <tree>/.bench-runs.json, written when a run starts, failed runs count); a save whose name or path matches tokyo|belgrade|asia unless --heavy "<reason>" (reason recorded in the count file, still counts); perf_bench compare; perf_bench build of anything but this tree; edit_bench --compare; --baseline. Defaults in a tree: perf_bench saves nyc, edit_bench save nyc and --runs 1 (outside: 3). --dry-run runs the gates and exits without counting.
On master nothing is refused.

Master's numbers: perf_bench run ... --baseline (all three saves) writes perfbench/baseline.json ({save: ledger line}); edit_bench --baseline writes editbench/baseline.json (that run's lines). Neither is written when the run is noisy or the ledger went over its cap. A tree run diffs against them (perf: the usual flags, vs "master baseline <label>"; edit: median per action, old -> new). No baseline file yet: it says so; the orchestrator writes them on master.

NOISY: cores.py list is read after the run's own claim and again before release; others = claimed minus own claim; above 4 at either point prints NOISY (n), adds noisy:n to the ledger line, and the baseline is not written.

watch.py: "busy:" line when claims have been at 12 or more for over 20 minutes in a row (polled each minute, at most one line an hour).
