## What changed (shonei-server 6ab8b68 code and tests, ada0bce docs, 8ba8657 restore never erases for room)

Differs from the brief's wording on purpose: the held game's files are not moved to a separate place; they stay in
the account folder and only the index entry moves (`games` to `deleted`), so a delete stays one atomic index write
and account deletion covers them by construction. Held games count against the account's 64 MB and give way early
when a player's save needs the room, so "up to 7 days".

- **Soft delete** (`trainworld_games.go`). `DELETE /trainworld/games/<id>` answers 204 and leaves the tombstone as
  before, so every client behaves the same; refused uploads, leaderboard figures and the Community share still go at
  once. The game itself (save, backups, pinned copy, picture) moves from `games` to `deleted` in the account's
  index with a new `deletedAt`, files left where they are: one atomic index write, the same shape T-1828 used on
  2026-10-29. The client's version deletes and card deletes (`groupHeads`) all arrive as this one DELETE, so they are
  covered; there is no other server path that erases a single game.
- **Purge**: `purgeDeleted(ix, now)` drops held games past 7 days (`twDeletedKeep`) at the account's next write
  (PUT, DELETE) and from `sweepDeletedLoop`, every account each hour (was a one-off sweep at start, matching
  feedback's 6-hour loop and T-1828's). The list and undelete also refuse anything past 7 days, so the promise does
  not hang on the sweep's timing. T-1828's leftovers have no `deletedAt` and go by their (October) tombstone, so they
  are erased at once.
- **Room**: held bytes count in the store's 16 GB and the account's 64 MB, but not in the listed `used` (the
  account panel's "storage used") or the 50 games. A save that would be refused `full` or `server-full` first
  erases held games, oldest first. So parking by upload-and-delete is bounded by the account's 64 MB.
- A held id answers 410 to PUT and claim even after its tombstone is pruned (1,000 a year).
- **Account deletion** removes the whole account folder (`deleteGamesLocked`), held games with it, unchanged.
- **One write path**: the body of `handleGamePut` is now `storeGameLocked` (check verdict, conflicts, caps, files,
  index, leftovers, purge); the player PUT and the admin restore both call it. Options: quarantine (player only),
  fresh (the id must be new), dryRun.
- **Admin restore** (`trainworld_restore.go`), create-only, each write a new random id:
  `GET /trainworld/admin/games/<account>/deleted`, `POST .../undelete {game, rev?, dryRun?}` (the held game's
  current rev or a listed backup/pinned rev, with its name, facts and picture; the held copy stays, so it can be
  restored twice), `POST .../put[?dryRun=1]` (multipart meta {name, facts}, save, picture?). Writer `server-restore`
  until a browser claims it; no backups, no figures. A damaged save is 422 and not quarantined. Unknown account 404.
  A restore that does not fit is 507 `full` and never erases a held game for room (8ba8657).
- **Key**: `SHONEI_GAMES_ADMIN_KEY`, new. `adminHashOK` (trainworld_names.go) uses `SHONEI_FEEDBACK_ADMIN_KEY`,
  which local tools read from `~/shonei-feedback-admin-key.txt` and agents use for GETs only (Anita, 2026-11-12).
  The restore routes take only the new key (constant time, 404 unset, 401 wrong); the server refuses to turn them on
  if the new key equals the inbox key. The tool reads `~/shonei-games-admin-key.txt`.

Go tests: `TestTwDeletedGameIsHeldSevenDays`, `TestTwHeldGamesGiveWayForRoom`, `TestTwAccountDeleteErasesHeldGames`,
`TestTwRestoreKey`, `TestTwUndelete`, `TestTwRestorePut`, `TestTwRestoreNeverErasesHeldGames`; the three delete tests that assumed deleted-for-good were
rewritten to the held rule; the admin routes are in `twRoutes` (rate-limit and CORS tests). `go test .` passes (40 s).

## The tool

`trainworld/tools/ops/restore_game.py list-deleted|undelete|put`. Dry run unless `--yes`; the dry run goes to the
server with `dryRun`, so it runs the real check and caps. `put` reads day, cash, mode and city from the save's own
header; stations and lines are not in the header (the network would need decoding), so `--stations`/`--lines`
(the backup's index has them), else the card shows 0 until the player opens the game and it saves. Its help holds
the streamed one-folder R2 command from T-3786 as the manual fallback, Anita's yes each time.
