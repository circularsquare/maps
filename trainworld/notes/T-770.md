## T-764, T-773: what each check does when tripped (tested on a scratch tree with stand-in steps)

- **Sim copy without junctions** (`check_sim`, at the start, before and after each gate, before
  each joint solve and after a failed solve step): at the start, "RUN FAULT, nothing run" and no
  batch folder (tried on the real runner with `--rows nic`); mid-run, the region's rows are taken
  out of the registry and stay `built`, the run stops (exit 2), the report's `fault` says why.
- **STOP**: `status` prints the path (and whether the file is there); a run will not start with
  it present; the run's first line prints it too.
- **Silent step**: `quiet_watch` in the step process arms faulthandler's C timer (fires while C
  code holds the GIL), re-armed by a thread when the log grows; the runner prints one line per
  silence. A stand-in step silent for 14 s with `TW_QUIET_S=5` got 4 stack dumps in its log.
- **merge_cells** writes to `res9/staged/`, runs `read_pack.check` there (2 s on Tokyo), and only
  then replaces the pack. On Melilla the output is byte-identical to the committed merge_cells'; a
  rule broken on purpose (an empty cell) fails the step with the pack untouched.
- **Re-gate with no result** (T-773): the group is restored, the run stops, no row parks, new
  packs stay built and registered. A region gate with no result does the same (rows unregistered).
- **Only new members FAIL the re-gate**: those park; the group solves once more without them, and
  the rest ship. An older member FAILing, or a FAIL on the second solve, parks every new member of
  that solve.
