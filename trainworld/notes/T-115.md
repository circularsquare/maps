# T-115: Philadelphia city pack

Add Philadelphia from the existing US tier-1 pack pipeline, explicit non-overlapping metro
boundary and cached open data. Verify population/jobs/cells/gravity/water pack invariants.
No New York data changes. Keep CPU within project cap and document source and extent.

## Extent and inputs

`phl` uses Philadelphia City Hall as its local origin: longitude -75.1636, latitude 39.9526.
The boundary is the standard Philadelphia-Camden-Wilmington MSA's 11 counties:
Bucks, Chester, Delaware, Montgomery and Philadelphia PA; Burlington, Camden, Gloucester
and Salem NJ; New Castle DE; Cecil MD. This is disjoint from the existing New York county
set. Mercer/Trenton is its own metro area and remains outside both packs; corridor/town
demand is T-117 rather than silently expanding either local market.

County definition verified against the [BLS Philadelphia metro definition](https://www.bls.gov/regions/mid-atlantic/news-release/2024/areaemployment_philadelphia_20240828.htm),
which lists the component counties. Census county polygons are the same 2020 cartographic
file already cached for New York. Population uses 2020 TABBLOCK20, jobs and resident job
holders use LODES 8 2023 WAC/RAC, work-from-home uses ACS 2019-2023 B08301/B08126.
Water and polygon spreading use the existing TIGER 2020 pipeline, 25 m water/50 m spread
grid, H3 resolution 9; gravity uses the existing Rust pack solver.

## Multi-city cache correction

The shared ACS extracts now retain both cities' tracts, and `wfh.extract` returns only the
requested city's rows. Previously a superset cache would mix another city's industry
work-from-home rates into a rebuild. `notes/t115-cache-check.py` checks distinct rates,
retention of both extracts, and cached rebuilding without another fetch.

## Build and validation

Build with `venv/Scripts/python.exe trainworld/pipeline/build_city.py phl`, CPU limited to
two Cargo/BLAS threads. Public data download required the normal network sandbox
escalation, approved automatically. Cached NJ and most water files were reused; large
state ZIPs use range requests for the DBF member instead of downloading full archives.
The outputs are `data/packs/phl.json`, `phl.bin`, and `phl.boundary.geojson`; city packs
remain gitignored, like New York. `notes/T-115-build.log` captures the reproducible build.

Source totals: 6,245,051 people, 2,980,509 jobs, 2,997,448 resident job holders. No jobs or
resident job holders were lost in the join to 2020 census blocks. Philadelphia currently
uses source job locations without the New York-specific employer corrections.

Completed in 93 seconds. Pack is 4,413,412 bytes raw, 2.65 MB gzipped, 110,578 cells,
3,173 gravity zones. Work-from-home weights total 2,500,663 home-end and 2,464,724 work-end;
gravity balances on 2,464,724 commute trips, mean zone distance 17.28 km. Independent
`read_pack.py phl` checks array alignment/lengths, H3 IDs and local coordinates, totals,
gravity row/column constraints, water run encoding and eight river/bay/land locations.
Worst independent row error 7.7e-8, column error 6.9e-5; all pass. Census population equals
the published county 2020 base exactly; LODES jobs are 5.1% above annual-average QCEW
(different job-count definitions), all 11 counties present. `../../artifacts/trainworld/T-115-pack.png` was visually
inspected: Philadelphia/Camden and Wilmington concentrations read correctly with rural
outer counties and river gaps.

The reader's old per-cell home-commuters <= population assertion was invalid for newer
LODES RAC (job counts, not unique people) against POP20. 943 tiny cells exceed POP20,
with ~1,988 home weights against ~505 old residents in total. The reader now checks finite,
nonnegative weights, regional home <= population, work <= jobs per cell and exact shipped
totals; it does not cap or discard these inputs. New York's independent read check also
passes unchanged. `look_pack.py` axis labels now refer to the pack origin, rather than
calling every city's origin Midtown.

Root integration: Vite distributes phl.json/phl.bin alongside nyc pack assets. This prepares
the data but does not activate a second local-demand solver or intercity trips; those are
explicitly T-116/T-117. Current spec reflects that boundary.
