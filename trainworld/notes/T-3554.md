# T-3554 finish: land and archive a tree in one command

Code: `trainworld/checks/agent-tree.mjs` (new `finish` subcommand; `land` and `remove` unchanged in behaviour, `land`
now shares `landTree` and `rebuildWasm` with it). Edited in the tree `.tw-trees/landtool`; it reaches the main tree when
the orchestrator lands that tree.

## Usage

    node trainworld/checks/agent-tree.mjs finish <name> "<commit sentence>" [--task T-1,T-2 --outcome "..."] [--notes notes/T-1.md] [--keep-tree] [--dry-run] [--log <file>]

Steps, one line each (`[n/5]`):
1. changelog: if the tree's `trainworld/changelog/next.json` differs from its base (merge-base with master), the tree's
   copy is restored to the base content (`git checkout <base> -- file`, or deleted if the base has none) and each item whose
   id is new relative to the base is added in the main tree with `changelog.py add` (text, `--area`, `--fix`, `--task`, `--by`).
   Items already in the main tree with the same text and task are skipped. Prints each item moved, and a count of edits to
   existing items that were discarded. `edited`/`hidden`/`parent` of moved items are not carried (agents don't set them).
2. land: the old `land` logic (uncommitted work committed, rebase onto master, squash to one commit, fast-forward). A tree
   whose branch already has commits works the same way (it is squashed with any uncommitted work).
3. WASM: `npm run wasm` in the main tree only if the landing touched `trainworld/sim/`.
4. remove the tree (skipped with `--keep-tree`).
5. `tasks.py done <id> --outcome ... [--notes ...]` for each id (`--notes` goes to every id).

Everything else (git output, CRLF warnings, WASM logs, tasks.py output) goes to a log, by default
`artifacts/trainworld/finish-<name>-<time>.log` (the system temp folder if that folder is missing); the path is the last line.
On failure: `FAILED at step n/5 (...)` with the error in full, a `state:` line (items moved, whether master has the commit,
whether the tree is gone, which tasks are archived) and the commands left to do by hand. It does not resume: rerun only the
listed commands (a second `finish` would say "nothing to land" if landing already happened).
`--dry-run` makes no changes (no revert, no log file) and checks for changes outside `trainworld/` and for nothing to land.
Python is `venv\Scripts\python.exe` of the main tree, or `TW_PYTHON` if set.

## Tested

In a throwaway local clone in the scratchpad (own `.tw-trees`, so no commit reached the real master; clone deleted after):
- `--dry-run` with a changelog item, one branch commit and one uncommitted file: right lines, nothing changed.
- Full run: item moved to the clone's main next.json and reverted in the tree, 2 files squashed into one commit, tree removed,
  log written. Step 5 first failed (the clone lacked the untracked `notes/board-live.json`): the failure report, state line
  and hand-run list were right.
- A `sim/` change: step 3 ran `npm run wasm` and failed (no app in the clone, deliberately); report right, stopped there.
- Two task ids with `--keep-tree`: both archived, tree kept.
Not tested: a real WASM rebuild through `finish` (same code as `land`, only the output is logged), a rebase conflict, an
ff-only refusal from a dirty main tree (both throw with the old messages).
