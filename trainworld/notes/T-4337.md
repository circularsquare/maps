# T-4337 (groupsopen)

Cause: game/groupsClosed.ts kept closed group numbers per save slot; group numbers restart in every game, and a new game or another save in the slot matched them again.
Fix: each closed group is kept with a signature of its oldest line (number, name, colour, first stop place); it counts as closed only while the world has a group of that number with that signature. The check runs on every world, so a stale world during a load corrects itself. Only the player's own toggles write storage (a load never erases a slot's record). Number-list records from T-4329 still apply: matched groups are upgraded to signatures on first sight.
Cousins: new game (no groups, all open), another save in the slot (signature differs), file open, restore, shared network (viewing: no key, keeps nothing), `?new=1` (no slot, writes nothing). Reopening the first game in the same slot keeps its closed groups only if it is the slot's game again (record kept until the player toggles in another game).
Limit: only the first stop being redrawn on the exact same spot in a new game keeps the group closed; a rename or recolour of any line changes nothing. Signature: oldest line number and first stop lng/lat; older records with name and colour are read by those two parts.
Checked: typecheck clean. Game run on :6144: new game A in the autosave slot, two lines grouped (numbers 0 and 1, names "Line 1" and "Line 2", first colour), group closed, stored with the first stop's place. New game in the same slot, same two default lines grouped about 0.8 km east: group open, record untouched. The first version of the signature (number, name, colour, station id) would have matched here, since a new game starts those over; so the signature now holds the first stop's lng/lat.
