## Summary

**Recommendation.**
- **One anita.garden account for noritetsu and anitabuilder.** Both pages live on anita.garden,
  so they share browser storage: signing in on one signs you in on the other. The server keeps its
  noritetsu accounts as they are (Google, or a username and password with an optional recovery
  email) and adds anitabuilder's data beside them under `/trainworld/`. No sign-in code is written
  twice.
- **An account holds**: the leaderboard opt-in and display name, each normal game's score figures
  (stage 1), and later the games themselves, synced between devices (stage 2).
- **Boards rank points a day** (the game's own score: 20 a rail trip and 1 a passenger-km over
  the past 24 game hours), one world board and one per region (T-975). Normal games only; a
  sandbox game, or one that has been a sandbox, never sends a score. Each person shows once per
  board, with their best game.
- **Honest enough for friends**: figures are sent by the page, so anyone could fake one, as on
  noritetsu and the map games. The server bounds them, a sandbox is never listed, and from stage 3
  a row can open that game's network to look at, so a fake score with no network behind it is
  plain to see. You can hide a row by hand.
- **Placement**: a person icon in the dock's row beside the saves button, and the same icon on the
  start menu card. Leaderboards: a small trophy on the Cities tab's "All cities" row.

**Stages**: 1 sign-in and leaderboards; 2 games synced between devices; 3 a board row opens that
game to look at (sharing by link, M4).

**Questions for you**

   (like noritetsu's % of a country) or train rides a day?
3. Do you want games synced between devices (stage 2)? noritetsu syncs rides, so I assumed yes.
4. A privacy page and terms for anitabuilder, copied from noritetsu's and adjusted: you would
   read them before sign-in goes live.

## Accounts

**Shared identity.** The page calls the existing sign-in routes (`/noritetsu/config`, `signin`,
`register`, `login`, `refresh`, `password`, `email`, `forgot`, `signout-all`, `account`) and
keeps the session in the same storage key noritetsu uses (`noritetsu.auth.v1`), so one sign-in
serves both pages. Tokens and refreshes behave as on noritetsu (60 days, refreshed once on load).
Google's client already allows anita.garden. Server changes for this: anitabuilder's routes accept
noritetsu's token; deleting the account also deletes its anitabuilder data, and both pages' delete
question says so; CORS for the local Vite ports (6100-6199) besides 8800; the account cap (2,000,
alert at 1,000) shared, perhaps raised.

If you prefer separate accounts, the cost is a second copy of the sign-in code on the server
(the account parts of noritetsu's 2,300 lines of Go with Google and passwords) or a refactor of it
into a shared module, and players sign in twice.

**Privacy**: no real name is ever needed. A password account's username is private (a login,
never shown); the Google login's email and name are never read or stored; the recovery email is
optional and confirmed before use; the board name is chosen by the player, at most 24 characters,
through the map games' name filter. A board shows the name, the figure and nothing else unless the
player shares a game (stage 3). Google's sign-in script loads only when the account panel opens,
not with the game.

## The account panel

A person icon (head and shoulders outline) at the right end of the dock's icon row, between the
saves button and the Controls button; hover "Account". The start menu card has the same icon at
its top right, so a player on a new device can sign in before picking a game. Both open a centred
panel like the saves panel:

- **Signed out**: Google's button, then username and password with Log in, Create an account and
  Forgot password, as noritetsu has; Privacy and Terms links at the bottom.
- **Signed in**: "Signed in as alice" (or "Signed in with Google"), the recovery email field with
  noritetsu's warning when there is none ("Add a recovery email. Without one, a forgotten password
  means a lost account."), Change password, Sign out everywhere else, Sign out, Delete account
  (asked first). From stage 2, sync's state ("Synced 2 min ago", or the error).

## Leaderboards

**What is ranked**: points a day, the figure the Cities tab already shows. Boards: `points`
(the whole network) and `points_<region>` (the points of trips starting in that region's zones,
T-975's regions). A per-zone board (about 2,000 of them) would be mostly empty, so none. Points
change once a game hour, so a board shows each game's figure at its last save, not a peak: a
network that loses riders drops. Each person shows once per board, with their best game; a row
has rank, name and points ("4.56M", the exact figure in the hover).

**Who is listed**: signed-in players who joined, from normal games with points above 0. A sandbox
game sends nothing (the save header's `mode`; a game that switched once stays a sandbox), so its
Join is greyed with the hover "Sandbox games are not listed". Deleting a game in the saves panel
while signed in removes its figures. Leaving the leaderboards takes every row off at once and
keeps the name for next time, as on noritetsu.

**The panel**: a trophy icon at the right end of the Cities tab's "All cities" row (hover
"Leaderboards"); nothing elsewhere, so it stays out of the way. It opens a centred panel: a board
picker (World, then the regions that have rows), the top 50, the player's own row under them
when lower, and at the bottom one of: "Sign in to be listed" (opens the account panel), a name
field with Join, or Leave the leaderboards. "Nobody here yet." on an empty board.

**Keeping it honest enough**:
- The server refuses figures outside bounds (points a day at most 10^9, rides at most 10^8, a
  share at most 100%, at most 64 regions per game).
- No sandbox (above).
- From stage 3 a row whose game is shared opens that network read-only, so friends can see how a
  score was made.
- A short hand-edited hide list on the box (`trainworld/hidden.json`, account ids) for a row you
  want gone; nothing more. The simulation is deterministic, so a doubtful save could be loaded
  locally with the same data version and its points recomputed, but no tool for that is planned.

## Server (shonei-server, a new `trainworld.go`)

Store dir `trainworld/` (gitignored runtime state, never shipped by deploy.ps1), keyed by the
noritetsu account id; in memory only the opted-in figures, as `noriIndex` does.

| Stage | Method and path | What |
|---|---|---|
| 1 | PUT `/trainworld/score/<game id>` | the game's figures: `{mode, day, points, rides, regions: {<id>: {points, rides, share}}}`, at most 8 KB |
| 1 | DELETE `/trainworld/score/<game id>` | a deleted game's figures |
| 1 | PUT `/trainworld/optin` | `{on, name}`, the name filter as noritetsu's |
| 1 | GET `/trainworld/board?board=<key>` | top 50 and the caller's row (`points`, `points_<region>`) |
| 1 | GET `/trainworld/boards` | which boards have rows |
| 2 | GET `/trainworld/games` | the account's games: id, name, mode, day, rev, savedAt, bytes |
| 2 | GET, PUT, DELETE `/trainworld/games/<id>` | one game's save bytes (TWG1, as written to a file), PUT with `baseRev` (409 on a mismatch) and the figures |
| 3 | POST, DELETE `/trainworld/games/<id>/share`; GET `/trainworld/public?g=<share id>` | a read-only link to one game |

Nothing of noritetsu's ride routes can be reused (their save format is rides); the account,
token, name filter, rate limiter and CORS helpers can. Limits as noritetsu's, sized for saves:
2 MB a game (New York's real network is 75 KB; all of Japan's real network 570 KB), 20 games an
account, a 2 GB budget for all saves with a refusal past it, per-IP buckets on every route.
Deploying is yours (agents cannot ssh to the box); the agent hands you the commands.

## Stage 2: games on the account

The browser slots stay the working copy, as noritetsu's rides in localStorage do. Each slot gets a
stable game id when it is first synced. While signed in:
- **Upload**: after an autosave, at most once every 2 wall minutes and when the page is hidden,
  the clock worker (which already holds the bytes) PUTs the game with the rev it last had, so the
  main thread does no work.
- **Download**: on load the start menu and saves panel also list the account's games not in this
  browser, marked with a cloud icon (hover "On your account"); Open downloads one into a new slot.
  A slot whose account copy is newer and which has not changed here takes the newer copy.
- **Both changed** (played on two devices): nothing is overwritten (T-743's rule). This browser's
  game stays in its slot and becomes a new game on the account; the account's copy opens as a new
  slot named "Tokyo, other device" with its day.
- **Signing out** asks whether to keep this browser's games, as noritetsu asks about rides.
- A sandbox game syncs like any other; only its score is never sent.

## Stage 1 as built (2026-10-23)

Rules and placement: docs/ui-panels.md "Account and leaderboards"; the API: shonei-server's
`docs/trainworld-api.md`. Calls made while building, beyond the design:

- **Is it on?** The page asks `/noritetsu/config`, which now carries `trainworld: true`, never a
  `/trainworld/` route: on the live server before the deploy those 404 without CORS headers, a
  console error. Old server, no server or no answer: no icon, no further request.
- **Which server.** anita.garden uses market.anita.garden. A localhost page uses none unless
  `?acct=local` (127.0.0.1:8083) or `?acct=live` was given once, so smoke and agents' pages make no
  request that can fail. The live server's CORS now admits localhost 6100-6199 as well as 8800.
  A localhost page on the live server keeps its own session key, so it never signs a local
  noritetsu out.
- **Game ids** live in localStorage per browser slot (`trainworld.score-games.v1`), not in the
  save header: nothing in the clock worker or the save format changed. A copy loaded from a file is
  a new game. `?new=1` pages and slots open read-only elsewhere send nothing.
- **Sandbox latch** on the server: a game that sent figures and then turned sandbox sends
  `{mode: "sandbox"}` once; the server drops its figures and refuses it with 403 for good. A game
  that was always a sandbox sends nothing at all.
- **Cities**: the best 64 a game, a server cap. Per-city boards are listed in the picker only once
  they have rows (plus this game's own cities), so ~1,000 zones cost nothing.
- **Kept out**: rides, train share, the slot's name (free text that would need the filter).
- The Join stays open in a sandbox game (joining is per account; the player's normal games count),
  with "Sandbox games are not listed" under it, instead of the design's greyed Join.
- The icon tabs shrink to 27 px when the account tab is there, so the row fits the 280 px dock.

## Deploying (Anita)

Agents cannot reach the box. Nothing to set up on it: no new environment variable, no Caddy change.

1. Read `trainworld/app/public/privacy.html` and `terms.html` (they ship with the next game build).
2. In PowerShell, from the shonei-server folder: `.\deploy\deploy.ps1`. It runs `go vet` and the
   tests, builds, stops the service, uploads, starts it and checks it is active (about a minute).
   It builds from the files on disk, so pushing first is not needed for the deploy.
3. Check: `curl https://market.anita.garden/noritetsu/config` shows `"trainworld":true`, and
   `ssh root@5.161.112.237 journalctl -u shonei -n 30 --no-pager` has a `[trainworld] store at` line.
4. The game build that has the icons (the next `deploy.py` publish after this lands) then shows the
   person icon on anita.garden/trainworld/. The order does not matter: a game build before the
   server deploy shows no icon; a server deploy before the game build changes nothing visible.
5. To hide a row later: deploy/README.md "anitabuilder leaderboards".
