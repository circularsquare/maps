# T-2576: `toWorld` per edit

2026-11-05, agent toworld (tree `tw/toworld`). Follows notes/T-1358.md "`toWorld` per edit".

## What changed

All in `workers/clockClient.ts`, new `edgesOf` (called by `toWorld`):

- **Edge views kept.** An edge row that was in the last state (found at its old index, or one off
  after an edge was added or removed) gives its old `TrackEdge` while the lines over it are the same.
  When the edge rows array is the last one too, the last edges array comes back as it was.
- **Edge-to-lines map kept.** The map is the last one while every line row is the last row or has the
  same id and the same path (a train-count edit replaces a row and leaves its path). Otherwise it is
  built again, from each line's distinct edge ids kept per row (`lineEdgeIds`, a WeakMap on the row).
- Nothing else in `toWorld` changed. A view is taken only when its row is the same object and its lines
  list holds the same ids, so `world.value.edges` holds equal values to before; edges that did not
  change are now the same objects (nothing in app/src compares or keys by an edge object; checked by grep).

## Measured

Real save (New York, 109 lines, 1,647 edges), 6x CPU throttle, one Chrome page, the old `toWorld`
(edges rebuilt each state) and the new run on every state, back to back, alternating which goes first;
the new keeps its cache from state to state. The edges of the two compared deep (values, Maps) on
every state: equal in all 37 states of the last run (and the earlier runs).

| ms per state at 6x | old | new |
|---|---|---|
| train-count edits (11), mean / median | 5.9 / 6.2 | 2.4 / 2.4 |
| the edges step alone, train-count edits | 2-3 | 0.0-0.2 |
| new route, station, undo, redo, remove line and undo/redo of it (25), mean / median | 8.1 / 7.4 | 6.7 / 6.5 |

A train-count edit costs 0.40 of before. An edit that changes a line's path or the lines list (a new
line, a removed line, undo of either) has to build the map again and costs about what it did (the
runs swing by whichever goes first and by the machine's load; one earlier run had these states a little
slower, another a little faster). A first try that kept a WeakMap of views per edge row was slower than the
old code in those states (a WeakMap set for each new view), hence the walk by index.

The state after the series (6 to 12 train edits, a new route with a station, undo twice, redo, removing
five lines each undone and redone) is deep-equal to the old code's, per state.
