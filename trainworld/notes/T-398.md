# T-398: lower a demand worker's memory peak

## Measured first (native, counting allocator)

A temporary probe ran one solving worker natively as `demand.worker.ts` does: the market, the
cities' commute engines, their everyday layers; New York's real track (`nyc_real_track.json`),
periods 0, 1, 4 (one of two workers), free flow and three crowding rounds, then a layout edit
(a station 300 m east), a train-count edit (T-124's kept path) and the first network again. Every
output hashed and dumped (summaries, loads, entries, purpose parts, cell modes, selections,
station riders, flows, station flows). The probe is in the scratchpad (`t398/probe.rs.txt`), like
T-395's. `alloc.rs` now counts a moving `realloc` as holding both blocks for the copy.

Where New York's peak (353 MB) was: steady 281 MB after a solve, plus during a crowding round the
period's strategy tables (43 MB) and the market's pass (29 MB). Set-up itself peaked lower
(197 MB on the first network; on an edit the old periods are already dropped in `set_network`, so
it never rose above the steady figure). So the cuts went where the peak was, not only set-up:

| cut | New York | nine cities |
|---|---|---|
| market: per-station rows over served zones only, not all zones (was 24 MB a period kept + 24 MB in each pass) | about -51 MB steady, -17 MB pass | same |
| strategy tables: u16 node ids, one bit per boarding route node instead of an f32 (43 to 18 MB) | -26 MB at the peak | same |
| everyday: pairs 24 bytes not 32, a 4-byte-a-slot pair table sized from the last count, `edge_pair` reused in place and left empty while a layer has no pair | -8 MB steady, -17 MB set-up transient | about -73 MB steady (8 layers no station reaches) |
| commute `SubOut::od` over the city's access stations only, not S x S | 0 | -70 MB steady (3.5 MB a city a period) |

The nine-city set opens all nine Northeast packs as solved populations on New York's network, so
the eight others are reached by no station: in the game those open bare (T-325), and the last two
rows matter for cities a few stations reach in a network spread over several.

## Results

| | New York peak | steady | nine cities peak | steady |
|---|---|---|---|---|
| before | 353 MB | 281 MB | 698 MB | 622 MB |
| after | 256 MB | 222 MB | 458 MB | 420 MB |

Times (native, New York, first network / layout edit / train-count edit / layout edit): set-up
809, 456, 7, 475 ms before; 799, 476, 5, 464 after. Solve 23.8, 24.0, 8.1, 23.6 s before; 23.4,
23.4, 8.0, 23.3 after. Nine cities: set-up 1107, 714, 24, 694 ms before, 1149, 674, 14, 675 after.

Every output identical to the byte at all four steps, New York and nine cities (130 MB and 506 MB
dumps).
