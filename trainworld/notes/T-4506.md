# T-4506 Smoke's patched rows check fails on an edge's cost (agent edgecost, 2026-11-27)

**Summary**
- Smoke on master 888dc9c73 logged "T-4214 check: the patched rows differ from the state's: edges 2: cost". It is not a
  regression from the commits since b5697efed: none of them changes how an edge is priced, and the same error was seen
  before in T-4153's game run ("edges 0: cost") and T-4367's ("edges 6: cost"). It is a timing race that smoke caught
  this time.
- Cause: ground that lands outside an edit re-prices track (a road tile: `Network::add_roads`; a terrain block or a water
  mask: `rework_ground`). When it lands after an edit's patch went to the page and before that edit's state is read, the
  patch holds the price from before and the state the price after. Nothing told the page's patched map (`clickWorld`)
  of the new price, so the check (clockClient.ts `checkPatched`) saw the two disagree. An edge row's `cost` is the only
  field ground moves, which is why only `cost` shows.
- Fix (app only, no sim change): the worker sends the patch again when ground lands and moves the price of an edge the
  page holds patched since the last state read (clockPatch.ts `patchOutside`), with the message station names already
  used (renamed "named" -> "outside"). The page lays it as it lays any patch, so its map holds the new price and the
  check compares it with the state.

## Why the price moves after the patch

- `edge_cost` is written only by `derive` (inside an edit's apply), `add_roads` and `rework_ground` (sim
  net/derive.rs, net/edit.rs). An edit's own re-pricing is in its patch, and an edit with no patch makes the check skip
  that state, so only ground can move a patched edge's price before its state.
- Ground comes in on its own time: previews fetch the road tiles under the ghost (`roadsUnder`, not waited for), the view
  fetches terrain blocks and masks, and only Construct waits for the ground under the blueprint (`groundForBlueprint`).
  So a segment placed before its tiles land is priced on the roads in hand, then re-priced when they land.
- The window is an edit's apply to its state read: milliseconds in a small game, up to 5 s for the track tool's segment
  (its state held for the pointer's rest, T-2404), longer while trips are being calculated.
- Before T-4299 a road tile's re-pricing was not named to the rows at all (the state kept the old price); since then
  `take_touched` names it (`drain_priced`), so the state has the new price and the check could see the difference.

## The fix

- stateRows.ts: `patchedSince`, set when a patch reads rows (`touchedRows`), cleared when a state read begins (`begin`).
- clockPatch.ts `patchOutside(api)`: when `patchedSince` is set and an edge among those touched since the read has another
  price than the last patch gave it, `mapPatch` again and send it as "outside". With terrain or water the model marks
  every record re-priced (`repriced`), `mapPatch` gives none, and the page notes a missing patch, which skips the check
  for that state (the state reads every record then).
- clockGround.ts calls it where ground goes into the model: road tiles (`roadFeed`'s landed callback, before its
  `sendStateOutside`), terrain blocks (`ensureBlocks`), zone masks (`ensureMasks`), the world's water.
- protocol.ts, clock.worker.ts, clockClient.ts: "named" renamed "outside" (a change outside an edit: station names,
  ground).
- The price gate keeps it off the drawing path: while a segment's state is held, a road burst away from the new track
  sends nothing. When it does send, it costs what an edit's patch costs (worker 7-11 ms, page 1-30 ms by save size,
  notes/T-4214.md, notes/T-4267-measure.md).
- Not done: making `peek_touched` drain the re-priced edges as `take_touched` does (sim wasm/touched.rs). That would put
  every road-repriced edge into each edit's patch and re-lay them on the drawn network for a price change; the check
  compares only edges an edit touched, which stay in the touched list until the read.
- docs/architecture.md (the tools' map paragraph) says when the patch is sent again.

## Game run (Vite 6127, a new game in Tokyo, play.mjs; probes in the scratchpad)

- Three probes that did not open the window: smoke's `buildLine` in Tokyo, a route and Construct sent back to back,
  and the same in Osaka right after a camera jump. Each edit's state came straight after its patch (the view's ground
  had landed before the first edit, since edits wait for masks), so nothing was re-priced in between.
- The player's track tool sequence, which opens it: in fresh ground (Nagoya) a ground-level 2 km segment placed early
  (`edit(route, true)`, its state held), then ghosts asked over it every 80 ms for 2.5 s, as a moving pointer does. Each
  ghost fetched the road tiles under it, which landed while the segment's state was held. Messages: applied (patch),
  edited, outside (patch), state, roads, state. The segment's edge: $74.9M in its first patch, $304.9M in the outside
  patch and in the state (its road crossings). No T-4214 error. Without the outside patch the last patched price would
  have been $74.9M against the state's $304.9M: the reported error. Run twice, the second on the final code (edge 0 in
  a fresh game, same figures).
- Not run in the game: the terrain and water paths (read from the code).
