# T-3721 A played copy shares as Copy, not Sandbox

Server (shonei-server fa61219, not deployed): `twGame.Copy` next to `Sandbox` and `Modded`; `PUT /trainworld/score/<id>`
takes `{"mode":"sandbox","copy":true}`. Modded wins over copy; a later plain sandbox notice keeps a copy reason. The
share carries `copied` (with `sandbox`) and the Community rows send it. An old latch has no reason and reads as a
plain sandbox; unlatching clears `copied`. Leaderboards untouched. Test: TestCommunityShareOfACopyIsTaggedCopy.

Game: account.ts `latch()` adds `copy: true` for a normal-mode game with the copy mark; Community.tsx shows the
existing "Copy" string (`savesPanel.copyMark`) on a row with `copied`, else "Sandbox". No new strings.

Proof against a local shonei-server (8083), own Vite 6176: a copy (openView of copyFromShare, Save, 3 lines built)
shared -> row `{sandbox:true, copied:true}`; a sandbox game shared -> `{sandbox:true}`, no `copied`.

Games latched before this ships, and ones latched by an open old tab, stay Sandbox: no reason was recorded and the
page never resends a latch it already holds.
