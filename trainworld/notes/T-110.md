# T-110: Immediate empty lines and copying

New line immediately creates a persistent line with zero stops and zero scheduled trains,
selects its bottom-left inspector, enters edit-stops mode and focuses/selects its seeded
unique Line N name so typing replaces it. N follows creation order, advancing past name
collisions. Copy line creates an independent duplicate useful for branching and selects it.
Preserve saves, undo, planned/empty status and model safety for zero/one-stop lines.


Backend implementation (2026-10-10)

- `addLine` now allocates a zero-train line even with no stops; blank name reserves a unique
  `Line N` from a persisted creation counter. Deleted IDs can be reused without reusing the
  creation number; undo does not rewind it. Successful copies also advance it.
- `copyLine {line, name?}` clones route, stops, allocated or legacy schedule, dwell, turnaround,
  cars, colour and badge. Default names are `<source> copy`, then `copy 2`, etc. Native undo is
  one line edit and the duplicated input vectors are independent.
- Zero/one-stop lines have empty paths, valid unbroken inputs and inactive service. Their UI
  status is planned; no profile arrays are indexed for those drafts. Existing schedule inputs
  are retained when removing down to a draft.
- TWT4 core remains intact. Optional `LUI1` trailing metadata persists creation numbering and
  custom symbols; old saves without the tail still load and use initial-based symbols. Known
  truncated extensions are rejected. Older readers ignore the tail, losing only new metadata.
- Native `draft_line_copy_symbol_save_and_undo` and
  `insert_stop_infill_ends_and_reduce_to_empty` cover drafts, full property copies, independent
  edits, save compatibility, undo/redo, ID reuse and name collisions.
- Combined native suite: 74 passed, 3 ignored (77 total), with demand feature.

Final integration: track WASM, TypeScript and production build pass. t109-ui-check.mjs confirms
