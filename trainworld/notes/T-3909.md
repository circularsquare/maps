# T-3909 everyday trips see trams as commutes do

## The cause (confirmed)

`EverydayApi` solves on its own `engine: DemandApi`, whose `tram_in` only `DemandApi::set_tram_lines` writes.
`EverydayApi` had no such setter and the demand worker (`setUpPops`) called it under `p instanceof DemandApi`, so
every everyday purpose (errands, leisure, school, university, medical, airports, attractions) held a tram line at a
train's cars (no 0.75 a section) and with no tram-only stops (no 3-of-6 cap). `sim/src/bin/frontier.rs` (T-3887)
copied the same gap on purpose ("the model here does as the game does").

## In the game

New NYC game on :6171, one tram line by the player's path (track tool type Tram, double, snaps off; 6 stations
about 440 m apart across Midtown at 40.750, -73.985 +-1.25 km; constructed; New line "Tram A"; More trams twice
at each level: 2 trams, 6.8 min). Riders a day on Tram A, all and by purpose (`twDemand.view().purposes`):

| state | all | work | everyday (school+errands+leisure+medical+attractions) |
|---|---|---|---|
| no tram flags anywhere (temporary worker edit) | 179,909 | 49,933 | 129,976 (7,764 + 64,526 + 51,748 + 2,916 + 3,023) |
| master: flags to commutes only | 173,930 | 42,778 | 131,152 (7,846 + 65,092 + 52,216 + 2,947 + 3,051) |
| the fix: flags to both | 156,748 | 44,153 | 112,595 (6,859 + 55,682 + 44,942 + 2,530 + 2,582) |

Giving the commutes the flags cut work riders 14.3%; giving the everyday layer them cuts everyday riders 14.1%, the
same step. The small opposite moves (everyday +0.9% in step one, work +3.2% in step two) are the shared crowding:
each layer's loads crowd the other's.

Rail trips a day on that game: 173,930 on master, 156,748 with the fix (-9.9%).

Real NYC save (`T-007-real-nyc.save`, no trams), same wasm, worker line as master vs fixed: 12,886,431 rail trips
and 895,752,175 trips a day both ways, identical.

Smoke on :6171 with `TW_CORES=4`: SMOKE PASSED, 29 checks, 282 s.

## The fix

- `EverydayApi::set_tram_lines` (everyday.rs), passing to its engine as its other network setters do.
- demand.worker.ts: `set_tram_lines` for every population but the market (`!(p instanceof IntercityApi)`), so the
  call is on `DemandApi | EverydayApi` and `npm run check` fails if either lacks the setter (seen: with the old wasm
  the typecheck failed with "Property 'set_tram_lines' does not exist on type 'EverydayApi'").
- frontier.rs gives its everyday layer the flags too; T-3887's frontier charts would move a little on a rerun.
- Test `everyday_trips_see_the_tram_lines_as_commutes_do` (demand/api/tram_tests.rs): the same network and flags
  into both; the everyday engine's cars are [10, 8, 1.5], its tram-only stations the commutes' (5), its `Service`
  the same layout, and its tram boardings differ from an unflagged layer's. `small_pack()` split out of `small()`.

## Not done here

- Longer trips (the market, `IntercityApi`) also hold trams as trains: no `set_tram_lines`, and
  `intercity/setup.rs set_network_in` hard-codes `tram: &[]`, `st_tram: vec![]` and `cars: cars.to_vec()`, which
  `DemandApi::period_net` turns into the market's seats and crush loads. Proposed as its own task.
- `a_tram_carries_at_least_the_bus_it_replaces` fails in this tree on code this change does not touch ("tram
  39123.62 against bus 60668.473"): likely since T-3910 (4354a2e6) a tram trip pays 2+2 boarding minutes and the bus none, so the test's premise
  ("the two board alike") no longer holds. Untouched here.
