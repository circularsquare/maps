# T-3234: where a real-network start spends its time (loadpath, 2026-11-11)

Status: done. One cut (every save load in the browser derived and settled the whole network twice);
the rest is the normal cost of a network that size, the same as loading the real save T-007.

## How it was measured

Headless Chrome on an own dev Vite (6122), 3 cores pinned (2 demand workers), fresh profile. Start on
the new-game sheet (sandbox, the city, Real world network ticked); seconds from the click. `world` =
`tw.world.value` set (track and lines drawn), `lines` = the demand view has lines (round 0), `clock` =
the clock released (playable). A Chrome trace (CDP `Tracing`, cpu_profiler) of one New York start,
then `console.log` probes with epoch times in the clock worker and the demand worker's `openCity` and
`recompose`. Scripts in the session scratchpad (`loadpath/loadprof.mjs`, `t007.mjs`, `anatrace.mjs`,
`anatime.mjs`); not kept.

## Where the time goes (New York, before)

| s from Start | thread | what |
|---|---|---|
| 0-2.5 | page | the clock worker's script loading (dev Vite; a bare start pays the same: its world at 1.9-2.8 s) |
| 2.6-3.5 | clock | world water, terrain index, the 5 zones' water masks fetched |
| 3.5-4.6 | clock | `TrackApi.load`: the network derived and settled **twice** (fixed, below) |
| 4.7-7.5 | clock | `sendState` -> `networkFromState`: `lineBands` 1.4 s, `besideSamples` 0.7 s of it (traced) |
| 7.9 | page | world: the network drawn |
| 3-15 | demand x2 | `openCity` of nyc, nhv, hfd, lck, phl at L0 in each solving worker (`DemandApi.at_level` + `EverydayApi.beside_with`; nyc alone 6-7 s contended), the aux and focus workers too |
| 15-20 | demand x2 | the market composed from 9 places (`recompose`, 3-4 s each) |
| 20-29 | focus + demand | round 0 solved |
| 29 | page | lines (round 0) |
| 29-80 | demand | rounds 1-3, then the clock goes |

Three cores hold the clock worker, two solving demand workers, the aux and focus workers, the shade
worker and MapLibre's: most steps above run about twice their uncontended time.

London is the same shape: 13 zones opened (lon is 3.7 MB, the rest small), 18 market places, the load
5.7 s in the browser (1.4-2.1 s natively), `sendState` 2.8 s.

## Real network or network size?

The real save T-007-real-nyc.save (109 lines, nyc+nhv+hfd+lck), loaded cold (`?continue=1`, demand
cache missed with a `perfOff` name), s from navigation: world 11.3, lines 22.7, r1 54.6, r2 66.2,
playable 77.5. New York's real network from Start: world 8.7, lines 21.7, r1 56.7, r2 68.8, playable
80.0. The same: the ~60 s after the lines show is the demand of a network that size and reach, nothing
real-network specific.

## What changed

`sim/src/track/wasm.rs` `TrackApi::load`: with pack water or the world's water in the model, the masks
are made for the save's frame and set before its one derive. Before, the old model's mask went into
`TrackWorld::new` and `rebuild_water` then derived and settled everything again with the right one. A
save whose lines `allocate_unallocated` gives trains (T-1146) is still derived again after that, as
before.

Checked natively against the old load, every real save and T-007 with their zones' water and
`world.water` installed as the game installs them: saves byte-identical, trains an hour and trains the
same; load time halved (New York 0.30 -> 0.15 s, Paris 0.29 -> 0.15, Tokyo 0.25 -> 0.13, London 2.05
-> 1.43, T-007 0.27 -> 0.14).

Browser, same setup, three runs each, old and new track WASM in turn on a quiet machine (s from Start):

| | load step old -> new | world old -> new | lines (round 0) old / new |
|---|---|---|---|
| New York | 1.6-2.8 (mean 2.0) -> 0.8-1.1 (0.9) | 8.3-8.8 (8.6) -> 6.0-8.8 (7.3) | 18-25 / 16-30 |
| London | 5.9-6.4 (6.1) -> 4.5-5.8 (5.0) | 12.6-13.1 (12.8) -> 10.9-11.9 (11.5) | 25-28 / 22-28 |

Round 0 and playable are set by demand and vary 15 s or more run to run (playable 80-107 s for New
York, 86-112 s for London across this task's runs, some with cargo compiling on other cores); the
change is inside that noise. Checks: both cargo suites (512,
692 passed), `npm run check`, smoke on 6122 (28 checks passed).

## Found on the way

- **London's real save is fixed up on every load**: `stop_every_pass` adds a stop to line 150 (SWR,
  24 -> 25 stops), so every load derives and settles London once more (0.7 s natively, the settle 0.15
  s of it, a few seconds in the browser). realsave should save after it; reshipping London moves its
  rates, so it is a task of its own.
- **London's `svc.update_all` is 0.53 s natively per derive** (New York 0.08 s, Tokyo 0.02 s), most of
  London's load.
- **`networkFromState` on a first load** is about 1-3 s in the browser for both cities (`lineBands`,
  `besideSamples`), between the load and the world being drawn. Already incremental for edits; the
  first full pass is not cached anywhere.
- Opening the reached zones' packs in each demand worker and composing the market is what holds the
  first figures (round 0) for any network reaching several zones.
