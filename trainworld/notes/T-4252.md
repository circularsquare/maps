# T-4252: Gemini code agents (tools/gemini_agent.py)

Her ask (11-25): use Gemini Neon agents to make code changes and handle tasks like Claude subagents. Her answer on
limits (11-25 00:22): "yes gemini code agents can run commands unattended inside their own worktree". And: ask the
first three runs which permissions they lacked or didn't need.

## What was built

- `tools/agy_session.py`: the run loop both Gemini tools share. One `agy` process with stream-json in and out keeps
  the conversation across turns; `work()` keeps the agent going until its reply carries a closing line; agy and
  everything it starts run in a Windows job object killed when the session closes or the runner dies. Also
  `ensure_agent` (writes a custom agent file), `read_rules` and `backstop_rules` (allow and deny rules).
- `tools/gemini_agent.py`: `start <name> --brief <f> [--task] [--tree] [--new-tree] [--cores 2] [--timeout 90]
  [--model] [--trial]`, `list`, `stop <name>`. Detached runner; cores claimed as `gemini-<name>` with the runner's
  pid, released in `finally`; TW_CORES and CARGO_BUILD_JOBS set for what it runs; with --task, `tasks.py start`.
  Run folder `artifacts/trainworld/gemini/agents/<name>-<time>/`: agy.log (everything agy printed, stdout and
  stderr), agy-cli.log (agy's own log), steps.txt (each tool call and its state), settings.json, brief.md,
  report.md, state.json (runner pid, agy pid, status, conversation id).
- `tools/reports.py`: `Box.add` and `reports.py add`, for reports no hook sees. Gemini reports have kind
  "gemini" and session "gemini" (watch.py skips reports whose session is the watching orchestrator's own id).
- `notes/gemini-agent-rounds.json` (made by the first counted run): how many runs were asked the permissions
  question; asked while under 3, counted only once the answer is in the report; --trial runs ask but don't count.
- `tools/gemini_audit.py` rebuilt on the same loop (the audit fix below).

## What agy can and can't be made to do (agy 1.5.16, Windows 10 19045)

Evidence: probes in the throwaway tree gemtrial (stream logs in the T-4252 scratchpad), the two trial runs below,
and agy's own logs (`~/.gemini/antigravity-cli/log/`).

- **No OS sandbox here.** agy's terminal sandbox needs Windows 11 24H2 (its log: "Terminal sandbox unavailable").
  `--sandbox` and auto mode do nothing on this machine, so gemini_audit.py's "sandboxed" was never true.
- **Tool list: enforced.** A custom agent (`~/.gemini/config/agents/<name>.md`, `--agent`) gets only the tools
  its frontmatter lists. Asked to call invoke_subagent, define_subagent and search_web, the probe agent had none of
  them and the stream shows no such tool step. agy 1.5 retired list_dir, grep_search, find_by_name and
  multi_replace_file_content ("deprecated and has no effect"), so searching goes through the shell (git grep,
  Get-ChildItem).
- **Allow rules: enforced.** `--settings <file>` adds per-run rules (agy log: "CLI settings initialized:
  permissions=..."); her 24 global grants in `~/.gemini/config/config.json` merge in. On Windows a plain prefix rule
  needs an exact match (`command(git log)` did not allow `git log --oneline -1`), so the rules are anchored regexes
  whose arguments may not hold `; & | < > $ ` ( ) { }` or newlines. `git status; git stash list` was refused.
- **Deny rules: enforced, and they beat allows.** `git commit` was refused with "Matches user-configured deny
  rule" in every run; a deny on the temp folder beat agy's built-in temp grant; an in-tree deny
  (trainworld/research/gemprobe-denied.txt) held.
- **Writes outside the workspace: refused.** A write to the main tree's notes/ was refused; so was one through the
  tree's `trainworld/data` link (agy resolves the junction to the main tree, outside the workspace). The tree's
  other links (app/node_modules, venv, artifacts/trainworld) behave the same for the file tools.
- **How refusals behave in print mode.** A call no rule allows needs an approval nobody can give, and agy
  "soft-denies" it by cancelling the whole turn (log: "soft-denying tool confirmation", CancelCascadeInvocation):
  the reply stops mid-work and agy exits 0. A deny rule fails only that call. So the loop asks for a closing line
  (END OF REPORT) and a turn without it gets "carry on" (at most 12; the last says to wrap up).
- **Not enforced.** An allowed command runs whatever the tree holds: `npm run check` runs package.json's script,
  agent_cargo.py runs build.rs, `node trainworld/checks/x.mjs` runs that file, and the agent can edit all three. A
  determined or confused agent can therefore run anything as her user. Rules in GEMINI.md and trainworld/CLAUDE.md
  are asked, not enforced. Not worth guarding further without a sandbox (the advisor agreed).
- **Model.** gemini-4-neon-medium, her review pick. agy offers Neon low, medium, high and xhigh and nothing
  code-specific; `--model gemini-4-neon-high` is there for a harder task.

The rules of a run (gemini_agent.settings): allow git status/diff/log/show/blame/ls-files/grep, Get-ChildItem
(ls, dir), `npm run check --prefix trainworld/app`, `python trainworld/tools/agent_cargo.py test|wasm`,
`changelog.py add|list|reword`, `node trainworld/checks/<x>.mjs`, and reading the maps root. Deny git's writing
subcommands (commit, push, pull, fetch, merge, rebase, reset, stash, checkout, switch, restore, clean, worktree,
cherry-pick, revert, am, apply, gc, prune, update-ref, config, remote, submodule, filter-branch), aws, taskkill,
tskill, Stop-Process, wmic, anything naming 8800, agent-tree, smoke, tools/ops or tools/aws, the flags --output,
--no-index, -O, --open-files-in-pager and --ext-diff, MCP, and file writes to the temp folder, TASKS, DECISIONS,
ARCHIVE (both), LINES, TODO, notes/handoff.md, notes/asks.json, the three CLAUDE.md/GEMINI.md files, .git, .agents
and .claude. Rules files: the tree's GEMINI.md (already pointing at CLAUDE.md and trainworld/CLAUDE.md) loads by
itself; the first message says to read trainworld/CLAUDE.md first and overrides GEMINI.md's cores.py and handoff.py
steps, which would only be refused.

## The audit fix (gemini_audit.py)

Cause, from agy's logs of the T-4248 and T-4250 runs: plan mode, and the first shell command Gemini tried
("unknown_command", e.g. a search) was soft-denied, which cancelled the turn; print mode then returned the one line
written so far, exit 0. The 11-24 "reads denied until a --resume named the files" is the same mechanism. Now:
default mode, custom agent trainworld-reader (read files; run only git's read commands and Get-ChildItem; no
writes), the shared loop with a closing line (END OF ANSWER, at most 6 nudges), exit 1 without touching --out when
no complete answer comes, the conversation id on stderr, everything agy printed in
artifacts/trainworld/gemini/logs/audit-<time>-<pid>.log, default timeout 30 minutes. Re-runs of both briefs (same
--out paths) each answered in one turn: notes/T-4248.md, 158 lines, and notes/T-4250.md, 102 lines. They ran on the
first version of the reader, whose only working tool was reading files (it read about 40 files by path, no search);
a later quick run of the current reader used git grep and Get-ChildItem, and its `git stash list` was refused by
the deny rule.
