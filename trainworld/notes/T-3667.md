# T-3667 Handoff state by command, asks by command

Tools (in this tree, not committed): `trainworld/tools/handoff.py status`, `trainworld/tools/asks.py add|answer|list`.

## handoff.py status
Read-only, about 4 s (the world_run status call and one PowerShell process list are the slow parts; both have time
limits). Sections: master vs origin (last fetch, no network); 8800 build vs master; each tree under `.tw-trees`
(branch, +ahead/-behind vs master, dirty tracked files, newest change, count of processes whose command line names the
tree, the board agent on it); agents on the board with start times and the Up next queue; uncommitted trainworld paths
and serve.py in the main tree grouped by folder; open asks; `cores.py list`; the world run (row counts, STOP file,
locks and claimed rows, from `world_run.py status`, whose own output is thousands of lines, so it is filtered);
unpublished changelog count. `--root` only picks which checkout to find the main tree from; live data is always read
from the main tree. Untracked files in trees are not counted (git -uno).
Notes: board-live.json "builds.master" can be stale (it was ff3a04cd while master was ff17f0d4); status prints both.
`world_run.py status` raises OSError when its stdout closes early; status reads all of it so it does not.

## asks.py
ids `a-YYYY-MM-DD-N`; N is one past the highest N seen for that day in asks.json or notes/asks-log.jsonl (every add
and answer is appended there), so an answered id is not reused. Writes asks.json by temp + os.replace under a lock file
`notes/asks.lock` (O_EXCL). `answer` removes the ask and logs the note. `list --full` prints the whole text. The file
shape `[{id, title, text, since, by}]` is unchanged, so `board/build.py read_asks` reads it as before. Tested on a copy
(`--root`): add, answer, answer of a missing id (exit 1), a new add after an answer got a fresh number.
The board's `ask-answer` action (answer or dismiss) is then done with `asks.py answer <id> --note "..."`.
