## What is still whole, and why

- **The track limits** (`Capacity::line_limits`) once per change, and the **fleet needs** and **running cost** built on
  them, with every line's money key (about 0.7 ms native per refresh). A line's limits depend on every other line on
  the track it shares; the capacity has no index from a line to the resources it holds, so which lines' limits an edit
  moves is not known without the pass. Same for `markers_in`, `full_track_in` and `turn_limits` (0.5 ms a state).
- **`profile_meta`'s copy out** (0.4 ms): kept in the model, but the worker reads all of it each state; a kept copy in
  the worker patched by line would make it local.
- **The moved lines' phase tables and stretch speeds** (1.6 ms): local, but on Asia a station on a long line moves 3
  lines of about 276,000 floats each.

## What names a change

The kept store (`sim/src/track/wasm/kept.rs`) has its own cursors, so no reader takes another's:

- applied edits' dirty edges and nodes (`kept.note` in `done` and `note_dirty`; the draw's records too), and the ends of
  every named edge, before and after
- re-priced edges: road tiles reworked (`add_roads`, `rework_ground`) push to `Network::priced`, taken by `take_touched`
  too. Before this a road repricing changed an edge's cost row with nothing naming it (a T-4291 gap, fixed)
- the lines the service noted (`Service::take_kept`; `note_all` at a reload)
- the lines whose price factor the app moved (`set_line_run_factors` compares old and new and names those, a line
  dropping back to 1 too); the passages and station buildings, set outside an edit (`link_stations`, `unlink_stations`,
  a removal's passages, `add_building`, `reshape_building`, `remove_building`: `note_extras`)
- at each state's first read (`take_changed_lines`, the full refresh) every line's money key and the passages and
  buildings, a net: what it catches with nothing named is recorded (`Kept::unnamed`) and `kept_check` reports it
- a load, a reload, a new frame or a water mask change: everything, built whole
- a line's share units move only when what they are made from moves (`units_key`), and only the edges and stops that came
  or went are shared again; a line whose weight moved shares all of its own again
- station buildings' members are kept per building, worked out again for a building whose corners changed or a named
  station that is or was its member

## The stamps

`line_stamp` hashes with a word hash (FxHash-like) in place of SipHash; the phase tables are hashed from the profiles
in place, two floats to a word; the return run is stamped from the service's run 1 (`back_stamp`, a line the service
does not run takes `line_back_path`). `peek_changed_lines` keeps its stamps, and `take_changed_lines` reuses them when
the kept generation and the noted lines are the same.

## Review fixes (review25, agent modelfix)

1. HIGH, confirmed: `set_line_run_factors` named no line, and the clock worker sets the factors after the state's first
   read (clockMain.ts `applyRunFactors` after `stateRows.begin`) and on a `regionShares` message with no state; a load
   clears them. So the load's own state worked the running cost out at factor 1, and the cash and the network ledger's
   running drained at it until something named a change. Fix at the cause: `set_line_run_factors` names the lines whose
   factor moved (`Kept::note_lines`). The same family, inputs set outside an edit: the passages and buildings (named now,
   `note_extras`; before only the full read caught them, so a money read between the op and its state was stale), and
   a line's local time (`set_time_zones`), which was in the money key though no kept figure reads it (taken out, so the
   net does not fire on it). The calendar (`set_line_rows`) is noted by the service; fleets, cash and the draw settings
   are no kept input. `kept_check` now reads the kept money as the reads between states do (`kept_now`), then reports
   anything the full read's net caught: with the old code, ?patch=check flags this at the load's state.
2. LOW: the flag changes `begin` takes go into `StateRows.flagsOwed` and leave it only when `edges` and `nodes` patch the
   sets by them, so a read that threw leaves them to the next. `nodes` also takes what moved since `begin` (an older
   save's stations unbound between two reads of the nodes, `adopt_old_names`).
3. LOW: `complexOfNodes` caches only when the rows have caught up with the model. After a read that left regions for the
   next one (`StateRows.behind`, `Regions.behind`) every station is read from the model; between an edit and its state
   the rows are used with the touched stations read from the model in their place (`nodes_info_of`), which is what reading
   every station gave (an untouched station's place, heading, platform and platform line are its row's), checked in
   ?patch=check against the whole read.
4. Edit speed, from the code: nothing in kept.rs is per edit and scales with the save beyond what each state did whole
   before. A refresh (the first read after something was named) does every line's money key, the fleet needs from the
   track limits (once per change), 10 running costs (a pass over the lines each) and the passages and buildings; the old
   state did the same passes, twice for upkeep and fleets. One whole pass on an edit's path was added: review21's fix
   made `complexOfNodes` read every station from the model (`nodes_info`, with the conflict nodes over every line, and a
   platform line per station) for a `lineRelated` query between an edit and its state, and the line panel's related
   stops and train table ask it again on each patch (their key is the world version, which a patch moves,
   clockClient.ts 1422). Fixed with 3 (only the touched stations are read). It could add to the line panel rows (stop
   reorder, undo, group drop) if the bench had a line panel open; it cannot explain the track piece. The rest fits the
