# T-4090 reply nudge

What: .claude/hooks/orchestrator.py `reply-nudge`, hooked on PostToolUse in .claude/settings.json (added; no permission prompt).
When her latest message has gone 180 s (REPLY_AFTER) with no reply text from the orchestrator, the next tool result carries
additionalContext "Anita's message has waited N min with no reply: reply to her now (a short text message, even mid-task), then go on."
Once per message (state: %TEMP%/claude-orchestrator/<session>.nudge holds the message key).

Design: no UserPromptSubmit and no Stop hook. The docs do not say whether UserPromptSubmit fires for a message queued mid-turn,
so the hook reads the transcript instead. It scans the last 3 MB backwards; the first entry that is either a main-thread assistant
text block (a reply, mid-turn text counts) or her message decides. Her message is a user entry with origin.kind human, or, when sent
mid-turn, an attachment queued_command with origin human; for that the time sent is taken from the matching queue-operation enqueue
entry (delivery can be later than sending). Task notifications and subagent hand-backs have other origins and are ignored.
A turn that ends has a reply text, so Stop needs no clearing. Fast path: one tail read, no handoff glob unless overdue.
Skipped when the input has agent_id (subagent) or the session is not named in a handoff "Orchestrator:" line.
Caveat: the docs say the transcript is written asynchronously and may lag; a reply written just before a tool call is normally on disk.

Tests (scratchpad/replynudge/test.py, fake transcripts): 4-min msg fires; again does not; non-orchestrator no; reply after msg no;
1-min msg no; agent_id no; queued mid-turn msg sent 5 min ago fires; stop event no output; new msg after an old reply fires.
