# T-3383 "busy single track" (bugs1, 2026-11-16)

Fixed wording; the 24m00s is not a cap.
Wording: a wait place on single track (resource kind 1) now reads "On the single track near X" / "On the single track"
(new key lineInspector.spotSingle); the "Waiting at busy track" row reads "Waiting at busy single track" when more of its listed seconds
are single-track places than others (key lineInspector.busySingleTrack). Both in all 12 language files (sources and context too).
24m00s: no clamp in `kingman`, `solve_one` or `line_delays`. The figure is a resource's delay per train times the number of
directions the line owns it (`line_delays`), and every line that owns the same single-track stretch shows the same figure, which is why
both lines had exactly the same number near the same station. Above 90% utilisation the delay rises linearly and steeply
(about 6,000 s per unit of rho for a 10-minute stretch), so 720 s per direction is an ordinary overloaded value. I had no Yakutsk save to
confirm the exact number; if she can drop the save in a folder I can read the resource's rho.
