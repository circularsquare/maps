# T-3707 Keep modded games off the leaderboards

Anita, 2026-11-18: players are already making mods for themselves ("we might wanna do it soonish since people are
going ahead already"). Her plan: a "modded" mark that takes a save off the leaderboards for good, as a sandbox does;
and the server takes scores only from the real game on anita.garden. Not now: spot checks that recalculate top scores.

## What was built

**The mark (game side).** `game/modded.ts`, `SaveHeader.modded` (a list of reasons, never removed), `MoneyState.modded`.

- `trainsworld.markModded("<name>")` is always defined on the page (frozen object). It is the one entry point: the
  mod loader of T-3377 calls it, and a mod written any other way is told to call it when it loads. The mark is the
  page's: the open game and every game loaded or started afterwards in that page are marked (clockClient re-posts it to
  any new clock worker; the worker takes it outside its queue so a load in progress is marked too).
- Marked by the page itself when (a) it is served from a host that is not anita.garden or a local or home-network
  address (localhost, 127.x, 10.x, 192.168.x, 172.16-31.x, `.local`): a copy hosted elsewhere such as a modder's site;
  (b) the build has `app/unofficial-build.txt`, which `tools/opensource/export.py` adds to the public repo, so any build
  of the public source marks its games (deploy.py refuses to publish a build from an app that has the file).
- Not marked from a page-side build check: the 8800 snapshot and agents' dev servers carry stamps nothing published,
  and their saves can reach Anita's account; a permanent mark there would be a false positive. Not marked for
  `?debug=1` either (it exposes internals to the console; a player Anita asks to open it must not lose ranking).
- The mark survives export to a file and import, Make a copy, backups, cloud sync, and a Community share and the copy
  opened from it (sharedSave keeps the field; a copy is unranked anyway).
- account.ts: `unranked()` includes modded. A modded game sends the server's latch `{mode: "sandbox", modded: true}`
  once, even when it never sent figures, so an older build that does not read the mark (an open v0.4.1 tab) gets 403
  from the latch. Achievement counts skip modded games.

**The server (shonei-server 662ed86, `trainworld_builds.go`).**

- Latch: `{mode: "sandbox", modded: true}` stores `sandbox: true, modded: true`, so every reader of Sandbox (boards,
  Community's Biggest) leaves it out with no new code path. Community shows such a share with the sandbox tag. Older
  servers ignore `modded` and latch as a sandbox, so the page needs no config flag.
- A `mode: normal` PUT is kept only with Origin `https://anita.garden` (or `www.`) and its `build` stamp on the list at
  `https://anita.garden/trainsworld/builds.json`. Refusal is 426 `{"code": "unpublished"}`, never 403: v0.4.1's page
  treats any 403 on this route as the sandbox latch and writes `sandbox: true` into localStorage for good.
- The list is fetched like Google's JWKS: every 10 minutes, and at most once a minute when a PUT names a stamp it does
  not know; `?t=<unix>` steps past the site's 10-minute Cloudflare cache. A failed fetch, a 404 after a list was seen,
  or an empty or malformed list keeps the last good one, also kept in `<TRAINWORLD_DIR>/published-builds.json`.
- v0.4.1 sends no stamp (checked in the live bundle `index-B767LdvH.js`: its build is `mwlo7xyt`, its score body
  `{mode, day, points, cities}`). An unstamped PUT is taken while no list has ever been fetched (the site answers 404
  today) and for 48 hours after the first list, for tabs left open across that publish; then never, even if the list
  later 404s (the first-seen time is on disk).
- `TRAINWORLD_BUILDS_URL` names another list or `off` (the Origin check stays). `SHONEI_DEV=1` admits noriCORS's
  localhost pages and skips the build check unless the variable names a list.
- The page sends `build: __TW_BUILD__` (the same stamp as the plays ping's `v`). On 426 it shows "Scores from this
  version are not listed. Reload the page for the newest." in the leaderboards and asks again after 10 minutes (a
  publish just gone live can be refused for its first minute).

**Publishing (deploy.py).** The vite build writes `dist/build.json` (`{build, version}`); deploy.py writes the website's
`trainsworld/builds.json` with this stamp first and the two before it, in the same folder `git add trainsworld/`
already takes, so the list goes live with the page and no server deploy is needed per release. `--verify --page`
checks the live list names the build first. A build without `build.json` is refused at preflight. Nothing changes in
the publish commands.

Deploy order does not matter: an old server ignores `build`; a new server before the next publish takes v0.4.1's
unstamped scores (no list yet).

## What a determined cheater can still do

The Origin header and the build stamp are public strings: a script with a real token can PUT any figures with
`Origin: https://anita.garden` and the live stamp. A userscript, an extension or devtools on anita.garden itself passes
every check, and the mark can be edited out of a save's header by hand. This keeps honest mods, forks hosted elsewhere,
and dev and stale builds off the boards; it is not a lock. The real defence is the later spot check that recalculates
top scores from the saves on the account.
