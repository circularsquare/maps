# T-3927 A died-load report names the game being loaded

The "automatic" report is the player's Submit feedback on the failure screen after a died load (T-2545 sets the
message; nothing sends by itself). Its context (`reportContext`, ui/FeedbackPanel.tsx) now carries `diedLoad`.

- Marker: `tw-load-started` in sessionStorage was "1"; now JSON (game/loading.ts `setLoadFlag`, `noteLoad`):
  kind (new game / real network / saved slot / file, backup or shared game), start city (new games), zones
  loading, station and line counts of the save once the page has the network, last step, ms since the pick.
  Steps: picked, clock worker started, game open in clock worker (from), network in the page, demand game|data|demand.
  No slot name. An old "1" flag still counts as died (no fields).
- Read side: `lastLoadDied()` parses it into `diedLoadReport`; reportContext adds `ctx.diedLoad`. Memory hint is the
  report's existing `memory` key. `feedback.py <id> --full` prints every context key, so it needs no change.
- Server: boundContext keeps any key (<=64 chars, 48 keys, 8 KB value). No server change.
- Proof (scratchpad diedload/prove.mjs, Vite 6188, headless Chrome, local API mocked, nothing sent): new game load,
  marker read every 250 ms, tab left without pagehide, restart, Submit feedback payload:
  `diedLoad: new game; zones nyc; start city nyc; 0 stations, 0 lines; last step: demand data, 8 s after the pick`
  context keys: version,browser,memory,language,lastFailure,diedLoad,state,graphics,currency,saves.
- Not exercised: saved slot / real network kinds (same code path, kind from the pick's choice).
- Player text: none changed. No changelog.
