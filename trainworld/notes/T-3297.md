# T-3297: a whole-save flip to left-hand running (estimate)

Agent lhtscope, 2026-11-12, read-only. Anita: "how hard would it be to implement a global flip to left hand
traffic? dont have to suppor both in the same save." This is T-3138 (open, P3) with its product calls added;
T-319's 2026-10-14 decision already allowed "a single global toggle at most".

## Answer

Small. The track model has had one running-side flag since before T-3137 (`Network::right_hand`), it is in
every save (the byte after the origin, `save.rs` `encode`/`decode_read`), and since T-3137 C1-C4 everything
the sim decides from the side reads it through one place (`lanes.rs`: `lanes()`, `join_away`, `join_for`).
What is missing is all app side: the app always makes the model right-hand and draws keep-right with a
handful of hard-coded signs. About **5-7 hours** of agent time in four stages, the drawing stage the biggest.
Existing saves stay right-hand with no work (they all stored 1).

## Where the side is decided today

### Sim (done; reads the flag)

| What | Where | State |
|---|---|---|
| Which lane of double track each direction uses | `lanes.rs` `Network::lanes` | reads `right_hand` |
| Junction moves and which cross (badge, capacity, train guard pairs) | `derive_moves`, `capacity::junction_crosses`, `build_nodes`, `move_conflicts` | from lane positions, so they follow |
| Single track joined to one track of a double: its way | `join_away`, `join_for`, `derive_ways` | reads `right_hand` |
| Flyovers (hand-laid and `add_route(.., flyover)`), which leg ramps over | `wasm/flyover.rs` `plan_flyover` (`crossing_out = left == right_hand`), `lay_flyover` | reads it; tests both sides (`flyover_tests.rs`) |
| Setting a way moves the joins | `wasm/oneway.rs` | `join_for(.., right_hand)` |
| Single-track passing, margins, sections, flat crossings between routes, overtaking, turning places, stop order | `capacity.rs`, `overtake.rs`, `lines.rs` | symmetric, no side |
| Quad's express side, double-up side, beside | `wasm.rs`, `crossings.rs`, `beside.rs` | geometric (the player's pick), no running side |
| Line paths `(edge, dir)` | everywhere | on double track `dir` *is* the lane, so paths, saves, keyframes, boarding and demand do not change |
| Schematic diagram | `diagram.rs`, `diagram.worker.ts` | no side |
| Real saves | `bin/realsave.rs` line 78 | `Network::new(.., true)` hard-coded |

Missing in the sim: a way to set the side on a new game and to read it. `TrackApi::new(lon, lat, right_hand)`
takes it, but the clock worker makes one model at start (`newModel`, `clock.worker.ts` 840, `true`) and a new
game reuses it through `set_empty_frame`, which keeps the old flag. Needs `set_right_hand(bool)` (refused
unless the network is empty, as `set_empty_frame` is) and a `right_hand()` getter. `realRoute.worker.ts`'s
models only trace geometry; their flag does not matter.

### App (keep-right hard-coded)

Each is one sign to multiply by a `keep` of +1 (right) or -1 (left), from the getter, through `ClockState`:

| What | Where |
|---|---|
| Trains on their own track | `rendererShaders.ts` train shader `side = g_run == 0 ? -1 : 1` (also carries passing stations' outer track and terminal bays, which are relative to it) |
| Click and hover on a train (CPU copy of the shader) | `network.ts` `rightOf` and `pointAt`'s passing bow, `run === 0 ? 1 : -1` twice |
| Turn-back crossover at a through station (from arrival to departure track) | `network.ts` `turnbackStrokes`, `along(.., -1, 1, ..)` |
| Platform crowds on each track's side | `platformCrowds.ts` / `stationLife.ts` (+ side = right of travel along the axis, docs/ui-map.md) |
| One-way stop half-dots (bus and rail) | `stopMarkers.ts`, `halfDot.ts`, `busLayer.ts` `v_nrm` |
| Exact edits' empty circles at a pass | the `side` DECISIONS T-3089 names |
| Comments and docs saying keep right | `rendererShaders.ts` 310, docs/ui-map.md 158/505/659, docs/track-and-service.md 698, docs/world.md 76 |

Not affected, checked: the line strokes (both tracks drawn alike; single track on the centre), `legShifts` and
`joinSign` (joins are geometric: left or right looking out along the piece), the single-lead crossover
(`singleLeadStrokes`, from the join), the snap ring and ghost (`tools.ts` `joinPoint`, from the pointer), the
line bands (an order of lines across a corridor), terminal bays (`acrossAt`, own track vs other), the train
guard (pairs from the sim). Buses are drawn on the road's centre line (`lane` 0 for a bus,
`network.ts` 1704) and route on OSM's one-way carriageways, which are already right for the country; only the
one-way stop half-dot has a side.

## Measured: real saves flip with no figure change

`checks/`-style run in the scratchpad (`lhtscope/flip.mjs`): each real save's network loaded as saved and
with its running-side byte set to left, fingerprinted with the existing `lanes_parity` binary (paths, fresh
routes, 600 station-pair searches, badges, junction inspectors, guard pairs, every capacity resource and its
figures, line figures, stop offsets):

| Save | 3+-end nodes | Badges right / left | Rows differing in any section |
|---|---|---|---|
| London (lon) | 532 | 0 / 0 | 0 |
| Tokyo (tyo) | 36 | 0 / 0 | 0 |
| Hong Kong (hon) | 40 | 0 / 0 | 0 |
| Singapore (sin) | 7 | 0 / 0 | 0 |

Why: real saves are all double track and `realsave` makes every junction that is not a station flying
(line 98), so no move crosses on either side. Flipping a real save is therefore the one byte; only the drawing
changes. A player network with flat junctions does change, correctly: the crossing move moves from the
inbound to the outbound side (the sim's small left-hand game in `t3137-lanes-parity.mjs` covers it).

## Why not a flip in the middle of a game

Paths survive, but what a player laid for one side is wrong on the other: a flyover's ramped leg is the one
that crossed under keep-right, so read keep-left it is the non-crossing leg that flies and the crossing one is
flat (a badge, a capacity hit); single-track branches joined to one track infer their way from the side, so a
one-way stub reverses and lines over it are rerouted or broken. So the side is chosen once, when the network is
empty, and fixed. (A flip could mirror joins, but flyovers would have to be laid again; not worth it.)

## Stages

1. **Sim plumbing** (0.5 h): `set_right_hand` (empty network only) and `right_hand()` in the WASM interface;
   a test; `realsave --left` (or the `ship` step setting the byte). `npm run wasm`.
2. **Drawing** (2-3 h): `rightHand` in `ClockState`; `keep` in the train shader, `rightOf`/`pointAt`,
   `turnbackStrokes`, platform crowds, one-way stop dots, Exact edits' circles; docs. The check is the
   general one: **a left-hand game of a mirrored layout must be the mirror image of the right-hand game** (lay
   the same network with y negated in a left game: every sim figure equal, and the screenshot equal to the
   right game's flipped). Add the mirrored game to `lanes_parity` (`game-mirror-left`, compared section by
   section with `game` up to ids) and a Playwright check that screenshots both at zoom 18 (a flat Y, a flyover,
   a passing station, a dead-end and a through terminus, a single branch joined to each track, a train picked
   by click) and compares one against the other flipped. That one check covers every sign above, including any
   this list missed.
3. **The choice** (1-1.5 h): a control on the new game sheet, defaulted from the start city's country (a table
   of left-running countries, sources in DECISIONS), right for "Choose on map"; `newModel` sets it. The side
   shown in Settings, read-only. New strings through `l10n.mjs` (11 languages).
4. **Real saves and docs** (1-1.5 h): set left on the shipped real saves of left-running cities, decided city by
   city with a source each (London, Tokyo, Osaka, Sendai certainly; Hong Kong, Singapore, Madrid's metro
   probably; Paris and Seoul run both, and get their metro's side), `ship`, one `t2088-ridership` run on a flipped
   city to confirm the figures hold; SPEC/docs (world.md "Running side", ui-map, track-and-service 6.1), the wiki's
   track page, DECISIONS, T-3138 closed, T-2881 answered. Smoke.

About 5-7 hours in all. Against past work: T-3137 C3 (snap, ghost and built ends drawn by joins, with a new
check) was estimated at 1.5-2 days and landed in part of one; this is smaller than C3 in the app and has no
model change.

## Risks

- **Quiet**: a missed sign in a CPU copy (picking a train selects the one on the other track; a crowd stands
  on the wrong platform) shows only close in. The mirror check is what guards it; without it, expect a few
  rounds of "this one is still on the right" from playtests.
- **Capacity and flyover generation**: low. Both already read the flag and have left-hand tests; the real
  saves' figures were measured unchanged. The only figure change is on a player's flat junctions, which is
  the point.
- **Saves**: none. Old saves load right-hand as stored; the flag needs no format change.
- **The table of sides by country** is rail fact (railways, not roads: Sweden, mainline France and mainland
  China's national railway run left while roads keep right; Seoul and Paris mix). Wrong defaults are visible
  and cheap to fix.

## Stage 1 as built: the side per save, drawn by it (lhtscope, 2026-11-12)

- **Sim**: `TrackApi::set_right_hand(bool)` (false, changing nothing, once a node or line exists) and
  `right_hand()`. Nothing else in the sim changed: it already read the side through `lanes.rs`.
- **New games**: `NewGameSpec.rightHand` (absent: right); the clock worker sets it after loading the empty track
  in `newGame` and on a fresh page's empty game. `?new=1&side=left|right` for checks.
- **Map**: `ClockState.rightHand` (from `right_hand()`), `NetworkBuffers.keep` (1 / -1, from it in
  `networkFromState`), and the `rightHand` signal in `game/world.ts` (set from each state). Signs: the train
  shader's `side` times `u_keep`; `network.ts` `rightOf` and `pointAt`'s passing bow (picking) times `keep`;
  `turnbackStrokes`' through-station diagonal; platform crowd sides (`platformCrowds.ts` `place`) and station
  faces (`stationLife.ts`); one-way stop half-dots (`halfDot.ts` `halfFill` / `halfFillVector`, now also used by
  `stopMarkers.ts`, whose own copy went; the bus stop shader's `v_nrm` times `u_keep`).
- **Not changed, checked**: line strokes (each of a line's two tracks takes its colour; lines sharing track are
  ordered side by side by line id and the piece's a to b, which is not a running-side rule), flyover and
  single-join end shifts (joins are geometric), the snap ring, terminal bays (relative to the train's own track),
  the train guard (pairs from the sim). The Exact edits circles DECISIONS (T-3089) mentions are not in the code
  any more.
- **Check** `checks/t3297-mirror.mjs`: the sim's mirrored left game decides everything as the right game (366
  rows; the same game unmirrored differs in 538), and on the map B (mirrored, left) flipped matches A (right) in
  six close views (worst 0.27%, a curve's antialiasing at the frame's edge), while C (mirrored, right) differs in
  every view with trains (3.0% to 16.7%). Two runs, the same figures. What made it work: no two lines on one
  piece (line bands' order is not mirror-symmetric), the trains' loads off (riders come from unmirrored people),
  the clock stopped at 08:30 with a train every 3 minutes, the shot clipped to the map's own box.
- `t3137-lanes-parity.mjs`'s `game` fingerprint is unchanged (same hash as the baseline) with `game` now built
  by the shared `game(right_hand, sx, quad)`.
- Vite on 6169 (6164 was taken by another session's server).

- **Default side** (`app/src/game/runningSide.ts`): a country's railways' side. Sources:
  [Wikipedia, Left- and right-hand traffic, "Rail traffic"](https://en.wikipedia.org/wiki/Left-_and_right-hand_traffic)

  [chiark.greenend.org.uk](https://www.chiark.greenend.org.uk/~mwaller/rail/countries/0e_tech.html) (rule of the

## Stage 3 as built: switching a game with track (lhtscope, 2026-11-12)

- **Sim**: `Network::flip_reversals` (lanes.rs), `TrackWorld::flip_right_hand` (world.rs), `TrackApi::flip_right_hand`
  (wasm/flip.rs). In place, ids kept: the reversals' `oneway` 1 <-> 2, the side flipped, rates settled again (the
  save's pacing flags cleared), `reload`, the history dropped; then each line the flip broke (and was not broken
  before) is moved through its same stops (`route_hops`, a way back unless it runs once) in one batch and derived
  again; one with no path stays broken. The report: pairs `[kind, id]`, 1 a piece turned round, 2 a line moved, 3
  a line left broken, 4 a junction now crossing flat (`junction_crosses` false before, true after), 5 one-way track
  no train can use (`node_unusable` newly non-zero).
- **Why reversing is the whole fix for flyovers**: joins are ground left or right, so the legs still meet the same
  physical tracks; with the other side those tracks carry the other way, and turning both legs round makes the
  ramped leg carry exactly the move that now crosses the main. No geometry changes. A pre-T-3137 leg with no join
  counts too (the rule is "a run meeting double track where a join would count").
- **App**: `ToClock` "flipSide" (answered with "answer"), handled in the worker as a rebuilt model would be
  (`restart(gameNow(), "autosave", "rebuilt")`, dirty for autosave). Settings' Game section: the Trains keep row;
  the other side asks first when there is track (the confirm question), then the list (a Modal, "Switched to the
  left": To fix, Fixed; each row locates and selects the line, junction or track and closes the list); under the
  row a count and Show list until another game opens (`flipSites` in `game/world.ts`, cleared on a load that is
  not "rebuilt").
- Tests: `wasm/flip_tests.rs` (side set only while empty and saved; a flyover switched both ways stays
  grade-separated, legs turned, the line moved onto the other leg, history dropped, and back; a set stub turned and
  a flat Y's badge kept and not listed; an unjoined set stub turned).
- Checks: `checks/t3297-side-switch.mjs` (the sheet's defaults: New York Right, Tokyo, London and Paris Left, the
  world map Right, real Tokyo Left, real Shanghai Right, a pick staying; a sandbox flyover switched in Settings:
  question, list with the two legs and the line under Fixed and nothing to fix, keep -1, no flat badge, the line
  running, a row locating, Show list, switched back; a sandbox from the real Singapore network keeping Left, its
  shipped right-hand save switched as it opened). Pictures `artifacts/trainworld/t3297-side-*.png`.
- Not exercised in a browser: a list with To fix rows (lines left broken, new flat junctions, unusable one-way
  track); the sim reports them and the list renders them, but no layout in the checks produces one.
