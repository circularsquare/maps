# T-3525: speed limit for a whole selection

Agent speedsel, 2026-11-18. Builds on T-3405 (per-piece limit, `PieceLimit.tsx`, `wasm/limits.rs`).

## What changed

- **Sim**: `piece_limit(kmh, kind, crossover)` in `track/net.rs` is the one rule for what a piece keeps: none on a
  crossover, for 0, or at or over the kind's top speed; else at least 40. `Network::set_edge` and
  `TrackApi::set_edges_limit` both use it, so a limit at the top is never stored: such a piece joins an unlimited
  neighbour (`unjoin_near` compares limits), a rebuild to a slower kind that brings a limit up to the top drops it,
  and an old save's `LPS1` entry at the top loads as none (decode goes through `set_edge`).
- **Panel** (`PieceLimit`): the logic moved into `usePieceLimit(edges)`, shared with the bar. Limit on now only opens
  the Speed limit row at the top speed, storing nothing; a step down stores a limit; stepping back up to the top
  takes it off with the row still open; Limit off sends 0 and closes the row.
- **Select bar** (`PickLimit` in `ui/Blueprint.tsx`, after the one-way buttons): a "Speed limit" toggle (`btn text`,
  on while any picked piece has a limit) and, when on, the same stepper (10 km/h steps, 40 up to the highest top in
  the pick). Value is the speed the whole pick runs at (limit, else the kind's top), "Mixed" when pieces differ.
  From mixed, a step down starts from the slowest piece (every piece then gets one limit below all tops, so it never
  sticks) and a step up from the slowest piece still under its own top (`nextLimit`, `game/pieceLimit.ts`). The
  first version stepped up from the slowest piece outright, which a checker caught sticking: two tram pieces at 80
  (their top) with rail at 90 wrote 90 again on every +; regular beside high speed stuck at 170 the same way.
  Scratch `steps.mjs` (node --experimental-strip-types, run with the tree path) replays nextLimit with the sim's keep
  rule on those cases and 2000 random picks: + always reaches every piece's top, - reaches 40, no step is a no-op. Every step is one `pieceLimit` edit with every picked piece but
  crossovers (`limitPieces` in `game/blueprintPick.ts`), so one undo. Blueprint and built alike, free, at once (no
  Rebuild). Select tool only: plain selecting's pick is one blueprint piece whose panel is open. Hidden on the
  phone's one-row bar (`.bp-limit` in the 600 px media block). In the bar the stepper is 28 px tall to line up
  with the bar's buttons (the panel's stays 24).

## Checks

- Rust: `limits_tests.rs` expectation "500 -> 160" changed to "500 -> none"; new test
  `a_limit_at_the_top_is_none_and_joins_unlimited_track` (two pieces set at once, one undo restores both, a piece
  set to 160 joins its unlimited neighbour, `set_edge` with 160 stores none). Both suites pass (647 + 844).
- Game probe (play.mjs on 6186, scratch `probe2.js`, `probe3.js`): a 7-station built line in New York, 6 pieces,
  picked by double click with the Select tool. Speed limit, four steps down: all six read back 120 from the sim.
  Each Ctrl+Z steps all six back together (130, 140, 150, none). From none one step gives 150 on all, one undo
  clears all. 150 then + gives none on all (the top). Mixed (three at 80, three none) shows "Mixed"; + gives 90 on
  all. Toggle off clears all in one edit, one undo restores 120 on all.
- A fresh pick already at 150 (no toggle click), one step up: none stored on all six, the stepper stays at 160 with
  the toggle on (`probe4.js`; a step marks the stepper open, a fix the advisor caught).
- Smoke PASSED (29 checks, 350 s) on 6186.
- `checks/t3405-piece-limit.mjs` updated (Limit on now stores nothing and shows 160) and PASSES on 6186.
