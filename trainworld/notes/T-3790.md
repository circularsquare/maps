## 3. Cause

`realauto.py build` leaves out every line the track model does not run (`not_running` -> `auto_<id>_drop.json`,
second pass), and passes a city at 90% running, so a lost line makes no noise. The sim is not the cause: the
11-13 realsave exe and a HEAD one give identical results on the same inputs (hon, ber), and HEAD realsave on the
11-11/11-12 work files (`data/work/realauto`) runs every line (ber 133/133, hon 46/46). Lines stop running for two
model reasons: an edge refused because a junction gets a 9th track end (`set_edge` -> `TooManyPorts`,
MAX_PORTS 8; the error is discarded, the count printed as "N edges refused"), and a line whose path turns
back at a node it does not stop at. Which lines hit those moves with small upstream changes. Pinned by
swapping one stage with everything else fixed (fresh REALNET_OUT each, scratch `runs/`):

- **Moscow: both the rebuilt graph and T-3782's extract.** The graph is `data/packs/realgraph/ru.rgr`, rebuilt
  11-16 to 11-18 for track snapping (60bdc135 unused rail kept, 079d9c8b rail kinds, 6a04cec2, d997c203); the
  11-13 copy was fetched from data version 2026-11-13. Lines running, fresh builds, everything else HEAD:
  old extract (11-11, same as T-3777's o5) + 11-13 graph 110; old extract + today's graph 95; T-3782's extract
  (o4) + 11-13 graph 102; T-3782's extract + today's graph 90 (what shipped, which also had 268 stale drops
  listed on its first pass in o4). 1189-1297 edges refused in every run; which 250-265 lines fail moves.
- **Berlin tram 93: T-3318's `build_lines` pattern order** (fd613794, 11-12 12:42, after Berlin's 10:40 build:
  longer patterns win, so 99, M10, RE4, RB23, S1 gain stops). Same extract, net with the old order: 133/133;
  with today's: two junctions near Potsdam (-21276,-13755 and -21036,-13946) get 9 ends, 2 edges refused, 93 off.
  The graph swap changes nothing here.
- **Hong Kong** (not reshipped): 751, 761P, 751P turn back partway once the corridors stage is rerun (11-11 net
  and geometry + today's corridors: those 3 off; all 11-11 files: 0 off). realcorridors.py's code barely changed
  since then and the 11-13 hk graph gives the same result, so most likely a graph rebuild before 11-13 (ecd8c0d5,
  11-12, light rail into the graphs), not proven: no older graph is left on R2. Hong Kong Tramways goes off at a
  9-end junction once today's net and geometry are used.
- **St Petersburg**: 21-31 edges refused, 31 lines off in a fresh build (120 lines, 4 routes and 12 stations
  short of v0.4.2); same ru graph as Moscow, not swapped (not needed for the upload).
- **Stale drop lists** (a second, smaller fault): `auto_<id>_drop.json` is never cleared, so a build in a reused
  REALNET_OUT leaves out lines that failed in any earlier attempt (T-3782's o4 builds: sai 32 listed on the first
  pass, mos 268, osa 2, hon 4). A fresh build in an empty folder still loses lines (sai 120, hon 42, osa 160),
  so clearing it alone recovers nothing shipped.

Advisor: called before step 3 (one-stage swaps, hon first; gua's new save put back on its advice) and before
reporting (Moscow's extract run added, the hon and stale-list claims corrected, the pack folder re-verified).
