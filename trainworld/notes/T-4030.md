# T-4030 Tracks held as their own records in memory: plan

Agent trackmodel, 2026-11-22. Plan only, nothing built. Read on tw/track (`.tw-trees/_track`, after 4a1) and
trackstop's tree (4a2, in flight). Design: T-3444-design 01, 05, 07, 08, 10. Advisor consulted before the split (it
asked for the station-as-node count, a quad owner, 4a2's real files, checks with power, ids for stages; all below).

## 1. What exists vs the design

The design says players' records (bundles of 1-16 tracks, nodes with per-track joins, platforms on tracks) are
compiled into a derived graph of one-track edges cut at stop points. What exists after 3a1-4a1:
- **Pieces are both the record and the derived edge.** `EdgeData` (net.rs) holds `tracks: u8` (1 or 2; `set_edge`
  refuses others), `oneway: u8` (single only, 0 = inferred by ways.rs), `join: [u8; 2]` (single only, left/right of
  the double across). Read at 47 `edge_tracks` sites in 21 files, 24 `edge_oneway` in 11, 13 `edge_join` in 8.
- **Tracks are derived, not stored.** compile.rs `layout(n, ..)` makes `Track { piece, way, off, partner }` on every
  compile from those fields. TWT7 writes way, purpose, offset flag and partner per track, but the reader counts any
  value other than the piece's own as unread (save refused as newer).
- **One track each way** is assumed wherever an entry `edge << 1 | dir` stands for a track: `track_of` (10 sites),
  `span_slot` (1 or 2 tracks only), `partner_entry`, the port masks `NodeTracks::to` behind `moves_after`/`move_ok`/
  `turn_ok` (12 sites), routing's `2 * ne` state arrays (`find_path_side`, `loop_back`, wasm.rs), reverse entries
  `p ^ 1` (10), raw `<< 1 |` builds (32 in 14 files). Decoders: `path_edge` 67 sites in 20 files, `path_dir` 30 in 11.
  App: the train shader's single keep side (`u_keep`, 4 files), `Strokes.lane` (two tracks as one stroke), about 20
  TS files decoding `>> 1`.
- **Stations cut pieces.** Placing one splits the piece at a node (draw.rs `station_at` -> `station_ops`). Since 4a1
  `Station` and `Platform { station, len, along }` are records, but a station's id is its node's, a platform names its
  track by the node's axis (`along`), and line stops are node ids (`line_stops` 71 sites in 24 files). Node-keyed
  station reads: `platform_len` 119 sites in 31 files, `is_station` 44, `station_built` 43; nearly all in the edit
  side (draw, rebuild, links, costs, stations, validate). Run side reads few: capacity 22, service 4, wasm/service 4,
  boarding 2, overtake 2.
- **Runs** (`service::Run`): `segs` are path entries, `nodes`/`stop_idx` name real nodes; built in service.rs
  `build_run` (4a2 edits three lines there).

## 2. Target in memory

- **Track records on the bundle record.** `EdgeData` stays the bundle record (a piece runs node to node). Its tracks
  become `Vec<TrackRec>` in slot order: `key` (0-15, unique in the piece, kept by splits and undo, lowest free on
  add), `way` (a to b, b to a, both; "automatic" only on a single until 3f's rule goes), `purpose`, `off_cm`,
  `partner` (a key or none, set by 01's bracket rule on every lay or way change), `join: [Join; 2]` with
  `Join::Auto` (old rule: every matching track across), `Join::Loose` (connects to nothing: her 11-21 evening call
  for an added track, which supersedes 01's Add a track bullet), `Join::To(slot across)`. A track is named in memory
  by (piece, key); `TrackId` stays the compile's dense id.
- **Paths name tracks.** A line's path entry packs (piece, key, dir) as `piece << 5 | key << 1 | dir`, so
  `path_edge` still gives the piece and every geometry read stays right. Kept returns (`line_back`), ops and the save
  (spans with slots) use the same. Routing searches (piece, key, dir) states over each node's track-end moves.
- **Derived edges** (new `derived.rs`): one per track between derived nodes: `{ track, s0, s1, a, b }`. Its first
  part keeps the track's `TrackId`, so on every old save the derived edges are the tracks and the ids are today's
  capacity keys. Extra parts come from a free list. `Run::segs` and keyframes hold `DEntry` (`dedge << 1 | dir`,
  a newtype); run-side geometry goes through `dg` accessors (piece, window, length). Wasm exports map back to piece
  entries plus a per-entry track offset, so the app's decoding stays.
- **Stations off the track: anchor nodes** (not settled by 01; ours, internal). A cross-section of platforms placed
  mid-piece (01's derived stop node: one bundle's platforms with one middle) takes a node id with no ports, as ferry
  ports and BRT stations already have, at that middle. Its platforms lie at (piece, key, start chainage, length)
  (TWT7's reserved platform bit 1). The anchor is the derived stop node: the compile cuts the served tracks there, so
  `Run::nodes`, line stops and the node-keyed save blocks keep working without parting station ids from node ids in
  this task. One station per anchor holds until a station has two cross-sections (4b's merged twins, 4d/4e's joined
  platforms on two bundles or levels); 4b still owns parting station ids from node ids, as T-3959 planned, and its
  3-4 h stays. **To confirm at e**, read but not traced: `nodes_info` gives an anchor a station row (x, y, heading,
  platform length) and demand's `StationGeo` takes rows with a platform, but how the app draws a platform's shape
  and how demand decides a station is used were not read; `station_tracks` falls back to 2 with no ports, so prices
  must read the platforms' tracks. If any of these needs the node's pieces, g's app part grows.
- **Old quad** stays two pieces grouped by `LBN1` (3b: one alignment moves their lengths), and More (4) keeps drawing
  two pieces: the hidden twin line (twin.rs) runs a line on "the other pair", so a one-piece quad would lose it until
  6c. One-piece quads are 6a's (T-3968) with 6c; 4b's converter merges old pairs only where lengths match to the bit
  (07 step 3 with step 6's rule).
- **Smart picks** (4a2) name a station (`LineData::picks`). With anchors that holds through every stage here. At 4d
  (several platforms per way) a pick must name a platform id and edge.

## 4. Risks

- **Compile cost** (08 R8: whole compile at load 30 ms or less on real NYC, a platform edit 2 ms or less natively,
  also on the 5,400 km stroke). A platform edit must put its piece in a cut-only touched set, never the set that
  derives geometry again; windows are index ranges into the piece's geometry, never copies. Measure at e and g with
  the parity bin's timing, base against branch in one run.
- **The packed entry (c).** Raw `>> 1`, `<< 1 |` and `^ 1` on entries are the quiet failure: each site is audited,
  and bus paths (bus/lanes.rs, busway.rs share the helpers) keep their own encoding. Fingerprints print mapped entries.
- **Saves.** Every new field goes in a slot the current reader already counts as unread (node bit 1, platform bit 1,
  slots and ways other than a piece's own), so an older tw/track build refuses rather than loses, and the body level
  needs a bump only if a stage changes a layout. `pipeline/readsave.py` and T-4026 (shonei-server) learn each field
  as it lands. Header level is 41 on tw/track against master's 38.
- **Undo.** Records carry keys and anchors, so undo restores them; derived ids are not restored but recompiled. Every
  stage that moves derived ids (b, e, g) checks that an edit then undo gives the pre-edit fingerprint, or figures move
  after undo (T-1863).
- **Power.** Gates A and B use nothing new, which is how four stages landed tables nobody ran (layout of 3+, joins by
  id). Each stage's cargo test above uses its new capability; that is the real check.

## For Anita (needed at stage g, not before)

Once a station is no longer a point on the track, what should dragging a blueprint station (or a platform end) do?
Today it moves the station's node and bends the track. Recommended: it slides the station along its track, keeping
the track's shape, and bending is done by dragging the track's own points.
