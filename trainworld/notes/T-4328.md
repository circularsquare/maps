# T-4328: OpenFreeMap through our own address as a last route

Research and draft only (11-25). Nothing deployed, no Cloudflare or DNS change, no game run. Her words: "can investigate proxying, but we should only do this in cases we actually need to i think". So the proxy is the third and last entry of ROUTES in app/src/map/openMapTiles.ts: tried only after https://tiles.openfreemap.org/ and https://tiles.openfreemap.org// both fail, and before the dismissable notice (0.4.6.1).

## 1. OpenFreeMap's terms on proxying

Read 11-25: https://openfreemap.org/tos/, https://openfreemap.org/, https://github.com/hyperknot/openfreemap (README, raw copy at https://raw.githubusercontent.com/hyperknot/openfreemap/main/README.md). Nothing on proxying, mirroring or passing tiles through another host appears in any of them. What does appear:

- Use: "Using our public instance is completely free: there are no limits on the number of map views or requests." (home page and README). "There's no registration, no user database, no API keys, and no cookies."
- Commercial use: "Yes." (home page FAQ). Licence of the project: MIT.
- Attribution: "Attribution is required." "If you are using MapLibre, they are automatically added, you have nothing to do." Alternative clients, print or video must add the credit line; "You do not need to display the OpenFreeMap part, but it is nice if you do." The game and the maps use MapLibre, so the attribution control already shows it. The website pages also name OpenFreeMap in their footers.
- Caching (README): "TileJSON responses for /planet/latest and non-existing versions may be cached for up to 1 hour and their tiles for up to 1 day; specific version URLs are cached long term." This is the schedule the Worker should copy.
- Terms of Service: "You agree to use the Site legally and responsibly." Users may not "Collect data from the service in automated ways, except for offline downloads as described below", where the offline limits are "at most 3,000 tiles and at most 50 MB", "at most 4 parallel requests", "a unique User-Agent identifying your app". Then: "For anything else, please contact us at info@openfreemap.org." They may use Cloudflare as their own CDN.
- Self-hosting is encouraged: "You can either self-host or use our public instance." Everything is open source.

Reading: a pass-through that fetches only what a real player's map asked for, caches it, and sends it on is the same traffic OpenFreeMap serves to browsers, just with our Worker as the client (and with fewer requests to them, since our edge cache answers repeats). It is not bulk collection. But the "automated ways" clause is written about collecting data, is broad, and is not clear on a proxy that passes live map views through. Nothing forbids it; nothing allows it in words.

What to ask (draft, no names in it; to info@openfreemap.org, her call whether to send, she does all contact):

> Hi, we run a browser game and some map pages that use your public tiles through MapLibre. A tracker list (EasyPrivacy, 2026-11-24, easylist/easylist#26522) now blocks https://tiles.openfreemap.org/planet for some visitors, so their maps are blank. We would like to add a last-resort route: a small Cloudflare Worker on our own host that passes /planet and /planet/<version>/z/x/y.pbf to your server, on request from a visitor whose first two routes failed. It sends no cookies or visitor details, identifies itself with its own User-Agent, caches the TileJSON for an hour and versioned tiles for a long time, and keeps your attribution. Is that fine with you? If you would rather we did something else, or want a contact address in the User-Agent, tell us.

Until there is an answer: the Worker is built to be harmless to them (see below), and used only by players whose map would otherwise be empty. I would still ask before shipping, since it is one short email and the ToS says to ask for "anything else".

## 2. The Worker (draft)

Route: data.anita.garden/ofm/* in the anita.garden zone. Only two kinds of path are passed, so it is not an open proxy:

- /ofm/planet (TileJSON)
- /ofm/planet/<version>/<z>/<x>/<y>.pbf (versions look like 20260311_001001_pt)

Everything else answers 404. GET and HEAD only; OPTIONS answers the CORS preflight.

```js
const UP = "https://tiles.openfreemap.org";
const HOST = "https://data.anita.garden/ofm";
const TILE = /^\/ofm\/planet\/(\d{8}_\d{6}_pt|latest)\/\d{1,2}\/\d+\/\d+\.pbf$/;
const VERSIONED = /^\/ofm\/planet\/\d{8}_\d{6}_pt\//;
const ALLOWED = /^https:\/\/(([a-z0-9-]+\.)*anita\.garden)$|^http:\/\/localhost(:\d+)?$/;

function cors(req, h) {
  const o = req.headers.get("Origin");
  if (o && ALLOWED.test(o)) { h.set("Access-Control-Allow-Origin", o); h.set("Vary", "Origin"); }
  h.set("Access-Control-Allow-Methods", "GET, HEAD, OPTIONS");
  h.set("Access-Control-Max-Age", "86400");
  return h;
}

export default {
  async fetch(req) {
    const url = new URL(req.url);
    if (req.method === "OPTIONS") return new Response(null, { status: 204, headers: cors(req, new Headers()) });
    if (req.method !== "GET" && req.method !== "HEAD") return new Response("no", { status: 405 });
    const isJson = url.pathname === "/ofm/planet";
    if (!isJson && !TILE.test(url.pathname)) return new Response("not found", { status: 404 });

    // a fresh request: no cookies, no referer, no visitor address, our own user agent
    const upstream = UP + url.pathname.slice(4);
    const ttl = isJson ? 3600 : VERSIONED.test(url.pathname) ? 31536000 : 86400;
    const res = await fetch(upstream, {
      headers: { "User-Agent": "anita.garden-tile-passthrough (last-resort route; see openfreemap.org/tos)", "Accept-Encoding": "gzip" },
      cf: { cacheEverything: true, cacheTtlByStatus: { "200-299": ttl, "404": 60, "500-599": 0 } },
    });
    const h = cors(req, new Headers());
    h.set("Content-Type", res.headers.get("Content-Type") || (isJson ? "application/json" : "application/x-protobuf"));
    const enc = res.headers.get("Content-Encoding"); if (enc) h.set("Content-Encoding", enc);
    h.set("Cache-Control", res.ok ? `public, max-age=${Math.min(ttl, isJson ? 3600 : 86400 * 30)}` : "no-store");
    if (!res.ok) return new Response(null, { status: res.status, headers: h });
    if (!isJson) return new Response(res.body, { status: 200, headers: h });
    const j = await res.json();
    j.tiles = (j.tiles || []).map((t) => t.replace(UP, HOST));
    return new Response(JSON.stringify(j), { status: 200, headers: h });
  },
};
```

Notes on it:
- TileJSON is rewritten so its tile addresses point at us. The game already swaps the OpenFreeMap prefix for the route it used, so the rewrite is redundant for the game and needed for the website maps.
- Cache: the TileJSON answer is cached at our edge an hour and in browsers an hour; versioned tiles at the edge for a year and in browsers 30 days (OpenFreeMap says versioned URLs are cached long term); unversioned or "latest" tiles one day, as they say.
- No cookies in either direction (the upstream request is built fresh; OpenFreeMap sets none).
- CORS answers only anita.garden, its subdomains and localhost; others get no allow header.
- To check when it is live (not before): that no list matches data.anita.garden/ofm/planet (rerun the matcher from T-4275 over the new URLs; EasyPrivacy's rule is anchored to the tiles.openfreemap.org host, so it should not); that data.anita.garden's existing R2 files are unaffected (a route on /ofm/* only catches that path); response headers of a tile and the TileJSON.
- The matching 204 problem: a tracker answering 204 to a blocked host never reaches the proxy, because the browser asks our host, not theirs. A rule matching the word planet on any host would block it too; then this route fails and the notice shows.

## 4. Cost

Facts: Workers Free is 100,000 requests a day, then the Worker stops answering (requests fail); Workers Paid is $5 a month with 10 million requests a month included and $0.30 per extra million (Cloudflare's published prices; I did not read her plan, tools/ops/check_resources.py does not show it). A cache hit at the edge still counts as a Worker request, but costs no upstream traffic. Egress from Workers is free.

Estimate. About 26k plays a day (check_resources.py's last run). The share of players who fail both OpenFreeMap addresses is unknown: the first report came within hours of the rule and the double-slash route should rescue most uBlock and Brave users. Say 1% to 10% of plays reach the proxy, so 260 to 2,600 loads a day. A load of a city draws about 30 to 80 vector tiles (view plus the game's own readers) plus one TileJSON; panning adds more. Call it 100 requests a load for a session: 26k to 260k Worker requests a day. Browser caching cuts repeat players.

- 1% (26k a day): inside the free plan.
- 5% (130k a day): over the free plan's 100k; needs Paid, about 3.9M a month, inside the 10M included: $5 a month.
- 10% (260k a day): 7.8M a month, still inside Paid: $5 a month.
- Beyond 10M a month: $0.30 per extra million, a few cents.

So at worst it is the $5 Paid plan if she is not on it already; likely free if the first two routes rescue most players. A runaway is not possible beyond what players actually load, and I'd add a Workers rate-limit rule only if the numbers jump. Data.anita.garden's own 97% cache hit rate is for R2 files and does not carry over; this route has its own cache, upstream hits only on first sight of a tile. Upstream cost to OpenFreeMap: one fetch per tile per Cloudflare location per year at most (versioned), far less than the same players asking directly.

If she is on the free plan, a cap-failure just means the proxy route fails and the notice shows, as if the proxy did not exist.

## 5. The game side (third ROUTES entry)

map/openMapTiles.ts, one line:

    const ROUTES = [OPENFREEMAP, OPENFREEMAP + "/", "https://data.anita.garden/ofm/"];

The loop in openMapTiles() already does what is needed: it reads the TileJSON from each route in order, moves on when a route is refused, gives an error status, or answers with no tile addresses, and puts the tile template on the route that worked. Tried: only when route 1 and route 2 both fail, once per load (the answer is kept for the session; on failure it is asked again next time). Tiles then come from data.anita.garden/ofm/planet/<version>/z/x/y.pbf, since the Worker's TileJSON already names that host. Then the notice, if this route fails too.

Cost for a normal player: none. A blocked player pays two failed requests before the third; could save them by remembering the working route in sessionStorage, which I would add if she likes (about 5 lines).

CSP: the live index.html's CSP must allow data.anita.garden as a connect and image source; it already loads packs from there, so probably yes. Check at implementation.

Needs her answer before the code: send the email first or ship first; and the Worker deploy. No game run was done for this draft.

## 6. Her website's 11 maps

Files: website/<map>/index.html. All load `style: 'https://tiles.openfreemap.org/styles/dark'` (noritetsu also positron; cityhistory, languagedots, religiondots and others name OpenFreeMap in their footers, so attribution is there). The style JSON at /styles/dark is not matched by the rule. The style's vector source then points at https://tiles.openfreemap.org/planet, which is matched. So all 11 show a land colour but no roads, water, boundaries or labels from vector tiles when blocked. Maps that draw only their own data over a plain basemap lose little; the ones leaning on OpenFreeMap's roads and labels lose the most.

The same Worker serves all of them with no change, since its CORS allows every anita.garden subdomain. Each map needs the same small change T-4275 made to the game:
1. load the style with fetch, and set the vector source's url to a protocol address such as twtiles://planet;
2. register a MapLibre protocol (maplibregl.addProtocol) that tries tiles.openfreemap.org/planet, then tiles.openfreemap.org//planet, then data.anita.garden/ofm/planet, and returns the TileJSON from the first route that gives tile addresses.
Written once as a shared script (about 40 lines, e.g. website/assets/ofm-routes.js loaded by each page) and the style line in each map replaced by a call to it. Per map: korearail, cityhistory, londonriders, flights, languagedots, nycriders, japanrail, religiondots, ancestrydotsna, ancestrydots: one style line each (korearail 703, cityhistory 388, londonriders 761, flights 343, languagedots 3109, nycriders 787, japanrail 891, religiondots 10768, ancestrydotsna 981, ancestrydots 979). noritetsu has two (803 dark, 824 positron), and must be checked for style edits made after the load (it may recolour the style's layers; the fetched style object has to be passed through the same edits). Maps whose code sets layer paint on the loaded style by name need no change; maps calling map.setStyle later need the helper at each call.

Not in the 11 but with the same line: trackdepth and the pages in website/assets (guessthecity.html, citycircles.html), plus the working copies in the maps tree (seoulriders, koreariders, japanriders, chinaethnicity, isochrone, neighborhoods, and so on, found by grepping openfreemap). Same helper.

Pushing the website waits for her word. Roughly 1 to 2 hours of agent time for the helper and the 11 maps plus a check that each still draws; the Worker has to be live first.

2. Build the Worker as drafted and add the third route to the game after she has seen it; deploy by dashboard. Expect free-plan use for the game unless blocked players are many; $5 a month if she is on the free plan and it grows.
