# T-3722 Exit to main menu sometimes missing

Anita, 2026-11-18: "random but sometimes on 8800 i dont see the "exit to main menu" button on saved games. seems
kinda random when this is the case."

## Cause

The button ("Save and quit to main menu", right end of the New game row in Saved games) had one gate:
`startup.value === "ready"` (ui/SavesPanel.tsx). `startup` turns "ready" only when the page's first game has its
first demand final (`loadComplete`, game/loading.ts), the moment the loading card goes. Every game opened (a slot,
a backup, an account game, a file, a new game) reloads the page (T-1196), so every game starts at "loading" again.
The button was missing for as long as the loading card was up, and (read from the code, not probed) for good if a
load never finished.

Measured on :6184 with only 2 demand workers (a headless check, not her machine's figure), real NYC save (T-007):
the card stayed 97-105 s each time it was opened (from a file and from its slot); the button appeared only after. A small or new game's card goes in seconds. So
whether she saw it depended on the save's size and on how soon she opened Saved games: the "random".

Ruled out: the gate reads no slot, account, Community or file state; slot list and active slot have no part in it.
T-3687's diff (sandboxfix: money names its slot, publishSlots on an empty file) does not touch it. The start menu
does not render the Saved games panel (its own list), and the Dock and top bar that open the panel are in game only.

## Fix

- ui/SavesPanel.tsx: the gate is now `!choosing.value` (the start menu is not up), so the button shows from the
  moment a game is picked, its load included. The one deliberate hide is the start menu, where there is no game to
  leave (the panel is not reachable there anyway).
- workers/clock.worker.ts: showing the button during a load exposed a race from T-3478. A leave that arrived before
  the worker had read the pending game (a file or backup picked in Saved games, page reloaded into `?load=file`) took
  the early "game still opening" path, and the picked game was lost: never written to a slot. `initIncoming` is now
  set from `msg.pending` as init starts and settled once the pending game is read, so such a leave waits behind the
  load and saves the new slot as T-3478 meant. (The same race existed before via Open on another slot in that window.)

## Checks (scratch scripts in the exitmenu scratch folder, not standing checks)

- Real save opened through play.mjs, before the fix: button absent with the card up, present after the final.
  After the fix: present at once.
- Real slot (no `?new=1`): leaving while demand solves (10 s in, card up) and leaving the instant the game is picked
  (before the worker loaded it) both reach the start menu; the game reopens with all 109 lines.
- File mid-open: Saved games > Open a file (T-125-northeast), leave 2.5 s after the reload. Before the worker fix
  the start menu listed only the old game (the file's game lost); after it, both games listed and the northeast one
  reopens with 110 lines. The leave then waits until the file's game has loaded into its slot (not timed); the panel
  is closed by the click and nothing shows during that wait.
- `npm run check` clean; t2850-main-menu (5 PASS), t3478-new-game (all PASS, its leave-while-opening cases
  included) and smoke (29 checks) pass on :6184.
- sandboxfix (T-3687) edits clock.worker.ts too, in other hunks (`intoNewSlot`, `moneyState`, `manageSlot`).

Left alone: clicking the button on the old page in the ~2 s between picking a file and the reload drops the file's
open (the earlier leave wins `ClockClient.leave`); the panel is closed by the pick, so a player would have to reopen
it and quit within that window. Pre-existing and not worth a change.
