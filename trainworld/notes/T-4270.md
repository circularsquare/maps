# T-4270 smoke: t133, t144, t3192 fail with "errors: [Getter/Setter]"

Cause: the checks' own bundling (checks/lib.mjs loadApp, and t3192's own build), not the game. Their Vite builds ran with
configFile false, so workers took Vite's default iife format; the clock worker's graph reaches i18n/index.ts, which has a
top-level await, and iife refuses that. The app's real config sets worker.format "es" (vite.config.ts). The game bundles fine.

Fix (checks only): both builds set worker: { format: 'es' }. loadApp also writes the bundle's chunks to a temp folder and
imports the entry from there, since an es worker and the app's dynamic imports leave chunks the entry imports by relative
path (a data: URL cannot resolve them; inlining them made a top-level-await cycle that never settled).

Not explained: why they passed at a17111304. The same failure happens with app/src checked out at a17111304 in this tree,
so no app commit between caused it; the uncommitted checks/ reorganisation in the main tree is not the cause (tree has
HEAD's checks). Node 22.23.2, vite 8.3.4, rolldown 1.2.13 (node_modules dated 11-23).
