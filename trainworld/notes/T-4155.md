# T-4155 Streets arriving after a pan hold the worker for seconds (agent trackstream, 2026-11-24)

Found by T-4143: after a pan on the Asia save, the street speeds of the new zones land (`ensureStreets`), every bus
line is timed again (`rework_buses`: rebuilt, the global capacity pass, train counts, retime) and the clock worker
resends the whole state with both hours' trips and boarding (3.9-4.4 s while trips calculate), even where no bus runs.

## What changed

- `TrackApi::add_pack_streets` (sim/src/track/wasm.rs) returns -1 when the arrays do not fit, else how many bus lines
  it timed again. `TrackWorld::rework_buses(area)` (world.rs) takes the new grid's lon/lat box
  (`StreetGrid::lonlat_box`, streets.rs) and times again only the bus lines whose route points' box meets it (0.02
  degrees of slack), plus every BRT line when one of them is BRT (their lanes are worked out together). The first
  speeds of a game still time every line (`Pace` samples streets only once there are any).
- Why that is exact: `Streets::car_kmh_at` takes the first grid with a zone at a point, so a new grid only speaks where
  none did before, and a bus samples the streets only along its route's points (`Pace::along`), which lie inside their
  box. A line whose box misses the new grid gets the same `build_line` as before; the capacity pass, train counts and
  retime run exactly as before whenever any line is timed again.
- `ensureStreets` (app workers/clockGround.ts) sends the state and schedules a snapshot only when a line was timed
  again; the town outline still goes out for every pack.
- Not changed: when a bus line is met, the state, trips and boarding go out as before (whole). Making that a service-only
  state would touch clockMain.ts (editworker's, T-4149).

## Checks

- New Rust test `streets_rework_tests`: two bus lines 200 km apart; speeds over one time only that one (1), over
  neither time none (0) and change nothing, and in each case every line's round trips and trains equal a rework of every
  bus line. Both suites pass (735 and 964 tests). Existing callers of `add_pack_streets` (bus_tests.rs, bin/frontier.rs)
  read the new return.
- `npm run check` passes.
- perf_bench nyc (label trackstream-t4155): map 13.2 s, trips 121.4 s, edit 0.7 s, cpu 255.8+11.3 s, tab 2,263 MB, page 48,
  clock 65, demand 1,163 MB, 64.5 MB down, solver 204.4 s, 12,672,465 rail trips/day: the same rail trips and memory as
  master's lines (T-4136's 12,672,465); its flags against v0.4.5 are master's since that publish. Wall times on 3
  shared cores at the cap.
- smoke passes (30 checks; the real save's demand final 13,035,408 rail trips a day, as before).
- edit_bench not run: its edits are in an area whose streets are in, where nothing here changes.
