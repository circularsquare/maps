# T-4098: every edit fails after deleting a terminus past a one-way station

Agent oneway, 2026-11-23. Tree `tw/oneway`. Player report 11-23 (pasted by Anita, not in the feedback inbox: the
24 h and 30 h reads hold no such thread and no save), on live v0.4.5.

## Finding

The same bug as T-3945, fixed on master 11-21 and not yet live. Master needed no new fix.

- v0.4.5 is commit b0899150 (build mwpvgpdw = 2026-11-21 03:52 UTC; no tags in the repo). Built in a second tree
  (`agent-tree.mjs new oneway45 b0899150`, removed after).
- Cause on v0.4.5: `Service::update_scoped` hands the capacity pass only a line's way out. A line over a one-way
  stretch whose way back calls at the other leg's platform (a one-way station is a stop of its own, T-3605) keeps
  that platform's old user, with its old stop number, after any change to the line. Deleting the terminus is such a
  change. Once the line has fewer stops than that number (0 when it breaks), the next holds pass panics; each
  panic undoes the edit ("That edit failed and was undone."), the fourth in a minute stops the track model, and
  every later edit is refused with the same message. That is the player's lockout.

## Evidence

- Native, the player's path (`deleting_termini_past_one_way_stations_keeps_capacity_whole`, oneway_tests.rs):
  double track to a junction, two one-way single legs with a station each, double again to T, X1, X2; line
  S0, Pa, Pb, T, X1, X2 (out by Pa, back by Pb); saved and loaded; X2 then X1 deleted with a train count set after
  each. v0.4.5: the capacity differs from a fresh build right after deleting X2 (a stale user at Pb). Master:
  equal to a fresh build after every step. Three throwaway variants (terminus right after the loop; the legs in
  either order; a longer line with deletes and train counts after) agree: drift on v0.4.5 every time, none on master.
- In the game (play.mjs, sandbox NYC, the t3348 split built by its edit ops): lines West - South - East,
  West - South - North - East and West - North - East, East removed with the station delete op, then train counts,
  new track, line removal. Both builds: no failed edit. Deleting East is refused ("LineStops") when North (the
  westbound leg) is a stop, on both builds alike; it goes through with only South. My toy layout leaves only
  passing users stale, which never panic; the panic needs a stale stopping user past the shortened line's end.
- The panic itself, on a real v0.4.5 save: T-3945's player save (trainsworld-espana-day-172.save, from that task's
  scratch). On the v0.4.5 tree, deleting edge 2000 five times: four "Rust panic in edit: capacity.rs:1519 index out
  of bounds: the len is 0 but the index is 5", then "The train simulation stopped working. Reload the page to go on.
  Your last autosave is kept.", then every edit (train count, another delete) "Internal". On master the same save
  takes all of them (delete and undo five times, a train count, deleting edge 1800).

## Stuck saves

A save holds the network, not the capacity resources: a load rebuilds them whole, so a stuck v0.4.5 game's save is
clean on load. Checked on master: the espana save above, and a v0.4.5 save made right after deleting the terminus
(scenario West - South - East), both load and take edits (track deleted and undone, train counts, new track). On
v0.4.5 itself a reload also clears it, until the next edit that hits the stale platform. Nothing to add on master.
