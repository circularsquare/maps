# T-3771: per-line money history (linehist, 2026-11-19)

## What the game keeps per line

Only `lineDays` (clock.worker.ts; `SaveHeader.lineDays`, `MoneyState.lineDays`): per line id, [day, fares, running cost]
per day, capped at `LINE_DAYS = 31` (30 closed days and the day now) since T-3566, so the rule Anita asked for already
held for every line that still earns or costs. The line panel chart (`ui/inspector/LineMoney.tsx`) reads only the last
30 closed days and draws no column before the line's first kept day; nothing reads further back. There is no other per-line
day array in the save (stars, goals, notes, shapes are not history). On a long game it is at most 31 x 3 numbers per line:
in the 109-line real network about 15 KB of JSON for all lines at day 2303, against 23 KB for the (folded) network ledger
and growing with years for the network and region ledgers, which T-3757 folds.

One gap: a line that stopped earning (no entries written since) kept its last entries, however old, until deleted; an old
save with such a line loaded them. Fixed: `dropOldLineDays` removes a line's days older than the 31 kept, on load and at
the end of each settled hour; a line with none left is dropped. No save level change, no strings changed.

## Probes (real NYC network, 109 lines, synthetic 2,200-day ledger from T-3757's mk.mjs, scratch in linehist/)

- Old save with 400 days per line (lines 1-3): loads with 31 per line (2271..2301), ledger 190 entries, cash 6000,
  network fares total 5449.726 and build 341.498 as before the change; a line whose days all ended 100 days earlier is
  not loaded at all.
- After 2 game days at the game's speed 2 (960x here, a game year would take about 9 hours of real time, so years were
  not run; years of play only add network and region ledger entries, which T-3757 folds): max 31 days per line, all
  109 lines, network ledger still 190 entries, cash and totals moving only by the days played, heap 381 -> 386 MB.
- Save size before/after: the per-line part was already bounded, so none for active lines.

## Side question: Undo after building track

On master (this tree, real NYC save, normal mode), Ctrl+Z / Ctrl+Shift+Z: undo before Construct reverts the drawn blueprint
(edges 1653 -> 1652 -> 1653, no cash involved). After Construct (cash 9991.48 -> 9807.41, build ledger 351.92 ->
535.99), Undo changed nothing: edges, cash and the build ledger all stayed, and Redo likewise. Readings taken 2 s after
each step with the clock paused, so not stale. Built track is not undoable, so there is no refund. Not fixed.
