# T-4221 bubbles stay on screen after turning them off following a load (player report, Chinese, 11-24)

Report: "sometimes, when a game loads with the population bubble map on, after the load finishes, turning the bubble map off leaves the screen stuck showing the bubbles". No diagnostics came with it (not in the inbox: forwarded by Anita), so the player's browser and build are unknown.

## Finding: the same report as T-4029 (Twitter 11-21), already fixed on master and not yet published

- T-4029 (5380f87e1, 11-22): DemandOverlay.draw() returned on a lost WebGL context before the branch that empties and hides the canvas; a load is when browsers drop contexts. Fixed: draw() blanks without GL first. Its changelog item (c049 in changelog/v0.4.6.json, area schematic, fix) exists but is marked hidden.
- The live build is v0.4.5 (other feedback of 11-24 reports v0.4.5), which has neither T-4029 nor T-956's hidden-canvas change. So the player most likely met the T-4029 path.
- T-956 (Safari, last frame kept after a 0x0 shrink) is the same family; the visibility:hidden in fitSparse covers it for any engine.

## Read from code (no new cause found)

Every draw path with nothing to draw (None, a selection gone, the overview) reaches the blank branch, and the only things that skip it are a lost context (fixed) or no camera with bubbles still wanted. setBubblesVisible has one caller (commuterView effect, reads display.commuters after the focus block); nearby, "near", "far" and "inter" sets feed the same canvas, but all are cleared or hidden by the same blank test. Station circles, trip routes and the others are 2D canvases that blank without a context.

## Runs in this tree (master plus nothing; no app edit)

Chrome headless, play.mjs, Vite 6180:
- New York, Total on, None: canvas 1098x823 visible, then 0x0 hidden.
- New York and the real NYC save, reload with Total on, None clicked 0 to 6 s after the load, watched 8 s: 0x0 hidden throughout, no page errors.
- Forced context loss on the demand canvas (WEBGL_lose_context) with bubbles on, then None, then restoreContext: 0x0 hidden at once, stays hidden after restore.
Firefox: play.mjs drives Chrome only, not run.

## Outcome

No code change, no new check (T-4029 notes record its repro; the loss path is only reachable by forcing a loss). No changelog item added: c049 already covers it. Nothing for the player to read changed.
