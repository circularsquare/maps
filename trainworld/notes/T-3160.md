## Method

`checks/t2802-memory.mjs` (notes/T-2802.md) on scratch production builds of the worktree (`TW_LINK_PACKS=1 vite build
--outDir <scratch>`, served by `checks/static-serve.mjs`), before and after the change, same machine, 4 claimed cores.
New: `DESKTOP=1` runs it in a 1400 x 900 desktop window with 3 solving workers (what T-3472 measured); without it, the
emulated Pixel 7 with 1 solving worker. Walk: start menu, Start in New York, demand final, five camera jumps, a
three-station line with the clock running 45 s. MB after a forced collection: Chrome's private bytes; per context
V8 heap used + ArrayBuffers + WASM. "Rest" is the renderer minus every context (Blink, compiled code, isolates,
WebGL in the renderer, allocator). Run-to-run spread is 30-50 MB at the renderer.

## T-3491: what changed

The page kept every zone's coarse outline decoded (61 MB of coordinate arrays) and, on desktop, every zone in
`OutlineEdges` (segment holders 40 MB, vertex numbers 23 MB, rings and keys 14 MB): about 150 MB from the start
menu on, plus a copy of every zone's lines in MapLibre's worker (97 MB of heap there at the menu against 45 now).

- `coarseOutlines.ts` keeps the file only as `PackedOutlines` on every device (decoded a zone at a time, the last 64
  kept), as phones already did.
- Desktop draws the coarse outlines from `map/coarseEdges.ts`: the packed file plus one Int32 a point, the other
  zone holding the border from that point to the next (5.4 MB), worked out once by `workers/outlineTopo.worker.ts`
  (0.3 s, about 60 MB passing in a worker that then ends). Same rule as `OutlineEdges`: a shared border is drawn by
  the first zone in the file's order still drawn coarse, none the focused zone holds. Compared with `OutlineEdges`
  over the whole file (every zone; 300 zones taken out with another focus; 400 zones only): the same segments for
  every zone. `OutlineEdges` now holds only exact outlines (and a phone's coarse zones near the view).
- No outline features while the map is blank (start menu, a game loading), where the layer was hidden anyway.
- The features of zones that leave the view's surroundings are dropped, so the page holds what MapLibre draws.

With every realm shown (`checks/t3491-outlines.mjs`, `opened=all`), page heap at world zoom 190 -> 82 MB, Europe
194 -> 50, Germany 196 -> 42, New York 197 -> 41; the same 4,015 features and 805,863 points at world zoom, and
the screenshots match pixel for pixel over the map (`artifacts/trainworld/t3491/`). In a fresh game only the
start realm's zones draw (28 features at world zoom).

Smoke 29/29 on the worktree's dev server. On the production builds the real save's demand final is 12,679,832 rail
trips before and after (the static server's 404s fail two checks on both).

### What the page's buffers were

A heap snapshot of the page at the first line (desktop, 3 solving workers, after a collection): 215 MB of
ArrayBuffers, 156 MB of them one object, the market's corridor table (`demandClient` `modesTable`, also the newest
entry of `corridorTables`): 8,182,819 rows over 7,424 places, `longer` Float64 62 MB, `air` and `car` Float32 31 MB
each, `from` and `to` Uint16 16 MB each. So on a one-city game the 232 MB is held, not churn: it arrives with the
first solve that has a market (at demand final, before any line, the page held 34 MB of buffers). The rest: the
packed outlines (10), the coarse outlines' partner table (5), the published views (`pushed`, 10), bubbles (about 10).
The demand cache writer copies the whole table for each write (`writeStored`), so a write briefly holds it twice.

### What changed

- The table goes to the page with `longer` as Float32 and `air`, `car` as Uint16 shares (steps of 1/65,534; 65,535
  for NaN; `game/corridorShares.ts`): 156 to 94 MB, on the page and in each cache write's copy. Measured on this
  game: the world's longer trips 262,445,273.70 to 262,445,273.75; by plane 13,805,678.7 to 13,805,677.8; by car
  246,609,580.6 to 246,609,581.6. Rail figures are untouched (their columns stay Float64): the real save's demand
  final is 12,679,832 rail trips a day before and after. `CACHE_FORMAT` 9, so old cached results are not read.
- The realm shade's worker is started for each cut and ended with its answer on every device (a phone already did),
  and decodes only the zones a cut names. Desktop: 32-42 MB less all game. Cuts come when the realms shown change.
  Screenshots at four zooms in a fresh game match pixel for pixel over the map.
