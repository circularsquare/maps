# T-4585: reloads stopped feeling instant

Her words, 11-28: "why does reload cache no longer feel like its instant? what conditions need to be satisfied for
reload cache to work? do i have to like not change anything or something". Agent reloadcache, tree reloadcache.

## What a reload needs (from workers/demandCache.ts, demandClient.ts `tryCache`/`writeCache`, saveFile.ts)

The kept result is the slot's last final, stored under the network's hash. A reload shows it, and the loading card
goes, when all of these hold:

1. **The final of exactly this network was written.** Written about 1 s after the final on the real NYC save (8.4 MB,
   36 ms of page work, the rest the cache-write worker). Asia is bigger and unmeasured; a reload while the write is in
   flight keeps the previous final, which is another network's. Any edit after the final (cars, a headway) makes the
   save's network another one: miss "none".
2. **The same data.** Every covered zone's pack hash and every market pack's hash, and each market key also carries
   the SHA of the world's `market-drives.bin` (fetchMarket: `sha(pack) + drivesSha`). A pack or drives difference is no
   stand-in (T-4202's rule, Anita 11-24): a full load. 8800 serves hard links made at each snapshot build, so data
   reaches it at the next rebuild. Market rows and the corridor file are in DEMAND_KEY, so those stand in.
3. **The same zones, markets and levels.** tryCache wants the stored zones and markets to equal what this load needs
   (reach plus zones open in every worker; markets = reach, near stations, and the selected city's). A solve covers
   everything open; `closeFull` drops a pack without a new final, so a final written while a city outside the network
   was selected (its market open for the panel) keeps that market in its key: the next reload misses "zones" until the
   next edit's final. Coarse zones key as `<hash>:coarse` from the save's fine list.
4. Code version and worker count: a difference stands in (T-4202). CACHE_FORMAT or the network form (`canonical`): a
   full load, once per change.

**Even a hit waits for the network.** `hold` is set only when the loaded game's network arrives (submitNetwork), and
`cacheDone` needs `latest()` to be the cached network, so the card goes at the network's arrival either way. The
"ahead" lookup (T-1539, keyed by the save's bytes and BUILD) only shows the figures behind the card earlier. It is
written only when the final's network is the one the load worked out (no edit since the load) and is lost at each
8800 rebuild (BUILD).

## Test (one reload, own Vite 6117, real NYC save in a slot, 3 cores, a country run on 6 others: noisy)

First open went through play.mjs's file path, which keeps `?new=1` (no slot writes: skip "off"); opened the file again
from a page without it. After the final (write ok, 8,357,699 bytes, 0.9 s after the final), reload and pick the slot:
ahead lookup at 3.8 s after the click missed (expected: the slot's bytes are the re-saved file's, key b59c.. vs the
file's 60ce..); the network arrived at 17.9 s; the cache showed and the card went 0.6 s later (read 308 ms). The fresh
final landed 102 s after; the new write carried the ahead pointer. So the mechanism works on today's code.

## Suspects from the brief

- Market or pack part of the key on country runs and rebuilds: **in, by design** (drives file and packs; above).
- A recent landing changing the network form or key: T-4543 (11-27) adds `gaps` only where present, switch off: out.
  CACHE_FORMAT 13 since 11-24: one full load per save then. Clock-side timing changes (T-4438 tram cap, 11-27 19:02)
  change the network legitimately: one full load for saves they touch.
- Final never written on a big save: written on NYC; possible on Asia when the reload follows the final within seconds.
- Auto's worker count: out (`poolN` is the pool before the memory cut, 3 on her machine; a difference stands in).

## Changed (tree reloadcache)

- workers/demandTrace.ts: `dm-cache` events in the diagnostics: each read once settled (ahead, readMs, miss reason or
  shown, standIn) and each write (wrote: ok, MB, ahead; or skip: off, days, newer, same). diag_report.mjs prints them
  under KEPT TRIPS. Typechecked; not run in a game (it sits in the sampler's try).

## Proposal for her (T-4586)

Let a difference in the trips to other places stand in, as a code update does: the drives file, a market pack's
data, or a market opened only for a selection. Cost now: the first reload of every save after a country run reaches
8800 is a full load (NYC about 2.4 min on 1 worker, Asia about 8 min). The lie: for the minutes of the fresh
calculation, the intercity figures are the old data's; city packs that changed still mean a full load. About 2 hours.
