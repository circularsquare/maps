# T-4275: roads and water missing behind tracker blockers

## Cause

- EasyPrivacy gained `||tiles.openfreemap.org/planet` on 2026-11-24 23:11 UTC (easylist commit 200afb42a2, "A: https://simpleflying.com/", easyprivacy/easyprivacy_specific.txt, under "Port scanning Fingerprinting Trackers"). It has no `$domain` and no end anchor, so it matches OpenFreeMap's TileJSON `https://tiles.openfreemap.org/planet` and every vector tile under it (`/planet/<version>/{z}/{x}/{y}.pbf`), on every site.
- EasyPrivacy is on by default in uBlock Origin and Brave Shields. NordVPN Threat Protection blocks the same URL and answers 204 with no body, hence the player's console error "Failed to execute 'json' on 'Response': Unexpected end of JSON input" and the 204 on `planet`; OpenFreeMap's own demo was blank for them too.
- Not a 0.4.6 regression. Between the 0.4.5 and 0.4.6 publishes nothing changed in how roads, rivers and water load (same style URL, same TileJSON, no fetch option, host or worker change). 0.4.6 was out by 19:55 UTC 11-24 (bookkeeping a825a5357); the rule landed 3 h later; the first reports came about 02:30 UTC 11-25. The one new request in 0.4.6 is `track.js` (T-4126), which no list matches.
- What a blocked player loses: everything the basemap draws from vector tiles (roads, water, rivers, labels; the land colour and the satellite imagery still show), and the game's own readers of the same tiles: road crossing prices (`workers/roadFeed.ts`), bus roads (`map/busRoads.ts`), ferry water (`ferry/`), street snapping. "Map is gone, can't place new routes" (feedback 1795578339) fits.
- NordVPN's "allow trackers on anita.garden" is per page, so it let `planet` through; allowing tiles.openfreemap.org alone did not (the player's report). The Google Analytics URL NordVPN named (gtag G-RW5BF5TNQH) is not loaded by the game page (the live index.html's CSP allows only its own scripts and Google sign-in); it comes from another anita.garden page.
- Upstream: easylist/easylist#26522 (opened 02:28 UTC 11-25, from the maplibre.org side) asks for the rule to be removed or limited; open with no reply at 04:55 UTC, the rule still in master. Lists refresh on their own schedule (EasyPrivacy's header: expires 4 days), so some players keep the rule for days after a fix.

- Not checkable: NordVPN's own list (not public), and DNS lists beyond AdGuard DNS and Peter Lowe.

## Fix

- `app/src/map/openMapTiles.ts`: `restyle` points the style's vector source at `twtiles://planet`; `basemap.ts` answers that protocol with `openMapTiles()`, which reads the TileJSON from the first route in `ROUTES` that gives tile addresses (`https://tiles.openfreemap.org/`, then `https://tiles.openfreemap.org//`) and puts the tile template on that route. A refused request, an error status, or an empty or unparseable body (NordVPN's 204) counts as blocked.
- `busRoads.roadTileTemplate` uses the same answer when the live source has no tiles yet, so bus roads, crossing prices (sent to the clock worker) and ferry water get the same template as the map.
- Unblocked players make the same requests as before, the TileJSON now through our protocol handler (one request a load); tiles stay plain https, fetched by MapLibre's worker.
- OpenFreeMap serves `//planet/...` byte for byte as `/planet/...` (same etag, x-ofm-debug "specific PBF planet"), but its CDN caches it under its own key (tiles MISS), so only blocked players use it. `/%70lanet` is served too; the double slash is the plainer of the two.
- Limits: it works against ABP-syntax matchers (uBlock, Brave, AdGuard), since `||host/planet` doesn't match `host//planet`. NordVPN's matcher can't be tested from here: if it merges double slashes, NordVPN players stay blocked until the list is fixed. A host-wide rule (`||tiles.openfreemap.org^`) would beat it too; that is what the proxy below is for.
- Ruled out: everyone on `//planet` (splits OpenFreeMap's cache for every player); waiting on upstream alone (stale lists for days); a fallback tile provider (none free and keyless in the OpenMapTiles schema the style and road readers need).
