# T-2840: what Map detail Low saves in memory

Agent reviewfix, 2026-11-09. Measured only; `map/lite.ts` is unchanged. Check: `checks/t2840-lite-memory.mjs`
(`TW_CORES=2 node trainworld/checks/t2840-lite-memory.mjs http://localhost:6177/ both 2`), raw runs in
`artifacts/trainworld/t2840/runs-both.json`.

## Method
- Map detail forced through the stored display setting (`lighterMap` "off" = High, "on" = Low), so Auto plays no part.
  Order High, Low, High, Low for each kind (2 runs each way), a fresh Chrome profile per run, 2 cores, one demand worker.
- Desktop: the real New York save (109 lines) imported, settled at the demand final, Chrome at 1400x900, device scale factor 2.
  Phone: emulated Pixel 7 (DPR 3), a new game, the first line (three stations, 2 km apart) built, settled.
- Then the camera to z12 (-73.98, 40.75), 7 s, z14 (-73.985, 40.758), 7 s, 3 s more; then memory read:
  OS private bytes (commit, `PrivatePageCount`) and working set (resident) of each Chrome process of the profile, by type;
  JS heap after a forced GC (CDP `Performance.getMetrics`); the demand workers' WASM (`memBytes`).
- Frame times: 4 s of a camera stepped each animation frame at z13, the gap between MapLibre `render` events, at 1x and at 4x CPU throttle.
- Visible style layers: High 41-45, Low 27-31.

Averages, High to Low:
- GPU process private: desktop 900 to 430 (-470, -52%), phone 311 to 204 (-107, -34%).
- Renderer private: desktop 2297 to 2251 (-46, inside the spread of 370 between Low runs), phone 856 to 907 (+51, noise).
- Everything of Chrome's, private bytes: desktop 3290 to 2782 (-508, -15%), phone 1258 to 1205 (-53, -4%).
- Everything of Chrome's, working set (resident): no real change. GPU process working set -13 desktop, -10 phone; renderer's moves with its noise.
- JS heap and WASM: the same.

## How far to trust it
- The saving is in the GPU process's committed (private) bytes, which is the framebuffer and tile textures: Low halves the
  canvas pixels at DPR 2 (ratio 1 instead of 2 is a quarter of the pixels) and draws fewer layers. Its resident size
  barely moves (about 10 MB), so what the GPU process actually holds in RAM is not shown to drop. Headless Chrome on this
  machine uses ANGLE/D3D11 with the blocklist ignored; on a phone the GPU memory is the same RAM as the page's, on a
  desktop it mostly sits in video memory, so the commit figure is an upper bound of what a phone would save.
- Renderer figures move by 200-400 MB between runs of the same setting on desktop (the real save's solve is not
  deterministic in what it keeps), which is more than any difference between High and Low. Phone renderer runs agree to about 30 MB.
- Frame times: at 1x all runs sit at the 60 Hz frame (16.6 ms) except one desktop Low run (20.9, likely a hitch). At 4x
  throttle Low's median is 0 to 2.5 ms better and its p90 better on the phone (19.7-26.5 ms against 30.8-33 ms); on
  desktop the p90s overlap (24.9 and 76.6 for Low, 50 and 75.9 for High).

## Reading
Low saves no resident memory that these runs can see. It saves committed GPU memory: about 100 MB on the phone setup
(4% of the browser's committed total), about 470 MB on a DPR 2 desktop (15%). Nothing in the renderer, the JS heap or the WASM changes.
