# T-4027 Geofabrik download URLs after the folder move

New `pipeline/geofabrik.py`: `url(extract, suffix=".osm.pbf")` resolves a working URL (HEAD 200, redirects followed) for an extract id.
Order: the URL in Geofabrik's `index-v1-nogeom.json` (cached a day in `data/work/geofabrik-index-urls.json`, stale copy if the fetch fails),
then old layout `<id>-latest.osm.pbf`, then folder layout `<id>/<name>-latest.osm.pbf`. If a -latest redirect lands on a 404 dated file
(today's, not yet published) it tries the previous 5 days' dated files in that folder (HEAD guesses, not a listing parse).
Raises RuntimeError listing each URL tried and its status.
`extract_id(url)` maps an index URL to today's id from either layout (drops `-latest.osm.pbf`, collapses a repeated last segment).

Callers changed: world_run.downloads (RuntimeError now counts as a retried failure), routes.download, osm_water.read_inland, japan_zones .poly, world_plan.geofabrik.
The `GEOFABRIK` URL templates in routes.py and world_run.py are gone. Ids and cache file names are unchanged. docs/world-run.md names no URL form.
