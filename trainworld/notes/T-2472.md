## 3. What a player downloads

How: headless Chrome, a fresh profile (empty cache), the production build on `http://localhost:8800/trainworld/`
at commit 8f9cb6af, `?new=1&demandWorkers=2` (2 workers is what an 8-thread player gets, `poolSize()` in
demandClient.ts), a new game in New York, then `map.jumpTo` Tokyo then London at zoom 11, then a 3-station
line in each (what a player does to get a city's demand). All requests including the workers' were
logged (Playwright `request.sizes()`); repeats of one URL and Range are counted once, as the immutable
caching on the published site would. 8800 sends everything uncompressed, so the "published" column
re-prices each file as the live site serves it: gzip -6 for the website's JS, CSS, WASM and sounds, the
`gz/` staging sizes for pack JSON, raw for `.bin` and terrain. Sizes of the 6 worker scripts were
logged as 0 (the browser reports no size for worker scripts), so I added their gzipped size from
`dist/assets` (1.36 MB) to the first load.

| Step | As 8800 serves it | As published | What is in it |
|---|---|---|---|
| First load, new game in New York | 37 MB | **21.8 MB** | bins 9.8 (`nyc.bin` 7.6 whole, `phl.bin` 0.4, the rest range reads), pack json 3.2 (`outlines.json` 2.6 gz of 9.5 raw), JS 4.3 (index 3.85 raw, workers 5.2 raw), WASM 1.2 (two files, 3.1 raw), rail overlay `regions.json` 1.56, basemap tiles 0.8, terrain 0.43, fonts 0.16, rail overlay tiles 0.13, css 0.06, sounds 0.06 |
| Pan to Tokyo (no line) | 7.9 MB | 7.7 MB | `tyo.bin` 6.6 whole file, basemap 0.8, overlay tiles 0.2, boundary 0.08 |
| First line in Tokyo | 25.3 MB | 17.0 MB | **one-time**: `market-drives.bin` 11.8 (raw) + `market-rows.json` 2.7 (gz of 11.0). Per city: bins 1.2, basemap 1.1, terrain 0.16 |
| Pan to London | 5.1 MB | 4.7 MB | `lon.bin` 3.6, basemap 0.8, tiles 0.2, boundaries 0.15 |
| First line in London | 3.2 MB | 2.2 MB | bins 0.65, market 0.37 (gz of 1.34), basemap 0.94, terrain 0.17 |
| Whole session | | about 53 MB | |

So a city costs 5 to 8 MB to look at and 1 to 2 MB more to build in, apart from the one-time 14.4 MB the
first line pulls in anywhere. The real save adds, at load, `market-drives.bin` 11.8, `market-rows` 2.7,
39 range reads of bins 3.8, six market packs 3.2 gz: 22.5 MB on top of the first load.
The `.bin` is the biggest line of each city and it does not compress on the wire today (section 6).

Caveats: gzip -6 estimates (GitHub Pages and R2 will differ a little); basemap tile bytes depend on where
the camera is; the rail overlay (`noritetsu/regions.json`, `us.pmtiles` etc.) came from 8800's
`/noritetsu/` here and from `data.anita.garden/noritetsu/` on the live site (realRoute.worker.ts), the same files.
A return visit pulls only what changed: pack files on R2 are `immutable` for a year; the site files carry
whatever cache headers GitHub Pages sends (not measured here).

## 4. The player's RAM

How: the same headless Chrome. Per process, Windows `WorkingSet64` and `PrivateMemorySize64` of every
`chrome.exe` whose command line holds my profile folder (what the Chrome task manager adds up), via
`procs.ps1`; the page's JS heap from `performance.memory` (with `--enable-precise-memory-info`). Dedicated
workers live inside the renderer processes, and `performance.memory` inside a worker reports nothing, so the
workers' share (WASM memory and their JS) is in the renderer totals, not split. The JS heap swings with
garbage collection (260 MB to 670 MB between two reads 20 s apart), so read it as a range. Two demand workers
unless stated. Scripts: `scratchpad/sizes/measure.mjs` and `mem.py`.

| Moment | Page JS heap | Renderer processes (3) | GPU process | All Chrome (private) |
|---|---|---|---|---|
| New game, New York, idle | 249 MB | 1.04 GB | 0.36 GB | **1.5 GB** |
| Same with 1 demand worker | 249 MB | 1.00 GB | 0.34 GB | 1.4 GB |
| Same with 3 demand workers | 253 MB | 1.16 GB | 0.36 GB | 1.6 GB |
| After a line in Tokyo | 564 MB | 2.07 GB | 0.38 GB | 2.5 GB |
| After a line in London too | 581 MB | 1.67 GB | 0.43 GB | 2.2 GB |
| Real save, demand final | 260 MB | 3.24 GB | 0.46 GB | **3.8 GB** |
| Real save, 20 s later | 669 MB | 3.22 GB | 0.44 GB | 3.8 GB |

Each demand worker is about 80 MB when idle. The real save starts 3 more demand workers (11 workers in
all, not 8) and the renderers go from 1.0 to 3.2 GB: the heap is not where the memory sits (260 to 670 MB),
the WASM memory and worker buffers are. A player on an 8 GB laptop with other tabs open would feel 3.8 GB.
The GPU process is 0.33 to 0.46 GB; the map's own texture memory is not separable from it.

## 5. Anything else

- **Browser storage**: after both runs, IndexedDB `anitabuilder` has one store, `saves`, empty (`?new=1`
  never writes a slot; the real save file is 75 KB). `localStorage` has 4 keys, 1.1 KB in all. No service
  worker, no Cache API. The demand cache (`demandCache.ts`) is keyed in memory.
- **Save files**: T-007-real-nyc.save 75 KB, T-125-northeast.save 75 KB, the China saves 22 to 23 KB.
- **git**: `.git` is 2.8 GB for the whole maps repo (packed 2.24 GB). Trainworld's share was not measured.
- **Build output growth**: 8800's `app/dist/assets` is 27.5 MB raw (7.5 MB gzipped), 20 files. Six worker scripts
  are 1.4 to 1.7 MB each and look like copies of shared code: `clock.worker` 1.67, `demand.worker` 1.52,
  `realRoute.worker` 1.46, `shade.worker` 1.44, `cacheWrite.worker` 1.09 MB (all raw).
- **Disk fullness**: C: is 96% full (42 GB free), so a 15 GB cleanup matters more than any one folder.

## 6. What could improve

Sizes are rough. "Player would notice" is about speed or memory they can feel.

### Download and R2

| Idea | Saves | Effort | Player notices |
|---|---|---|---|
| Compress `.bin` on the wire. gzip on 16 sampled bins gives 0.52 of the size (nyc 7.4 to 4.1 MB, `mic` 12.0 to 5.3). Readers that use Range requests (clock worker, walk grid) need the raw bytes, so either split each bin into a Range-read part and a whole-file part, or compress only the whole-file reads | R2 by about 1.0 GB per version; New York first load by about 3.4 MB, each city pan by 45% of its bin | medium to high (format split in the pipeline plus loaders) | yes on slow links: Tokyo pan 6.6 to about 3.6 MB |
| First line pulls 14.4 MB of worldwide data (`market-drives.bin` 11.8 raw / 6.8 gz, `market-rows.json` 2.7 gz). Load these only for the regions a line touches, or gzip the `.bin` | up to 14 MB of the first line's 17 | medium (shard by region; a rows file per region exists in principle) | yes: the first line waits on 14 MB |
| Keep two R2 versions, not all; delete older after a publish (COMMANDS in `notes/T-924.md`) | 2.9 GB per old version | low (rclone purge) | no |
| Worker bundles duplicate shared code (1.4 to 1.7 MB raw each, 5.2 MB for the three loaded at start): split the shared code into one cached chunk | about 1 MB gz on first load | medium | slightly |
| Fetch `outlines.json` (9.5 MB raw, 2.6 gz) only when the world view needs it, or tile it | 2.6 MB of the first load | medium | slightly |
