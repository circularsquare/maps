# T-3635 the row of dates in the top bar (feedback 1794744778-ef2051d1)

Fixed by clockdup, 2026-11-18. Changelog clockdup-1.

## What it was

Each item in the row was an old copy of the top bar's clock box (`.clock` in `Clock()`, ui/TopBar.tsx), stopped
at a past game time. The game dates in the screenshot are the 2021 calendar's Japanese holidays.

## Mechanism (reproduced with a simulated rewriter; the player's own trigger not identified)

The date sat in one span beside the holiday dot: `<span class="date"><HolidayDot/>{date text}</span>`. The dot
is none, an `<i>` or a `<button>`, so on a holiday turn Preact inserts the dot before the date's text node. When
something outside the game has moved that text node under another element (a `<font>` wrapper),
`insertBefore` throws NotFoundError partway through the clock's diff. Preact's error recovery then forgets the
clock's `<div>`: the next render mounts a new `.clock` and the old one stays in the bar, frozen. Each later
dot change adds one more, newest first, which is the order in the screenshot.

Repro (headless Chrome, Osaka, ja, a line built so Japanese holidays count, clock run across each midnight;
`scratchpad/clockdup/translator.js` + `multi.js`, scratch only): a rewriter that wraps each top bar text node in
`<font><font>` and keeps the original node inside, re-wrapping new text through a MutationObserver.

| | into Feb 11 | Feb 23 | Apr 29 | Golden Week button | errors |
|---|---|---|---|---|---|
| before | 2 clocks | 3 | 4 | 5 | 4 NotFoundError |
| after | 1 | 1 | 1 | 1 | 0 |

A rewriter that replaces the text node with new `<font>` nodes (what Google Translate does, per Martijn Hols's
write-up "Everything about Google Translate crashing React") left one clock before the fix, since Preact 11
skips a detached reference node, but froze the shown time and date for good (23:20 for 26 game hours). After the
fix the time and date stay right in both modes.

Any throw in the clock's diff has the same effect, so the fix also removes stale copies whatever threw.

Not settled: which extension the player had. Real Google Translate replaces text nodes, which did not duplicate
the clock here; loading the real Google Translate widget in the test browser was refused (it sends page text to
Google), so that path is untested. The player's stale clocks read 02:00 (one 01:00) on the holiday, where the
simulated ones read 00:00 on the day before; the 02:00 is unexplained (Japan's zones are all UTC+9, so the dot
turns at midnight in Kansai). The fix does not depend on either.

## Fix

- After each render the clock removes any other `.clock` directly in the bar (a layout effect on its own
  root), so whatever makes Preact remount it, a stale copy lasts one game minute at most. Checked by putting two
  copies in the bar by hand: 3 before the next minute, 1 after, the live one kept.
- The clock's time and date are elements whose text the game sets itself each render (`useOwnText`), with no
  Preact text node inside: nothing a rewriter does to the text can freeze it or break the diff.
- The dot has its own slot (`span.dot-slot`, `display: contents`), so it is only ever inserted into an empty
  element.
- `translate="no"` moved from the clock to the whole `#topbar` (city name, split share, cash, clock, speed):
  Chrome's own page translation now skips the bar, so the cash and share can't freeze either. The cost: a
  player translating the page into a language the game doesn't offer sees the bar's few words ("Sandbox", the
  real-speed labels, "World") untranslated. Untested against real Chrome translation.

The other top bar text (city name, share, cash, the 16x button, the slider's figure, the save notice) is each
the only child of its element, with no changing sibling, so it can't duplicate anything; under a rewriter that
ignores translate="no" it could only stop updating.

Hovers (data-tip) are drawn elsewhere and still translate.
