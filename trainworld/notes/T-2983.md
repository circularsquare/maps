# T-2983 Bus stop Auto/Manual switch (agent e1, 2026-11-16)

Not changed; measured only. checks/t2983-bus-switch.mjs (in tree tw/e1) builds a 5-stop bus line on the real save, waits for demand, and switches busSpacing 600 / 0 / busHand six times, printing the worker's own timings.

On a quiet machine each switch is about 90-110 ms in the worker: apply 5-10, state 13, buffers (networkFromState, cached per line) 30-35, post 5, trips 8-20, boarding hour 20-22. The first switch of the session was not slower (99 ms). Under load (other agents' cargo and checks) the same switches read 200-440 ms, and the buffer step alone 110-180 ms, so the 0.2-0.5 s and 1.4-2.5 s in the task were probably a loaded machine or a much longer bus line.

What is left would be skipping the buffer rebuild when only a bus line's stops change, but the line strokes carry each segment's stop-to-stop stretch (`stretchOf` in network.ts), so a stop change does change them; the saving is at most the 30 ms. Not worth a risky change. Suggest closing, or reopening with a Japan-size bus case that really reads over 0.2 s on a quiet machine.
