## Settings: which ones matter before a game loads

From `ui/SettingsTab.tsx`, top to bottom. "Before" means it changes loading, memory, language or what gets
calculated, so a player needs it before picking a game.

| Setting | Before? | Why |
|---|---|---|
| Help, Account, Community icons | no | Account and Community are already on the start menu |
| Language | **yes** | already on the start menu and on the New game sheet (T-2753); keep it there |
| Demand bubbles (Day, Purpose, Size, Opacity, Detail, Colors), Station circles | no | how figures are drawn |
| Show (trains, names, capacity, crowded, flat, ramps, side by side, labels, terrain), Show levels, Buses and ferries | no | drawing only |
| Game (side, mode, tutorial, buses obey one-way streets) | no | belong to a loaded game |
| Real network, Stations up close (faces, sound, volume) | no | drawing and sound |
| Map (flat/globe, drawn/satellite), Line width, Base map, Rotate, Zoom buttons | no | drawing only |
| Theme (light/dark, colour) | optional | cosmetic, but it also colours the start menu |
| Panel and text size | **yes** | scales the start menu card itself; a player with too-small text needs it there |
| US units, Currency | no | in-game figures |
| Use more cores | **yes** | read only at the next load: faster solve, more memory (up to 5 workers at about 400 MB each) |
| Run in background, Recalculate trips while paused | no | the running clock |
| Calculate intercity trips | **yes** | today phones only. Off, a solving worker uses about 174 MB less on New York's real save and loses 0.35% of rail trips; the load is not faster (263 s with, 279 s without, notes/T-2867.md) |
| Memory row | info | not a setting |
| Default bullet shapes | no | drawing |
| Submit feedback, Discord, Ko-fi, About, Changelog | feedback **yes** | About and Changelog are on the menu already |

**Pick (4 plus feedback):** Language (stays where it is), Calculate intercity trips, Use more cores, Panel and text
size, and Submit feedback. Theme only if she wants a fifth.

Two calls the intercity row needs from her:
- On a computer there is no intercity setting today: it is always on, except for one tab after "Load without inter-city
  trips" or "Play without intercity trips". Showing it on the landing page makes it a real setting on every device
  (it would then also show in Settings on a computer).
- Every pick from the menu turns intercity trips back on (`keepMarket`, her rule of 2026-11-10: "a game opened from the
  start menu has them again"). With a checkbox on the menu, the checkbox would decide that instead. "Load without
  inter-city trips" in the memory warning would just untick it.
- Wording to fix along the way: the hover "if enabled, game may crash on phones with <4gb of RAM" is about phones
  only, and the strings spell it both "intercity" and "inter-city".

## Feedback without a game

- **Mid-load, feedback is already reachable.** The loading card lets clicks through to the dock. Checked at
  "Calculating trips" (5%, about 50 s left) on a 1400 px window and on a 390 px phone with touch: Settings tab, then
  Submit feedback at the very bottom of the longest tab, and the form opens. So it can be reached, but it is hard to
  find: the last control in the longest tab, and nothing on the loading card points to it.
- **Not reachable on the failure screen.** "Failed to load :( Try reloading the page." covers the page; the dock's
  Submit feedback shows faintly behind it and takes no click. The only ways out are Try again, Back to start and
  Play without demand.
- **Not reachable after a crash or a reload.** The reload goes to the start menu, which has no feedback today. The
  form only exists inside the Settings tab, so the start menu and the failure screen can't open it until it is
  mounted on its own, the way the account panels are (`startAccountUi`).
- **Bug found on the way:** after a load that died (the iOS out-of-memory reload, `tw-load-started` left set), the
  start menu draws over the "Ran out of memory. Close other tabs and try again." screen, and the text sits unreadable
  under the logo (scratch shot `died.png`). This needs its own task.

**What a report sent from the landing page would carry:** version, browser, device memory, language, graphics,
currency, and `state`, which before any game reads only "page open 0 min / clock: nothing unanswered; trips none
yet; status loading" (the demand pool has not started). It loses:
- the last failure's text (`loadFailure` is held in the page, so a reload clears it);
- which game was loading, how far it got (stage, percent, time left) and whether it ended. The died-load flag is
  read and cleared at startup, and `pagehide` clears it on a deliberate reload, so a player who gave up at 68%
  leaves no trace.

Proposal: keep a small "last load" record in browser storage (game name, stations, cities, stage, percent, started
at, ended or not, failure text), updated as the bar moves. A landing report sends it, along with the saved games'
count and the biggest one's stations and cities. For her Osaka case, that would say "Osaka, N stations, stuck at
Calculating trips 68% for 9 min, never ended".

## Three versions

- **A: gear in the card's top row.** A gear icon between the language and the account button opens a small panel:
  intercity, more cores, panel size, and Submit feedback at its foot. It sits in the same place on the New game
  sheet's title row. It is the smallest change, but feedback takes two clicks behind an icon. The game has no
  feedback icon, so a stuck player has to guess that the gear holds it. On a phone the panel covers the save card.
- **B: Settings and Submit feedback row in the card.** Under the saved games (under Start on the New game sheet)
  are two text buttons, Settings and Submit feedback. Settings opens the three rows in place under them. Feedback
  is one click and in words, and the card scrolls on a phone as it does now. The card grows by one row, plus three
  more while Settings is open.
- **C: page footer line.** Beside "build · About this game": Submit feedback, the language select (moved out of the
  card) and the two checkboxes, always visible, with no panel. The card stays as it is. Panel size does not fit.
  On a phone the line wraps under the update row and is mostly covered by it, and 12 px muted text is easy to miss.

**Recommendation: B.** It has feedback in words where a returning player looks, works the same on the menu and on
the New game sheet, and fits a phone. Whichever version wins, also put the same Submit feedback button on the
failure screen beside Try again, since that screen is where a failed load leaves the player.
