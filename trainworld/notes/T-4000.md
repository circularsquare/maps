# T-4000: removing single track refused with "No way back from this station on one-way track"

Player report 1795275871-c41f9b5f (11-21, v0.4.5, ja): removing single track sometimes shows
"この駅から一方通行の線路では戻れません" (`issues.noWayBack`) and the removal can't be done.

## Cause

`Op::DeleteEdge` (`TrackWorld::apply_raw`, sim/src/track/world.rs) reroutes every line whose path
used the removed piece by `Network::route`, a search for the outward path only. It took any path that
did not add a turn back. The reroute sets the line (`set_line`), so the line goes into the edit's
`touch.lines`, and `TrackWorld::check` runs `check_line` on it as if the player had edited the line.
Where the only other way between the stops is one-way track, the outward reroute exists but has no
way back, so `check_line` says `NoWayBack` and the whole removal is refused. With no reroute at all
the line would simply have been left broken (its path over removed track is skipped by the check),
which is the rule for removed track. `TrackApi::pieces_ops` (removing a station a line stops at) had
the same unchecked reroute.

## Fix

`Network::route_runs(l, stops, path)` (net/paths.rs): `check_route` with the path's own `runs_once`.
Both removal reroutes (DeleteEdge in world.rs, the station users in wasm/links.rs `pieces_ops`) take
a path only when it passes; otherwise the line keeps its old path and is left broken, as before
T-3094 brought one-way track. This covers the other `check_line` refusals a reroute could hit
(one-track stops, tram track) too. `way_reroutes` and `flip_right_hand` already filter on a way back
and were left alone. docs/track-and-service.md "Lines" says so.

Not covered: a removed station's line whose stops lose it with no reroute, keeping its old intact path,
is still checked (pre-existing; not met here).
