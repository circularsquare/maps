# T-3812 schematic zoom-out cap and drawing indicator

Agent schemzoom, 2026-11-19, tree `.tw-trees/schemzoom`. All in `diagram/view.ts`.

**Cap**: `minScale()` = min(0.1 x view width / box width, 0.1 x view height / box height) of the shown drawing's box
(`d.box`, every region drawn so far, or the city choice's drawing). So at the cap the larger of the box's two sides is
1/10 of the view's matching side: a square network covers 1% of the view, a thin one still shows its length. Applied in
the wheel handler (never pushes a view already past it) and in `place()` and `compose()` (`clampScale`), so it rises
and falls with what is drawn. It is always below the fit scale, so the camera can fit everything.

**Indicator**: `drawingShare()` keeps `diagramProgress` up while a plan region has no layout and no older drawing
covering its stations (so an edit's re-layout shows none), value = (regions done + current layout's share) / regions.
Same string ("Drawing diagram", `diagramButton.calculating`); no new strings.

**Proof** (Vite 6199, real NYC save plus a 4-station line in Athens, camera over Athens, scratch `scratchpad/schemzoom`):
indicator rises 0.5 -> 0.95 -> gone over 22 s while NYC lays out (it used to go at the first region).
Zoom out 40 notches with only Athens drawn: line width 10.0% of view (flat network, so the width rule). With both
regions: box 8.4% x 10.0% of the view. NYC alone: 8.2% x 10.0%. t2163-diagram-clicks, t2888-diagram-width,
t3420-visibility pass. Shots: artifacts/trainworld/t3812-schemzoom.png (indicator while NYC draws),
t3812-aegean-limit.png, t3812-both-limit.png, t3812-ny-limit.png. Typecheck clean.
