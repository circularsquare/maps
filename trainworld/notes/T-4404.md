# T-4404: Gemini's git reads can't start a program or write a file

Cause: the allow rule takes any options after git status|diff|log|show|blame|ls-files|grep. The old deny line covered
only " --output| --no-index| -O| --open-files-in-pager| --ext-diff", missing clusters (-nOless), abbreviations
(--open, --ext, --outp: git takes any unique prefix), quotes PowerShell joins (--out"put", "-O"), --textconv and the
options before the subcommand.

Done (tools/agy_session.py git_option_denies, part of backstop_rules, so gemini_audit gets it too):
- Long options refused with every prefix git accepts, quotes allowed between letters: --output, --open-files-in-pager,
  --ext-diff, --textconv, --no-index, --exec-path, --config-env, --git-dir, --work-tree, --namespace, --paginate,
  --super-prefix, --attr-source. --no-ext-diff, --no-textconv and --output-indicator-* stay allowed.
- Short -O alone or inside a cluster (-nO, -inOless, "-O", -"O"less).
- Any option between git and the subcommand (-c, -C, -p...). The allow rule already needs the subcommand right after
  git; the deny keeps that true if it loosens.
- Known over-refusals: a pickaxe or -G text starting a cluster with O (-SOLD), a quoted search text holding " --output".
  The agent rewords the call.
- Not controllable: git diff runs a configured external driver or textconv by default, but config is only in .git/config
  and global config, which the agent cannot write (git config denied, .git protected).

Tests: scratchpad gitrules/test_rules.py, re.fullmatch on 21 good (T-4261 quoted greps, play.mjs calls, -C3, -c count,
--no-ext-diff, --output-indicator-new) and 37 bad strings: all as expected.
Trial gitrules-trial2 (artifacts/trainworld/gemini/agents/gitrules-trial2-20261127-102634): git grep -e -e ran;
git grep -Oless, git diff --output=..., git -c core.pager=x log refused ("matches user-configured deny rule").
(Trial 1 failed on a core claim at the cap, nothing ran.)
