# T-4183 play.mjs on a production build

Cause: none of the hooks are stripped. window.tw and window.twDemand are set on ?debug=1 in every build (not under import.meta.env.DEV), and window.tw.client.lastLoad is set in production too. play.mjs start opened http://localhost:<port>/ always; 8800 serves its front page there and the game under /trainworld/, so no game loaded and the ready wait timed out. (A new game's lastLoad is null by design; only a file load sets from:'file'.)

Fix (checks/play.mjs): start takes --base <folder> and defaults it to trainworld on :8800. Git Bash rewrites a leading-slash argument (/trainworld/) into C:/Program Files/Git/trainworld/, which is why the folder is given without slashes. A failed start now logs each page's hook state to the play log. Cost to players: none, no app change.

Checked on 8800 (production, light): start T-007-real-nyc.save loaded in 19 s; counts 109 lines, 1756 stations, 4498.6 km; wait.final gave 12,672,465 rail trips/day and 899,564,070 total, same as the batch check's figures. Slow starts seen on the way were the core ledger queue (waiting for 2 cores), not the game.
