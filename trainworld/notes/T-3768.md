# T-3768: settings spacing from one rule, and a standing check for touching controls

Anita, 2026-11-19: "in settings the trains run on left/right and switchto sandbox button are touching, they should
have margin (we should maybe have a programmatic way of laying this stuff out so i dont have to keep pointing out
minor settings layout issues)".

## The cause

The settings tab was a block of rows each bringing its own margin: `.slider` 8 px on top, `.checks` 2 px, `.game-mode`
none, `.stack` none, plus one-off fixes (`.game-mode + .game-mode`, `.level-show + .checks`, `.donate` 12 px,
`.settings-top` 8 px under, `.lang-row` 4 px under, `.pickers` 8 px). A row whose class had no top margin sat flush
against the row above: the running side (`.slider`) then the sandbox row (`.game-mode`) at 0 px; the Tutorial row
then the bind-stations check at 2 px; the Real world network buttons then Show stations at 2 px.

## The rule (app/src/ui/style.css, after `.stack`)

`.settings-list`, its `[data-search-group]` and the start menu's `.start-settings` are a flex column with
`gap: var(--row-gap)` (8 px); their children's margins are zeroed; a heading is `calc(14px - gap)` above and
`calc(4px - gap)` below (14 px above, 4 px to its first row, as most sections had); a bare `.group` or `.stepper`
child keeps its own width (`align-self: flex-start`); the superholiday day row keeps 2 px under the day row. Flex
gaps skip `display: none` rows, so the settings search needs nothing new (tried "sandbox", "stations", "language":
the first heading sits under the box, the rows evenly spaced). The one-off margins above are deleted. A `<dialog>`
in the list (the running side's list of places, drawn inline by SideRow) is left out of the margin reset, so it
stays centred (probed: 394 px above and below at 1400x900). Rule written into docs/ui-panels.md "Look".

  Advanced (0 px), History / 1d (0 px), "...in New York" / its $0 scale (2.3 px); the line panel's Detailed
  schedule icon / Trains button (2.9 px).

  the Station type buttons under it, 1.8 px. Rows holding a control are 28 px (T-1802) and those buttons are 28 px,
  so the stepper's 24 px buttons leave 2 px. Any two stacked rows of full-height buttons in a `.rows` list touch the
  same way; a row gap there changes the T-1802 rule, a design call.

## The check: checks/t3768-panel-gaps.mjs

A new New York game in normal mode (sandbox hides the switch button) with one 3-stop line built by the edit API, at
1400x900 and at 390x844 (mobile, touch). Panels: Settings in a game, Settings as before a game loads (money state
set to null), Build, Lines, Stations, Finances, Cities tabs, the line and station panels, Advanced fares, the start
menu's settings. It collects visible controls (border box; a bare icon button by its icon and text) and lines of
text (the font size tall, leading left out, cut by any clipping box such as an ellipsis) and fails a pair closer
than 3 px on both axes or overlapping, unless they share a `.group`, `.stepper`, `.sort-head` or `.shape-grid`, or
are text in one block. `--gaps` prints the settings row gaps above; `--panels <dir>` saves each panel and a crop
around each pair; `--shot <tag>` the settings tab. About 5 minutes for both widths.
