# T-3928 Longer trips with no route are skipped uncounted

## What changed

- `pass_window` (intercity/pass.rs): where a destination has no strategy (`Columns::strategy` is `None`) it adds the
  trips taken there (`all`'s column, which holds the longer trips, commutes and outings, plus the turned-round
  `mall` column in a window) to a per-pass `dropped`, calls `kernel::note_dropped`, then skips as before. The total
  is `Pass.loads.dropped`.
- `IntercityApi::dropped(q)` (exports.rs, wasm-bound): the period's average over crowding rounds (the
  `avg.dropped` line beside the other loads' averaging), 0 if no solve. Windowed passes merged in logsum.rs already
  carried `Loads::dropped`. Not in `summary()` (editrestart owns the worker); an app caller adds the call itself.
- `DestAssign::taken()` accessor (kernel/assign.rs), since the field is private to the kernel.
- Test builds: the same gate as T-3923 (`KNOWN_DROPS`, `DROP_LOG`), so every intercity test fails on a skip.
  Tests: `no_intercity_trips_are_skipped`, `intercity_trips_towards_an_unsearched_station_are_counted`
  (intercity/tests.rs).

## Results

- No fixture skips anything on master: nothing needed a known-case mark. The full suites pass with the panic on.
- Bit-identical: a scratch hash over `pass_searched` and `pass_on` (loads, c_loads, st, xfer, pair_rail, rail
  figures) plus `seg`, `board`, `alight`, `entries` on the small intercity fixture and the Tokyo/Gunma fixture was
  49e99944417d5253 with the changes stashed and 49e99944417d5253 with them.
- The skip is nearly unreachable by construction: a destination whose search did not run has infinite route costs
  (`Skims::r`), so the pass never takes trips towards it. It fires only where costs are known and the strategy
  is not (never with a full table or a fresh search). The forced test lends a one-station table the full table's
  route costs to make it happen. So a nonzero `dropped` in a real game would mean a real inconsistency.

## trip_real_network (ignored test, trip/tests.rs)

Cause: T-3888 (98250f77) made the walk tier ride where the walking rule refuses every station pair, so a destination
can have rail riders with `pc.why != RAIL_OFFERED`. The test's check loop skipped those destinations, so its sum
(1657.389) fell short of the solve's rail_home (1662.064). Fix: the loop skips on `pc.r <= 0.0` instead. The check
now gives 1662.076 against 1662.064 (7.3e-6); the other two origins are within 6.5e-5 and 3.9e-5, under the
unchanged 1e-4 limit. The test's tolerance was fine; the expected value was not changed.
