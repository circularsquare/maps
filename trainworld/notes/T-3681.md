# T-3681 Search box in settings

Anita, 2026-11-18: "would be nice to add a search setting to settings. so people can type a string and find
matches, or alias matches. people having trouble with finding certain settings frequently."

## How it works

`ui/SettingsSearch.tsx`. The box sits above the tab's body (`.settings-list` in `SettingsTab.tsx`) and filters the
rows already drawn, so each control keeps working in place; nothing is copied.

- Rows: each child of the body, except `.checks`, `.stack`, `.shape-grid` and `[data-search-group]`, whose children
  are the rows. Sections run from one `.h` to the next. Rows before the first heading (Help/account icons, Language)
  and the foot (`data-search-alone`: feedback, donate, about) belong to no section.
- A row matches when every typed word is a substring of its heading's text plus its own shown text (text nodes,
  `aria-label`s of icon buttons and selects, option names) plus the keywords of any label inside it. Normalised with
  `game/search.ts` `normalise` after NFKC (case, accents, full-width letters, punctuation).
- Keywords: `ALIASES` maps a label key to a keyword message. A row gets them when one of its elements' whole text
  equals that label in the current language; a heading's keywords count for its whole section. The English keyword
  list and the label's English are always searched too, so "language" or "satellite" work in any language.
  `["settingsTab.volume", "settingsTab.sound"]` reuses a label as a keyword (Sound finds Volume).
- `data-search-follow` rows (the holiday days under Day, the ramp's colours under Colors) show with the row before.
- Hidden rows carry `data-search-out` (CSS `display: none !important`; an attribute because Preact rewrites
  `class` and `.slider`'s `display: flex` beats `[hidden]`). The first shown row gets `data-search-first`
  (no top margin), so it sits 8 px under the box like the tab's first row.
- A MutationObserver on the body re-filters while a query is up (Memory's 2 s figure, rows that appear, a language
  change). Esc in the box clears it. The query is component state, so leaving the tab clears it.

26 keyword entries (24 keyword lists; Sound also finds Volume; the account list also on Sign in), translated into all 12 languages (pass 1 only, by me with
`l10n.mjs batch/merge/lint`; Chinese and Japanese lists use 、). No back-translation or review pass: the lists are
never shown, and the English list is searched in every language anyway.

## Checks (scratch, `scratchpad/setsearch/probe1-4.js` through `play.mjs do`)

- satellite -> Map section (Map/Satellite); dark -> Theme; miles -> Units (US units, Currency); language -> the
  Language row; size -> both Size sliders and Panel and text size; sound -> Sound and Volume; feedback -> Submit
  feedback with no heading above; zzqx -> "No settings match".
- Terrain clicked while filtered flips and the filter stays.
- Typing "b" in the box leaves the Build tab shut; Esc clears.
- Body innerHTML identical before a search and after clearing it (the one run that differed, right after a reload,
  differed only in Memory's figure ticking 1.3 -> 1.4 GB); no `data-search-*` left.
- A `<dialog>` in the body (the side switch's list of places, SideSwitch's `SiteList`) is skipped, never hidden.
  "Sign in" (the signed-out account button) gets the account keywords too; untested, accounts are off in dev.
- Placeholder width at 390 px (room 111 px): every language fits; fr, pt, ca, de and ru use the bare word for
  "Search" (Rechercher, Buscar, Cerca, Suchen, Поиск), as Community's search box does, since the longer forms
  would clip.
- Japanese: placeholder 設定を検索; "language", "satellite", 航空写真, 衛星, ダーク, ｍｉｌｅｓ all find their rows;
  switching language while "satellite" is typed re-filters in the new language.
- Box geometry: 9 px under the pane's top, 7-8 px to the first row, same with and without a query.
