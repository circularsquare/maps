# T-4341 Station building tool on phones

A player, via Anita 11-25 ("this complaint seems somewhat priority"): "the station building tool is broken on
mobile: cannot drag to adjust building size; long-pressing a corner only deletes one single corner and no further
corner editing is possible. Worse still, station buildings cannot be demolished even after deleting all tracks and
platforms connected to them."

Agent bldgmobile, tree `.tw-trees/bldgmobile`, 2026-11-25.

## Causes (from the code)

1. **No drag by finger.** `map/buildingDraw.ts` took handle drags from mouse events only, and its `onDown` returned
   on touch. A finger's drag makes pointer and touch events and no mouse events, so MapLibre panned the map. The bus
   and ferry tools already had a pointer-event path for fingers (T-1517); this tool never got one.
2. **One corner deleted, then nothing.** The delete came from Android Chrome's own long press (its `contextmenu`,
   which the tool reads as a right click); iOS sends none, so iPhones could not delete at all. The offered outline has
   4 corners and the floor is 3, so exactly one delete is allowed, refused silently after that (the reason is only in
   the hover tag, which touch hides), and with drag broken no edit was left. The long press leaves no stuck state in
   the tool: the browser follows it with mousedown, mouseup and click at the spot, which a closed outline ignores.
   A cousin found in the run: the touch bar sits beside the last corner, so after a delete it jumped onto another
   corner and swallowed the next drag there.
3. **No way to the Remove button.** Nothing refuses the removal (the sim's `remove_building` only refuses a missing
   id; the delete tool on an empty floor picks the building and removes it, mouse and touch, shown in the run). But
   the building's Remove building lives only in the panel of a station inside it, and a click or tap on an empty
   floor selected nothing (`pick.ts` turns a floor into its first member's complex; none, null). Once its last
   station went, the panel route was gone, on desktop too.

## Fixes

- `buildingDraw.ts`: a finger on a handle of the closed outline (18 px reach for a corner, 14 for an edge's middle)
  turns the map's drag pan off before MapLibre's touchstart and drags as the mouse does (8 px slop); held 500 ms
  still on a corner it deletes it, and at 3 corners says "A station building has 3 to 24 corners." as a notice. A
  second finger cancels the drag (pinch). Android's contextmenu is ignored on touch, as in the bus tool. The touch bar
  sits above a closed outline (centred, 18 px over its top corner); while drawing by hand it stays by the last corner.
- `map/touch.ts` holds the finger constants (`TOUCH_HANDLE_PX`, `TOUCH_SLOP_PX`, `LONG_PRESS_MS`); the bus and
  ferry tools import them instead of their own copies (same values).
- A click or tap on an empty building's floor with the select tool selects it (`{ kind: "building", id }`, set in
  `main.ts` `selectAt` where `pick()` found nothing; `pick()` itself is unchanged, so hovers, the cursor and the
  build tools are as before). The panel (`BuildingInspector`) shows the station panel's building section alone: name,
  Area, Edit outline, Remove building. Removing it clears that selection (`remove.ts` `selected`).
- Desktop: the mouse path is unchanged; the one desktop change is the click on an empty floor. Undo and saves are
  untouched (building edits stay outside the undo history, no save change).

## Run (emulated phone, 412 x 860, touch, new New York game, a 3-station line)

| Step | Result |
|---|---|
| Offer opened from the upgrade row | closed, 4 corners; touch bar over 0 handles |
| Corner dragged 40 px | moved 39 px, map still |
| Edge middle dragged 30 px | 5 corners, map still |
| Corner held | 4 corners, map still, bar over 0 handles |
| Each of the 4 corners dragged 18 px after the hold | 18, 18, 18, 18 px |
| Held to 3, then held at 3 | 3 corners; notice "A station building has 3 to 24 corners." |
| One-finger drag off the outline | the map pans |
| Built (bar's tick), then every line, track and station removed | 1 building left, empty |
| Tap on its floor | selection building 0; panel "Station building, Area 11,300 m², Edit outline, Remove building" |
| Remove building, Remove | 0 buildings, selection cleared, "Removed the station building." |

Before the touch bar change, the same run's drag after the hold moved 0 px: the bar covered that corner.

## Strings

None new. Reused: "A station building has 3 to 24 corners." (the refusal's text) now also a notice when a finger holds
a corner of a 3-corner outline; the building section's "Station building", "Area", "Edit outline" and "Remove
building" now also open alone for an empty building.

Changelog: bldgmobile-1, track, fix: "fixed dragging station building corners on phones; clicking an empty building
opens it to remove".

## Left

- A hold while drawing by hand no longer takes back the last corner on Android (it never did on iOS); the touch bar's
  back button does.
- A selected empty building has no outline drawn on the map (`buildingFloors.drawSelected` goes by member stations),
  and the cursor over an empty floor stays the plain one. Small; not filed.
