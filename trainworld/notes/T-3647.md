# T-3647: tram lines on one-way stops broke in 0.4 (agent tramoneway, 2026-11-18)

Status: fixed in `.tw-trees/tramoneway` (branch tw/tramoneway), not committed, waiting for a checker.

## Cause

Not the T-3565/T-3605 routing. T-3386 (landed 2026-11-16, first published in 0.4.0) changed how single track takes
its way from its joins: before it, **any station on a run of single track made the run two-way**; since, a station
says nothing and the run is one way where its joins say so. T-3386's own note said "saves with a station on such a
run will change way on load". A 0.3.5 game where kerbside tram stops sit on single track joined to a double's tracks
(a street split into two singles around a stop pair, a balloon loop off a double stem, a stub branch) loads in 0.4
with those pieces one way. Lines built on them in 0.3.5, which ran both ways there, then:

- end at a stop on now one-way track: the train can't turn there, so the way back runs on to the next place it can
  turn (a track end, T-3595) and comes back: the long detour (his third picture; our A5: 386 s -> 638 s);
- pass a one-way stop with no track for the other way beside it: routed through it both ways (the "forced both ways";
  expected from the routing rule, not reproduced in the scene, below);
- run up a stub branch with its stop short of the end: the whole branch takes the one way out of its join, no train
  can enter, and the line is broken, "Track this line ran on is gone" (our E2, E4);
- and **nothing the player does clears it**: deleting the stop doesn't restore the old way (stations no longer vote),
  and the track panel's "Run trains one way" switch, the hand repair, is refused with "{line} has no other way" on
  **every piece in the game** while any line is broken (`oneway_plan` pulls in every `back_lines` line and refused
  for one that had no way before the edit either).

What 0.3.5 itself did with explicitly one-way legs (the player's switch): lines through them both ways were refused
there too, so his layout is consistent with inferred legs (not shown from his save).

## Fixes (no routing rule changed)

1. `oneway.rs` `oneway_plan`: a line already broken never refuses the switch; it runs again if the edit gives it a way.
2. `lanes.rs` `derive_ways`: a run with a bare end and a station anywhere on it runs both ways (a terminus branch).
   T-3386 kept that only for a station at the very end, so a stop short of the end (a tail track) made a branch no
   train could enter or leave. Split legs joined at both ends keep their way through stations (T-3386 unchanged).
   `t3386_a_station_inside_the_run_keeps_its_way` now uses split legs; checks/t3379-single-fixes.mjs expects the
   bare-ended branch two-way.
3. Old saves: `TrackApi::set_load_level` (the header's `level`, passed by `loadGame` for a player's game, not a real
   network start) before `load`; at level <= 18 (`save::OLD_STATION_WAYS`; 0.3.5 wrote 18, 0.4.0 wrote 21)
   `Network::pin_station_runs` pins every single-track run that has a station on it and now takes a way by its joins
   to both ways (oneway 3, what the panel's switch stores), before the load's straightening and line checks. Pins are
   saved, so later loads keep them. The track panel then offers "Use automatic way" on those pieces.

A save already re-saved in 0.4 carries no trace of its old ways (inferred ways are not saved), so fix 3 can't reach
it; fixes 1 and 2 still help it (stub branches run again by themselves; the switch works).

## Calls for Anita

- Two of the fixes change what was decided, so they are hers to keep or drop:
  - the terminus-branch rule reverses what T-3386's own test and checks/t3379 asserted (a branch to a bare end with
    a station short of the end ran one way). I can't see a layout that one way helps: no train can use such a branch;
  - the old-save pinning puts lines back on shared two-way single track (A1, A2 go back from 534 s to 561 s planned,
    and the flat-junction marks where the pinned legs meet the double come back). It is a small migration, against
    "no real migration effort" for saves, made because this is a player's save.
- A line ending at a kerbside stop on truly one-way track (built in 0.4, or after "Use automatic way") still goes on
  to the next place it can turn. Options: (a) leave it (real trams need a loop there); (b) let a line's end stop on
  one-way track be served by the end before it with the train turning at the last stop it can (changes what the stop
  list means); (c) offer the switch in the line panel's warning. I'd keep (a) and make the warning say why.
- "Track this line ran on is gone" is also shown for track that is there but runs the other way; a separate string
  ("Track this line runs on goes the other way") would have told him what to switch.
- Untouched, seen on the way: turning "Run trains one way" off asks "Run trains one way on this track?" with a "Run
  one way" button when lines change (the question reads as if turning it on).
