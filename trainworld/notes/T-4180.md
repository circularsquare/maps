# T-4180 agent-tree.mjs finish lost work left in an unfinished merge

Cause: the tree had MERGE_HEAD. landTree committed it as "work in progress" (a merge commit), `git rebase` drops merge commits, then `reset --soft` to the target left nothing.

Fix (checks/agent-tree.mjs, top comment updated):
- `inProgress(dir)`: refuses (land, finish, and both dry runs, before anything changes) when MERGE_HEAD, CHERRY_PICK_HEAD, REVERT_HEAD, rebase-merge or rebase-apply exists. Message says to finish or abort it there.
- Committed merges (an agent merged master into its tree): handled, not refused. landTree squashes the branch to its net diff against the merge base (`reset --soft <merge-base>` + commit) before the rebase. Chosen over refusing because merging master into a tree is a normal thing to do, and the merge base after such a merge is master's merged tip, so the net diff is only the agent's work. Dry runs report the count.

Tested on scratch trees (from HEAD~3) landing into a throwaway tw/ branch: in-progress merge refused by land, finish --dry-run and land --dry-run; committed merge landed as one commit with only the agent's file; plain tree landed unchanged. Trees and branches removed afterwards. Never landed on master.
