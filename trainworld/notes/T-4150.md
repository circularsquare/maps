# T-4150 The page takes an edit's state at the cost of what changed (agent pageedit, 2026-11-24)

**For Anita.** After every edit the page takes the worker's new state, and about twenty things on it (the money and
points figures, the bus layer, the loose-end markers, the station labels and more) each went through the whole map
again. On your Asia save that was 104-117 ms of a station's wait, plus 45-110 ms of the browser cleaning up after them.
Now most of them go through only what the edit changed: 65-69 ms, and 8-10 ms of cleanup. That is about 85 ms off a
station placed (4% of about 2 s) and about 140 ms off a station removed (10% of about 1.3 s). Nothing you see changes
except timing. The biggest page cost left is the drawn network going into the renderer and the frame after it (65-180
ms and 50-220 ms), which is T-4153 and T-3444 stage 5's, not this task's.

## The mechanism (game/worldDiff.ts)

- `toWorld` keeps each record's view object while its row is the same: stations, lines, line figures and edges already
  did; nodes now do too (`nodeViews`). So a record whose object is the same is the same record.
- `worldDiff(a, b)`: the stations, lines, edges and nodes that differ between two worlds, each with its object before and
  after, read off identity by walking both lists in id order (pointer compares, no maps unless a list is out of order).
  Each kind is worked out when first read. Any two worlds: a lazy reader that skipped a state, or `moneyWorld` holding an
  older one, diffs from the world it last read. A new game's records are new objects, so repeated ids count as changed.
  Derived on the page, not taken from rowsedit's list (T-4149 had not landed); the worker's delta rows would let the node
  and edge diffs skip the walk (below).
- `PerRecord`: values kept per record id with the inputs they were made from, made again only when an input is another
  object or number. Network-wide inputs (a line's part of the base fares, which any line's edit moves) are kept out of
  the expensive part and applied in a cheap second step, in the same arithmetic order, so figures are bit for bit the same.
- Checks: `?patch=check`, or `twPatchChecks(true)` in a DEV page, makes each moved reader build in full as well and
  log a "T-4150 check" error on any difference (`freshly` runs a build with every `PerRecord` bypassed).

Moved onto it: `busPlaces` (kept while no bus line, no station within a walk of the stops' reach and no train line
stopping in it changed; built from the stations a chain of walks from a stop reaches, which gives the same places, walks
and connectors as every station), `BusLayer.set` (skips its rebuild when no bus line, BRT station or passage changed,
the places and groups as before; `busStopLinks` kept per bus line stops), `lineGeo` (per line, per world read),
`baseTrips`, `incomeFor`, `dayPoints`, points' `assemble` and cover, `lineShares` (per line per demand view),
`stopsOf`'s bus stop names (per bus line, kept unless a changed station is within its naming box), `EndMarkers` (the
nodes an edit changed and the ends of the edges it changed, looked at again when their network comes), `railCountries`
(counts patched), and the stars' `zoneViews` (once per day's figures).

## Stage 2: the readers by what the state's rows say changed (agent pageedit2, 2026-11-25)

**For Anita.** After an edit the page's figures (fare income, points, achievements, the bus layer, station labels and the
rest) now look only at the lines and stations the edit changed, found from the rows the worker sends, instead of
walking the whole save to find them. On your Asia save the page's own work for a station placed went from 65-69 ms to
27 ms (35 for the first edit after a load, since fixed), and the figures' share of any edit is 11-29 ms (18 in the
middle of ten), against about 60 before. A removal's page work is still 29-78 ms (49 in the middle of six): most of
what is left there is outside the figures, the delete tool's hover after a delete (stage 3, T-4284), and swings a lot
from edit to edit. Nothing you see changes except timing.

### The cause, in the code

Stage 1 made each reader keep its values per record, but each still found out what changed by walking: `worldDiff`
compared all 18,000 node and edge records by identity, `lineGeo` built a deps array of every stop's station for every
line (every reader of fare income, base share, points and region shares paid it), achievements went over every line's
every stop (and `longestRide`, quadratic in a line's stops, for every line), `edgesOf` listed the lines over every edge
again when any line's path moved, and `pickedState` built a map of every edge with nothing picked. Two cousins kept
readers from ever skipping: `toWorld` made a new passages array (`pairsOf`) and took the state's new buildings array
on every world, so `d.links` was always true and the bus layer rebuilt every bus line on every edit; and a state after
an anchor move (`touched.all`) or a whole post broke any chain of known changes.

### What changed

- **Steps from the rows' delta** (workers/clockClient.ts `takeRows`, game/worldDiff.ts `noteStep`, `stepIds`): each
  world the page builds notes the edge and node ids its states' deltas carried (changed rows and dropped ids), plus the
  edges whose lines `edgesOf` changed. The delta is exact even when `touched` says `all` (an anchor move: every drawn
  position moves, no row does), so the page uses the delta itself, not `touched`. Worlds are numbered and the last 32
  steps kept in a ring by number, so no world holds an older one. `worldDiff(a, b)` with `b` built from `a` within 32
  steps looks up only those ids (nodes in the map, edges and stations by binary search in the id-ordered lists);
  any other pair walks as before. The diff memo is now keyed older-then-newer (stage 1's memo kept every past world
  alive through the chain of `from`s).
- **A whole post keeps equal rows** (`takeRows`): a row posted whole that equals the held one (`sameValueDeep`) keeps
  the held object, so a load's later states and a whole state asked for leave the views, and every reader keyed on
  them, as they were.
- **`reading`** (worldDiff.ts): the lines a per-line reader must redo, the changed lines plus the lines stopping at a
  changed station, from one station-to-lines index moved world to world by the changed lines. `PerLine` keeps a value
  per line from the world it last read and remakes only those.
- **Readers**: `lineGeo` takes the previous world's geo for every line not in `reading` (fare income, base share,
  points and region shares); `networkFigures`, `corridorFigures` (each stop's corridor ends as bit masks, the union by
  complex number) and `demandFigures` (the sleeper ride per line; busiest station by complex number in arrays, in the
  order first met) per line; `edgesOf` patches the lines over only the moved lines' edges, and finds each edge row's old
  view by walking both id-ordered lists (one station removal used to shift every later edge to a new view); the
  passages, separated pairs, buildings and full-track maps stay the same objects while equal; `pickedState` reads
  nothing with nothing picked; station labels plan from the stations the diff names and those whose complex the
  builder worked again (`complexChanges`); the bus layer keeps each line's source by its figures, its places keep
  through a train line's edit that stops at the same stations within the stops' reach, and BRT joins look only at
  groups with a BRT station; the income and points posts compare by value instead of `JSON.stringify`; line
  signatures (`lineFigures`), the hidden levels' station lookup and reversal marks use what is kept per row or world.
- **Checks**: each new path has a whole build beside it under `?patch=check` / `twPatchChecks(true)`: the id lookups
  against the walk of both lists, the lines over each edge against a whole listing, and the achievements' three
  figures against a build with every `PerLine` bypassed (`freshly`). DEV `twDiffStats` counts ids looked up and
  records walked.

## Stage 3: what an edit still made the page go over whole (agent pagestage3, T-4284, 2026-11-25)

**For Anita.** After a removal on your Asia save the page now does about 45 ms of its own work, from about 125: the
delete tool's look at what is under the pointer, the trains' fill, the tools' map and the snap and pick grids now
cost what the edit changed. The figures (fare income, points, achievements, complexes) are what is left: about 23 ms,
since each still goes over every line, and that is the next stage. Nothing you see changes except timing.

### Two measures

- (a) the take minus `setNetwork`, as stages 1 and 2 report it.
- (b) everything the edit makes the main thread do, minus `setNetwork` (T-4153's), frames, the undo warm-up and DEV-only
  checks: (a), the patch at the edit's word (`takePatch`: the tools' map and world), the demand layers, the delete tool's

### The cause, in the code

DEV step timers (`game/stepTimes.ts`, `twSteps()`), read first on the real New York save, split the work stage 2 left
unsplit. What scaled with the save:

- **Pick grids** (`pick.ts` `carryGrids`, `cellIndex.ts`): a carried level renumbered every old segment through two
  arrays the size of the strokes (`step`, `map`), each edit: 22-74 ms on New York inside the take, and the hover tag's
  first query after an edit paid it again (34-57 ms).
- **The demand layers** (`demandLayers.ts`, `renderer.setLayers`): every line's numbers again, a pass over every
  stroke segment for runs only the Traffic view reads, the trains' fill per sample, a width per segment checked plain
  in `setLayers`, and the fill compared slot by slot before writing.
- **The snap grids** (`snapIndex.ts`): the edge grid carried by comparing every edge's points and renumbering every
  segment; the node grid built whole for each world (each has a new nodes map), the tools' click world included.
- **The delete tool's pick** (`toolDelete.ts`): two loops over every node (stations not yet drawn, flyovers) on each
  hover, and edge lookups by `find` over every edge; the stations' reach (`renderer.stationReachNow`) worked out for
  every station's shape on each network.
- **`toWorld`** (`clockClient.ts`): the stations list and the nodes map made from every node row for each world, the
  state's and each click world's.
- DEV only, not in (b): `checkPatched` 1.3-4 ms a state on Asia, `checkHeld` under 0.1 (its set of every track segment
  runs only when a line was drawn ahead).

### What changed

- **Pick grids carried by runs** (`cellIndex.ts`): a carried grid maps its base items to their numbers now through runs
  (from, count, to), composed edit by edit; a carry costs the edit's runs and the items laid over (`RUNS_MAX` 4096).
- **Snap grids laid over** (`snapIndex.ts`): a grid is an older one with the edges or nodes changed since passed over and
  their new ones in a small grid of its own, built at once (`CellLevels` `now`); past 4096 laid over, built whole.
  The network's changed edges come from `mergeNet` (`edgeStep`: the posted edges, and the ones gone read off the last
  build's ids beside these) and from the patches (`clickMap.ts`, whose edge map is now a copy with the patch's edges set
  when the new ids come last); the nodes' from `worldDiff`. Answers in ascending ids, as a scan meets them.
- **Click worlds as sides** (`worldDiff.ts` `noteSide`, `sideOf`): the tools' click world is noted as its state's world
  with the patches' row ids, off the numbered chain (a click world on the chain would unchain the next state, stage 2's
  trap), so `worldDiff` from its state's world looks up those ids and its node grid is laid on the state's.
- **`toWorld`** lays the stations and nodes on the last kept world's by the changed node ids (a state's from its rows'
  delta, a click world's from its patches); a new node not after the others by id, or a bus stop's row, builds them whole.
- **The delete tool**: its node loops take the nodes near the pointer from a node grid (`pick`: stations and flyover
  junctions); `edgeOf` (binary search by id) for its edge lookups and `stationTrim`, `stationStub`,
  `describeRemovable`. The stations' reach is kept per station from the network last asked where its platform's
  numbers are the same (found by its place, one up or down, else by id).
- **Demand layers**: each line's numbers and busiest stretch-day kept per demand view (`PerRecord`, deps: its row, its
  figures, the period, the purpose, the stops key; the busiest the max of the lines' maxima, exact); no runs pass and one
  plain widths array outside the Traffic view, and `setLayers` takes plain widths as plain without a pass; the trains'
  fill kept per line table row from the last layers where the row's line has the same numbers, pending mark, sample count
  and stretches (the network's `patch.stretches`), and only the changed rows written (`putSlots` with names).
- From the batch17 review (notes/T-4285.md "T-4150 1" and "2"): `sameBuilt` checks each key is on both sides;
  `PerLine` takes the new world in `end`.

Every new path has a whole build beside it under `?patch=check` / `twPatchChecks(true)` (with `renderer.checkPatch`):
the node and edge grids' answers against a grid of every node or edge, the demand numbers, the busiest stretch and the
fill against whole builds, the reach against every station's, the laid stations and nodes against `toWorld`'s whole
lists.

## Stage 4: each line's terms kept, the take's whole passes laid by ids (agent pagestage4, T-4284, 2026-11-25)

**For Anita.** After an edit the money and points figures now redo only the lines the edit touched and add every line's
kept terms again (a tenth of a millisecond for all 242 lines), and the world the page builds lays the changed track
pieces and rows into the last one instead of going over all of them. On your Asia save the page's own work for a removal
is about 41 ms (was about 45) and for an undo about 31 (was about 40): not the 20 ms aimed at. The money and points
figures themselves dropped (points 3-8 ms to 1-2), but fare income still costs 3-5 ms and what is left is spread over
many steps of 1-5 ms each, listed under "Left". Nothing you
see changes except timing; the points' sums are regrouped by line, so a region's points can differ from before in the
last digits only.

### The cause, in the code

Stages 1-3 kept values per line, but each reader still paid per line per pass: a deps array (`PerRecord.get(id, [l, st,
dm, ...])`, with `...g.zones.map` and `...l.stops.map` a stop each), a closure, and arrays per period, for each kind of
day; and the points spread each region's trips over its boardings by adding every stop of every line again, so any edit
went stop by stop over the whole network. Beside the readers, the take went over every row: `takeRows` looked up every
edge and node row by id whenever an id came or went, `edgesOf` made the edge list by walking every row for each world
(the state's and the tools' click world), `patchRows` rebuilt the click world's rows with a map and a set, the click
world copied the map of every edge's lines, `chargeShares` mapped every edge of both worlds, and the income and points
posts copied, compared and posted every line's table. An edit that re-routes a line also named every edge of that line as
"moved", though most kept the same lines over them.

### What changed

- **`PerLine` per kind of day with a line's own input** (game/worldDiff.ts `start`, `kept`, `put`, `perLineOf`): a
  reader keeps a line's terms from the world it last read; `start(w, ins)` makes every line again only when another input
  (the fares, the zone boundaries) differs; `kept(id, dm)` returns the line's terms while it is not in `reading` and its
  demand figures (`dm`) are the same object, with no closure or deps array. A new result makes again only the lines whose
  figures it changed.
- **Fare income and the base share** (game/money.ts `incomeFor`, `baseTrips`): a line's own terms kept; its money made
  again only when its part of the base fares, the trips a boarding or the economy moved (a few sums); the day's totals
  each line's kept terms added in line order, as before. `scalesOf` takes each zone's fare multipliers once per fares.
- **Points** (game/points.ts `dayPoints`, `assemble`, `linePoints`, `lineCover`, `pointsPerDay`): a line's boardings
  by region and by region and period kept; a region's boardings are the lines' sums added in line order, and a line's
  points by region (boardings times 20 a trip a boarding plus km a boarding) made again only when its regions' trips a
  boarding changed. The cover, the covered entries and the day sums by region are kept per line by the objects they
  read. The arithmetic is regrouped (a line's terms first), so figures differ from before in the last digits.
- **Region shares** (game/regionMoney.ts `lineShares`) as income; **`chargeShares`** from the worlds' diff (in id order);
  the Build tab's switched-off counts (game/blueprintPick.ts `offTotals`) moved by the diff.
- **Corridors** (game/achievements.ts): only a corridor with a built station at each end on some line is joined; with
  none, no join of the network's stops at all (exact: no other corridor can be met).
- **Stops by id** (game/world.ts `stopsOf`): the last world's maps with the changed stations laid in (one copy of each
  map), while no bus line's stops changed and none takes its place's name.
- **The take** (workers/clockClient.ts): `takeRows` lays the delta's rows into the held ones by a walk of both id lists
  (no lookup a row); `edgesOf` lays the edges a step names (rows changed and edges whose lines changed) into the last
  world's views (`laidEdges`); the tools' click world reads the patch's lines over the kept map (no copy); `patchRows`
  by binary search; `edgeLinesPatched` names only the edges whose lines differ.
- **Posts** (clockClient.ts, clock.worker.ts, protocol.ts `order`): income and points send only the lines whose entries
  changed, with every line's number in order; the worker merges them into its tables in that order.
- **Checks**: every new path has a whole build beside it under `twPatchChecks(true)` / `?patch=check`: income (as
  before, now through the kinds' `PerLine`), points' entries (`assemble`), the cover, the day sums by region, the region
  shares, the stops by id, the laid edges, rows and patched rows, the charge shares, and the merged income and points
  tables the worker holds. DEV step timers `money.income`, `money.base`, `money.income.line`, `world.stops`.
