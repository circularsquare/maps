# T-123: Reduce demand-worker memory

Taking 2026-10-10, Codex, after Claude completed T-116–T-120 and T-125.

Scope: reduce repeated regional-market allocations without changing travel parameters,
pair order, routing, attribution or crowding results. Measure before/after on the real pack
and compare the existing Northeast fixture's complete result arrays. Start with parsing
endpoint sites directly rather than retaining a generic JSON tree, then compact pair indices
where measurements justify it. Keep the existing worker ownership and pool architecture.

## Implementation

The constructor deserializes only `zone_m`, `trip_rate` and a flat vector of five-number site
rows. Unknown source/description metadata is skipped. Rows are consumed in their original
order, with the same numeric types, defaults and weight validation; the temporary vector is
released before gravity pairs are built. Generic JSON arrays and per-row numeric vectors
are gone. Serde is a demand-only dependency; the clock module stays unchanged.

The resulting immutable pair vector and the origin/destination index lists release spare
capacity after construction. No pair precision, identifiers, order, formulas or attribution
changes. `usize` already has 32 bits in WASM; changing it to `u32` would not save browser
memory, so pair identifiers stay as they are.

Typed parsing alone reduced opening memory from 113.38 to 71.11 MB per solving worker,
and browser opening time from about 945–969 ms to 405–438 ms in the recorded runs.
Full-network peak remained around 137 MB, which motivated releasing table spare capacity.
Those intermediate results are in `T-119-browser-t123-after.json`; the final result follows.

Final browser measurement, five solving workers plus the auxiliary worker:

| | Before | After |
|---|---:|---:|
| Pool WASM memory after opening | 595.66 MB | 359.73 MB |
| Per solving worker after the full network | 137 MB | 127–128 MB |
| Estimated pool memory after the full network | 713.77 MB | 667.77 MB |
| Combined network first estimate | 1.82 s | 1.75 s |
| Combined network round three | 6.28 s | 6.10 s |

Opening saves 235.93 MB (39.6%); the full solve saves about 46 MB (6.4%). The pool estimate
adds the auxiliary worker's opening memory to the harness's rounded per-solver measurements;
it is WASM linear memory, not total browser RSS. The live network/strategy arrays still
dominate the full-network peak. Cold first-network timings varied between runs; the table
uses the identical second, combined-network solve. No speed improvement is claimed from
these two samples, only no observed steady-solve regression.

Demand WASM grows by about 29 KB gzipped because the typed deserializer adds code. The clock
module stays unchanged. Changing pair storage further or shared ownership was unnecessary
for this bounded task; later reductions should profile the live strategy/period arrays.

## Validation

100 native tests pass, six optional profiles/fixtures ignored. Added malformed-site and
metadata/field-order coverage. The full `northeast_profile` fixture (real NYC network plus
Philadelphia service, all five periods and crowding rounds) compares loads, boardings,
alightings, entries, regional boardings and population summaries to the pre-change dump.
Largest difference is 1.93e-16 relative to each array's maximum, JSON floating-point noise.
Both native logs and result dumps are saved with the T-123 prefix.

Demand WASM generation, TypeScript and Vite production build pass. The old-browser harness
uses an isolated context. The sandbox blocks remote basemap fetches in these runs; the
recorded errors are resource/style fetch failures, not demand failures. Its demand/line data
and worker timings still complete normally. Visual map QA is not claimed for this task.

`node trainworld/notes/t123-compare.mjs` passes: 74,835 recorded native values (excluding
timings) match, browser city/network/regional summaries and all line totals match, memory
falls and steady solve times stay within the regression bound. Evidence: `T-123-check.json`
and `T-119-browser-t123-before.json` / `T-119-browser-t123-final.json`.
