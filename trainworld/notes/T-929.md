# T-929 and T-931: market rows only where they change; the gate's rates test built once a run

## T-929: what a market row reads

A place's row (`intercity::world_rows`) is its own pack's sums, centre, airports and commutes, plus
its `near` list: for each place whose centre is under `near_km` (250 km), the sum over every zone
pair of the two places of `eachway`. `eachway` reads the two zones and the pair's rule (border,
income ratio, distance), which reads the two places alone; since T-377 each place is its own group
(its figures do not depend on which other packs are open). The commute list reads the place's own
pack, but every place it commutes to must be in the composition (its zone count is checked). So a
row is a function of its own pack and the packs of places near it, and a composition holding those
gives it to the bit, provided each sum is added up in the same order. Zones are laid out place by
place in place order whatever the composition holds, so for any pair of places the zone pairs come
in the same order, and the sums are the same.

## What changed

- `intercity.rs`: the near totals loop over the zone pairs of near places only (it scanned all
  151,252 zones' 11.4e9 pairs, 80 s, to find them), each pair of places summed in the order the
  scan would; `world_rows_for(header, only)` gives the rows of some places, with near totals and
  commutes only for pairs touching them; the commutes per place in one pass (was one pass a place);
  `place_trips` on zone spans, and as an `IntercityApi` method so `market_pack` does not parse
  every pack a third time; a composition parsed straight into its struct.
- `market_pack --only FILE` (`{"rows": [...], "compose": [...]}`): those rows from those packs,
  checked as the game opens them (market-rows.json's other rows with the new rows' packs).
- `market_zones.py`: `plan_rows` reads `data/work/market_rows.inputs.json` (per zone: place, the
  market pack's hash and size/time, the row's hash and centre; the `market_pack` binary's hash; the
  market rule's hash). Changed = new, changed pack, changed place, or a row that is not the one
  recorded (a run of older code, a restored file); gone = recorded but no longer registered with a
  pack. Rows redone: the changed ones and every place within 250 + 25 km of a changed or gone
  place's old or new centre (a changed pack's centre estimated from its sites, well under the
  25 km margin). Composition: every place within 275 km of a row redone, plus the places those rows
  commute to. After the run `unreached` checks the estimate against the new rows' own centres (a
  registered place within 251 km left out, or a wanted row missing, means a full run). No record,
  another binary or rule, a frame that is not equirect: every row. `--rows` no longer reads the
  airports or the joint commute files it does not use.

Also: master's `market_pack` and the new one (full) on the 799-pack copy write the same file (rows
and the pairs table, same SHA-256); the Rust test `rows_of_some_places_are_those_of_every_place`
(a row from its near packs only equals the full composition's; one near pack left out does not);
`unreached` on xuz with an empty composition names exactly the 15 places whose rows list xuz as
near. A join case on real data was not available in the time (the China batch had not joined);
the fresh case is the join's shape (packs rewritten, zones gone).

The serde_json parse of a float can be off by one in the last place (no `float_roundtrip`), so the
Rust test compares rows as written, not reparsed; the pipeline is unaffected (Rust writes, Python
reads and writes back, both exact).

## T-931: the rates test

`world_run.Run.build_everyday` at the start of `run`: `cargo test --release --features demand
--lib --no-run --message-format json-render-diagnostics` on the sim the gate reads (TW_SIM_DIR,
else the tree's sim/), the test executable copied to `data/work/world_run/everyday-<batch>.exe`
(7.3 MB, deleted at the run's end), its path passed to each gate as `TW_EVERYDAY_EXE`, which
`pack_gate._everyday_rates` runs (`every_pack_everyday --ignored --nocapture`, `TW_PACKS`) in place of
`cargo test`. If the build fails the gates build it as before. Built synchronously, before the first
region, so it stays inside `--jobs` (the gate built it with nothing else of the run going either).

Checked: the build from my tree's changed sim took 118 s at 3 jobs (deps cached); master's logs show
10-65 minutes for the same recompile under batch load (156 minutes over 2026-10-20 to 22, T-928).
`everyday_rates` on xuz, pih, hih and lon: the same rates through the binary (1.2 s) as through a
cached `cargo test` (0.9 s). Saving: every recompile after the run's first (each time sim/ changed
between regions, both slow gates of the two-hour batch), and the first one moves to the run's start.
