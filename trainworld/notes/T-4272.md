## The causes, from the code

- A station or delete on a running line's track went the whole way before its answer (`moves_no_train` false in
  `commit_local`) because the trains it makes headway lines need were paid at the click and refused when the cash was
  short, and only the settle over every line sharing that track says how many. With the trains bought after, nothing
  that can refuse such a click is non-local any more.
- Owed services that move running trains need what the whole path does around them: the trains running then noted
  (`before_edit` before the services, `note_changes` after) and the trains bought, edit for edit. Several such edits
  settled as one would not equal the whole path: the fleet is a running maximum (an intermediate state's trains are
  bought and kept), and only the first owed edit's undo record is exact.
- Every path that reached the world's `settle_owed` (another edit, an undo or redo, the Build tab's quote, a reload for
  the water) worked owed services out with no money and no trains noted: an undo right after a click never bought the
  trains the whole path bought, and the next edit's money check counted the owed trains as its own.

## What changed (stage 2)

- Rust, world.rs: `commit_local(op)` no longer gates on `moves_no_train` and checks no money; it returns `Local`:
  `Answered` (owed), `Whole` (it sets a line's trains, rates, rows or twin: `sets_rates`, schedules, weekend) or
  `SettleFirst`. An edit that can move running trains (`moves_no_train` false) is owed alone (`Owed::trains`): what is
  owed is worked out before it, and an edit after it works it out first; edits that move none are still owed together.
  The world's own settles inside commits, steps and trials go through `settle_owed_here` (a fallback; it asserts in
  debug builds that nothing train-moving reaches it).
- Rust, wasm/edits.rs: `TrackApi::pay_owed` works owed services out as the whole path's edit would: `before_edit` at
  the game time now, the world's `settle_owed`, `note_changes`, then the trains the running lines need beyond the
  fleet bought whatever the cash (`cars_needed` once), the fleet raised, what they touched noted and kept in
  `owed_pending` for the next edit's result or `settle_owed`. It runs first in `run`, `run_free`, `run_charged`,
  `run_off_history`, `step` (undo, redo), `rebuild_pieces`, `blueprint_cost_items` and the four water reloads.
  `run_answered` handles `SettleFirst` and runs the whole-way and joined cases with no spending limit (`unrefused`), so
  the ghost and every click keep one money rule. The station ghost's dry run checks no money (`attempt`).
  `take_trains_bought` gives the ledger each line's share by how much its trains rose; `take_settled_running` says
  owed services that could move running trains were worked out; `line_broken` reads one line's broken flag.
- Rust, links.rs: `delete_pieces` (Remove station, a multi-select delete) goes through `run_answered` too: a removal
  builds nothing, so the re-pricing of the track a removed station joins back into one piece is no purchase.
- Worker: the follow-up's settle piece books the trains bought (clockMoney.ts `bookTrains`: each line's share in the
  regions its trains run in, from the page's `lineShares`, the rest in ""), sends trips with the state when running
  trains could have moved, and steps the boarding account's lines they moved a piece at a time (`editSteps`), as an
  edit's are before its state; the edit path books trains an edit's own `pay_owed` bought. The click map's patch
  (clockPatch.ts `movedPaths`) leaves out a line whose owed services could say otherwise of it: broken or mended, a
  partly built line's run, its return run's stops (this settles stage 1's "patched rows differ ... nodes 3: line").
  The page's new hour (`epoch`) waits for a waiting follow-up's state instead of running it whole. The stop clicks'
  rows (`rowsOwed`) work out what is owed first, as `standAside`'s do (T-4339; after the game run and benches,
  typechecked).
- Tests (answer_tests.rs): a station on a running count line's track answered and equal to the whole path through undo
  and redo, eras and shifts included (`seen` now compares where running trains are drawn from); a delete that sends a
  headway line the long way round: answered, the trains bought after, equal through three undos and redos, with a
  station owed before it (worked out first) and one clicked while it is owed (works it out first); an undo before the
  services; the cash going below zero by exactly what the whole path with cash to spare spends, the ghost not refused.
  Eight tests that read services right after a station, delete or removal on a running line's track now call
  `settle_owed` first, as the worker does before its state (oneleg, blueprint, platform, bus twice, keeps, oneway,
  scope).

## Review of stage 1 (Gemini's, answered by agent answerfix)

Gemini's review: artifacts/trainworld/gemini/t4272/review.md. Each finding checked against the code.

1. **Old game's riders and transfers applied to a new game: real, narrow.** Riders and transfers kept while a follow-up
   waits were put at the queue's tail when its state went. A new game, an import, a slot opened, a flip or a panic's
   rebuild that ran that follow-up first queued them after its own restart, and neither message carries a game, so
   the old game's riders went into the new model (master ran them before the restart, which clears them). Only within
   the follow-up's few hundred ms. Fixed: each kept message carries the game it came in and is dropped at its turn when
   that game is gone (clockFollowUp.ts `keepUntilState`, clock.worker.ts `whenStateWent`), which is what master's order
   came to. Within one game they run after the message that ran the follow-up; demand's results coming after an edit
   is the usual case, so that order is harmless.
2. **Drawn lines not forgotten after `settle_owed`: real.** The edit's `forget()` runs right after its apply, before its
   services; the lines the owed settle then moved (planned rail lines through `take_moved_lines`, bus lines through
   `dirty_lines`) were forgotten by nothing, so the state kept their old samples and left them out of `touched.paths`
   until the next edit: a planned line stayed drawn over track just deleted. Fixed: the follow-up's settle piece calls
   `forget()` after `settle_owed`, which puts what the services touched into the last edit's result (or makes one after
   a preview, which leaves none). Game run: the station on a planned line's track and the delete of track under it
   were each answered at once, and the next state had `touched.paths: [0]` with the line broken.
3. **What a refused edit worked out was lost: real, and wider.** Every world path that runs `settle_owed` first left its
   result in `owed_done`: an edit refused for money (never read), one refused for its problems (rows noted, demand
   dropped), an undo or redo with nothing to take, and a trial with services (the Build tab's quote, `blueprint_cost_items`).
   The follow-up's piece then saw `owes()` false and skipped the rows, trips and snapshot; a preview's `done(Ok)` would
   have taken it and thrown it away (previews clear `last`). Fixed in the one place every path reaches:
   `TrackApi::settle_owed` settles anything owed and then takes whatever `owed_done` holds, whoever worked it out; only a
   successful edit takes it into its own result, in `settle` (no longer in `done`, which previews call). Test
   `what_a_refused_edit_or_a_trial_worked_out_still_reaches_settle_owed` (a money refusal, the quote's trial).
4. **Twin lines read after `twin_ops`: real cause; the divergence a test found was small.** The answered edit's own apply
   runs `twin_ops` and `way_reroutes` (`apply_rerouted`), and `settle_owed` read `Ahead` and `line_rates_all` after
   them, where the whole path reads them before. With the new gate off, a station that gives a planned line its twin,
   then undo, ended unlike the whole path in the removed twin's departure phases (its freed slot); trains and rates
   matched only because the settle moved none of the parent's. Running lines were already covered (`lines_touched`
   holds `t.lines`). Fixed: an answered edit whose inverse shows it set a line's trains, headways, rates, rows or twin,
   or made or removed a line, goes the whole way (`sets_rates` in world.rs, and any `schedules` or `weekend` touch); a
   line moved through a new station keeps all of that and stays answered. Test `a_station_making_a_twin_goes_the_whole_way`
   (a count line and a headway line, through three undos).
5. **Rows sent before the settle: real, brief.** An answered edit with no patch (or no click) is answered with its world;
   when another edit went ahead, `standAside` sent rows built before its services. Fixed: those rows settle first. Its
   cousin, a save while services are owed (only a game left while an edit waits for its ground could), now settles
   first too (`saveBytes`, `saveParts`: `settleOwedNow`).

Gemini's note on `sendMoney` from `regionShares` and `chargeShares` while owed: not reachable as stale. Owed services move
only lines that run no trains, which have no running cost, and an edit reaching a running bus line goes the whole way.
