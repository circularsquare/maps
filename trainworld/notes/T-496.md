## Where the time went, before and after (per placement)

- Click to edit sent: 10-20 ms (the station's name, `nameFor`), now ~7-9 (the name is worked out
  while the pointer rests 150 ms, used only if view, world version and loaded tiles are as then).
- Worker `networkFromState`: 40-75 ms, now 11-20 (9-12 on the main thread from a warm cache). What
  is left: laying the pieces end to end into fresh arrays (~4 ms; they are transferred, so they
  cannot be kept), the per-build maps and the edge sort for platform directions, the comparisons.
- Main thread per state: 27-45 ms, now 15-24. Station names were ~24 ms (every label rebuilt and
  measured, a forced layout of 1,700 elements), now ~10 including the complexes; complexes were
  built three times (~12 ms), now once (twice with links); capacity tags rebuilt every edit, now
  only when one changes; three `clientWidth` reads replaced by the overlay's kept size.

## What changed

- `map/network.ts`: `NetCache` holds each edge's track strokes (with a copy of its polyline, ends,
  flags), each line's strokes (path, stops, running, the first stroke of each path entry) and each
  station's platform shape (platform, lat, its ways and which one it follows). A piece is reused
  only when those inputs are bit for bit the same (floats compared as bits, so NaN heights match;
  the first version compared values and rebuilt every edge with a NaN). Entries not seen are
  dropped every build. `networkFromState(s)` without a cache is the old full build.
- `workers/clock.worker.ts`: one `NetCache` for the worker.
- `map/stationLabels.ts`: labels keep element and size when class and text match; the complexes
  come from `game/complexView.ts`. `complexView.ts`: `dotGroups` is `complexes` when there are no
  links. `map/capacityMarkers.ts`: a key of the tags; `endMarkers.ts`, `stationLabels.ts`,
  `capacityMarkers.ts` read `overlay.cssW/cssH`. `map/tools.ts`: `nameAhead`.
