## Fixed

- **T-4150 s1 #1, base fares after zone outlines load: real.** `baseTrips` kept its last result per demand view keyed on
  the world, fares, stations and share, not on `zonesLoaded`. `incomeByDay` and `lineShares` rerun when outlines
  arrive (same world), and got the base share worked out with the stops' old fare scales (stationCity before the
  outlines), until the next edit or solve. Only lines with stops near a border or with fares by city moved. Fix: the
  memo is keyed on `zonesLoaded` too (game/money.ts). Cousins checked: `incomeMemo`, `sharesMemo`, `pointsMemo` have
  it; `lineGeo` and every PerRecord over it take it through `g`; `railTripsByRegion`, `busPlaces`, `stopsOf`,
  `railCountries` read no zones (railCountries keys on `outlinesIn`).
- **T-4150 s1 #2, no squares after a load: real, on every load.** The page's first state sets `world` before
  `renderer.setNetwork`, so EndMarkers found its points with no network (none, as `ptAt` wants drawn track); the
  network then came as an empty diff (`worldDiff(w, w)`) and nothing was found again. With the select tool (the tool
  at load) at zoom 9 and up (the start view is 11.2), every blueprint square was missing until a tool change.
- **T-4150 s1 #3, a network older than the world: real.** `stale` was cleared at any new network, so a network built
  for an earlier world (a staged state's, or a rows world ahead of its network) dropped the later world's nodes. Same
  cause as #2, and a third cousin: a whole find past PATCH_MAX on such a network cleared `stale` too.
  Fix for all three (map/endMarkers.ts): a network holds the world when `renderer.netVersion` reaches the world's
  version; `stale` is cleared only by a network that holds it, and points found whole on a network that does not (or
  with none) are found whole again at the next network (`wholeStale`).
  Game run: a new NYC game with a line and three blueprint points, saved, opened from the file: 3 squares right after
  the load with the select tool, no tool change (artifacts/trainworld/t4266-squares-after-load.png).
- **T-4150 s1 #4, `diffList` fallback: real in code, not reached** (the model's lists come in ascending id order, so
  the fallback never runs mid-walk). Fixed anyway, small: the fallback takes back the records the walk found in one
  list only before matching the rest by id (game/worldDiff.ts).
- **T-4214 A #1, clickable map after constructing a plan: real.** `movedPaths` skipped a line whose plan path and
  back were unchanged, but constructing a partly built line's plan moves its run (`line_run_path`) and keeps the plan.
  Fix (workers/clockPatch.ts): the skip compares the run path too, and whether the line has a plan part; a patch is
  sent only when the run stops and `stopStart` (what the page's `toWorld` reads) are as posted, else none and the
  click waits for the network as before T-4214.
- **T-4214 A #2, a refused station's name held 60 s: real, and likely** (click where a station is refused, then
  click beside it: the second station took the next name or a numbered one). Fix (map/stationTool.ts `nameLater`):
  each name held is tagged with its ticket, and every caller says once its edits are answered whether a station was
  placed (`naming.placed`); a refused one's name goes from `namesOut`. All four callers: train/tram station, BRT,
  open-ground (stationFree.ts), port (stationPort.ts).
- **T-4260, `writeCache` racing itself: possible, not shown.** Two writes of one solve (the final's, then
  `solveDone`'s with the local flag) each await a hash, a key and the bubbles; if the first finished last it wrote
  `local: false` over `true`. Fix (workers/demandClient.ts, 3 lines: field `cacheSeq` by `cachedLocal`, and in
  `writeCache` a sequence taken after the "days" check and checked before "same"): only the last write asked goes on.
  demandClient.ts is aside3's and slowfocus's file; these lines are outside dispatch and the focus solve.

## Left, with the reason

- **T-4214 A #3, a save made while a name is looked up: real in code, not reachable.** The lookup takes 10-250 ms; a
  download or share by hand cannot start that soon after a click. An autosave in that window writes the station
  nameless, but the name's arrival marks the game dirty (clock.worker.ts `stationName`), so the next autosave writes
  it. Closing the tab inside the window loses the name whatever the save waits for (the lookup runs in the page).
- **T-4253, worker checks the first stop's base fare, panel every stop's: real difference, not reachable.** The panel
  is the only sender of `lineFare` and refuses first (its max over the stops is at least the first stop's), so no
  multiple past US$1,000 reaches the worker from the game. Worth folding into one rule if a second sender appears.
- **T-4231, T-4254: no finding.**
