## What a city's profit is

`dayProfitByRegion(w, inc, m)` (game/profitEstimate.ts), on the weekday's income: each running line's weekday fares by
its `fare` shares, its running cost a day (`lineRunningADay`, now shared with the edit note) by its `run` shares and
scaled so the regions add up to the clock's running cost (`runningADay`), and the network's upkeep by `upkeepShares`;
the rest (rounding) goes to "". These are the splits the clock's region ledgers use (regionMoney.ts), so a city's figure
is the Cities tab's split, on the forecast weekday. Regions add up exactly to `dayProfit`.

- Sent as `profitCities` for the cities the points send (`cities`, the top 64 by points), so a game counts in the same
  places on both kinds of board. Signed: a city can lose money while the game makes it.
- Country: the game's city profits summed, losses included; best game per board; a row only above 0. DECISIONS 2026-11-20.

## Client

- `account.ts` `figures()`: `profitCities`, in the change signature.
- `Leaderboard.tsx`: board keys `profit`, `profit_<city>`, `profit_country_<cc>`, mapped to and from the points keys
  (`profitOf`, `placeOf`), so the picker is the same component on both kinds and the switch keeps the place. The picker
  lists cities and countries with rows on either kind. Hover: just "{money} profit per weekday";
  `leaderboard.profitRule` removed from en.json and context.json (no translation had it).
