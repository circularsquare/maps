## Built (tree `farecols`, uncommitted)

- **BRT fare multiple**: `Fares.brt`, default `BRT_FARE` 1.00, 0 to 5 as the others (fareCurve.ts `brtFare`). A BRT
  line's rides pay it on the part above the base in place of the Bus multiple (`lineFareMul` takes `brt`). Set by
  `fareBus` with `brt: true` (no new op name, so the op lists in clock.worker, clockFollowUp and editCap need nothing).
  Demand: the snapshot line carries `brt` (clockDemand.ts, from `bus_brt`), the service copy and `muls` in
  demandClient.ts pass it; clusters take `fareW` from the packed network, so they follow. Money: money, regionMoney,
  stretchMoney pass `brt`. A BRT switch now always re-solves trips (clock.worker.ts, beside `ferryBoat`): a route with
  no road in town changes no times, yet its fares change.
- **One key list**: `KIND_FARE_KEYS` and `kindFares` (fareCurve.ts) replace the field-by-field copies in the "fares"
  op (clockEdits.ts), the load tidy (clockFares.ts) and the shared-save check (sharedSave.ts). The "fares" op had
  dropped `ferrySmall`/`ferryLarge` once (T-3892); a new kind can no longer be missed there.
- **Rows only for what exists**, Money tab and Advanced fares alike (`fareKindsInUse`, MoneyTab.tsx): high speed while
  a high-speed line exists, Bus while a bus line not on BRT exists (it used to show for any bus line, BRT included,
  but no BRT line pays it now), BRT while a BRT line exists. Boats: the Money tab already showed a row per size in use
  and still does; Advanced fares now shows Small and Large only with a line of that size, and Medium's "Ferry" row
  with any ferry line, as before (the brief's rule). So the two differ for a game with no Medium line.
- **Layout (Advanced fares)**: a thin rule under the "Add point" row (its cell spans the grid, 4 px each side). Under
  it, when a ferry line exists and the panel's inner width is 480 px or more (container query `fares`; the panel is
  558 px inside at full width), two columns 28 px apart: high speed, Bus, BRT and Transfer fare on the left, the boat
  sizes on the right, each its own grid whose last column is 24 px (the undo button). Narrower, the two lists turn
  `display: contents`, so the rows are the outer grid's as before, the transfer fare moved last by `order`. With no
  ferry line the rows are the outer grid's directly (one column, as before). Transfer fare goes in the left column
  so the rows under the rule line up among themselves; the right column's steppers end 41 px right of the curve
  rows' (whose last column holds "per km" and the bin).
- **Save**: fares are the JSON header's `fares` object, which takes keys freely; no level change. The server's
  save check (shonei-server) does not read fare keys.
- **Default jump**: a bus line switched to BRT goes from the Bus multiple (0.80 unless set) to BRT's 1.00.
