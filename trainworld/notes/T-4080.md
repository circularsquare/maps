# T-4080 stages 1 and 2: kept bus stops in the sim

Agent busstops, 2026-11-24. Design: notes/T-4080-design.md (Anita's picks 11-24: named stops stay put, connections
free with no upkeep, labels at street zoom). Stages 1 (kept stops, edits, undo, save) and 2 (held stops) are built;
stages 3-6 (names in the game, connections for riders, connections in the panels, labels) are not started.

## What is in the sim now

- **The kept stop** (`sim/src/track/bus/keep.rs`): a point (plane, mm grid), a name ("" none) and its connections
  (`KeepLink::Station(node)` or `KeepLink::Keep(id)`), stored once, on the side it was made from. The network keeps
  them by id (`Network::keeps`, `net/keeps.rs`: `set_keep`, `alloc_keep`, `keep_links` from either side,
  `station_keeps`, `keep_near`, `bus_lines_near`, `drop_keeps_except`). `KEEP_M` = 50 m (`CROSS_NEAR_M`),
  `LINK_MAX_M` = 1 km.
- **Edits**: `Op::Keep { id, data }` (world.rs), undoable like every other op. A kept stop made, moved or removed
  pushes its place into `Touch::keeps`; `lines_touched` then re-plans only the bus lines passing within 50 m. A name
  or a connection alone touches nothing (no re-plan, no departures placed again).
- **Held stops** (`bus::plan_by`): Auto lines add each kept stop within 50 m of the route (every pass) as a fixed stop
  (`KIND_KEPT` while planning, out as `KIND_MIDDLE`), before the crossings, so a crossing within 50 m folds in.
  Skipped where an end, a station's stop or an earlier held stop is within 50 m, outside the first and last stop, and
  past 1,000 fixed stops. Spaced lines take a kept stop as a candidate with the stations' priority (`spaced_stops`).
  Hand lines hold nothing. `BusStop::keep`: a held stop is its own kept stop's; any other plain stop takes the nearest
  kept stop within 50 m. Station stops never take one.
- **Lifetime**: an edit that leaves a kept stop with no name and no connection that holds removes it in the same edit.
  A connection to a removed station stops counting (lazy, as passages: `Network::link_live`). A kept stop no stop takes
  stays for the session; a load drops those (`TrackApi::load`, after the derive: none of them holds a stop, so no stop
  moves). The save leaves out kept stops with no name and no connection that holds.
- **Save**: trailing block `LBK1` after `LBE1`, written only when a kept stop is kept: count, then per kept stop x, y
  (mm, from the previous one), name, connections (count, then 0 + dense node index, or 1 + kept stop index). Save
  level **39 -> 40**, `BLOCKS` 42 -> 43, app `SAVE_LEVEL` 40 (app/src/workers/saveFile.ts, one line). `convert_frame`
  moves kept stops with the rest.

## WASM interface for stage 3 onward (`sim/src/track/wasm/keeps.rs`)

| Call | Gives / does |
|---|---|
| `keeps()` | id, x, y per kept stop |
| `keep_name(id)` | its name, "" for none |
| `keep_epoch()` | changes with every kept-stop change (names and connections too, undo and redo included): re-read then |
| `bus_stop_keeps(line)` | per stop of `bus_stops(line)`, same order: kept stop id or -1 |
| `bus_stop_keep(stop)` | the kept stop of one bus stop id, `u32::MAX` none |
| `keep_at(x, y)` | the kept stop within 50 m of a point |
| `name_keep(id, x, y, name)` | rename kept stop `id`; with `u32::MAX`, the kept stop within 50 m of (x, y), else a new one there (pass the bus stop's own place, so nothing moves). Empty name clears, and a kept stop left bare goes. `last_keep()` after |
| `connect_keep(id, x, y, kind, target, tx, ty)` | kind 0: a station node; kind 1: a kept stop id, or `u32::MAX` to make one at (tx, ty). Refused (1, `Issue::NoSuchKeep`, the app's fallback text): no target, itself, already connected (either side), over 1 km |
| `disconnect_keep(id, kind, target)` | removes it from either side; a kept stop left bare goes |
| `keep_links(id)`, `station_keeps(node)` | connections that hold, from either side: (kind, target) pairs; kept stops connected to a station |

Notes for the next stages:
- Stage 3 (names): the app picks the kept stop to edit by the design's place rule (`busPlaces`); `name_keep` with
  `u32::MAX` already reuses one within 50 m. A rename's edit result has nothing dirty, so the clock worker should
  watch `keep_epoch`. Renaming an existing kept stop is name only for demand; making one is a network edit (it can
  add a stop to another line within 50 m).
- Stage 4 (demand): `keep_links` / `station_keeps` give the connections; the design's two must-dos stand.
- Stage 5 (panels): "same place" is the app's (`busPlaces`); the sim's refusals carry no wording of their own.

## Small lies (all edge cases)

- Two kept stops within 50 m of each other along one route: the one earlier along it is held, and that stop is its
  own kept stop's even when the other is nearer. The player cannot make two in one place (`name_keep` and
  `connect_keep` reuse the one within 50 m); only route edits can bring two together.
- A station connection is a node id: a removed station's node id reused by a new station in the same session would
  bring the connection back, as passages (`links_live`) already do.
- A kept stop whose only connection was to a removed station keeps holding its stop for the session and is forgotten
  at the next save and load, so that stop can move after a reload.

## Review of stages 1-2 (keepreview with Gemini, 11-24): for stage 3 to fix first

# keepreview: T-4080 stages 1-2 (kept bus stops)
Verdict: PASS for landing on saves and undo; no-kept-stops path is the old path. Three findings worth fixing, all edge cases.

Checked by reading (no game runs, no benchmarks): old save loads (no LBK1, drop skipped, nothing written); LBK1 round trip (dense renumber, both-side links, station node ids, convert_frame); Op::Keep undo/redo with keep_free and Touch::keeps (merge_derived, rollback, LIFO ok); no-kept-stops path (plan_by, spaced_stops, near_route, lines_touched, encode, load all identical); kept stop on station stop or end (skipped by the 50 m check, end takes it via nearest_of, station stops get None).

## Findings
1. Out-and-back route holds the kept stop on one pass only (real, medium). bus.rs:581-594: the held-stop check uses ground distance to every entry of fixed, so the return pass (same street, project_passes gives it, bus.rs:244) is within 50 m of the outbound held stop and is skipped. SPEC/doc/notes say "one on each pass, as manual stops". Player: names a stop on the stem of a there-and-back line; the return direction stops somewhere else, up to ~200 m away. Fix: compare road distance too (as reach does with STATION_GAP_M), or exempt entries from another pass.
2. Bare kept stop left after a load (real, low). net/keeps.rs:116-129 drop_keeps_except removes B and strips Keep(B) from A, but A (no name, no other link) now stays, holding its stop. name_keep with "" returns early (wasm/keeps.rs:86-89) and there is nothing to disconnect, so the player cannot remove it. Next save omits it, next load moves the line's stops. Player: connect unnamed bus stop A to bus stop B on another line, delete that line, save, load. Fix: after dropping, drop kept stops left bare and replan, or drop to a fixed point before the derive.
3. Two kept stops 50-52 m apart on parallel lines (real, narrow). near_route sorts by (s, id) (keep.rs:55), so on line B the earlier-along K1 (45 m off the line) is held and K2 (0 m off, the one just named, 25 m on) is skipped (bus.rs:581-594); name typed on line B vanishes, K2 dropped at next load. Fix: when two candidates are within 50 m, hold the one nearer the route.
4. keep_epoch is not bumped when a connected station is removed or restored by undo (net/keeps.rs:32; link_live is lazy). Matters for stage 3-5 readers, so either bump it from set_station or have the app also read on the station dirty list.
5. keep_epoch restarts at 0 on load, so can equal the old game's value; the app must reset its cached epoch on load (stage 3).
6. Known and documented: a removed station's node id reused later brings the connection back at any distance (link_live has no 1 km check); a named stop whose line is deleted is saved but forgotten at the next load (design lie); 1,000-stop cap does not cover crossings and middles added after (needs hundreds of kept stops on one line).
7. Low: LBK1 decode aborts the whole load if a kept stop is outside the world (save.rs set_keep map_err); only reachable after a frame conversion. Other blocks skip bad entries instead.

## Stage 3: names in the game (busnames3, 2026-11-25)

Built: a bus stop's name can be set in its panel (the station's NameEdit, with `clearable`: emptying the box takes the name off), and shows in
the panel, the stop's hover, the bus line panel's rows and everything that reads `stationNames` (trip explorer, timetables).

- Worker: `renameBusStop { stops, x, y, name }` (clockEdits, `renameBusStop` in clockDemand): `name_keep` on the first of the place's stops that has a kept
  stop, else a new one at the stop's own place. `nameOnly` is true for a non-empty name on an existing kept stop (rows only, no network); making or clearing
  one is a normal network edit (it can re-plan lines near it).
- Rows: `ClockState.keeps` (named kept stops, `namedKeeps`, read again when `keep_epoch` moves; `forgetKeeps` in `restart` since a load starts the epoch over,
  review finding 5) becomes `Save.keeps`, same array while unchanged (`keepsKept` in clockClient, 2 lines in toWorld's save).
- `stopsOf` (world.ts): a plain stop takes the nearest named kept stop within 50 m (`KEEP_M`), else the automatic name. A stop with no name of its own in a place
  (`busPlaces`) where another has one shows that one. `namedBusStops(w)` lists the stops showing a player's name. The per-line cache (T-4150) also keys on the keeps array.
- Hover: `busStopTip` first row is the name. Bus line panel: `stopRows` splits a gap's street stops around each named stop; a named stop's row opens its panel.
- Not touched: pagestage3's files, except 3 lines in clockClient.ts (`keepsKept` and the one `keeps` spread in toWorld's save).

Small lies: the app matches a stop to a kept stop by nearest position within 50 m, the sim by the held stop (a held stop is its own kept stop's even when another is nearer):
differs only for two kept stops within 50 m, which only route edits can make. A name on a stop whose line is later removed waits for the spot, as designed.
Review findings 1-4 of stages 1-2 (sim) are not fixed here (this stage is app only).

Game run (nyc new game, sandbox, port 6178): drew and constructed a bus line (16 stops), named stop 6 "Probe Corner" in its panel (double click name, type, Enter): panel title,
hover tip first row and `stationNames` show it, its neighbour stays "Bus stop"; extended the line by a 4th point (26 stops): the stop stayed (to 0.02 mm) and kept the name,
the line panel lists "East Harlem / 19 street stops / Probe Corner / 4 street stops / Union Square"; export then import: the keep and the name came back, 26 stops.
