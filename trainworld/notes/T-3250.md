# T-3250: one-way track used both ways (player report, live v0.3)

Agent oneway, 2026-11-11.

## The report

Dale X on live v0.3 (3a442a6e), Shanghai, Kaixuan Road by Hongqiao Road, +2 level picked: "when dealing with the
intersection of two lines, bidirectional trains on one line use the same unidirectional track to travel (set tracks as
one-way)". The picture: a purple line beside a yellow one near a station, a short dashed dark piece on the purple's
left track with a yellow-and-dark dashed piece below it, purple arrows pointing both ways on one track, blue
triangles pointing up on the other.

## Reading

The player made a stretch of the purple line's track one way in each direction where it meets the yellow line: two
pieces of single track side by side, each set one way (or a flyover's one-way legs, which the ramp switch lays at a
new junction). The "dashed dark pieces" are trains: a train close in is drawn as its cars, which reads as a dashed
stroke in the line colour and dark. The blue triangles are ramp marks to +2 (blue is +2's Elevation colour); the dark
chevrons are the one-way track arrows. They watched purple trains going both ways on one of the one-way tracks.

## Cause: a drawing bug, live and master alike

The sim is right. A line that goes both ways over one-way track takes its own way back (T-3094,
`Network::back_path_of`), and `build_run` builds the return run (run 1) on it, so the timetable, capacity and
occupancy use both tracks.

The map is wrong. Every train of a line is drawn along **run 0's geometry**: the worker resamples run 0 only
(`clock.worker.ts`, "run 0 of every line resampled", `run_polyline(id, 0, ...)`), and the train shader's `trainDist`
places a run-1 train at `M.w - s` along those samples (`rendererShaders.ts`), the CPU mirror `tripAt` the same
(`map/network.ts`). So a return train is drawn on the outbound track, against its arrows; the track its return run
really takes (stroked in the line colour since T-3117) never shows a train. It hits every line with a way back of its
own: a player's pair of one-way tracks, and every branch line through a flyover (its return trains are drawn on the
plain leg). Not T-3202 or T-3212: those are single track run both ways. The arrows are right; the router never sends
a run against one-way track (a line with no way back is broken).

Same code on live (3a442a6e, worktree with the release-031 WASM) and master (409a962e plus the tree's uncommitted
work): nothing touching train placement for return runs landed between.

## Fix (built on master's working tree, 2026-11-11, after split landed)

A return run on its own way back is drawn along it, as a run 0 of its own row of the line table.

- `workers/clock.worker.ts`: when any line has a `back`, the line table doubles; row `nLines + line` holds that
  line's run 1 sampled by `run_polyline(id, 1, SAMPLE_STEP)` (`drawnBack`, cached by the back path, dropped on any
  edge edit, re-expressed on an anchor move), its length the run-1 profile's. No protocol change: the second half
  is found from `meta` (`backBaseOf`, `backSlotOf` in `map/network.ts`).
- `map/network.ts`: per-sample arrays for the slot from the back path (`runSamples`): strokes (the back-only
  strokes T-3117 adds, the path's own on shared edges, `LineEntry.backStroke`), so fill and stretch follow; lanes;
  bands taken from the path's on shared edges, negated where the way is reversed; passing bows via `linePassing`
  on the back path (scratch output, so the outer tracks are not drawn twice). `pathTable` gets the slot's entries.
  `trainFrame(n, profile, s)` gives the row, drawn run and offset; `tripAt` returns `geo`, `gr`; `trainCarAt` uses them.
- `map/rendererShaders.ts`: `trainDist` takes the slot for run 1 when `u_back_base` says there is one (`g_own`);
  drawing (side, end clearance, across, fill sample ahead/behind, front, cab) uses the drawn run `g_run`, the fill
  channel and the loads' stretch step keep the real run. `map/renderer.ts` sets `u_back_base` for the train and
  probe programs.
- `map/trainGuard.ts`: rows past the lines map to their line for sharing and guarding; candidates of such a run
  key their track by the slot's entries as a run 0 (track, conflicts, single-track turns); the view test and
  line box take the slot's samples. A known gap: `outerAt` (passing stations, beside each other) skips them.
- `map/pick.ts`: `tripMayBeNear` uses `trainFrame`.
