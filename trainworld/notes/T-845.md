# T-845: demand waiting forever in a far new game

Found building loop lines (T-798): a ring of six stations in a fresh `?new=1` game never got a final;
the same steps on the real New York save did.

## Repro (2026-10-21, own Vite on 6167, headless Chrome)

A line of 4 stations, a ring of 6 and a closed loop of 6, each 2 km across, built by the edit API,
waiting for `view.final` with the line in it (90 s limit):

| Start | Where built | Result |
|---|---|---|
| `?new=1`, camera left on New York | Tokyo, London, Toronto (ring, loop, line) | final in 8-12 s |
| `?new=1`, jumped there first, built at once or after a tool pick | Tokyo, London, Fukushima prefecture | final in 5.6-8 s |
| New game sheet: Tokyo, London, Paris, Fukushima | the start's centre | final in 6.8-9.1 s |
| `?new=1`, camera left on New York | Kansas (dead space) | final in 2.7 s (New York solved alongside) |
| `?new=1`, camera jumped to Kansas | Kansas (dead space) | **stuck**: `client.waiting` holds the 4-station network forever, the view stays on the empty network's version |

So any city with a pack works; what hangs is a network that reaches no zone while the view is over
dead space too, which a check or a player building away from every modelled place hits, and which
the real save never shows (its own stations always need New York).

## Cause

T-318's `idle()` in `workers/demandClient.ts`: when neither the view nor any station needs a pack,
`flush()` settles idle and returns before looking at the waiting network. Nothing is wrong with
loading nothing there, but the waiting network was never sent to the workers either, so its lines
never had figures and `waiting` was never cleared. Not T-801's market rule, nor a frame error.

## Fix

`idle()` is false while a waiting network has stations: `flush()` then dispatches it with no pack
open (the workers already solve an empty city list; lines no population reaches are in no cluster
and carry nobody). Dead space still loads nothing, the start over dead space still settles at once.
After the fix the Kansas line gets its final in 2.7 s with 0 riders.

## Check

`checks/smoke.mjs` step "far new game final": on a page of its own, a `?new=1` game builds a line
over dead space (view there too) and then one in Tokyo; both must reach a final, the first with 0
riders and the second with some. With the fix undone the dead-space case times out as above.
Scratch repro script (not kept): scratchpad `t845/repro.mjs`.
