# T-050 incremental capacity pass

Done 2026-10-09 by the performance agent (batch 4). Code in `sim/src/track/capacity.rs`
(`Capacity::update`), called from `Service::update_scoped` (`service.rs`) with what the edit
touched (`world.rs`, `commit`).

## What it does

The global pass (T-040) rebuilt every resource and every user on any line, schedule, crossing or
junction change: 10-13 ms at 10,000 route-km and 400 lines, the floor of every line edit there.
Now an edit throws away only the resources it can have changed and builds those again with the
same code the global pass uses:

- **Dirty edges**: what `derive` touched, plus every edge on the old and the new path of each
  rebuilt line. **Dirty nodes**: what `derive` touched, stations the edit touched, both ends of
  every dirty edge, every node on those paths.
- **Sections** (double and single track): a section is rebuilt when any of its edges is dirty or
  ends at a dirty node. All its directed track keys are rebuilt together, and sections only join
  inside that set. Why that is exact: a clean key next to a rebuilt one joins it only across a
  clean two-ended node between two clean edges, where the join test (same set of line
  directions, same track count, no platform) gives what it gave before; so if they join now they
  were one section before, and the whole old section was rebuilt.
- **Platforms, termini, junction moves**: those at dirty nodes.
- **Flat crossings**: those with a dirty edge on either side.
- **Solve**: the new resources, and the old ones a rescheduled line uses (its trains per hour
  changed, its resources did not).
- **Holds**: recomputed only for lines that own a rebuilt resource or one whose delay changed,
  plus rebuilt and rescheduled lines; the other lines' profiles are not looked at.

Resources keep no order: they are swap-removed, and new ones are appended. Users and section keys
sit in pools whose dead entries are compacted when over half. Indices into `cap.res` stay valid
until the next edit, as before. `Capacity::canonical()` sorts them for comparisons.

`Service::update` without a scope still runs the global pass (`update_all`, loads, tests).

## Checks

`incremental_equals_global` (capacity.rs): six synthetic networks (250 route-km, 70 stations,
12 lines, flat crossings and junctions), 80 random steps each: PI moves, schedule changes,
splits, deletes (lines reroute or break), flying junctions on and off, single and double track,
platform lengths, a stop dropped, a line removed, undo and redo. After every step the resources,
users, utilisation and delays equal a fresh global pass, and so do every line's holds, profiles,
round trips, trains and delay. Two deliberate mutations (keeping node resources; killing
sections only on touched edges) both fail it on the first steps.

One behaviour change in `world.rs`: touching a station now wakes the capacity pass even when no
line stops there, since a line passing through gets a platform resource. Before, that resource
appeared only at the next unrelated full pass.
