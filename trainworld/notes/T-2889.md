# T-2889: Portuguese (pt)

Language code `pt`, as `es` is plain (one neutral Spanish): Intl's plain `pt` is Brazilian Portuguese, and
Portuguese browsers (`pt-PT`) also map to `pt`. Write Brazilian Portuguese (pt-BR spelling after the 1990 accord:
"ação", "ótimo", "equipe", no "facto"), the much larger player population; where Portugal differs
(comboio/trem, autocarro/ônibus, ecrã/tela), use the Brazilian word.

## Voice

- Full sentences address the player as `você` in the imperative ("Escolha uma cidade", "Construa uma linha"),
  or with no pronoun. Never `tu`, never `vós`, never the formal "o senhor".
- Buttons, labels and toggles: the infinitive ("Construir", "Excluir linha", "Mostrar cores das linhas"), the way
  Brazilian software words them. Tool names are infinitives or plain nouns.
- Plain, short, a little cute, like the English. No "gerenciar", "otimizar", "experiência" as filler.
- Numbers are formatted in code (Intl pt: 1.234,5 and compact "763 mil", "1,2 mi"). Percent has no space (85%).
- Periods only on full sentences; phrases, labels and hovers end bare.
- Kept as written: km, m, mi, ft, km/h, mph, m2 and the money symbol.

# T-2889: Turkish (tr)

Language code `tr`. Intl's `tr` numbers and lists are right as they are (1.234,5; compact "763 B", "1,2 Mn"); the
page font Nunito covers ğ ş ı İ in its latin-ext slice.

## Voice

- Full sentences address the player as `sen`, in the imperative with no pronoun ("Bir şehir seç", "Hat kur"). Never
  the formal "siz" forms (seçiniz, kurunuz), never "-mektedir" or other office Turkish.
- Buttons and toggles: the imperative stem ("Kaydet", "Hattı sil", "Hat renklerini göster"); tabs and labels are
  plain nouns. Tool names are plain nouns or imperatives.
- Plain, short, a little cute, like the English. No "kullanıcı", no "gerçekleştirmek" or "yapmak" where a real
  verb exists.
- A noun after a number stays singular: "3 istasyon", "12 dakika". Plurals are still `one` and `other` ICU
  branches (both may read the same).
- Percent goes before the figure ("%85"). Periods only on full sentences; phrases, labels and hovers end bare.
- Kept as written: km, m, mi, ft, km/h, mph, m2 and the money symbol.

## Suffixes and placeholders

Turkish endings change with vowel harmony and soften consonants, so a placeholder that holds a name or a number
never takes a case ending or an apostrophe suffix ("{city}'de", "{n}'ncı" are out). Reword so the value stands
alone:
- A label and a colon: "Şehir: {city}".
- A postposition after the value, which takes no ending from a name: "{city} içinde", "{a} ile {b} arasında",
  "{n} dakika boyunca", "{line} için".
- The value as the first half of a compound whose ending is on the fixed word: "{name} istasyonu", "{name} hattı",
  "{city} yolcuları".
- The question particle never follows a placeholder; put a fixed word before it ("{what} silinsin mi?").
- Possessive endings on a fixed word that follows a value are fine ("a long chain of endings after a name is not: write "{name} hattı için" or reword to a label).

## Dotted and dotless I

Turkish has four letters: İ i (dotted) and I ı (dotless). Write each by hand, correctly ("İstasyon" opens a
sentence, "Işık", "ılık"), and never write a string that depends on case-mapping to come out right. The code does
call `toLowerCase` and `charAt(0).toUpperCase()` on some translated words (a period, purpose or day-kind name inside a sentence, the first term of a list), so a word the code lower-cases contains no I or İ and a word it capitalises does not start with i or ı (T-2889 checked every such key; a new Turkish purpose or period name must keep to this, or the code needs `toLocaleLowerCase(lang)`). `checks/i18n.mjs` folds the combining dot (U+0307) that a JS lower-casing of İ leaves, so a glossary stem still
matches.

# T-2889: Russian (ru)

Language code `ru`. Intl's `ru` numbers and lists are right as they are (1 234,5 with a no-break space; compact
"763 тыс.", "1,2 млн"). The page font Nunito covers Cyrillic only through its cyrillic subset, which this stage
added (`public/fonts/Nunito-cyrillic.woff2`, listed in `game/fonts.ts`); without it Russian falls to the system face.

## Voice

- Full sentences address the player as `вы` in the imperative ("Выберите город", "Постройте линию"), lower-case
  "вы", never `ты`, never office Russian ("осуществить", "данный", "производится").
- Buttons and toggles: the infinitive ("Построить", "Удалить линию", "Показывать цвета линий"); tabs and labels
  are plain nouns. Tool names are infinitives or plain nouns.
- Plain, short, a little cute, like the English. No "пользователь", "функционал", "опция" where a plain word exists.
- Percent: write "85%" with no space.
- Periods only on full sentences; phrases, labels and hovers end bare. Quotes and dashes: no em dashes (house rule);
  use a colon or a period. "ё" is written where it changes the word ("всё", "ещё"), as modern game text does.
- Kept as written: km, m, mi, ft, km/h, mph, m2 and the money symbol.

## Plurals

Russian has `one`, `few`, `many` and `other`. Write all four on every count plural; `one` is 1, 21, 31 ("1 станция",
"21 станция"), `few` is 2-4, 22-24 ("2 станции"), `many` is 0, 5-20, 25-30 ("5 станций") and `other` is a fraction
("1,5 станции", genitive singular). `#` is the count. A noun after a number that always reads as the genitive
singular or plural still gets all four branches (they may repeat).

## Cases and placeholders

Endings change with case, so a placeholder that holds a name or a number never takes an ending or a preposition that
needs a case ("в {city}", "на {name}", "{city}а" are out: names from the data stay as they are, and Russian cannot
decline "Osaka" or "Shin-Yokohama" by rule). Reword so the value stands alone:
- A label and a colon: "Станция: {name}", "Город: {city}", "Линия: {line}".
- The value after a fixed noun that takes a case itself: "линия {line}", "станция {name}" (the noun is inflected,
  the name is not: "на станции {name}", "от линии {line}").
- A number before a counted noun with a plural: "{n} мин", "{count, plural, one {# станция} few {# станции} many {# станций} other {# станции}}".
- Where English puts a name after a preposition ("Remove {what}?"), put a noun in front: "Удалить: {what}?" or
  "Удалить объект «{what}»?" when the placeholder is a name; a colon is shorter.
- Past tense and adjectives agree with a gender; a message whose subject is a placeholder avoids it: write
  "Станция: {name}, построена" rather than "{name} построена".

# T-2889: German (de)

Language code `de`. Intl's `de` numbers and lists are right as they are (1.234,5; compact "763.000", "1,2 Mio."); Nunito's
Latin subset covers ä ö ü ß, so no font work. German runs about a third longer than English: narrow places (buttons,
segmented controls, tabs, tags) use the short forms below, and a screenshot pass checks them.

## Voice

- Full sentences address the player as `du`, in the imperative with no pronoun where possible ("Wähle eine Stadt", "Baue
  eine Linie"). Always lower-case "du", "dein", never `Sie`, never "man" stacks or office German ("erfolgt", "vornehmen",
  "Durchführung"). Why `du`: games of this kind (Mini Metro, Transport Fever's community text, Dorfromantik, Cities:
  Skylines' German UI hints, indie builders in general) address the player as `du`; `Sie` reads like a bank or a tax form,
  and the English is friendly and short.
- Buttons, toggles and menu items: the infinitive ("Bauen", "Linie löschen", "Linienfarben anzeigen"); tabs and labels are
  plain nouns; tool names are nouns or infinitives. A button never needs `du`.
- Plain, short, a little cute, like the English. No "Nutzer" (say "du" or "Spieler" only where the English says player),
  no "Funktionalität", "Option" where "Einstellung" or nothing will do, no "Tätigkeit".
- Compounds are written as one word ("Fahrgastzahl", "Gleisbau"); when the compound is longer than about 18 letters in a
  narrow place, use a shorter noun or an abbreviation.
- Percent: "85 %" with a no-break space is Intl's form; in a message that writes a literal percent sign, write "85 %" (U+00A0).
- Quotes: „…“ . No em dashes (house rule); use a colon, a comma or a period. Periods only on full sentences; phrases, labels
  and hovers end bare. "ß" is written (Straße), never "ss", except where the string is upper-case.
- Kept as written: km, m, mi, ft, km/h, mph, m2 and the money symbol.

## Plurals

`one` and `other`, as English: `{count, plural, one {# Station} other {# Stationen}}`. Where the noun does not change
("# Min"), both branches read the same. A fraction takes `other`.

## Cases, gender and placeholders

German articles and adjectives take the noun's gender and case ("der/die/das", "den", "dem", "-e/-en"). A placeholder that
holds a name or a thing from the data has no gender the sentence can know, so never put an article, a possessive or an
adjective in front of one, and never hang a case ending or a genitive -s on it ("{city}s", "die {name}" are out). Reword so
the value stands alone:
- A label and a colon: "Station: {name}", "Stadt: {city}", "Linie: {line}".
- A fixed noun, then the value: "Linie {line}", "Station {name}", "Zug {train}" ("auf Linie {line}", "an Station {name}").
- A preposition that takes no article before a name: "in {city}", "nach {city}", "von {a} nach {b}", "zwischen {a} und {b}"
  (place and line names take no article).
- Where English says "Remove {what}?" with an unknown thing: "{what} entfernen?" does not need an article; "Gelöscht: {what}"
  likewise. Do not write "Den/Die/Das {what} entfernen?".
- A message whose subject is a placeholder avoids a predicate adjective or participle that agrees: "Linie {line}: gebaut"
  rather than "{line} ist gebaut" (the participle is invariant, so "ist gebaut" is fine; "{x} ist fertig" is fine, but not
  "{x} ist lang" if x could be plural; use a label and colon then).
- Number words: a count before a noun ("{n} Stationen"), never "ein/eine {n}".
- A placeholder holding a purpose, period, level or day-kind name (lowercased by the code in English) is a German noun and
  keeps its capital: `game/purposes.ts`, `Blueprint.tsx`, `OneRider.tsx`, `schedule.tsx`, `TrainInspector.tsx`,
  `MarketTrip.tsx` and `TripInspector.tsx` lower-case a translated word through `lowerWord` (`i18n/index.ts`), which leaves
  German as written (T-2889). So a German period, purpose, level or day-kind name is written as it would be inside a
  sentence: a noun with its capital ("Arbeit", "Frühspitze", "Tunnel"), and it must be fine after "in", "an", "für" with no
  article. The code also capitalises the first letter of some translated words (`capitalise`, `cap` in
  `blueprintStretches.ts`), which is harmless for German.
