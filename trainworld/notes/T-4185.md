# T-4185 One undo takes back one player action (agent undocopy, 11-24)

Cause: the sim's undo history had one step per edit, and the worker sends Copy line, New line (rail, bus, ferry) and a
stops edit that changes a line's type as several edits (the line, then badge, headways, weekend share; the type, then the stops).

Fix: `TrackApi::join_edit(on)` (sim/src/track/wasm/edits.rs): while on, `run` applies each edit through
`apply_off_history(.., with_edit = true)`, the mechanism T-3646/T-4104 made, so it undoes and redoes with the edit before it.
workers/clockEdits.ts turns it on after the first edit of addLine, addBusLine, addFerryLine, copyLine (`joinAfter`) and for
the stops edit of withAutoFast; `apply` turns it off in its finally. Undo drops the joined edits that set a line the undone edit
made; redo makes them again. workers/clockWord.ts no longer marks these ops `noUndo`, so an undo right after is drawn at its click
(undoShow, from the network before the edit): the copy's undo drew 10 parts on NYC, 23 on Asia; a new line's 2 and 6.

Checks: sim test joined_edits_undo_and_redo_with_the_first (agent_cargo.py test, 740 + 969 passed); typecheck clean;
checks/t4170-one-path.mjs on NYC and Asia pass, with new cases (copy then undo, new line then undo: line count back, undo drawn).
Game run: the check is the real game on both saves; after a copy, one undo leaves 110 (NYC) and 222 (Asia) lines as before.
Not covered: a stops edit with autoFast (joined by the same call, no check). Smoke not run (rule of the night).
