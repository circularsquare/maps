# T-3640 a long-played network still can't be shared

Cause: the game refused its own save before sending. Sharing with "Let others open a copy" builds the save in the page (game/sharedSave.ts forShare, which reads it back through readChecked). readChecked had a cap on the save header of 8 MB (MAX_HEADER). A long game's header holds every region's ledger, one entry per game day each, so it grows with days played. Swattik's share on the server (2ia58w78 rev 7, day 1093, 173 regions) has a 6.07 MB header (6.38 MB unpacked, 824 KB gzipped); each game day adds about 20 KB, so about 100 days later it passed 8.39 MB. forShare returned null and community.ts showed errSend ("This network could not be sent."), the generic text, not "too big". It worked once and then stopped, which fits. The drawing was fine (163 KB gzipped, cap 1000 KB).

Reproduced: his rev 7 save with 300 days of ledger added (11.9 MB header, 1.0 MB gzipped) gave forShare null before the fix and a 1.03 MB save after. 100 days (8.0 MB) passed both ways (the cap is 8.39 MB).

Fix (game only): MAX_HEADER dropped (the unpacked cap of 32 MB already bounds it); forShare returns "big" when the re-gzipped save is over the server's 2 MB, community.ts shows "This network is too big to share." for that. At his growth the 2 MB gzip cap is reached about 400 more game days on (real ledger data packs about 7.7x). Past that the share fails with the "too big" text; with "Let others open a copy" off it still goes (drawing only).

Ruled out: server body limit (Caddy has none, Go MaxBytesReader sums to 3.1 MB), drawing caps (Go twParseDrawing passes NYC 854 stations, asia 1876, na476 1793, Japan real 9075 stations/678 lines at 692 KB, his own rev 7 shape), HTTP timeouts (ReadTimeout 5 min; a network failure shows "account.unreachable"). Other errSend sources that remain: exportForShare 60 s timeout, a header value that is not a number (NaN saved as null), server bad-upload/bad-drawing/bad-save.

Also seen: the drawing step alone took 40 s (NYC), 67 s (1,800 stations), 166 s (his), 184 s (Japan 9,075 stations) paused on this machine; SHARE_WAIT_MS is 5 min, so a slower machine or bigger network meets "The diagram could not be drawn. Try again."

Follow-ups for the orchestrator: (1) thin or pack the per-day region ledgers in a shared save (or raise MaxTwCommunitySave / MAX in sharedSave.ts to 4 MB together, a server deploy); (2) the drawing wait for a 9,000-station network.
