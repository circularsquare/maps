# T-4280 Edits name the lines they changed for the renderer (agent linenames, 2026-11-25)

**For Anita.** After T-4274 each line had its own place in the trains' tables on the graphics card, but to find which
lines an edit changed the renderer compared every line's numbers with the last ones, 9-43 ms of an edit on your Asia save.
Now the worker, which makes those numbers, says which lines it changed, and the renderer writes those and compares
nothing. On your Asia save the renderer's part of an edit is 10-28 ms (a station placed 12, removed 10, line 33 deleted
28, its undo 23), against 50-149 ms in T-4274 and 14-60 ms in T-4262 stage 2, with the same bytes sent as T-4274. That
is about 40-120 ms off an edit's wait of 1-2 s there (3-8%). Nothing you see changes: the map and the trains draw the
same, checked number for number on the graphics card after every edit.

## Why the renderer compared, and what names the lines now (the code)

The trains' tables come from three places in the clock worker, and each now names the lines whose values differ from
the last ones posted, at the place it makes them:

- **Samples and bends** (where each run goes, `samples`, `bendAt`, `bends`): `ClockState.touched.paths`. T-4149 filled
  it from the model's list of moved lines, which missed a return run on its own way back (all of them are sampled again
  after any track edit, `backDrawn.clear()`, unnamed), and named every bus and ferry line on most edits (dropped onto the
  same route). Now clockMain.ts keeps a dropped run's samples and bends until it is sampled again (`dropped`,
  `droppedBack`) and names it only where the new ones differ (`resampled`), so the list is exact and costs a compare of
  the runs sampled again only. The model's list running over (`take_moved_lines` says all) no longer names every line.
- **Phase tables** (`phases`): `ClockState.touched.phases`, new. `StateRows` already compared each re-read line's tables
  (`readPhases`); it now remembers those that differ until a state carrying the tables is posted (a network's or a train
  count's, `phasesPosted`). Past 48 lines it reads every table in one call (`splitPhases`), and there compares every
  table with the last (that read is a pass over all of them anyway); a fresh read names all.
- **Stretches and lanes** (`stretch`, `lane`: side-by-side bands, track spacing, passing tracks): `NetPatch.stretches` and
  `NetPatch.lanes`, new, from the drawn network's build (map/network.ts). Paths cannot name these: deleting a line moves
  the bands of the lines that shared its track without moving their runs. A run is named where the build made its
  samples again to other values (`sampleValuesDiffer`, stretches and lanes apart, so a band change sends no stretches),
  or its passing places along it changed (`NetCache.passOf`, `samplePass` being worked out every build). Most runs made
  again have the same values (a station placed on shared track remakes every line through the split piece).

The renderer (renderer.ts `trainNames`, trainSlots.ts `putSlots` with `SlotNames`) writes a table's named lines, those
whose slot moved or grew, and those blanked, and nothing else; `bendAt` also where a line's bend points moved slot. It
uses a list only when the network came as a patch on the one drawn, `touched` is not "all", and the table was last
written from exactly the previous network's arrays the list is about; otherwise it compares as before, counted per table
in `renderer.trainCompares`. A train count (`setService`) writes the phase tables by `touched.phases` the same way; the
client now drops a train count's state when it holds no network to put it on (clockClient.ts `takeNet`), so it asks for
a whole one, as it does for a network it cannot merge.

What still compares, each a table last written from arrays built whole on the page: the demand views' fill
(`setLayers`, every network: 4-7 ms a call on Asia, the compare in it), the Traffic view's bands in the lanes, and hidden
levels. Making those by line is demandLayers.ts's (`buildLayers` makes every line's fill and widths again).
