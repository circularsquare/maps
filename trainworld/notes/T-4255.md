# T-4255: Port PR 29 (cached shortest-path trees in stop-marker scans)

Ported Leni-Vienne's PR #29 ("Speed up stop-marker scans on large rail networks") by hand against current master, with a lower retained-tree memory cap.

## What was ported

- `trainworld/sim/src/track/net.rs`: re-exported `paths::PathTree` under `#[cfg(feature = "track-api")]`.
- `trainworld/sim/src/track/net/paths.rs`: added `PathTree` (`arrivals: Vec<[u32; 3]>`, `prev: Vec<u32>`) and `Network::path_tree`, refactoring `find_path_side` onto a shared `search_paths` helper while **keeping master's `self.edge_barred(e, tram)`** (so trains and trams stay off T-3378 busways).
- `trainworld/sim/src/track/perdir.rs`: added `Network::route_legs_with` (used by `route_legs_t` and `route_memo`) and parameterized `leg_run` over the route closure so one-way-station leg routing shares `HopMemo` instead of bypassing it.
- `trainworld/sim/src/track/wasm.rs`: extended `HopMemo` with `StopSearches` (keeping `PathTree`s for the line's stops across candidates and the current candidate's trees only while it is tried), split `route_plain_memo` out of `route_memo` while **keeping master's 3-argument `net.carry_worth(&path, &carry.0, &plain.0)`** (T-4223), and routed `route_plain_close` through `memo.hop`.
- `trainworld/sim/src/track/wasm/lines.rs`: split `stop_tiers` into `stop_tiers` (using `HopMemo::for_stop_scan`) and `pub(super) fn stop_tiers_with` (calling `memo.try_station(n)` per candidate) so unit tests can compare cached vs uncached scans directly.
- `trainworld/sim/src/track/wasm/tests/route_tests.rs`: added `stop_tiers_cached_matches_uncached` verifying exact equality between cached, capped-cache fallback, and uncached scans on an open branching/reversing network and a 3-stop ring.

## Memory cap and what it costs

- PR #29 capped retained `PathTree` arrays at 32 MiB (`line_limit = (32 MiB / bytes_per_tree) - 6`), which added up to +19 MiB of WASM linear memory under the small-device 8 MiB grow step.
- This port lowers the cap to **8 MiB** (`STOP_TREE_BUDGET = 8 * 1024 * 1024`), keeping retained tree memory within Anita's 10 MB edit-speed memory guideline (`DECISIONS.md`, T-4144).
- **What the cap costs:** Each `PathTree` uses `(2 * edge_count + 3 * node_count) * 4` bytes. On medium-to-large single-city networks (e.g. Belgrade, ~1–2k nodes/edges), a tree is ~20–60 KiB so 8 MiB holds 130–400 trees — enough to cache every stop's arrival-side trees on even a 58-stop line with zero fallback cost. On very large multi-city saves (e.g. 10k nodes / 12k edges, ~216 KiB/tree), 8 MiB holds ~32 line trees plus 6 candidate trees; stops past the first ~32 `(stop, arrived, tram)` keys fall back to single-target `find_path_side`, trading a small fraction of the speedup on 40+ stop lines to avoid permanently growing WASM linear memory by 19+ MiB on small devices.
