# T-2403: blueprint lag after a click, fixes 1, 2, 3 and 5 of notes/T-2388.md (2026-11-04, agent lagfix)

## What changed

1. **Achievements off the edit path** (`game/achievements.ts`): `networkFigures` and `demandFigures`
   read `achWorld`, the stations list and the running lines (line and line-stats objects), which is the
   same object while those stay, so a track edit no longer reruns them. The corridor sums by place are
   kept per corridors object and set of places (`corridorSums`). For this, `toWorld`
   (`workers/clockClient.ts`) keeps a line's `LineStats` object while its row stays, as it already did
   for stations and lines.
2. **The clock worker's network** (`map/network.ts`): `complexPassages` keeps each complex's joins
   (`NetCache.passages`, by first member) while its members, their station pieces, places and passages
   stay; a player's passage between two complexes (none should exist) works everything out again. A
   line's band is compared by `sameBand` only when it is a different object (lineBands already hands
   back the last profiles when no path or edge under a line changed).
3. **The LOD band in slices** (`map/renderer.ts` `workBand`, `map/strokeLod.ts` `simplifiedLater`): after
   the significance, a zoom band's copy is made in 8 ms slices (fill, boxes, `a_wmul`/`a_full`, upload),
   one band at a time; the full set is drawn meanwhile (the copy differs from it by under 0.25 device px).
4. **`fullAttr` once** (`map/renderer.ts`): the network lines' `a_full` is only `writeFull`'s (the buffer
   is allocated empty in `strokes`); the track's is patched by runs like the other attributes, unchanged
   runs copied on the GPU. `?patch=check` compares the patched track `a_full` with a whole one.
5. **`toWorld`'s nodes map** kept while the node rows are the same objects, so the snap's node grid
   stays. After a click's state a node is new, so that state still rebuilds the grid once.
