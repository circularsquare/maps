# T-3759 Station names bound to their complex by choice

A player: since T-3750 a station complex can no longer have a name apart from its stations. Anita, 2026-11-19: a
toggle to bind, on by default; a game-wide setting for new stations; "ideally just one button for binding".

## What is true now

- **Data shape** (advisor called before building; it agreed and added the old-save pass). Each station keeps its
  stored `name` + `named` (T-2683), its part in the complex's name, whose rule is T-3750's unchanged
  (`nameSource`: oldest typed, else oldest, over every member, bound or not). New `StationData::own` (String, empty
  while bound): an unbound station shows it. Two strings so the complex keeps a name when every member is unbound,
  and unbinding the name source never moves the complex's name. Undo comes through `Op::Station`.
- **One shown name**: `StateRows.foldNames` gives each row `name` = own, else the complex's (a complex of one: what
  that station shows), and `hub` = the complex's name where it differs. Labels, panels, lists, buildings and the
  diagram all read these rows; `complexTitle(s)` (`hub ?? name`) is the complex's name for the complex view title,
  Stations tab complex rows and diagram labels.
- **Renames resolved in the worker** (`renameStation`, `renameComplex` in clock.worker.ts), the UI sends intent:
  - station panel opened alone / Stations tab row with "Show stations separately": `renameStation`. Unbound: own
    name only (alone in its complex: its stored name too, typed, so a complex it forms later is called what the
    player saw). Bound: renames the complex.
  - complex view title, cycle button there, a Stations tab complex row: `renameComplex`: the name source takes the
    name, typed (`type_station_name`); unbound members keep theirs.
  - `stationProps` (platform changes) with the shown name is no rename; with another name it renames as the panel.
  - `complexRename` and the `stationName` op are gone.
- **The toggle**: station panel, single-station view of a complex of 2+, not a port: link icon button beside the
  name, lit while bound, hover "Use the complex's name". Unbinding shows the stored name again (as a split does);
  binding shows the complex's.
- **The setting**: Settings, Game, "Name new stations after their complex", on by default, the player's own
  (orchestrator, after review: "mostly a player preference"): `DisplaySettings.bindNew`, remembered in the browser,
  shown before a game is loaded too, used in every game; nothing in the save header. The page sends it to the
  worker on each change and after each load ("bindNew"; a worker with no game drops it); the worker passes it to
  `TrackApi.set_bind_new`, which keeps it across loads. New
  stations (`station_at`, `free_station`) start with own = their placed name when off; the quad twin copies the
  station beside it; ports never take part. Ticking it with some station unbound asks "Name existing stations after
  their complex too?" with "Only new stations" / "Rename all stations" (`bindAll`, one `Op::Batch`, one undo).
  Escape = only new.
- **Save**: block `LSN1` after `LFZ1`, written only when a station is unbound: count, then per unbound station its
  node index (dense) and its own name (string). LEVEL 26 -> 27, BLOCKS 32, pin test updated.
- **Older saves** (level <= 26, `OLD_BOUND_NAMES`): all bound, then on the first state build after the load
  (`take_old_names`) the worker unbinds each typed bound station whose stored name differs from its complex's
  (T-3750 showed those with their own name), with that name, off the undo history (`adopt_old_names`,
  `run_unrecorded`). Everything shows as it did before.

- **Labels**: an unbound member of a station building keeps its own label beside the building's name
  (`stationLabels.placeBuildings` leaves it out of the members whose names go). Far out (below zoom 13,
  `FLOOR_ZOOM`, where buildings' names start) a complex has one label with the complex's name: the first of its
  name groups in the list (most lines) shows `complexTitle` and the rest hide (`stationLabels.complexWide`, at
  placement; `labelGroups`/`NameIndex` untouched, a label keeps its group's `name` for reuse and the patch check).
  Close in each station shows its own (orchestrator, after review).

## Manual rename and unbinding

Built as decided: with binding on, a station panel rename renames the complex. Making a manual rename unbind
instead would undo T-3750's fix for the players who asked for it (their rename of one station is meant for the
whole complex), and would split names silently; the toggle keeps the split a visible choice.
