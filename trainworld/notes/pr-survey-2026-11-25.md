### PR #30: Fix automatic bus catchments extending past rail-linked stops (`Leni-Vienne`)

- **What it does:** When an automatic bus line divides its route into walking catchments for its street stops, it currently skips rail-linked stops when finding each stop's neighbours. As a result, a bus terminal or street stop next to a string of rail-linked stops gets assigned the entire stretch of road past all those rail stations, making distant riders appear to walk 2 minutes to the terminal instead of using the nearby stop. This PR includes rail-linked stops as boundaries in automatic mode so street-stop catchments stop halfway to the neighbouring rail station.
- **Fits master:** **Easy, with two small updates.**
  - [bus.rs](file:///C:/Users/anita/projects/maps/trainworld/sim/src/track/bus.rs#L697-L703): the exact buggy loop is still in master unchanged.
  - [bus_tests.rs](file:///C:/Users/anita/projects/maps/trainworld/sim/src/track/wasm/bus_tests.rs#L48-L69): master changed under **T-3924** (every Auto stop is now a demand stop, `a.bus_street(b)` is empty), so the context lines around the existing test moved slightly.
  - [docs/demand-kernel.md](file:///C:/Users/anita/projects/maps/trainworld/docs/demand-kernel.md): PR #30's diff says `600 m (BUS_REACH_M)`, whereas **T-4224** lowered `BUS_REACH_M` to **500 m** ([ARCHIVE.md](file:///C:/Users/anita/projects/maps/trainworld/ARCHIVE.md#L8), [DECISIONS.md](file:///C:/Users/anita/projects/maps/trainworld/DECISIONS.md#L169)).
- **Correctness:**
  - **Bug in master is real:** In [bus.rs](file:///C:/Users/anita/projects/maps/trainworld/sim/src/track/bus.rs#L697-L703), `open` filters out every stop with `station.is_some()`. If a bus has one non-station terminal at `s = 0` followed by 9 rail-linked stops over 9 km, `open` has length 1, so `stops[0].cover` becomes `[0.0, 9600.0]`, giving the terminal a 9.6 km catchment!
  - **Edge case 1 (Spaced / Hand mode):** PR #30 only fixes `!spaced` (Auto mode) ([pr30.diff](file:///C:/Users/anita/projects/maps/artifacts/trainworld/gemini/prs-2026-11-25/pr30.diff#L28)). In Spaced/Hand mode, `cover` is clamped to `g ± SPACED_COVER_M` (so it cannot stretch 9 km), but a street stop right next to a rail-linked stop can still extend its corridor past the rail station up to `SPACED_COVER_M`. That's minor, though using `boundaries = 0..stops.len()` unconditionally would be simpler and consistent.
  - **Edge case 2 (Closed loop bus):** If `closed == true`, `stops[0]` (`s = 0`) and `stops.last()` (`s = len`) share the same stop id; if `stops[0]` is a rail station and `stops[1]` is a street stop, `j = 1` sets `a = 0.5 * (stops[1].s + 0.0)`, which is right. If `stops[0]` is a street stop and `stops[1]` is a rail station, `a = 0.0`, `b = 0.5 * stops[1].s`, also right.
  - **Edge case 3 (Coverage gap around rail-linked stops?):** In Auto mode, after this fix, the stretch of road between `0.5 * (prev + rail_stop)` and `0.5 * (rail_stop + next)` is no longer covered by any street-stop corridor; riders there reach the bus through the rail station's normal station walking access (up to 300 m / 500 m walk to the station). That is the intended design (and matches what already happens when a bus stops only at rail stations).
- **Player-visible change:** Changes bus demand catchments and fixes absurd 2-minute walks over multi-kilometre stretches in the trip explorer; will shift ridership on Auto bus lines that run alongside rail stations. **Anita's call** because of [CLAUDE.md](file:///C:/Users/anita/projects/maps/trainworld/CLAUDE.md#L208) ("Buses are settled; no more bus tuning unless she asks") and because it changes ridership numbers, though this is clearly a bug fix rather than tuning.
- **Save format:** None.
- **Already decided / built:** No task or DECISIONS entry. (Related: T-3924 made every Auto stop a demand stop; T-4224 set `BUS_REACH_M` to 500 m.)
- **Recommendation:** **Port with changes** (pending Anita's OK). Fix the doc's `BUS_REACH_M` figure (500 m, not 600 m), adapt the `bus_tests.rs` context to T-3924, and check the real-save diff (and consider applying the boundary fix to Spaced/Hand mode too).

### PR #34: Capacity: a section runs on through a one-way pair (`xoaninc`)

- **What it does:** Fixes a capacity quirk where a double-track line splitting into two one-way single tracks (a one-way pair) and rejoining created three separate track sections instead of one. Because each section starts its own Kingman queue, busy lines sharing a one-way pair were delayed three times even though no trains merged or diverged; this PR lets directed track sections continue straight through a junction whenever the exact same set of trains enters and leaves.
- **Fits master:** **Easy (applies cleanly).** [capacity.rs](file:///C:/Users/anita/projects/maps/trainworld/sim/src/track/capacity.rs#L521-L541) matches the PR line for line (author rebased on 2026-11-24).
- **Correctness:**
  - **Incremental vs global capacity (`Capacity::update`):** Checked [capacity.rs](file:///C:/Users/anita/projects/maps/trainworld/sim/src/track/capacity.rs#L1334-L1455). When an edit touches any edge or node of a junction, `dn` marks the junction node, `he` marks *all* incident edges at that node, any existing `Tag::Section` touching `he` is killed and all of its keys are added to `kk`, and `build_sections` rebuilds them together. So incremental capacity stays consistent with global capacity (and the PR's test verifies `cap_matches_global`).
  - **Broader effect than just one-way pairs:** Removing `live_ports != 2` for directed track (`te && tf`) also joins sections across **any** 3+ port junction where the same set of `(line, run)` continues straight: for example, a flat crossing where Line A+B run north-south and Line C runs east-west (previously Line A+B had two sections plus the junction resource; now they have one section plus the junction resource), or a branch junction where a third line only uses the *opposite* direction of the double track. That is physically sensible (junction moves are already separate `ResKind::Junction` resources), though it will slightly reduce Kingman delay on existing saves that have shared lines passing through flat crossings or one-way pairs.
  - **Mixed tram/rail `edge_section_s`:** Joining across a junction uses `net.edge_section_s(path_edge(run.segs[i0]))` ([capacity.rs](file:///C:/Users/anita/projects/maps/trainworld/sim/src/track/capacity.rs#L583)), which already happens at 2-port nodes in master; not a new bug.
  - **Note on `tw/track`:** The track rework (`T-3951`, [ARCHIVE.md](file:///C:/Users/anita/projects/maps/trainworld/ARCHIVE.md#L191)) keys capacity by track id; if ported to master, it will need to be carried over when `tw/track` merges (or checked against `tw/track`'s `build_sections`).
- **Player-visible change:** Removes phantom extra queues at one-way pair ends (and through-junctions with unchanged line sets), making busy shared lines slightly faster there and slightly shifting demand figures on saves with those shapes. **Anita's call** under [CLAUDE.md](file:///C:/Users/anita/projects/maps/trainworld/CLAUDE.md#L27) ("how fast or far things go") and the figure-shift rule ([CLAUDE.md](file:///C:/Users/anita/projects/maps/trainworld/CLAUDE.md#L200-L202)), though it is a clear capacity bug fix.
- **Save format:** None.
- **Already decided / built:** No task or DECISIONS entry (T-3565 added one-way pairs; T-3945 fixed a separate scoped-update crash).
- **Recommendation:** **Port as is** (after Anita's OK and a real-NYC figure diff). Small, clean, well-tested fix for a real phantom queue.
