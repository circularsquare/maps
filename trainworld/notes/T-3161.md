# T-3161: flat junction badges on a two-way single track between two doubles

Agent flatbadge, 2026-11-11. Design and investigation only, no code changed. T-3164 at the end.

## What is happening

Reproduced on a new game: two double tracks crossing (east-west and north-south), and a single track chord from
the east-west one (east of the crossing) to the north-south one (north of it).

- Left on automatic, the chord runs one way (westbound off the east-west line, onto the northbound track of the
  other). Each end meets the track beside it, so no train crosses anything: no badges.
- Turn "Run trains one way" off and both ends get the Y badge.

The badges are true. A train running the chord the other way (southbound off the north-south line, then eastbound
on the east-west line) has to get from the far track to the chord at the first end, and from the chord to the far
track at the second, so it crosses the other track at both ends. Real railways call this a single-lead junction,
and that crossing is its known weak point. The game charges the waits for it once lines run both ways over the
chord.

What misleads is the drawing. When single track runs both ways, the game already connects each end to both tracks
of the double (it has to, or half the trains could not use it), but the map still draws the end landing on one
track only. So you see a clean merge with a badge on it and nothing that crosses. The track the end is drawn on
makes no difference to what trains can do once it runs both ways.

For comparison: press Reverse on the chord and both ends move to the far tracks, drawn crossing the near ones,
with a badge at each. There the picture and the badge agree.

## Options

### 1. Draw the link to the far track (my lean)

Where a single track that runs both ways joins a double, draw a short crossover from the track it lands on to the
other track, on the side the trains come from or go to, like the turn-back crossovers drawn at termini. That is
what a real single-lead junction looks like, and the badge then sits where the crossover leaves the track, so the
crossing is visible. One-way ends draw as today. No new text.

- A player sees: zoomed in (where double draws as two tracks), a short diagonal at each two-way end; zoomed out,
  as now.
- Work: app drawing only (the move table already has the link). About 3 hours with a check, the placement ghost
  included.

### 2. Say it in the badge's tag

Keep the drawing; the sim tells the app when a junction's only crossing comes from single track running both
ways, and the tag gets one more line.

- A player sees, hovering the badge:
  ```
  Flat junction
  Single track runs both ways, so some trains cross the other track
  ↕ 0
  ```
- Work: about 1.5 hours (a reason per node in the snapshot, the tag line, a check).
- Weaker than 1: you have to hover to learn it, and the picture still disagrees with the badge.

### 3. Say it at the switch

Under "Run trains one way", when it is off and an end joins double track, one line of text. This is where the
choice is made, so it says what the choice costs.

- A player sees, in the track inspector:
  ```
  Some trains cross the other track at both ends
  ```
  ("at one end" when only one end joins a double).
- Work: about 1 hour. Goes well with 1 as a small extra; on its own it leaves the map as confusing as now.

### 4. Don't badge single-lead junctions (not recommended)

Drop the badge where the only crossing comes from a two-way single end. The waits would still be charged, and the
line panel would still list "Flat junction near ..." for lines through it, so the map would hide a real cost and
contradict the panel. About 1 hour.

**Lean: 1**, optionally with 3. The model is right; the map should show what it is doing.

## As built (agent flatbadge, worktree .tw-trees/flatbadge, 2026-11-11)

Anita picked option 1. Also T-3164 and T-3189 in the same marks code.

- **T-3161** (`map/network.ts` `singleLeadStrokes`, called beside `passingTracks` in the turn-back builder): for
  each single piece with no way (`ClockEdge.oneWay` 0) and a counting join at an end, the double end at that node
  leaving most nearly opposite the single gets a 40 m stroke (`SINGLE_LEAD_M`, clamped to 0.8 of the piece) with
  `F_TURNBACK`, its lane going from the joined track at the node to the other (join 2, right looking out along the
  single, is the double's left looking out along it). Faded unless both pieces are built. Drawn only where double
  draws as two tracks, as turn-back crossovers are. No sim change.
- **T-3164** (`sim/src/track/lanes.rs` `Network::node_unusable`, bits `UNUSABLE_IN` 1 / `UNUSABLE_OUT` 2): on the
  node's move table, for one-way single (non-crossover) ends only, so a double's dead inbound track at a one-way
  taper is not flagged. `nodes_info` flags bits 4 and 8; `ClockNode.unusable`; marks `M_CONVERGE` 5 / `M_DIVERGE` 6
  pushed for every non-station node in `buildNetwork`; glyph in `gradeMarks.ts` (two arrows, red ring, like
  `M_BAD`), tags `gradeMarks.converging` / `gradeMarks.diverging`. Not in the drawing preview (a new route's way is
  inferred, so it cannot make this). Test `t3164_one_way_pieces_no_train_can_use` (both running sides).
- **T-3189** (`gradeMarks.ts`): the ramp's `tri` became `quad`, corners (-0.65r, ±r) and (0.65r, ±0.25r). No other
  place draws the ramp glyph (the toolbar's ramp switch icon is a side view, left as is).
- Checks: `checks/t3164-unusable-oneway.mjs` and `checks/t3161-single-lead.mjs` (new) pass on Vite 6114. Pictures:
  `artifacts/trainworld/t3164-converging.png`, `t3164-diverging.png`, `t3161-lead-both-H.png`, `t3161-lead-both-V.png`,
  `t3189-ramps.png` (device scale 2).
- T-3189 follow-up: one-way track chevrons sat on marks (`t3189-ramps.png`, the -1 ramp). `buildNetwork` now places
  them after every mark is pushed and passes the marks near one-way track (bounding box plus 50 m) with the stations
  and junctions as points to keep clear of, so the chevron shader's existing 14 px clearance skips a chevron on a
  ramp, flat crossing or junction, or unusable badge. Picture `t3189-chevron-after.png`. Line chevrons on one-way
  loops (T-2991) still clear only their stops.

## T-3164: unusable one-way track

Easy to detect from the move tables. At a node where single track meets, an end whose track carries trains into the
node but whose `to` mask is empty means trains arriving there can go nowhere (one-way pieces pointing into each
other), and an end whose track carries trains out of the node that no arriving end's `to` reaches means no train
can get onto it (pointing away from each other). Both are a few lines in `lanes.rs` beside `derive_moves`, run only
for nodes the edit touched. Automatic ways never produce this (a run takes one way end to end), so it only comes from
ways set by hand, which is exactly the case she means. Leave out bare track ends (a half-built stub is not a
mistake) and, for a first version, stations (a line that runs once may end there). Then a node flag in the
snapshot, a badge like the flat junction's with its own glyph, the tag text, a Rust test and a check: about 2-3
hours. A chain where each node looks fine but the whole stretch still can't be reached would need a walk over the
network; not worth it now. Draft tags, close to her words:
```
Unusable converging one-way track
Unusable diverging one-way track
```
