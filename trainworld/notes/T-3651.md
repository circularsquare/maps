## Cause

T-3565's one-way stations (a station on one-way single track) are served once a round trip, by the run whose track
passes them. Which run that is came from **the quickest route through the line's other stops**
(`Network::route_legs`, and `legs::place` for where the station goes in the stop list): a one-way station on that
route's track went to run 0, one on the way back's to run 1. That works when the two legs are the only way through,
as in a split double. With straight double track between the legs' junctions (the passing tracks), the quickest
route both ways is the middle, so **neither run passed either platform**. Then:

- `place` put both stations in by cost (`best_slot`), which tried every slot through `route_legs`, where the same
  quickest-route rule again found no run passing them and fell back to routing through every stop in order;
- the cheapest order that routes at all put one side platform last: the line ended at a side platform and turned
  back at the real end station mid-line, its way back running up and down the middle tracks.

Reproduced on master's code both ways:

- Rust (`t3651_side_platforms_beside_passing_tracks`): stops came out [T, n, Q, s] for a line given or clicked as
  T, n, s, Q; run 0 turned back at Q; run 1 crossed the middle double five times.
- In the game (scratch `scene.mjs`, play.mjs, New York sandbox, built by pointer): double track main, two single legs
  drawn from its nodes (their way comes from their joins: one each way, no player switch), a station on each leg,
  straight double between, single track to an end station. A line clicked Amboy St (east end), E 51st St (north
  platform), E 52nd St (south platform), Ocean Av (single-track end) became [E 52nd St, Amboy St, E 51st St,
  Ocean Av]: it started at a side platform, turned back at Amboy St, and ran over the middle tracks; 5.8 km, round
  trip 2,373 s. Picture: artifacts/trainworld/t3651_master.png (all four tracks in the line's colour, as in Zui's
  second picture).

Removing the middle tracks leaves the legs the only way through, which is why it "only correctly pathfinds after I
remove the tracks".

## Fix (no rule changed; T-3565's rule now holds with a faster track beside the legs)

- `perdir.rs` `route_legs`: a one-way station that neither quickest route passes is taken by the run that can reach
  it without turning back more often (`leg_run`, in the stops' order: forward first, then the way back for what is
  left). Stations the quickest routes already pass are untouched, so every existing layout routes as before.
- `perdir.rs` `take_legs` and `legs.rs` `place`: the same for where a one-way station goes in the stop list: each one
  neither quickest route passes is put into the run that takes it without an extra turn, at the slot that costs least,
  and its gap and order then come from that run's path as before (never from `best_slot`'s cost, so click order still
  never matters).
- `perdir.rs` `back_run_of`: the way back is no longer the forward path run backward when a one-way station of the
  line is off the forward path (double track everywhere else made that look valid, and the way back then skipped its
  platform).

After: the same scene clicked in either order makes [Amboy St, E 51st St, E 52nd St, Ocean Av] (or its reverse),
each run on its own leg, the middle unused, no turn back except at the two ends; 4.3 km, round trip 824 s. Picture:
artifacts/trainworld/t3651_fixed.png (middle grey, as in Zui's third picture).

Saves: a line saved in the broken order comes right on load (`legs::straighten_legs` reorders every line with
one-way stations through `ordered`, which now finds the legs); the Rust test saves a line as master made it and
loads it. A line the player ordered by hand keeps its order, as T-3565 says.
