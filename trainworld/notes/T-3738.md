# T-3738 shared save links preview the player's map

Design only, 2026-11-18, agent sharepreview. Nothing built, nothing deployed.

## What you'd see

Paste a share link (`https://anita.garden/trainsworld/?share=abcd2345`) into Discord, X, iMessage, Slack or
WhatsApp and the card shows that network's schematic, like its Community card but without the station names
(lines in their colours, white station pills), at 1200x630, with the share's title and who made it in place of
"trainsworld / Build trains around the world!". The link itself doesn't change, so every link already posted gets
the picture too the next time a site fetches it. A share that was stopped, hidden or banned keeps the generic banner.

## How it is today

- The link is `anita.garden/trainsworld/?share=<8 letters>` (`shareLink` in `app/src/game/community.ts`). It points
  at the game's own page, a static file on GitHub Pages. The game reads `?share=` with JavaScript after it loads.
- The banner comes from fixed meta tags in `app/index.html` (`og:image` and `twitter:image` =
  `https://anita.garden/trainsworld/preview.png`, 1200x630). The file is `app/public/preview.png`; Vite copies it and
  deploy.py puts it in the website's `trainsworld/`. Link previewers read the page without running JavaScript, so
  they see the same tags for every share. A static page can't change them per share.
- Pictures the game already makes:
  - Save cards (480x320 PNG, drawn in the clock worker) go to the account server as each game's private picture
    (`/trainworld/games/<id>/picture`, sign-in needed). T-2887 says these must not be reused for Community, since a
    page can upload any picture as one.
  - Community cards are drawn in each viewer's browser from the share's drawing data (the schematic as numbers),
    which the server already stores and serves to anyone (`/trainworld/community/<id>/<rev>`).
  - No share has a picture file anywhere. That was your call in T-2887: no uploaded images (offensive pictures,
    names in pixels no filter can read, the illegal-content duty of a picture host).

So the picture has to be drawn by the server from the drawing it already checked. That means the schematic, not
the geographic map.

## How it would work

**1. The server draws the picture.** A new route on shonei-server,
`market.anita.garden/trainworld/community/<id>/<rev>/preview.png`:
- drawn from the stored drawing: the background, each line's casing and stroke (trams thinner, high-speed lines
  with their pale middle stripe), station pills white with an ink outline, framed to fit 1200x630 the way the cards
  are. No names, so no font is needed. Light theme colours from the game's schematic. Lines get the card's minimum
  width in pixels (`widened(... MIN_LINE_PX ...)` in `Community.tsx`), or a continent-sized network draws as nothing.
- written in plain Go, no new library (the server is stdlib only). Every stroke is round-capped, so a line is just
  a chain of capsules, and a pill is a capsule too. A short anti-aliased capsule painter covers all of it.
  `golang.org/x/image/vector` would only fill shapes, so it wouldn't save much.
- drawn when a share goes up (in the background, so sharing isn't slower) and kept as
  `community/previews/<id>.<rev>.png`. Shares from before this get theirs drawn the first time a previewer asks.
  At most 2 drawn at once, so a burst of old links can't hog the box.
- 404 in exactly the cases the drawing is 404 (stopped, hidden, banned, an old rev, Community off). The rev is in
  the address, so it is cached forever and a re-share gets a fresh picture. Deleted with its share or old rev.
- its own rate-limit bucket, generous (say 120 a minute per IP): Discord's and X's fetchers come from a few shared
  addresses and give up after a few seconds.

**2. Cloudflare changes the tags on the way out.** anita.garden is GitHub Pages behind Cloudflare (website
CLAUDE.md). A small Cloudflare Worker on the one path `anita.garden/trainsworld/` (the page only; the game's
scripts, fonts and data never pass through it):
- no `share=` in the address: hands the page on unchanged.
- with one: asks the server for that share's card (`/trainworld/community/<id>`, already public, the one the game
  asks for), cached 5 minutes, and gives up after about 1.5 s. Then it rewrites `og:image`, `twitter:image`,
  `og:title`, `og:description`, `twitter:title`, `twitter:description` and `og:url` (the link itself) on the page.
  Cloudflare's rewriter escapes the title and name as it writes them in.
- on any failure (server slow, share gone, a 429) it hands on the page untouched, so the worst case is today's
  banner. The worker is set to let pages through if Cloudflare's free limit (100,000 runs a day) were ever reached.
- the published page (`website/trainsworld/index.html`) has the same tags as `app/index.html`, once each, with only
  front matter added and no Jekyll layout, so those are the tags to rewrite.
- to confirm when built (from memory of Cloudflare's docs, not from a file here): that a route on exactly
  `anita.garden/trainsworld/` also matches with `?share=` on it and leaves the assets alone, and the let-pages-through
  setting at the limit. If the route has to be `/trainsworld/*`, every script and font of every load counts as a run,
  and the daily limit becomes the thing to watch.
- players get the same page as now, with different tags in its head. Nothing in the game changes.
- the code lives in the maps repo (`trainworld/tools/sharepreview/`, the worker and its `wrangler.toml`).

## Cost

- **Storage**: a save card (480x320) is about 16 KB at the median. A 1200x630 schematic has about 5x the pixels but
  mostly flat colour, so roughly 30-80 KB (a guess until one is drawn). Even at the 5,000-share cap that is under
  400 MB. It counts in Community's 2 GB budget.
- **Server load**: one render per share rev, a fraction of a second; after that it is a file served from disk.
- **Cloudflare**: free plan; one worker run per page load of the game. I didn't check plays per day against the
  100,000 limit (the play counts are on the box); letting pages through at the limit is what keeps it safe.
- **Privacy**: nothing new becomes public. The drawing is already open to anyone, and the title and display name
  are already on the card, through the name filter. The picture has no station names. One catch: Discord, X and
  iMessage keep a preview they already made after you stop sharing, and we can't take those back. iMessage keeps
  the picture inside the message.

**Estimate: about 3-4 hours of agent time.** The anchor is T-3326 (pictures in feedback: a server part plus a game
part, about 3 hours from filing to landing by the commit times).
- the server's picture painter: 1-2 hours, the uncertain part, since nobody has written one here
- the route, the stored files, deleting them with the share, the bucket, tests: about 1 hour
- the worker, tried locally with `wrangler dev` against a local server: about 45 minutes
- a check that the HTML a previewer sees has the right tags, then notes and docs: about 30 minutes

Not in the estimate: your `wrangler login`, the two deploys, and the one real test, pasting a link into Discord or X
after both are live.

## The other way (if you'd rather not put a worker on Cloudflare)

The server answers a new short link (say `market.anita.garden/s/abcd2345`, or a nicer subdomain, which needs a DNS
record and a Caddy line) with a tiny page carrying that share's tags, and sends people on to the game. Copy link
would give the new form. Old `?share=` links keep working but keep the generic banner. It needs a game publish, a
`/noritetsu/config` flag so the game only hands out the new link once the server answers it, and an HTML page from
the server (whose CLAUDE.md keeps HTML in one template file). Same picture, same cost, about 30 minutes more. I'd
pick the worker: no new link form, old links get pictures too, no game publish.

## Strings (new, English only, seen in link previews)

- `og:title`: the share's title, e.g. `Big plans`; with no title, `Alice's network`
- `og:description`: `6 lines, 1,756 stations, by Alice`; with the name hidden or missing, `6 lines, 1,756 stations`
- unchanged when the share isn't there: `trainsworld` / `Build trains around the world!` (reused)

The server doesn't know city names (the game has them), so no city in the description unless the server is given
the list.
