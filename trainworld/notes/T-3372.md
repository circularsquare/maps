# T-3372 Finer terrain classes, hexes back (agent terrain, 2026-11-12)

Anita (Chongqing screenshot): "why is our terrain not more detailed? i see in chongqing we seem to mostly follow a
really coarse grid with seemingly some smaller exceptions that are at a finer grid." Then: "i'd like to pursue this
blending and bring back hexes".

## Cause

`zone_terrain.classes_of` caps each 115 m cell's class at the class of the slope between 1/240 degree mean
elevations (against towers and raised roads, notes/archive/t1500-1999/T-1854.md). The cap was copied nearest-neighbour
onto 4 x 4 blocks of cells and binds on about half the land in Chongqing (49%), a quarter in the Tokyo block, a sixth in
the Tyrol, so most class borders were 460 m squares.

## Method

`Fine.coarse`: the coarse slope (unchanged, central differences over 920 m) is taken bilinearly at each fine cell's
centre, then classed by COARSE_THRESH_DEG. The slope is interpolated, not the elevation: a bilinear elevation surface
has a gradient that jumps at coarse cell edges, which would draw squares again. Bilinear never exceeds its four
neighbours, so a tower field inside flat ground stays capped flat. No threshold changed.

Class changes on every 4th cell boundary against the others (T-3266's count): Chongqing 11.3x -> 1.02x, Tokyo block
8.2x -> 1.02x, Tyrol 3.8x -> 1.01x. The old squares included 460 m flat squares on mountainsides wherever the 920 m
central difference cancelled (ridge lines, the axis of a narrow valley); those go, so a little flat becomes hills or
mountains (images `artifacts/trainworld/t3372/t3372-classes-*-before-after.png`, classes only, 3 px a cell).

## Hexes

T-3266's code change reversed (`cost::hex_centre`, `TERRAIN_HEX`, `TERRAIN_HEX_SHIFT`, the hex test, the tint's hex
lattice, `game/terrain.ts`'s hex helpers), size unchanged at 1/768 degree: the data now changes at the 115 m cells,
about a hex, so a smaller hex would show the cells' squares inside and a larger one would drop detail.
Screenshots: `artifacts/trainworld/t3372/t3372-pair-<place>-z13|z15-<light|dark>.png` (before left, after right).

## Data

World blocks: `data/terrain-world-v2/`, `world_terrain.py build data/work/terrain-fine-world data/terrain-world-v2
--jobs 6`, 1,060 s, 19,341 files, 0.751 GB (v1 0.706; log `data/work/t3372-world.log`). Built from T-2901's all-land
intermediate `data/work/terrain-fine-world/`, not `data/work/terrain-fine/` (the zones' older, partly partial one).
The game's dev path and the build read v2; publishing goes under `terrain-world/v2/` on R2 (`tools/deploy.py`'s
TERRAIN_PREFIX): `python trainworld/tools/deploy.py --terrain-world --terrain-dir trainworld/data/terrain-world-v2`
(`--terrain-dir` new: uploads a data folder without a build). A release made from this code is refused until v2 is
complete on R2. `data/terrain-world/` (v1) stays as it is: the live game and older releases read v1 on R2.

Per-zone `data/terrain/<id>.terrain`: nothing in the game reads them (they are copied into builds as
`packs/terrain/`; `t1270-terrain.mjs` and `t2613-terrain-net.mjs` read them to find mountain spots). Fresh ones made
with the new code are in `data/work/t3372-zones/`, to swap in once no join is running.
