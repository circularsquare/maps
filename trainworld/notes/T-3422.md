# T-3422: trains run over a blueprint part of a flyover (agent bugs2, 2026-11-16)

Cause: `Network::line_constructed` (sim/src/track/net.rs) checked only the line's `line_path` (run 0). Round one-way track
(a flyover's legs are one-way single) the return run takes other edges (`back_path_of`, T-3094), which were never checked, and
`construct_line` / `line_build_cost` (wasm/links.rs `line_parts`) never built or priced them. So a line ran with its other
leg still blueprint, and "Construct line" left it so.

Fix: `Network::back_only_edges(l)` (edges only the return run takes); `line_constructed` requires them built;
`line_parts` adds them to what Construct line builds and quotes. Effect for old saves: a line whose return leg is
blueprint stops running until that leg is constructed (what the report expected).
Check: sim test `a_line_does_not_run_while_its_way_back_is_blueprint` (wasm/oneway_tests.rs). cargo test (566, and 751
with demand) pass.
Board report (aejormor, 2026-11-15, "Trains use unbuilt track"): a line built with one-way single-rail pieces ran over
rails Construct line never built. That is this cause; covered. Their second report (the line creator refusing the next
station after a one-way single-rail station) is a different bug, not looked at.
Not covered: the T-3403 profit map had the same blind spot (see T-3403). Other users of `line_path` only
(rebuild.rs, twin.rs, capacity) were not audited for the return run.
