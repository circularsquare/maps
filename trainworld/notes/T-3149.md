# T-3149: what each click does when editing a line's stops or route

Built from the code, 2026-11-11. Current is master in the main tree (HEAD ed4f66fa). Live is v0.2.1, the worktree
`.tw-trees/hotfix` (branch tw/release-021, f5a2b979). "DIFF" marks a cell where current and live differ.
All paths below are under `trainworld/app/src/` (live: `.tw-trees/hotfix/trainworld/app/src/`).

## Where the handlers are

| Mode | Left click / tap | Right click | Keys | Touch hold |
|---|---|---|---|---|
| Rail and tram line stops (new line or Edit stops; the same tool, `tool == "line"`) | `map/tools.ts: lineClick` -> `map/stopMarkers.ts: activate` -> `tools.ts: toggleStop` / `toggle` | `stopMarkers.ts` constructor `map.on("contextmenu")` -> `loopAt` -> `tools.ts: loopStop` / `toggle` (current only; live has none) | `tools.ts: key` (Escape exits, Enter exits) | `stopMarkers.ts: pressDown` (current only) |
| Hand bus stops (Edit stops on a by-hand bus line) | `tools.ts: lineClick` -> `map/busStops.ts: click` | none in either | same `tools.ts: key` | none |
| Bus route (new, or Edit route) | `map/busDraw.ts: click` -> `handleClick`; empty spot -> `add` | `busDraw.ts` constructor `map.on("contextmenu")` -> `rightClick` -> `rightAction` | `busDraw.ts: key` | `busDraw.ts: onTouchDown` -> `longPress` |
| Ferry route (new, or Edit route) | `map/ferryDraw.ts: click` -> `press` -> `handleClick`; empty spot -> `add` | `ferryDraw.ts` constructor `map.on("contextmenu")` -> `rightClick` -> `rightAction` | `ferryDraw.ts: key` | none (Loop button only) |
| Station building outline | `map/buildingDraw.ts: click` | `buildingDraw.ts` constructor `map.on("contextmenu")` | `buildingDraw.ts: key` | none |

Tram: `stopMarkers.ts` is the same code for trams; only the "trains reverse" hover words change (`tram` flag). Nothing differs
in clicks. Rail "Exact edits" (manual stops, T-3023) exists in the live code with its toggle hidden; current has dropped it
(T-3109). Left out of the tables.

Bus "auto" stops (the sim places them): `lineActions.ts: toggleEditStops` refuses, so there is no stop editing at all. Only the
route can be edited (bus route rows).

The Done / Save / Make line buttons are in `ui/ToolNotes.tsx` (Done leaves the line tool; Save route / Make line call
`bus.finish()` / `ferry.finish()`). Touch Loop button: `ToolNotes.tsx` `loopButton`, `game/ui.ts: loopTap` (current only).

Terms: "end" = the active end of a bus or ferry route (its last point; `endIndex()`). "seam" = where a loop closes (first point and
last point of a ring, or the point a looped-back route joins).

## Table 1: rail and tram stops (stop markers on every station)

Rail has no "finish" gesture. Every stop edit is saved at once. Escape, Enter and Done all just leave the tool.

| Gesture | Current | Live v0.2.1 |
|---|---|---|
| Left click, station not in the line, reachable | Adds a stop (`insertStop`; the worker fits it among the stops, the route may change). Tag: "Click to add a stop" / "...and change the route" / "Trains reverse at..." | same |
| Left click, station with no track to the line | Red tag "X is not on track this line can reach" and the gap flashes; nothing added | same |
| Left click, middle stop | Removes it (every visit). Tag "Click to remove the stop" | same |
| Left click, last stop (end) | Removes it. Same tag | same (an end is just a stop) |
| Left click, first stop | **DIFF.** Removes it (a ring that loses its first stop re-closes on the new first, T-3050). Tag "Click to remove the stop" | Depends on the sim's tier: if the line can be closed into a circle (tier "close") the click closes it ("Click to close the loop"); if it is a ring (tier "open") it opens it ("Click to open the loop"). Otherwise removes it. So the first stop could not be removed by clicking once the line could close |
| Left click, stop before a loop of track at an end | **DIFF.** Removes it | Turns the line round that loop ("Click to loop back here"); the turned line's stop opens it again ("Click to stop looping back here") |
| Left click, any stop of a ring (not the first) | Removes it (ring of three then opens) | Removes it |
| Left click, empty map | Hint in the notes bar, nothing placed | same |
| Left click twice on the same stop | Add then remove (or remove then add): net nothing. No double click handling | same, but on a first/turn stop it was close then open |
| Right click, first stop, line can close | **DIFF.** Closes into a circle. Tag "Right click to close loop" (only if the sim says it can) | nothing happens |
| Right click, any stop of a ring | **DIFF.** Opens the ring there; the stretch leaving that stop goes. Tag "Right click to open loop" | nothing |
| Right click, stop before a loop of track at an end | **DIFF.** Turns the line round it. Tag "Right click to loop back here"; on the turned stop "Right click to stop looping back here" | nothing |
| Right click, any other stop or station | **DIFF.** Red tag "Can't loop back here" for a moment | nothing |
| Right click, empty map | Nothing (menu suppressed) | nothing |
| Enter / Escape / Done button | Leave the tool and select the line | same |
| Backspace / Delete | Nothing | nothing |
| Touch tap | Same as a left click | same |
| Touch hold 500 ms on a marker | **DIFF.** Same as a right click there | nothing |
| Touch Loop button, then tap a marker | **DIFF.** Same as a right click there (button shows only with 2 or more stops, rail lines only) | no button |

Where the sim decides: the tier of each station (`stop_tiers` in `sim/src/track/wasm/lines.rs`, mirrored for the first paint in
`stopTiers` in `stopMarkers.ts`) decides which right click does what, and whether a station is addable, a reroute, cut off, or
a reversal. Current: right click on the first stop closes only if the sim says a closing path exists (tier "close"), else
"Can't loop back here". Live: the same tier decided what the left click did.

## Inconsistencies

1. Same click, three meanings on a bus or ferry route (current): on the last point it saves, on any other point it deletes, and
   on a lone point it does nothing while the bus tag still says "Click to delete" (bug in `busDraw.ts: placeTag`; the ferry tag
   checks for 2 points, the bus tag does not). In rail, a click on the last stop removes it.
2. Saves on the last point but deletes on every other point (current). That is the "click to save, right click to delete"
   case. Right click on the same last point is then the only way to delete it (or Backspace).
3. Right click means delete in live bus and ferry, but loop in rail (current) and, since T-3118, in bus and ferry too. In live a
   right click on a rail stop did nothing. So against live, bus and ferry right click changed from "delete this point" to "loop
   here", and rail gained a right click.
4. Loops are made differently: live rail loops with a left click on a tier-marked stop; live bus and ferry loop with a left
   click on the other end. Current has moved all three to right click.
5. Delete a middle point: live bus and ferry right click (middle ferry port could not be deleted by touch at all); current
   left click on all route modes, and left click on rail stops. Rail remove has always been a left click.
6. Hand bus stops have no loops, so they stay left-click toggle only. Fine, but the Edit stops bar shows no Loop button there
   (correct).
7. A double click on a middle point on a route deletes it and then saves the line (current). A double click on a rail stop adds
   and removes it.
8. First stop on rail: current can remove it with a click; live could not once the line could close. Bus and ferry first points
   are removed by click in current; live closed the loop.
9. Touch: ferry has no hold gesture, but bus and rail do (500 ms). All three have the Loop button. The rail touch hint says
   "Hold one to loop back there"; ferry has no hint line of that kind.
10. Escape: a new rail line keeps its stops (it only leaves); a new bus or ferry line with 2 or more points is made; an edited
    route is dropped. Three meanings for Escape across the modes.
11. Tag wording: bus "Right click to close loop" and rail "Right click to close loop" match; the ferry loop-closed message says
    "any port", the bus one "any point", rail has none; live ferry said "its first port".
12. Rail can end the tool by Enter, Escape or Done with no save step; bus and ferry need Save (or a click on the end).

## Proposal

Change as little as possible from live, and make the same gesture mean the same in every mode. Left click adds or removes one
point or stop everywhere, and right click only ever changes the loop. The last point of a bus or ferry route is the one
exception on left click, kept from live: it saves the route, and the tag says so every time. Rail has nothing to save, so the
last rail stop simply removes like the rest. Right click on the last point of a route deletes it (as live), and Backspace takes
back the last point. Everything else follows from those four lines. Fixes that need no choice: the bus tag must not say "Click
to delete" over a lone point (hide the row, as the ferry does); right click on a lone point deletes it (as live); the ferry
gets the same 500 ms hold as the bus and rail; a double click acts only on empty ground (it must not delete a middle point
before it saves). Escape stays as in live.

Proposed standard (bus, ferry; rail where it applies):

| Gesture | Bus and ferry route | Rail and tram stops | Hand bus stops |
|---|---|---|---|
| Left click, empty | Add point at the end | Hint only | Add a stop on the route |
| Left click, station not in line | (ferry: add that port) | Add a stop | n/a |
| Left click, middle point or stop | Delete it | Remove it | Remove it |
| Left click, last point | Save the route (tag says so) | Remove it | n/a |
| Left click, first point | Delete it | Remove it | n/a |
| Left click, previous point = last | Save | Remove | n/a |
| Right click, last point | Delete it | nothing | nothing |
| Right click, middle point | Loop back to it, then save | Turn the line round a loop of track if the sim allows, else "Can't loop back here" | nothing |
| Right click, first point | Close the loop and save | Close into a circle if the sim allows | nothing |
| Right click, point of a ring | Open the ring there | Open the ring there | n/a |
| Right click, lone point | Delete it | n/a | n/a |
| Right click, empty | Take back the last point | Nothing | Nothing |
| Double click | Empty ground only: save | Nothing | Nothing |
| Enter, Save button | Save | Leave the tool | Leave the tool |
| Escape | New with 2 or more points: save. Edit: drop. | Leave | Leave |
| Backspace | Take back the last point | Nothing | Nothing |
| Touch hold | Same as right click (ferry too) | Same as right click | n/a |
| Touch Loop button then tap | Same as right click | Same | n/a |

Against live this changes: bus and ferry middle and first points (left click was nothing or close-loop, now delete or, via
right click, loop), and right click on middle and first points (was delete, now loop back or close). These two are already what
current does. The proposal only adds the four fixes above, so against current it moves almost nothing.

One alternative, if you want left click to mean exactly one thing everywhere: make left click on the last point of a bus or
ferry route delete it too, and save only by Enter, the Save button, Escape or a double click on empty ground. It removes the
exception, but players who click the last point to save (live) would delete a point instead.
