# T-3668 Agent reports reach the current orchestrator

Agent `inbox`, 2026-11-18. Tree `.tw-trees/inbox` (branch tw/inbox), nothing committed.

## What was found (Claude Code 2.1.327)

- **A `SubagentStop` hook works and fires in the parent session.** Tested with two throwaway headless sessions
  (`claude -p --settings <scratch hooks>`, each starting one background subagent). Its input carries `session_id`
  (the parent's), `agent_id`, `agent_type`, `agent_transcript_path` (`<project>/<session>/subagents/agent-<id>.jsonl`),
  `last_assistant_message`, and `background_tasks` (with the agent's description). `SubagentStart` and
  `PostToolUse` on `Agent` fire too (the latter carries `agentId` and the output file).
- **`last_assistant_message` is the wrong field for us.** Interactive agents (entrypoint `cli`) hand back through the
  `SubagentHandback` tool; their last plain text is a stray working line ("Now the notes file.", "Sed missed; edit
  directly.") in 13 of the 15 finished agents of session 59c85afe, and the other 2 have none. Headless agents (`sdk-cli`) have no
  `SubagentHandback` at all, even with `--advisor fable`, so a headless probe cannot show the interactive case.
- **The report is in the transcript.** Each handback is an assistant `tool_use` named `SubagentHandback` with
  `input.message`, followed by a tool result `{"success":true}`. A resumed agent can try again and get
  `success:false` ("an earlier report was already delivered"), then send its follow-up by `SendMessage` to `main`
  (a080b877, T-3650). A resume shows in the transcript as a user entry (isMeta) "The coordinator sent a message".
- **`agent-<id>.meta.json` sits beside the transcript**: `description` (carries the T-id), `model`, `spawnDepth`
  (2 for an agent's own helper, with `parentAgentId`), `finished`.
- **Unproven**: that the hook fires in an interactive session after a `SubagentHandback` (it cannot be registered in
  a running session without editing settings.json). The parsing is proven on the real interactive transcripts; the
  live check below closes the gap.
- **The old tab still wakes.** Its agents run inside its process (closing the tab kills them), and each one's
  finish starts a turn there whatever we do. The inbox removes the relay and the new tab's replies (the 71 relays and
  96 replies of the research count), not the wake: the old tab should end that turn in one word.
- SendMessage from the new tab to an agent the old tab started: not tested. Treat adopted agents as unreachable:
  a follow-up goes to a fresh agent on the same tree and notes.

## What was built (in the tree)

- `trainworld/tools/reports.py` (new). `hook` is the SubagentStop hook: keeps top-level agents (spawnDepth 1) of a
  trainworld orchestrator session (registered by `watch.py --session`, or on handoff.md's Orchestrator or Previous
  line; registration outlives the Previous line, so an agent finishing hours after a handover still lands). The
  reports are every successful `SubagentHandback` message and `SendMessage` to main in the agent's transcript (ones
  already kept or read are skipped by id). A stop with neither is a pause when the transcript carries the harness's
  "delivered through SubagentHandback" reminder (the agent waiting on its own background work, which also stops
  it): nothing is written. Only an agent without the tool (headless, or interactive before about 2026-11-17) is
  kept by its `last_assistant_message`. One file per report, `notes/agent-reports/r-<sha1 of agent+kind+text>.json`, written
  by temp file + `os.replace`; an existing id is skipped, so repeat stops and parallel finishes are safe. Always exit
  0, no stdout; errors go to `notes/agent-reports/hook-errors.log`. Name: the board agent holding the task, else
  "You are agent `x`" in the brief, else the description. Also `list [--all]`, `show <key>`, `read <key>... |
  --session <id> --by <name>` (moves the file to `read/`), `sweep` (backfill from transcripts, handbacks and messages
  only), `register`.
- `trainworld/board/watch.py`: every 10 s prints `agent report <id> <name> <task> (<kind>, session <8>, <time>):
  <first line> (reports.py show <id>)` for each unread report from another session (its own agents' reports reach
  the orchestrator directly; no double). `--session <id>` registers the session; without it the watch takes the
  Orchestrator line at start. It exits with "session x orchestrates trainworld now; this watch stops" once handoff.md
  names another orchestrator, so the old tab's Monitor stops waking it.
- `trainworld/tools/handoff.py status`: new section "unread agent reports (from sessions other than the current
  orchestrator)", one line each, plus a count of the orchestrator's own unread.
- `trainworld/tools/tasks.py done|close <id>` marks that task's unread reports read.
- `trainworld/.gitignore`: `notes/agent-reports/` (maps is public; reports are working state like board-inbox.jsonl).

Tests (scratch, `.../scratchpad/inbox/test_reports.py`, `test_watch.py`, `replay_turns.py`, all pass): fed made-up
SubagentStop input for every agent of session 59c85afe: each finished top-level one gives records equal to its real
handbacks (a080b877 also its SendMessage follow-up), three still-running agents (pause stops, stray last text) give
nothing, the depth-2 probe is skipped, an unregistered session writes nothing, repeat stops write nothing, 54 stops
(12 parallel, each agent 3 times) give the same 21 files as one pass and no temp left, a registered session off the
handoff still writes, list/show/read/read --session/sweep behave. Over the 300 newest maps transcripts: 289
handbacks, 10 messages, 62 last-text reports (all from 11-16 agents that had no handback tool), 12 with nothing
(running, or 11-16 runs that never finished). The watch prints
another session's report once, not its own, and exits at a takeover; the status section lists the old session's
unread. Real `handoff.py status` runs (section shows "none").
