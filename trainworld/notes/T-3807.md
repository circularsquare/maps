# T-3807 Change display name in account settings

Anita, 2026-11-19: "some people get confused by this and put what they want the map to be called rather than what
they want their display name to be, and then they cant change it and they're sad. lets make it changeable in account
settings? maybe throttle twice a day or something, but no real urgency." For hotfix v0.4.4; needs a server deploy.

## Where the name lives, and every place it shows

One field: `name` on the account's entry in shonei-server's `trainworld/players.json` (`twProfile.Name`), one per
account. It was set by the leaderboard opt-in (`PUT /trainworld/optin`) or by a first share (`meta.name` on
`POST /trainworld/community`), through `sanitiseName` (control characters out, trimmed, 24 runes) and `isProfane`
(the map-game filter). There is no uniqueness rule anywhere; two players may share a name.

| Place | How it gets the name | After a change |
|---|---|---|
| trainworld leaderboards (`/trainworld/board`) | read live from the profile per request | new name at once |
| Community cards, share links (`?share=`), the detail view | `fillShareNames` reads the profile live; shares store the owner id only | new name at once |
| Community search by sharer | `ownersNamed` over live profiles | finds the new name only |
| Link previews (T-3738 PNG) | no names painted | nothing to change |
| Moderator hides (`community/names.json`) | per account and name | a new name shows; the hidden name stays hidden for that account across renames (below) |
| Moderator hides (`community/names.json`) | per account and name; `renamed` drops the old name | as before T-3807: a new name clears the hide |
| A viewed or opened copy of someone's share | slot named "<title> - <name>" in the viewer's browser when opened | keeps the old name; it is the viewer's own local game name. Left alone |
| Feedback threads | `accountName` (username, else noritetsu's board name) copied at report time | keeps the name as of the report; Anita's inbox only. Left alone |
| noritetsu leaderboards | a separate `BoardName` on the noritetsu account, set on the noritetsu page | does not follow; separate field, untouched |
| City Circles / Guess the City boards | typed per score, no account | unrelated |
| twstats page, `/trainworld/stats` | no names | unrelated |
| `tools/trainworld_plays.py` | username or noritetsu `boardName` | unrelated to this field |
| Saved games, shared save bytes | carry no account name | unrelated |

Nothing looks anything up by the name or puts it in a URL, so changing it breaks nothing.

Before T-3807 the name could already change, unthrottled: Leave the boards, then Join with a different name (the
field is prefilled and editable), or a share sending a name. There was just no control for it while on the boards.

## What was built

Server (shonei-server, commit db12e1d, `trainworld_rename.go`):

- `PUT /trainworld/name {"name"}`: sets the name without joining or leaving the boards; answers as `/trainworld/me`.
  400 `need-name` (blank) / `bad-name` (filter). Per IP 30/hour, 10 back to back. Config reports `trainworldRename`.
- The limit, in one place (`checkRenameLocked`) and used by all three writers (the new route, the opt-in, a share's
  name): at most 2 changes in any 24 hours per account. Kept as `renamed` (unix seconds of the last two) on the
  player's entry in `players.json`, so a deploy or restart does not reset it. Past the limit: 429 `rename-limit`
  with `retryAfter` seconds, nothing changed.
- Not counted: a first name (none before), the same name again, a failed check or save, and leaving a name others
  cannot see (hidden by Anita, or refused by a later filter), so a player can always fix that one.
- Tests: `trainworld_rename_test.go` (two pass, third 429 with the wait, same name and flag and Leave still pass while
  limited, allowed again a day after the first, kept across a restart; the limit shared by optin, share and the
  route; filter refusals; leaving a hidden name is free). `go test ./...` passes.

Game (tree dispname):

- Account panel, the flag and name row: **Change name** at the row's end, once the account has a name and the server
  says `trainworldRename`. It puts a field (the current name, 24 characters) with Save and Back in the name's place;
  Save closes it and the row shows the new name. Refusals show under the row. Players without a name still get one
  from Join or Share, as before.
- Join and Share show the limit in the same words when they would change the name.
- `game/account.ts` (`setDisplayName`, `renameOn`, `renameRefused`), `ui/Flag.tsx`, `ui/flag.css`,
  `game/community.ts` (the share's refusal), docs/ui-panels.md.

## Hidden names across renames (shonei-server fdaa596)

Before, any rename took a moderator hide off (T-3227's rule), so a player could change away from a hidden name and
back, and it showed again. Anita, 2026-11-19: "yeah hidden name can stay hidden across renames, i guess. i haven't
actually hidden anyones name yet but seems fine." Now a hidden name stays on the account's list in names.json until
Unhide: a different name shows as normal (and the panel's hidden line goes), and going back to the hidden one by
Join, Leave and Join back, Share or Change name hides it again. The hide is per account; another account may use the
same name. `renamed` is gone; tests in trainworld_names_test.go. `go test ./...` passes. No game change was needed.
## Left as is, for Anita

- A moderator hide is cleared by any rename (T-3227's rule): a player whose name was hidden can change away and then
  back to the hidden name, which then shows again. That was already possible through Leave and Join; with this
  control it is one counted change (leaving the hidden name is free), well inside the limit. Keeping hidden names on the list across renames would
  close it.
