# T-4426: occasional test under non-default settings

Check: checks/settings-matrix.mjs. Each scenario is a fresh Chrome profile, a sandbox New York game, one built line, a demand final.
It passes when the settings read back as set, the demand pool is the size they give (poolSize and the running pool), the final
arrives with no failure, no "Demand stopped" note and no page error, and trips are counted.

Scenarios (add one in SCENARIOS): defaults (control), Cores slider 1 and 5, 2 GB device memory, Android phone (touch, mobile UA, its
own defaults), Calculate intercity trips off, coarse demand, 32-bit browser (?bits32=1). Settings come from ui.ts DisplaySettings and
workers/deviceMemory.ts. The browser pin's ?demandWorkers is removed by an init script, or it would override the Cores slider and Auto.

Cadence: the ledger is the main tree's notes/settings-check-ledger.jsonl, one line per full run. Within 24 h of the last the check
stops (--force); within 7 days it warns and runs; --last says when it ran. docs/orchestrator.md names it.

Proof run (2026-11-28, tree settingschk, own Vite, after T-4583): 7 of 8 passed in one full run. Pool sizes: Auto 3, Cores 1 gave 1,
Cores 5 gave 5, low memory 1, phone 1, 32-bit 1. Intercity off and phone count 69M trips/day against 963M with intercity on. coarse-demand
failed once on a net::ERR_CONNECTION_REFUSED page error (no url; unrelated to the setting as far as seen) and passed on its rerun;
the check now prints failed request urls so a repeat can be placed. About 4 minutes for the eight.

Not covered: the real NYC save and big saves under these settings (budget row Tooling); phone-sized memory pressure (memFree query); Safari/Firefox.
