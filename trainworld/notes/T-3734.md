## Stage 2: one write-block answer (done)

Agent slotown2, T-2843 machine C, with T-3698 and two fixes in it. All in `workers/clock.worker.ts`.

`writeBlock(attempting)` answers why the game in hand may not be written now, first match in the order the saves
panel has always named it: `newer`, `failed` (`saveFailure`), `storage`, `otherDevice`, then with no lease `viewing`,
`testPage`, `otherTab` (`leaseTaken`), `noLease`, and last `switching`. `attempting` skips `failed` and `storage` and
carries on down the chain: a write about to be tried is the retry of those two, as autosave always was. Filtering the
answer instead would have let a tab with a failed save and a lost lease write without the lease. The four places:

- `writableNow`: no block, or only `switching` (a swap is a moment and the slot stays the page's; the page was never
  told otherwise, so writable and the leave prompt don't flip during one).
- `publishSlots`'s reason: `BLOCK_REASON[block]`, `saveFailure` for `failed`, `clockWorker.noLocks` for `noLease`
  without `navigator.locks`. Keys and English unchanged (SavesPanel matches "another device" in the text).
- `autosave`'s guard: `writeBlock(true)`. Same as before; its other-device test is now the guarded one
  (`activeSlot && ...`), which only differed when the slot is "", where there is no lease either.
- `flushBeforeSwitch`: the blocks that make the slot not this page's (`NOT_MINE`: newer, otherDevice, viewing,
  testPage, otherTab, noLease) throw "Make a copy" only when `edited`, else leave without writing. **T-2843 finding
  4 fixed**: before, `dirty` was tested, which the clock's own settling sets, so a second tab with its clock running
  could not go back to the menu or open another game. The old `newer && !edited` line is this rule's `newer` case.
  `failed`, `storage` and `switching` still go to `autosave()` and its "could not be saved".

`saveByHand`: when `autosave()` returns false and the block is then `otherTab` (the lease was lost during the press,
or the write was refused as T-3611 made it), it answers `clockWorker.savedInOtherTab` instead of `couldNotSave`. This
is **T-3698** and the same wrong message on the held writer (stage 1's "seen on the way"). The other choice, taking
the slot back at once, was ruled out: in the two-tab races the held writer would move the taker's newer manual save
out of the slot. The next manual save takes it back as before (no-lease branch, `keepOtherTabs`); the check proves it.
No new flag.

## Plan for stages 3-4

**Stage 3: every message about a game carries one stamp.** A load counter taken when the worker starts a game
(`loadGame` / `intoNewSlot` / `intoView` / restart), sent on `loaded`, `state`, `money`, `saveSlots`; the page's
edits carry the stamp they were made under. `protocol.ts` gets the field; `clockClient.arrive` keeps the current
stamp; only a different game drops a message. It replaces `MoneyState.slot` (account.ts `sendScores` and
`gameForShare` compare the money's stamp with the slot list's, coordinate with whoever holds account.ts then) and the
stop clicks' `gamesLoaded` capture in `map/tools.ts`. Count the message kinds that carry game state first (not done
here). Checks: `t3734-load-gap` and `t3734-stops-out` pass unchanged. About 1.5-2 h.

**Stage 4: the save code moves out of clock.worker.ts** into `workers/slots.ts` (name free): `writeBlock`,
`publishSlots`, `noteUnsaved`, `flushBeforeSwitch`, `intoNewSlot`, `intoView`, `autosave`, `keepOtherTabs`,
`saveByHand`, `manageSlot`, `leave`, the cloud queue and `cloudAfterWrite`, the lease holders, with their state as
one module object; the worker calls in. No behaviour change. The checks' stand-ins survive it: two-tabs patches
`saveFile.ts` (not moved) and gates only inside the worker whose script URL has `clock.worker`; load-gap holds
`wasm/track/sim.js`. Checks: all three t3734, `t1826-saves`, `t3478-new-game`, smoke. About 1-1.5 h.
