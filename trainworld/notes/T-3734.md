## Stage 3: one game stamp (done)

Agent slotown3. Advisor called once before settling the shape (it caught the in-place load gap below, and that a
queued stop edit must carry the click's stamp, not one taken at post).

**The stamp** is the worker's existing load count `game` (T-715), moved only by `restart()` (every load, new game,
and the "rebuilt" restarts of a panic's rebuild and a side switch). The page's copy is `gameStamp` in clockClient.ts,
set to `loaded`'s `game`. It replaces two page counters: clockClient's private `game` (the clock's) and
`gamesLoaded` (a count of `loaded` messages, T-2124), renamed in tools.ts, LineInspector.tsx, achievements.ts and
Achievements.tsx. They differed only on an error `loaded` from "new" at the page's start (4 sites in the init path),
where the old count moved and the stamp does not; nothing is played yet then, and the effects keyed on it (profit
reset, posted steps, toasts' known set) start from their first run either way.

**What carries it** (counted, as the plan asked):

| Direction | Kind | Stamp |
|---|---|---|
| worker to page | `loaded` | `game` (as before) |
| | `money`, and `state`'s money | `MoneyState.game` (replaces `MoneyState.slot`) |
| | `saveSlots` | `game`: the game `active` holds (`slotGame`) |
| page to worker | `clock` | `game` (as before) |
| | `edit` | optional `game`: only the stop queue's edits (tools.ts `queueStop`, LineInspector `sendStops`) |

Not stamped, on purpose: the other ~25 worker-to-page kinds. The channel is ordered, and some are about the incoming
game before its `loaded` (`restart` sends `opened`, `home`, `listOrder`, `lineShapes`, `hiddenLines`, `newHeadway`
first; `loadGame` sends `stationsAhead`, `netAhead` before it restarts), so dropping by stamp on arrival would drop the
right ones. Not stamped either: the page's figures messages (`income`, `regionShares`, `points`, `riders`,
`transfers`, `chargeShares`, `star`, `achieve`, `lineNotes`). One sent before the page heard of a load lands on the
new game for the second until demand sends the new game's (T-715's reset of the per-line income is the guard
today). Never stamped: `leave`, `saveSlot`, `import`, `newGame`, `flush`, `export` (T-3478 and T-3722 are leaves
sent during a load).

**The slot list's stamp** (`slotGame` in the worker): the game the active slot holds. A load into another slot or a
view (`intoNewSlot`, `intoView`, `open`) moves it beside `activeSlot = key`, so a slot list sent during the load (a
BroadcastChannel nudge, a lost lease) still names the game being left. A load into the active slot itself (the page
opening its slot, the account's newer copy fetched over it, the rebuilt restarts, a test page's new game) moves it in
`restart()` and publishes the slot list there, since no other list follows those loads. Without that publish the
money's stamp ran ahead of the list's for good and no score was ever sent; `t3734-load-gap` would still pass (it
asserts only that no wrong PUT goes out), so the probe below checks the steady state.

**Where it is compared** (the one place for each direction):
- account.ts `sendScores` and `gameForShare`: `m.game !== saveSlotsState.game` skips (was `m.slot !== slot`).
  `gameForShare` reads the list's stamp with the money, before its `await`. The `sendMoney()` T-3687 added after
  Make a copy is gone: a copy is the same game, so its stamp does not change.
- clock.worker.ts `processMessage`: a `clock` or `edit` with a `game` other than the worker's is dropped there, before
  anything runs; an edit is answered `ok: false` with no issues, so nothing waits and no notice shows (the clock's own
  test in `handleMessage` is gone). Unstamped edits (every edit but the stop queue's, and the checks' bare posts) are
  never dropped: a side switch keeps ids, so dropping an ordinary edit across its "rebuilt" restart would lose a
  player's change today's code keeps.
- The page's stop queue keeps its own tests (a click taken under one stamp is not built or followed up under
  another), now on `gameStamp`; the worker's drop covers the moment between the post and a load the page has not
  heard of yet. LineInspector's refusal callback is skipped when the game changed (a dropped edit has no issues to
  say).

Behaviour: nothing a player sees changes. One window closed: a stop edit sent just before the worker swapped games
under it (the account's newer copy, a rebuild) was applied to the new game's ids; it is dropped now. Save format
unchanged (`MoneyState` is not written).

**Probe** (scratch, `scratchpad/slotown3/stamps-probe.mjs`, ~1 min): after each kind of load the money's stamp, the
list's and `gameStamp` agree with the expected `active`: test page (0, 0), Make a copy from it, page open of a slot
(1, 1: the in-place publish), Open a file, a backup's restore, Community's Open (viewed), Save on the viewed game,
Open a slot: all PASS. An edit posted with the stamp before is dropped (fares 2.5 stay 2.5), with the current stamp or
none applied (3.44, 3.55).
