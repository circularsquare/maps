# T-2588: the North America save's network key changed on every load

Agent netkey, 2026-11-07, main tree, Vite 6178, 3 cores (`TW_CORES=3`, `demandWorkers=2`). Save:
`artifacts/trainworld/anita-2026-11-05/north-america-day-361.save` (the one T-2579 used). Check:
`checks/t2588-netkey.mjs` (logs in `artifacts/trainworld/t2588/`: `before.log`, `diag.log`, `patched.log`, each with
its JSON).

## Cause 1: the eras tail (fixed, `workers/demandCache.ts`)

`saveNetKey` hashed the save's whole network bytes, and those end in the eras tail (`ERA2`, T-1071): per line, the
patterns trains ran before an edit and the trains changing over, drawn only, and pruned by `prune_eras` as the clock
runs. Every autosave writes a shorter tail (on this save 18,958 bytes at the import, then 10,171, 1,767, 0 over three
reloads), so the key changed each load. Tokyo's save has no eras, so its key held. The snapshot demand reads never
looks at eras or shifts.

Fix: `saveNetKey` hashes the bytes without the tail (`withoutEras`, the same split as the sim's `split_eras`). The
arriving network is still compared with the stored one, so a false hit would be caught.

Measured (key without / with the tail, per reload): `3e6244d0` on all three; with the tail `65132451`, `73d03ef3`,
`40e1d6a3`. One line's trains +1 gives `1cfa5316`. The import's own key differs (`dd8cf583`): the file's bytes are
re-encoded when the slot is first written, so Open a file's first reload misses ahead, as before (T-2552).

## Cause 2: a stray zone counted in the read ahead's need (applied as T-2718, `workers/demandClient.ts` `tryCache`)

With the key stable, the read ahead found the entry but missed on "zones" on reloads 2 and 3. At that moment
`solveNeed` held `lns`, a zone the page opened before the network's reach was known (`unknownReach`, T-2579): the
stored network does not reach it and it is not in view, so `closeStrays` closes it before the load's solve, and the
stored entry rightly has no `lns`. The read at the network hits once it has closed. The same thing is T-2579's "started
on another game's camera, the read ahead still misses".

Patch for `app/src/workers/demandClient.ts`, `tryCache`, right after `const need = this.solveNeed(svc);`:

```ts
      // T-2588: ahead of the network, a zone opened before the reach was known that this network neither
      // reaches nor views is not counted: closeStrays closes it before the load's solve
      if (ahead && need) {
        const reached = this.reachedSet(svc), viewed = this.viewedSet();
        if (reached) for (const id of this.unknownReach) if (!reached.has(id) && !viewed.has(id)) need.delete(id);
      }
```

(`solveNeed` returns a new set, so deleting from it is safe.) Tried through an init-script override of the same
logic (`patched.log`): reload 1 none (the import's key), reloads 2 and 3 hit ahead, the arriving network the same
(no second read), `lns` the one zone dropped each time. Filed as T-2718.
