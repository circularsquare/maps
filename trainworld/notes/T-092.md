## What a click changes

While drawing, the route is `[start, lead-in, PI 1 .. PI k, cursor]` and the preview is exactly
what finishing at the cursor would build. Clicking the cursor's point and moving on gives
`[.., PI k, PI k+1, cursor]`:

- every vertex up to PI k is the same (the lead-in too: it points at the first click, fixed once
  that is placed), so every curve before PI k and everything up to where PI k's curve starts is
  identical, to the last bit;
- PI k's curve keeps its corner and its in-leg share; its out-leg share goes from the whole leg to
  the cursor (a leg next to an end node is all available, SPEC 6.1) to half the leg to PI k+1, so
  it gets tighter only if that leg was what limited it, that is when PI k+1 is less than half the
  previous leg away;
- PI k+1 becomes a corner with its own curve as the cursor moves away.

`a_click_keeps_the_track_drawn_before` (sim/src/track/wasm.rs) draws seven clicks from a track end
through the real `preview_route` and checks all three, sampling both alignments every metre up to
the start of the previous click's curve (identical to 1e-9 m); its clicks cover both cases (two
clicks tighten the previous curve, three leave it exactly as it was). In the app, a six-click route
drawn with real mouse events: before and after each click the preview's points agree within half a
pixel from the start up to around the previous click, and differ only after it (the exact check is
the test).

Freezing the previous curve completely would need the last curve to use only half its leg to an
end, which would make the finished track differ from the preview or change old saves (fit is
shared by every edge); not done (DECISIONS).

## Code

- `route_op` (wasm.rs) is T-023's again: the clicks are PIs (radius from `PiInput.radius`, auto
  when absent), `lead_in` adds a PI on the heading of a start or end on existing track
  (`lead_in_along` is the shared part, also used by T-093). `leave_dir` and `geom::through` (with
  its tests) are gone.
- Reshaping: `edge_pis` (`[T-079 edge 1/0, per PI x, y, set radius, level, radius used, km/h,
  curve middle x, y]`), `preview_edge`, `set_edge_pis`, `set_edge_level`. `edge_shape`,
  `set_edge_thru`, `preview_edge_thru` are gone. `reshaped` puts a set radius the edit did not
  change back to auto when it no longer fits (`relax_radii`): splits freeze the radii beside them
  and those refused every drag of a neighbour.
- App: `map/edgeEdit.ts` drags PIs again (op `edgePis`, preview `previewEdge` with `pis`), Escape
  cancels a drag; the track inspector (`ui/inspector/others.tsx`, `Shape`) has T-064's radius
  stepper back, and a note on a T-079 stretch. Tool hint: "Click where the track should turn."
