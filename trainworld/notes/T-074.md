# T-074: station labels during panning

Done 2026-10-10. Code: `app/src/map/stationLabels.ts`, `ui/style.css`, `perfFlags.ts`.

## Change

Keep the outer label box clipped to the viewport and move an inner compositor layer during a
flat mercator pan. Compare the rendered camera's linear terms, homogeneous divisor and viewport
size with the last placement, then project one fixed anchor to get the translation. Zoom,
rotation, pitch and resize use full placement. No MapLibre private fields are used.

Place names inside a 256 px margin and rebase after 128 px of pan travel, so incoming names do
not disappear during long drags. Collision priorities stay transfers, lines, constructed. A
network change, font readiness, showing labels again and the final camera frame after moveend
also re-place them. Relative name placement is stable between rebases; names may change at the
edge when a new collision pass runs. The outer clip stays still, avoiding a moving viewport.

`?perfOff=labelPan` restores the previous individual placement, without the padding or shared
compositor layer, for comparison. T-075's double-draw candidate was not adopted.

## Measurements

Chrome headless, installed Windows Chrome, 1360 x 900, production Vite build served through
`http://localhost:8800/trainworld/`. Isolated browser contexts, paused new game, 300 synthetic
stations, 150 labels surviving collision placement at zoom 11.8. Continuous held mouse drag,
240 moves with 16 ms waits, displacement below the rebase threshold. Order old/new/new/old.
The basemap and the invisible station-name layer are present in both versions.

CPU uses the sum of process CPU time from CDP `SystemInfo.getProcessInfo` divided by wall time,
expressed as percent of one core. Main-thread work uses CDP `Performance.TaskDuration` the same
way. No per-frame alignment inspection runs in the measured interval.

| Measure | Before, two runs | After, two runs |
|---|---|---|
| Total browser CPU, % of one core | 60.14, 59.32 | 38.91, 39.98 |
| Main-thread task time, % of wall time | 21.26, 23.69 | 14.00, 14.82 |
| Per-label style mutations during drag | 35,550 each | 0 each |
| Shared-layer transforms during drag | 0 | 237 each |

Mean browser CPU 59.73 -> 39.45 (34% less); main-thread work 22.47 -> 14.41 (36% less).
These measure this headless workload, not a guarantee for every display or network. They are
not directly comparable to T-045's foreground Windows process sampling. Long pans still need
periodic placement, and zoom/pitch costs retain the full placement path.

  pitch, padding, resize and hide/show changes; no page errors.

  Maximum alignment error 0.747 CSS px; no overlapping visible label rectangles beyond 1 px
