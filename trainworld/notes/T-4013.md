# T-4013: boarding-only and getting-off-only stops (agent boardonly, 2026-11-21)

Status: built in `.tw-trees/boardonly` (branch tw/boardonly, from master 182e8e8e), not committed.

## Ask

A player via Anita, 11-21: "being able to set stations to only allow boarding or only allow disembarking. seems
easy to do."

## What it is

- **The rule.** A stop of a rail line (train or tram) can be boarding only (riders get on, never off) or getting off
  only (off, never on). It holds on both runs; trains still stop and stand the dwell. Per line, per station of its
  stops (a loop's repeated visits alike). Bus and ferry lines have none.
- **Both runs, not per direction (my call, advisor agreed).** The player's words and the brief's rule ("a rider
  can't get off at a boarding-only stop") read that way, and the brief's in-game check (a boarding-only first stop
  changes riders) only means something that way. The real railway case, "picks up only on the way out of the city"
  (UK timetables' `u` / `s`), is per direction: outbound pick-up only, inbound set-down only at the same station.
  Both-ways settings cover half of it (no city-to-suburb local riders) but not the other half (the suburb's riders
  into the city still ride, and riders from the far end can't get off there). Not built; would be a fourth and fifth
  state per stop, or a direction per setting.
- **Sim**: `LineData::only: Vec<(station, kind)>` (`BOARD_ONLY` 1, `ALIGHT_ONLY` 2, `track/net.rs`),
  `Network::line_only`, filtered to the line's stops in `set_line` (so a stop edit keeps it on stations still stops
  and a removed stop loses it; copy keeps it). `TrackApi::set_stop_only(line, station, kind)` is one undoable edit,
  free, 1 when nothing changes; `line_stop_only` feeds `LineStats.stopOnly`. A hidden twin (T-3333) gets the same
  kinds at its stop beside each (`twin_data`, by position; its stops are the parent's position for position).
- **Demand reads it through the service span** (`LineSvc::only` per stop, `span::line_span`): the span is already
  per period and route node, in every engine (commutes, everyday, between cities), in the cluster remap and in the
  "same network?" comparison. Marks beside the share: -1 pass (T-3332), -2 getting off only, 2 + share boarding
  only (`span::stop_span` reads, `span_clamped` keeps marks through demand's 0..1 clamp). In `build_graph`: getting
  off only drops the board edge and sets `rn_tph` 0 (search paths read it directly); boarding only drops the alight
  edge and the walking-transfer edges from that route node (else riders get off by walking on). Run 1's slot k is
  listed stop n-1-k; the listed stop's index decides, whichever platform the run stops at. `span_key` hashes it.
  `update_scoped` wakes demand when `LineSvc::only` changes (as for stops), so the toggle and its undo send a new
  network. The boarding account needs nothing: it boards and lets off demand's numbers.
- **Found and fixed on the way: T-3332's pass never reached the kernel.** `span_for` clamped every span value to
  0..1, so -1 became 0: no boarding at a passed one-track stop (right) but alighting and walking on there still
  allowed (wrong: riders could get off a train that runs past on the other track). The clamp now keeps the marks
  (`span_marks_survive_the_clamp`). This can move riders on saves with one-track stations where trains pass; it is
  what docs/demand-kernel.md already said.
- **Save**: trailing `LBO1` block (count, then per line index, count, per stop its place in the stops and its kind),
  save level 37 -> 38. **The server's save check (shonei-server `trainworld_savecheck.go`) must learn level 38
  before the next publish.** Another tree adding a block at the same time collides at landing: take the next free
  level and block order then.
- **UI** (`ui/inspector/stopOnly.tsx`): while stops are edited, each stop row has a small switch before the remove
  cross: icon = the train's side with an arrow in and out / in / out; dim while both; a click cycles both ->
  boarding only -> getting off only -> both. Otherwise a set stop shows the icon (muted) after its name and time,
  hover naming it. The schedule window's timetable marks the station row; the departures board names it beside the
  station picker (departures stay listed: trains still leave a getting-off-only stop).
