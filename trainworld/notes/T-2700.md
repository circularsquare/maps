# T-2700: the route preview on all of Japan

T-2404 saw `preview_route` take 40-190 ms a pointer move on all of Japan (5-8 ms on New York). Done
2026-11-07 in tree `boarding`, on top of T-2699.

## What it was

Mostly not the preview. In isolation it is cheap: the app's WASM in Node on t737-japan-trains.save
with Japan's ground loaded (the world's water, the 60 Japanese zones' water masks and terrain; no
roads) takes 2-3 ms a preview. The 40-190 ms in T-2404's profile were the clock worker's memory grows,
which T-2699's allocator removed (the same call tree as the boarding steps' grows sat under
`preview_route` there), and a busy machine: the check's Chrome shares its pinned cores with the
demand workers solving after every click.

In the game after T-2699 (the T-2403 check, `japan`, 3 cores, 2 demand workers, with a trace): the
preview's own time p50 4.5-5.9 ms; the slow tail (p95 ~30-50 ms) are previews right after a click,
while the CPU is shared. Inside the slow ones the time is spread: pricing the whole network
(`total_and_built_cost`, ~20% overall, called 4 times a preview), `derive`, the ramp tries
(`bridge::build`), water lookups for the ground metres, and the polyline sampling.

## Change

- `world.rs` `TrackWorld::trial`: the rollback is `apply_and_derive(inv)`, the work
  `commit_with(inv, false, false)` did minus pricing the whole network twice for a result nobody read.
  A preview now prices the network twice instead of four times.

## Notes for later

- A WASM build with names for profiling: `cargo build --lib --target wasm32-unknown-unknown --profile wasm`
  then the wasm-pack cache's `wasm-bindgen.exe ... --target web --keep-debug` (no wasm-opt), copied over
  `app/src/wasm/track` for the run. `wasm-pack build --profiling` gave a module that panics in
  `geom::fit_capped` on ordinary previews (a check that build has on, likely an integer overflow that
  wraps harmlessly in the app's build) and hangs the game's load.
- Left, if a preview ever needs to be faster: `cost_before` is the same for every preview until the
  network changes (a version counter would let it be kept), and the network-wide pricing itself
  re-asks the water mask at every flat crossing.
