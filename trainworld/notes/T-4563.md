# T-4563: a Stop hook buried Anita's last message

Cause: both Stop notes (200k "look at what filled it", 500k cycling) were printed as Stop additionalContext, which makes the
session take another turn. That reply became the last thing Anita saw (focus view shows only the last reply).

Fix (.claude/hooks/orchestrator.py, .claude/settings.json):
- stop no longer gives context. It holds the note in `<state dir>/<sid>.pending.json` (hold()).
- The note is given at the next PostToolUse (post() now starts with take_held) or the next UserPromptSubmit (new hook
  command `prompt`, new "UserPromptSubmit" entry in settings.json). Subagent calls (agent_id) never take it.
- The 500k notice still prints its systemMessage at Stop (screen only, no new turn), so Anita sees it at once. Its
  instruction waits for the session's next tool call or prompt. An orchestrator sitting in Poll/REPL gets it on the
  next call; a fully idle one gets it when anyone writes to it. A newer cycling note replaces a held one.
  Chosen over keeping 500k at Stop because that would bury the final message the same way.
- Cost: an idle session does not start cycling by itself until woken; it was never able to do more than one turn anyway.

Tested with sample payloads (TEMP pointed at scratchpad): Stop prints nothing for 250k; prompt delivers once, then empty;
620k prints only systemMessage; subagent post gets nothing; main post delivers once. settings.json parses.
Fails open as before. The settings.json autoMemoryDirectory and code-guard lines are not mine and were left.
Takes effect for new sessions (hooks load at session start).
