## T-3257: View (maps, not committed)

**What it does.** Community's "Open a copy" button is now "View". It downloads and checks the share's save as before
and reloads the page into it, but the game goes into no slot: nothing autosaves it, it is not on the account, it sends
no figures (it was already a copy: header `copy`). It plays and edits like any game. Save makes it a normal saved game
named "<title> - <name>", the Playing card from then on.

**Where.**
- `workers/saveFile.ts`: `PendingLoad` import gains `view`.
- `workers/clock.worker.ts`: `viewing` (the name) and `viewCard` (its picture and facts, drawn when it opens and on
  each panel refresh); `intoView` loads it into no slot; `saveView` is the copy path (`manageSlot` create) under the
  view's name, then `savedByHand`; `saveByHand` (Ctrl+S, every Save button) goes there while viewing;
  `flushBeforeSwitch` lets a viewed game go unsaved; intoNewSlot, create and open clear it. `publishSlots` sends
  `viewing` (a SaveSlot with key "") and the reason `clockWorker.viewing`.
- `workers/protocol.ts`: `saveSlots.viewing`.
- `workers/clockClient.ts`: `openView` (was `openCopy`); `leaveViewed()` asks through the `ask` dialog and resolves
  true or false; `switchGame` and `leaveToMenu` wait for it, so every way of replacing the game asks (Open, Open a
  file, a version or backup, an account game, New game, Share again on another game, the main menu door, signing out
  with removal). The exported file is named after the view.
- `game/ui.ts` `ask` gains `stay` (no button or Esc); `ui/ToolNotes.tsx` calls it.
- `game/community.ts` `openSharedView` (was `openSharedCopy`) returns null when the player chose Stay.
- `ui/SavesPanel.tsx` `ViewCard` first in the list; the red reason callout and the test page's copy icon hidden while
  viewing; `SlotFacts` takes `unsaved`. `ui/TopBar.tsx` notice with Save.

**Calls made** (DECISIONS 2026-11-12):
- Edits allowed; it is a game, just not kept.
- Time played: per-game seconds are keyed by slot, so they start at Save. The account's own playtime (pings) counts the
  page being open, as always.
- Achievements: the game's own, as with any copy; a copy never reports achievement counts and never ranks, saved or not.
- Tab close or reload asks (the browser's question) only after a change, through the existing "unsaved" path
  (`edited && !writable`). An untouched view loses nothing that is not still on Community. A reload of a viewed game
  (F5) goes back to the game before it, since the pending load is used up.
- The ask dialog keeps its "Confirm?" heading, so the body drops her "are you sure?" and reads "<name> won't be saved."
- The share dialog's tick "Let others open a copy" is unchanged: from the sharer's side others still get a copy. The
  privacy and terms pages ("anyone can also open a copy of the game and play it") stay true.
