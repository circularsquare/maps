# T-4258: Port PR #34 — capacity sections through one-way pairs

Ported from `xoaninc`'s PR #34 on `circularsquare/trainsworld` (credit: `xoaninc`, Xoan Macias).

## What changed

- `trainworld/sim/src/track/capacity.rs` (`build_sections`): instead of breaking every track section at any node with `live_ports != 2`, directed track (`te && tf`) now joins across a junction whenever `sig[a] == sig[b]` (the exact same set of `(line, run)` enters and leaves). Single track (`!te && !tf`) still stops at any junction (`!parts`), reversals still stop (`net.turns_back`), merges and diverges still cut because `sig` changes, and junction moves remain separate `ResKind::Junction` resources.
- `trainworld/sim/src/track/wasm/oneleg_tests.rs`: added `cap_matches_global` and `a_one_way_pair_starts_no_queue_of_its_own`, verifying that two lines P->Q and one Q->P across a one-way pair (both right-hand and left-hand running, before and after adding a station on a leg) each pass 1 section per direction instead of 3, and that incremental capacity matches global capacity.
- `trainworld/docs/track-and-service.md` ("Resources and utilisation"): documented that a track section runs on through a junction where the same trains come in and go on (as at a one-way pair).

## Correctness check

- Incremental vs global capacity (`Capacity::update` in `capacity.rs`): touching any edge or node of a 3+-port junction marks the junction node in `dn`, which marks all incident edges in `he`, kills any `Tag::Section` touching `he`, and rebuilds all their keys together in `kk`. Verified by `a_one_way_pair_starts_no_queue_of_its_own` and `capacity::tests::incremental_equals_global`.
- Note for `tw/track`: if `tw/track` (`T-3951`) keys capacity by track id separately, this change should be carried over when `tw/track` merges.
