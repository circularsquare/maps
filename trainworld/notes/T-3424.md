# T-3424: the changelog for the next update

Anita's ask (2026-11-16): agents put an item in the changelog whenever they add a feature or change something players
see; she can reword any item (not final, an agent may re-edit it at the release review) and hide any item (it stays
in the file, so the record shows we did it, but it does not reach the posted changelog).

## What's where

- `trainworld/changelog/next.json`: the open release (absent until the first item). Publish renames it to
  `<version>.json`. File: `{release, line, items[]}`; item: `id` (c001..), `text` (the agent's), `edited` (her
  wording or null), `hidden`, `task`, `by`, `at`, `rev` (+1 per save), `changed`. `line` is the start-menu line
  (80 characters at most), set with the CLI at release time. Areas, fixes and groups (`area`, `fix`, `parent`,
  `group`): notes/T-3466.md.
- `trainworld/tools/changelog.py` (stdlib): `add "<text>" --task T-#### --by <agent>`, `list`, `line "<text>"`,
  `publish --version v0.3.6 [--at ISO] [--dry-run]`. A lock file (`next.json.lock`) is shared with serve.py, so an
  agent's add and her save never overwrite each other.
- serve.py `CHANGELOGS["twboard"]`: GET `/twboard/_changelog` (file plus `version`), POST `{id, rev, edited?, hidden?}`
  with `X-Maps-Run`. A `rev` that is not the item's gets 409 with the current item. 8800's serve.py needs a restart.
- Board: "Changelog" in the top bar (hash `#changelog`). One card per item: task link, text box (saves 1.2 s after she
  stops typing and on blur, "Saving"/"Saved"), "Hide from the update" / "Show in the update", "Use the agent's wording"
  once reworded. Hidden items stay listed, dashed and struck through, badge "Hidden". On a 409 the box shows the new
  wording and her text sits below with "Use my wording" / "Discard". Refreshes every 15 s unless she has unsaved typing.
- Publish (`changelog.py publish`): visible items in file order, her wording where `edited`. Writes the entry at the top
  of `UPDATES` in `app/src/ui/updates.ts`, keys `updates.v036Line` and `updates.v036Change1..n` in `messages/en.json`
  (before the newest update's keys) and `context.json`, keeps each file's line endings, turns ' into the curly
  apostrophe, refuses braces, a missing or over-long line, and a version already in updates.ts. Then moves the file to
  `changelog/<version>.json` with `published`. Other languages still go through the usual translation step. Tested on
  copies of the three files only; no real publish was run. The publish notes (T-924 commands, orchestrator.md
  "Publishing") should say to run this before `deploy.py`.
- Notes tables on the board: a drag handle on the right edge of every header cell. The first drag freezes all column
  widths, then the dragged column grows and the table gets wider (it scrolls sideways inside the notes). Not
  remembered across reloads.
