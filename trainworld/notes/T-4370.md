# T-4370: iPad memory on a big save's load and edits (agent ipadmem, 2026-11-27)

`ipadmem/` (`ipad-run.mjs`, `ipad-run2.mjs`, `chrome-run*.mjs`, `*.log`, `*-alloc.json`, `*.heapprofile`).

- **1795673563** (Safari 26.6.1, iPad, 0.4.7): Kansai slot (oky, shg, osa, ttr; 1,042 stations, 84 lines), one solving
  worker; the tab died at "demand demand", 214 s after the pick (the died-load flag), then the out of memory screen.
- **1795675092** (Safari 26.6.1, iPad, 0.4.7): "crashes every 2 minutes while editing lines, and I have to reload". The

  long runs, and its notice tells the player to reload ("再読み込みすると再開します"). Not proven: a tab killed by iOS
  while editing leaves the same report. The memory climb during an edit's solve below is the other candidate; this
  task lowers it.

## Method

Production builds of the tree (`TW_LINK_PACKS=1 vite build --outDir <scratch>`, `checks/static-serve.mjs` on 6114).

- **WebKit** (Playwright's WebKit 2311 on Windows, Safari 26.5's engine): WASM with SIMD, workers and WebGL2 run; no
  OffscreenCanvas (some terrain tiles are not flattened; real Safari 26 has it). An iPad as the game sees it: Safari's
  Mac user agent, `maxTouchPoints` 5, 1180 x 820 at 2x, so one solving worker that is the aux worker too, intercity
  trips off, less detail on. Measured: the WebKitWebProcess's private bytes every 0.7 s (it holds the page and every
  worker, as iOS's WebContent process does; GPU work is in its own process). Its empty-game figure (1,060-1,250 MB)
  is above a phone's: Windows WebKit's own overhead, so read rises, not absolutes.
- **Chromium** with the same iPad settings (`deviceMemory` hidden) for who holds and who allocates: each context's
  JS heap, ArrayBuffers and WASM (CDP), and the sampling heap profiler with collected objects included (what each
  function allocated, garbage too). V8 counts boxed doubles as allocations, which JSC (NaN-boxing) does not make, so
  number-heavy functions read high there; arrays, objects, maps and strings are real in both.
- The real NYC save imported into a fresh `?new=1` game; edits remove the middle stop of the longest line (96 St).

## Cut

- `workers/demandSums.ts` `packDays`: counts every array's length, then writes the numbers into typed arrays of that
  size. Before, every number was pushed into plain arrays (each Float32 held as a double, with the arrays' growth),
  then copied. Old against new on synthetic views (30 lines, 5 periods, 3 days, 4 purposes, NaN, -0, Infinity, missing
  transfers): f32, f64 and idx byte for byte equal, station ids and days equal.
- `map/trainGuard.ts` `update` (each frame, every train in or near the view): its working arrays (candidates, their
  places, lengths, times, the new places, each track's list) are kept on the guard and emptied each frame; the box's
  corners projected without arrays; `trainFrameInto` (`map/network.ts`) fills one object. Same arithmetic in the
  same order: each track's registrations are taken in the order the frame first met them (`keys`), the order the new
  map each frame gave. Display only.
