# T-3945: every edit fails and the game won't save

Agent editfail, 2026-11-21. Tree `tw/editfail`.

## The cause

A Rust panic in the capacity pass, repeated until the track model was left down.

- `Service::update_scoped` (sim/src/track/service.rs) hands `Capacity::update` the old and new paths of each
  rebuilt line, so it can drop and rebuild the resources around them. It passed only `runs[0]` (the way out).
- A line whose way back calls at platforms the way out never visits (a street tram with a stop on each side of
  the road, a loop made of two one-way single tracks) leaves those platforms' resources behind with the old run's
  stop indices.
- When the line then has fewer stops (deleting track under it breaks it: 0 stops), `holds_with` indexes past the
  end: `capacity.rs:1558 index out of bounds: the len is 0 but the index is 5`.
- Each panic is recovered (the edit undone, "That edit failed and was undone."). The fourth in a minute (or the
  ninth in all) leaves the model down (`clockPanic.ts` MAX_PANICS_PER_MINUTE 3, MAX_PANICS 8). From then on every
  edit is answered "Internal" (same message), autosave stops, a save by hand and a download get no answer, and
  leaving (menu, opening another save) fails in `flushBeforeSwitch` with "This game could not be saved. Download it
  as a file before leaving it." whenever something was still unsaved. A browser reload brings the game back from the
  last autosave.

Not the cause: storage (the report says persisted yes, 5 slots, no failures); locale (the same panic in English).
The save message was never an older wording of `clockWorker.couldNotSave`: it is the English literal at
`slots.ts:212`, current on master, so it says nothing about the version.

## Evidence

- The player's save (scratch, not committed) loads on master; train counts, renames, line edits and station
  deletes all work. Deleting edge 2000 (tram line T6) or 1800 (T3) panics as above; native probe on the save's
  network bytes the same. The stale resources: a Platform at node 1838 with line 17 run 1 stop 5 (and line 20),
  at node 1675 with line 14 run 1 stop 5; in both, only run 1's nodes hold the node.
- Deleting 2000 five times in the open game: three "That edit failed and was undone.", then "The train simulation
  stopped working. Reload the page to go on. Your last autosave is kept.", then every edit refused.
- The player's in-game report, 1795272636-3feabbd3 (v0.4.5, Chrome 157, es, 16 GB): "clock: status track model
  down after a panic; last error ... recursive use of an object". Screenshot is the same "Deleting / That edit
  failed and was undone." as on Discord.
- Reach, feedback over 168 h (112 error/feedback reports read in full): one more, 1795063545-3aa25b46 (v0.4.2, a
  loop line made of two single tracks), `capacity.rs:1439 index out of bounds: the len is 4 but the index is 15`
  in an edit, recovered: the same class (a line whose two directions differ), that version's line numbers.

## Fix

`add_path` in `update_scoped` takes both runs' segments and nodes. After it, deleting every one of the save's
2400 edge ids one at a time (a fresh load each) gives 2338 deleted, 62 refused, no panic.

Test: `a_platform_only_the_way_back_uses_goes_with_the_line` (sim/src/track/wasm/oneway_tests.rs): one-way ring,
line A - B, its way back passes C; removing the line must leave the capacity equal to a fresh build. Fails on the
old code (a Platform at C keeps the removed line's user), passes now.

Checks: `agent_cargo.py test` (717 and 935 passed), the tree's WASM built, the probe deletes (2000, 1800 and 15
others) all go through in the game with no worker trouble, smoke passed (30 checks). A run with `--query lang=es`
opened in English (play.mjs did not take the language), so Spanish was not tried in the game; the panic is the
same with no page at all (native), so the language plays no part.

## Proposed, not built

The model-down state hides itself: after its one notice, each refused edit shows "That edit failed and was undone."
over it, which reads as a problem with that edit, and the player keeps trying. Drafts:

- Refused edits while the model is down say the model-down line instead (reused: "The train simulation stopped
  working. Reload the page to go on. Your last autosave is kept."), and save and download answer with it too
  rather than nothing.
- Leaving while the model is down goes without saving (the autosave is what the message promises is kept), so
  "Back to menu" works instead of failing.
- `slots.ts:209` and `:212` are English literals, shown untranslated in every language (the player's second
  screenshot: a Spanish panel title over the English line). They want message keys.
