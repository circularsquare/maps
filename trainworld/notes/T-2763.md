# T-2763: edits that wait on the clock worker

Anita's playtest: a placed station shows late, the "not enough money for trains" bonk while extending a
line comes late, deleting track or stations (even blueprint) is slow.

## Measured (real save, `checks/t2763-edit-lag.mjs`, Chrome pinned to 2 cores, ms click -> result in `world`)

| action | before | where the time goes |
| --- | --- | --- |
| place a station on built track | 1900 to 3700 | worker `buffers` 2100: the split piece makes every line over it lay its strokes again (`networkFromState`) |
| delete blueprint track | 110 to 350 typical, 2300 to 3600 now and then | a `removal` query first (1 to 100), then the edit; the state waits for the boarding account's steps (`board` up to 360) and a slow `buffers` |
| delete a built station | 400 to 3900 | `buffers` 210 to 2700: `nPhaseLines` 109, every line's run profiles are rebuilt |
| bonk, extend a line past the cash | 4 to 9 idle, 38 straight after a paid edit | the refusal itself is cheap |

The clock worker answers edits one at a time (`messages` chain in `clock.worker.ts`), and an edit's follow-up
(state, trips, boarding hour) finishes before the next message runs. Nothing here waits behind a demand
solve: the same cases run during one came out the same (blueprint delete 137 to 227, station delete
175 to 493). The shared cause is that the page draws nothing of an edit until the worker's state returns.
Track placement avoids it with the ghost standing in (T-1407); stations and deletes had no stand-in.

The bonk could not be made slow. In the worker a Money refusal is 4 to 9 ms (a dev-only message set the cash
to 0.01 and the fleet to 0). The wait Anita saw is most likely the click before it: `Tools.toggleStop` sends
one stop edit at a time, each waiting for the last one's state (0.2 to 3 s on a big network), so a second
click's answer starts after that. Not changed, see the proposal.

## Changed

- Station tool: a click leaves the ghost standing where it was clicked (`addPending` in `map/tools.ts`)
  until the worker's answer puts the station in the world; a refusal takes it away. Visible in 1 ms.
- Blueprint track no line is drawn over and no station touches (`stationTrim` 0): hidden at the click
  (`hideEdge`, a `u_hide` uniform in the stroke shader, `map/renderer.ts`), and the `removal` query is
  skipped (`game/remove.ts`, `setTrackHider` set in `main.ts`). The edit still goes to the worker; a
  refusal shows the track again. Visible in 0 to 3 ms. Larger or line-carrying deletes keep the old path.
- Worker: a blueprint `removeEdge` that dirties no demand line sends no trips and runs no boarding steps,
  as a placed segment does (T-1780). Typical state time 110 to 240 -> about the same; it takes out the 2 to 3 s
  boarding stalls.

## Proposals (not done)

1. **Built station delete**: the cost is the full phase rebuild (`nPhaseLines` = all lines). Rebuild only the
   lines the removal touches in `buildState`/`sendState`, and keep the rest of the render arrays. Worker work.
2. **Station placed on a split piece**: the 2 s is `networkFromState` redoing every line over the split edge.
   Keep a line's strokes when only an edge's id changes and its points do not (the cache compares `path`).
3. **Bonk**: a page-side price check needs the new round trip time, which only the track model has.
   Instead, let a stop edit that adds no cars answer `early` like a track segment, state after.
4. **Stop clicks**: send the next stop edit without waiting for the previous state (answer `early` for stop
   edits), so a second click is not held for the first one's follow-up.
