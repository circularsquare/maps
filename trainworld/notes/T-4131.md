# T-4131 Profile the track model's part of an edit (agent tmprofile, 2026-11-23)

## What was done

- Stage 1: the same click-to-map rows as T-4097 section 1, on master (8702f017), Asia save t3600-asianita-1852 (221 lines, 2,647 stations), clock paused, game on 3 claimed cores (play.mjs --cores 3), T-4097's scripts (`editspeed\p1-p4.js`, `analyze.mjs`, same CPU profile on in every run). Two full passes: one on the build the tree was seeded with (wasm-opt'd), one on the named build below. Ranges below span both passes (6 runs of each row where the row has several clicks).
- Stage 2: a WASM with function names, built in this tree only (nothing in Cargo.toml, package.json or the shipped build changed): `cargo build --lib --target wasm32-unknown-unknown --profile wasm` then the wasm-pack cache's `wasm-bindgen --target web --keep-debug`, no wasm-opt (T-2700's method; `wasm-pack build --profiling` is known to break). Output: scratchpad\tmprofile\named\. Profiled with the same CDP worker profile; names demangled by scratchpad\tmprofile\wp2.mjs. Profiles are in scratchpad\tmprofile\runs-named\ and runs-master\.
- Machine: 8-13 of 14 cores claimed by others throughout. Demand reported "final" at once in both passes (no trip workers fighting for cores, unlike T-4097's Asia runs), so these are the kinder numbers. The CPU profiler itself costs time: wasm frames run 1.5-4x slower while it samples (T-4097 had it on too, so the two tables match in method).

## 4. Tasks I'd file (titles and hours)

1. Re-time only the lines whose timing moved (`retime` by cluster): 6-9 h. The largest single piece of the apply: 18-343 ms per edit here, plus 321-587 ms in each station-tool preview, plus it widens `take_changed_lines`.
2. Edits move only the trains they can change (`before_edit`, `note_changes`): 3-4 h. 306-374 ms of a stop add or a track piece from a running station; more with the clock running.
3. A line's time zone looked up once (`utc_offset_at`): 1.5-2 h. 75-120 ms.
4. A line's fleet kind kept (`cars_needed`): 1.5 h. Small; file as P3 or fold into task 3.
(Not filed: `total_and_built_cost` rides on T-4097 part B; the five rework scans are designed out by 2, 3c and 4a and cost under 5% of apply.)

About 10-15 h in all. What they would save on this save: the track model's apply goes from 0.1-0.8 s to roughly 0.05-0.15 s on the bigger edits, which is 5-15% off the felt wait (the rest of the wait is T-4097's parts B to E), more on a running clock. The station tool's preview drops from 0.6-1.1 s to about 0.2 s on a busy line.

## Caveats
- One pass per row per build, six clicks in the stop rows, on a loaded machine; ranges, not medians. The CPU profiler inflates wasm time, so use the shares within a row, not the absolute ms of section 2.
- The named build has no wasm-opt (2.96 MB against 2.55 MB), so its applies read a little high; the two passes agree within noise.
- The seeded build was whatever the tree was seeded with at 15:09 (master's), so "master" here means that.
- Clock paused: `note_changes`' in-flight loop is smaller than in a running game.
