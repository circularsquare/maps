# T-3834 copied line left most periods empty

Cause: `copy_line` (sim/src/track/wasm/lines.rs) zeroed the three base rows (trains, tph, auto) but not `x`
(midday and afternoon rows of a 4 or 5 period line), so those kept the source's service. The worker's copyLine
(clock.worker.ts) also never applied the new-line headway default that addLine applies.

Fix: copy_line zeroes `x` too; the worker applies `headwaysFor(kind, newLineHeadway, rows)` and the new-line weekend
share after the copy, as addLine does (kind from the source: ferry, bus, tram, fast, rail). Where the player set no
default for a rail kind, a copy is empty in every period, as a new line.

Probe (scratch, nyc, source line 6/4/3 trains, default rail 600/900/1200 s), trains by period:
- before, 4 periods: source [6,6,4,3], copy [0,6,0,0]
- after, 4 periods: copy [3,3,1,1], headways 600/600/900/1200
- after, 5 periods (default 5 values 600,900,1200,900,1800): copy [3,2,2,1,1], headways as set
- after, 3 periods: copy [3,1,1]; no default set: [0,0,0] (as before)
Stops, name, colour unchanged. Docs: ui-inspectors.md Copy line.
