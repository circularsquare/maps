# T-4259: rename a line's stations together (port of PR 35)

Credit: **omi-key** (GitHub), PR #35 "Rename a line's stations together from its panel"
(https://github.com/circularsquare/trainsworld/pull/35). The Rust edit (`TrackApi.rename_stations`, its test
`stations_rename_together`), the worker op (`renameStations`) and the box list's behaviour are theirs; the port
changed the panel control and fixed the points below.

## What a player sees

- A rail line's panel, Stops heading: a small icon (a list with a text cursor) after the Related lines icon, while
  stops are not being edited. Hover: "Rename stations", then "Paste a list of names into a box to fill it and the
  ones below". The heading has nothing else new.
- Clicking it swaps the stops list for a box per station (list order; the bound stations of one complex share a box),
  the first box focused and selected. While open, the heading is just "Stops" (Related icon, rename icon and
  "boardings today" hidden).
- Enter: next box; on the last box, or Ctrl/Cmd+Enter: rename. Esc or Cancel: close, nothing renamed, panel stays.
- A changed box is bold, its hover the old name. The focused box's station gets the stop rows' hover light on the map.
- "Rename 3 stations" (greyed, reading "Rename", until a box changes): one edit, one undo.

## Read before run: what could go wrong, and what changed from the PR

1. **Esc** (Gemini): master's main.ts already returns early for any key in a text field (`keyIsTheirs`), so Esc in a
   box never cleared the selection; but other window listeners exist. The box's Esc now also stops propagation.
   Checked: Esc closed the boxes, the line stayed selected, its stop rows back.
2. **A station that vanishes meanwhile** (Gemini): the PR froze the rows at open and, if any changed station was gone at
   Rename, closed and dropped every typed name; `world.peek()!` could throw. Cause: a frozen snapshot. Now the rows
   are built from the line as it is on each render, and typing is kept in a map by row key (an unbound station's id, or
   the sorted ids of the complex's bound stations), so an undo, a deleted station or a reordered line takes only its
   own rows; untouched boxes follow names changed elsewhere. Save skips any station gone between render and click.
   Checked: typed into 3 of 4 boxes (a 2-line paste plus one typed), deleted the untouched station's node while open:
   3 boxes left with the typing intact, "Rename 3 stations" renamed all three.
3. **Header crowding** (Gemini): the PR's text button "Rename stations" sat between "Stops" and "boardings today"
   (long in German/Russian). Now a 22 px icon button styled as the Related toggle beside it. Measured at rest: the
   heading stays one line (28 px), 114 px free between the icon and "boardings today" in a 276 px panel.
4. **IME** (found reading): Enter while composing Japanese/Chinese text would have jumped boxes or renamed mid-word;
   key handling now ignores composing keys. Not run (no IME in the headless game).
5. Opening another line, or starting to edit stops, closes the boxes (effect on line number and editing state).
6. One undo: checked, Ctrl+Z after Rename gave all three names back at once.

Left out from the PR, for a small UI (DECISIONS 2026-11-25): the pulsing ring MapLibre marker on the focused station
(it would have been the game's first DOM `Marker`, with a new animation) and the "Renamed N stations" notice (the list
shows the new names). Not fixed: a pasted list longer than the boxes below drops its extra names silently (minor).
The PR's translations were not ported (its strings differ); the new keys show English in other languages until the
next translation batch.
