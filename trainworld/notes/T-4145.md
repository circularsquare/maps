# T-4145 The shared show-at-click base (agent editbase, 2026-11-23)

## The API (stage 0), for streams A to D

Changed from T-4144 section 2 only in being concrete. Names are final unless a later note here says otherwise.

### Worker: the word

- protocol.ts `FromClock`: `{ kind: "applied"; seq: number; word: EditWord }`, sent once after **every** accepted apply, before
  anything else that edit sends (rows, state, answer). The money-only, link, building and loan branches send it with an empty
  word. Refusals send no word; their `edited` answer goes straight after the failed apply, as now. lineclick's `linePath`
  message is gone (its lines are the word's `lines`).
- `EditWord` (protocol.ts), every part optional; ids are the ones the page draws now unless said:
  - `lines: { line; edges: Uint32Array | null }[]`: a rail line's strokes now draw these edges (null: the line is gone).
  - `hideEdges: number[]`: edges (track and the line strokes on them) not drawn until the next network. Any number.
  - `edges: { edge; built?; off?; level?: [number, number]; tracks?: 1 | 2 }[]`: an edge drawn with this look (its
    network strokes hidden, redrawn from the same segments with the look changed).
  - `hideStations: number[]`: station node ids not drawn.
  - `stations: StationBox[]`: station boxes drawn as built (see the page side).
  - `colours: { line; rgb: [r, g, b] }[]`: a line's colour (0-255).
  - `charge: number`: what the edit cost, in the cash's units (replaces the page's quote).
- Kind files, one per stream, each a pure function called after an accepted apply (clockWord.ts merges the parts; arrays
  concatenate):
  - `workers/clockWordStations.ts` (B): `export function stationWord(api, op, answer, posted, before?): Partial<EditWord> | undefined`
  - `workers/clockWordLines.ts` (A): `export function lineWord(...)` same signature
  - `workers/clockWordPieces.ts` (C): `export function pieceWord(...)` same signature
  - optional `export function stationWordBefore(api, op, posted): unknown` (and `lineWordBefore`, `pieceWordBefore`), called
    before the apply; its value is `before`. `answer` is clockEdits' apply result (`{ r, line, node, ... }`).
  - The base creates the three files as stubs (empty functions) so clockWord.ts compiles; each stream owns its file's body.
    In your tree before the base lands, write the file whole; at landing yours wins.
  - The line-path ops lineclick had (stop clicks, reorder, removeLine...) are in clockWord.ts already; `lineWord` adds others.

### Page: game/pending.ts

- `ahead(show: Show, opts?: { tries?: boolean }): Ahead`, made at the click, drawn at once. `Ahead`:
  - `send<T>(f: () => Promise<T>): Promise<T>`: `f` must call `edit()` synchronously (as `() => edit(op, ...)`); the entry is
    keyed by that edit's seq. Called again (another try), the entry moves to the new seq.
  - `drop()`: gone now (a stand-in for tries that all failed). `set(show)`: replace the guess.
  - A refusal drops the entry in the frame the answer lands, unless `tries`: then it stays, unkeyed, until `drop()` or the next
    `send` (stationClick: only the last refusal drops it). A guess never answered goes after 15 s.
  - Entries are armed by their word (its parts replace the guess's, part by part), and cleared: the map part by the first
    network taken after the word, the panel part (`fields`) by the first rows or state taken after it, `cost` by the first
    money, cash or state after it. "After" is arrival order on the page, so a state held for its trips that came before the
    word does not clear it.
- `Show` (all optional): `lines: Map<line, Iterable<edge> | null>`, `hideEdges: Iterable<edge>`, `edges: Map<edge, EdgeLook>`,
  `hideStations: Iterable<node>`, `stations: StationBox[]`, `colours: Map<line, [r, g, b]>`,
  `fields: Map<record, Record<field, unknown>>` (record `"line:12"`, `"station:40"`, `"edge:7"`), `cost: number`.
  - `StationBox = { lx, ly, ways: ArrayLike<number>[], perM, plat, side, tram, mid, built?: boolean }`: the station tool's
    `tk.lastBox` fields; drawn by the station shader like a built one (blueprint look unless `built`).
- Panels: `shown(record, field, value)`: the newest pending value for that field, else `value` (a signal read, so the panel
  redraws). `cashShown(cash)`: the cash minus the pending costs (the top bar uses it).
- The old calls stay as thin wrappers: `showAhead`, `dropAhead` (map/aheadShow.ts), `edgesWithoutEnd` (map/lineAhead.ts),
  `renderer.netVersion`, `renderer.hideEdge`.

### Undo (stage 0b)

- `{ op: "undo" | "redo"; after?: number }`: clockClient fills `after` (the newest edit still unanswered) when not given; the
  worker refuses the undo, quietly, when that edit was refused and nothing was accepted since. Callers need no change.

## What landed (stage 0 and 0b)

- **Worker**: `workers/clockWord.ts` runs each kind's part and merges them; the base's own part is lineclick's line path
  (the stop ops and removeLine, moved out of clock.worker.ts unchanged). Every accepted edit sends `applied`, the side
  branches (fares, fareRef, loans, link, buildings) an empty word. Refusals answer straight after the failed apply, as
  before; nothing was in the way of that already (only the ground waits that the apply needs come first).
- **Page**: `game/pending.ts` (the list), `map/aheadShow.ts` (the list to the renderer, the old `showAhead`/`dropAhead` as
  per-line guesses), `map/lineAhead.ts` (`AheadModel`, `aheadParts`: lines, edge looks, `standInStations`, `undoAhead`).
  clockClient stamps every message with its arrival order (a `WeakMap`, also on a state's `state`, which main.ts reads
  when it sets the network), so a state held for its trips or deferred behind the busy tag keeps its place.
- **Renderer**: the vec4 `u_hide_lines` is gone. A per-line texture (`u_ahead_lines`, LINES_W wide) and a per-edge one
  (`u_ahead_edges`, TEX_W wide, any number of edges) say which network strokes are not drawn; `u_ahead_n` how many ids
  each covers. Track drawn ahead has its own pass after the track (`aheadTrackVao`), lines as before (`aheadVao`).
  Station boxes ahead: a second VAO for the station shader, drawn in the same layers as the stations (pass 0) with its
  own centre-line texture on unit 11; hidden stations go through `stationHid` (with the hidden levels').
- **Cash**: the top bar shows `cashShown`.
- **Undo, stage 0b**: (1) `after` on undo and redo, filled by clockClient from the newest unanswered edit; the worker keeps
  the newest refused edit since the last accepted one and refuses such an undo quietly (no notice: the refused edit's
  own notice already shows). (2) The newest edit on the history, sent while nothing else was waiting, keeps the network
  drawn before it; an undo of it right after (nothing edited since, its network in) is drawn at its click: what differs
  between the two networks (track and line strokes by a hash per edge and per line, stations, line colours) is hidden
  in the network drawn and drawn from the one before. The hashes are worked out in idle moments after the edit's
  network is in (`warmUndo`); the click then costs about 34 ms on New York (77 ms without, 161 ms before the hash was
  made cheaper). Not yet: the panels at an undo's click (they wait for the rows), redo, and a second undo in a row.
- **Dev check**: main.ts warns when a network taken after a line's word draws other edges than the word said.

## Checked

- New York save, my Vite: a line deleted by its op alone is drawn gone from its word 18 ms after the send (network 2.2 s);
  the network clears it; undo puts it back. A refused edit shown ahead (hidden edge, cost 5) is gone in the answer's own
  task, the cash back. `tries`: kept through a refusal, gone at `drop()`. An undo sent while a refused edit was out is
  refused. An undo after a line delete is drawn at its click (8 lines' strokes and one station from the network before).
- Station stand-in: a box drawn as built off the track at South Ferry, screenshot
  artifacts/trainworld/t4145/ahead.png (before.png without it).

## Not done, for the orchestrator

- The four pending signals in game/world.ts (`pendingTrains`, `pendingCars`, `pendingHeadway`, `pendingWeekend`) are kept
  as they are. They already show at the click and fold fast clicks into one edit sent when the last lands; moving them
  onto `shown()` would change only where the value lives, with the folding to redo. A stream that touches them can.
- DECISIONS candidates (main tree, at landing): an undo is drawn at its click only for the newest edit with nothing
  else waiting; an undo asked while the edit it meant was out, then refused, takes nothing back, quietly.

## Edit bench (asia, nyc against 8d4c0f22; both runs on loaded cores, 72-94% busy before the game)

| action, median ms | Asia before | Asia after | NYC before | NYC after |
|---|---|---|---|---|
| undo: shows | 1094 | 19 | 245 | 29 |
| delete a line: shows | 1704 | 9 | 439 | 13 |
| stop reorder: shows (its path, from the word) | 1040 | 123 | 327 | 31 |
| track piece: built | 1271 | 713 | 426 | 404 |
| station: shows | 1105 | 878 | 340 | 320 |
| construct a line: built | 932 | 730 | 464 | 396 |

- Undo, delete a line and the reorder's path now draw at the click or the word: about 98% off undo's wait on Asia
  (1,075 of 1,094 ms). The "built" columns moved 5-54%, but nothing in the base makes the network sooner and both runs
  were on busy cores, so I don't read those as gains.
- The ledger lines for `8d4c0f22+changes` show "construct a line: shows" 84 / 31 ms: a miscount. A word carrying only the
  charge redrew the (empty) ahead model and the bench counted it. Fixed after the run (no redraw for a word with nothing
  to draw; the bench counts `setAhead` only when it draws something). A rerun waited on the bench lock behind two
  other agents' runs and was stopped; construct's true "shows" is its "built".
- Stop clicks gave "no sample (no edit message)" on master's line as well: a bench gap, not this change.
- The bench now stamps `r.setAhead` (tools/edit_bench.mjs), counted in "shows" from the click's input, so the streams'
  show-at-click is measured.
