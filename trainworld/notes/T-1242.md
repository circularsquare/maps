# T-1242: player-facing text, reviewed against the proposed guidelines

2026-10-24. Every player-facing string in `app/src` (ui/, the map's hover tags, issues, notices,
the loading card, start menu, settings, credits) and `app/index.html`, read against the proposed
"User-facing text" section in `research/llm-isms.md` section 4. The guideline ids (W1, S3, T2...)
are that section's. H is trainworld's "Panels show what can change". No code was changed.

How it was read: a scratch script pulled about 2,260 string literals and JSX text runs with their
file and line; the player-facing ones were read in full, with the surrounding code where it
mattered whether a string is shown or only a hover. Worker messages (save errors, load failures)
were grepped too. Refusal reasons written in Rust (sim/) are out of scope.

Overall: the game's text is already plain. There are no dashes between phrases, no all-caps
headings (no `text-transform: uppercase` anywhere), one exclamation mark, one "please", and none of
the AI word list. Most rows below are the two-part line, the interface noun as subject, and a few
words used two ways.

**41 rows: 24 proposed changes, 15 marked "keep?"** (borderline: Anita's call, my lean given)
**and 2 withdrawn** after her answers.
Line numbers are as of 63d1dca plus today's working tree. Templated parts are kept as `${...}`;
every proposal is the same length or shorter than what it replaces, so dock rows still fit 280 px.

## Applied (2026-10-24, tree t1242)

Every answered row is in the code as she answered; 16 and 36 (no answer) are as they were. Calls:

- **2**: "Build trains around the world!" under the start menu's heading (capital B, as the menu's
  other lines are in sentence case), and the same as the page's description meta.
- **11**: "Asking the demand model." is "Working out this trip" (one trip asked); its neighbours
  went the same way: "The demand model has no answer for this trip." is "This trip could not be
  worked out.", and the Trip title's hover says "Trips are worked out area by area" where it said
  "The model decides trips area by area".
- **26**: cut. The "Blueprint" note under an inspector's header stays (a state); its hover
  ("This track is built when you construct it") went, since the Construct button right above it
  says the same.
- **29**: cut. The sentence was for track drawn before T-092 (an old save's stretch through
  squares, not corners): the squares turn into corners on the first change. Dragging works the
  same either way, so the player needs no telling; the Corners hover keeps its first sentence.
- **31**: there was a real refusal: taking out a loop's only middle stop (A, B, A less B) left
  A, A, refused as "A line needs at least two different stations." Now stops repeated in a row
  count once (`distinct_stops`, sim/src/track/wasm/lines.rs, in `set_stops` and
  `set_line_with_trains`), so that leaves a one-stop line, inactive like a line with none (test
  `stops_at_one_station_make_a_one_stop_line`). One stop on its own was already allowed; the line
  panel's "No route: fewer than two stops." note is gone, and its sub line counts "1 stop".
- **37**: the capacity tag's last line was "Helps: <advice>", the fix for that kind of full spot.
  "Helps:" is gone and every advice line is an instruction now ("Add another track, or a station
  along it where trains can pass.", "Add a flyover so trains pass without crossing."), in
  game/capacityKinds.ts, which the line panel's full-spot alerts read too.
- **38**: kept "explore". "Open" or "see" would do, but "Click to explore this trip" names the
  tool (Explore a trip, the T key), and a new verb there would make two words for one thing.
- **Build/construct sweep**: construct is the action of paying for blueprint, built the state.
  Changed: "Cost to build" (built track) to "Cost to construct"; "Build a flyover" to "Construct
  a flyover" on a built junction (paid at once) and "Add a flyover" on a blueprint one; "Flyover
  built for $X." to "Flyover constructed for $X."; the selection bar's "Constructed: ..." to
  "Built: ..."; "constructed track/station/crossover/flyover" in the removal questions (game/remove.ts,
  game/blueprintPick.ts) to "built"; "Constructed track (and stations) cannot be moved." to
  "Built ..."; "Everything here is constructed already." to "built"; "Each constructed station
  costs..." to "Each built station"; "Building costs money" (Settings and New game hovers) to
  "Construction costs money"; the placing refusals "Cannot be built here." to "Cannot be placed
  here." and "Cannot be built like this." (dragging) to "Cannot be moved there.";
  "Track cannot be built within 5 degrees of a pole..." to "Track cannot go...". Kept: "X
  constructed for $Y." notices, "Once constructed, upkeep", "Trains run once it is constructed"
  (all the action), "Track and stations built", "Nothing built" (state), the Build tab's name.
- Also: 21 (Sign out everywhere else) removed from trainworld's account panel; noritetsu's own copy
  untouched. "less" is "minus" in every money hover: row 35's, the Lines tab's sort hover, row 36's
  Profit hover and the Cities tab's profit and sort hovers. "Nothing is refused for money" is
  "Infinite money" everywhere: row 15, row 16 (the top bar's Sandbox box), Settings' Sandbox hover
  and the New game sheet's Sandbox button ("Infinite money, and the cash is hidden").
