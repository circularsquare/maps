# T-3908 buses speed up and slow down at stops

Change: `sim/src/track/bus.rs`, `ramp()` and `run_profile`. Each stretch between two standstills (stop to street stop to stop) was one constant-speed phase; it is now three phases: speed up at `BUS_ACCEL` (1.1 m/s2), cruise, brake at the same rate. The cruise speed is solved so the stretch takes exactly its old time (T = d/v + v/a). If 1.1 is too gentle for a short or fast stretch (a*T^2 < 4d) it uses a triangle with a = 4d/T^2, so the time still holds. Rail's profile.rs is untouched (phases already carry `a`; the app's Speed view and the drawn bus read them through `speedAt`/`state_at`, so no app change).

Unchanged by construction: `arr`, `dep`, `duration`, `dwell`, street-stop stand times (only the ramp inside each stretch moved). Nothing in the sim reads bus phases except via those profile functions, so run times, timetables and demand do not move. Tests: existing asserts on arr/duration equal to auto_time/flat pass; two tests that assumed a flat speed were updated; new test `a_ramp_takes_exactly_the_stretch_time`. agent_cargo test: 712 passed. wasm built. No app code changed, so no typecheck needed.

In game (NYC, sandbox, one 4-point bus line, Speed view): screenshots in artifacts/trainworld/T-3908/ (speedview_stop.png best). The line is dark at the stop and shades to red over about 25 m, then cruises. The Speed colour scale puts city speeds (20 km/h) in one red band, so the ramp is a short dark-to-red gradient at each stop, not a long one: physics at 1.1 m/s2.

Cost: a few phases per hop instead of one (4 per stretch vs 1 per hop-plus-stands); no per-frame work added.

A stop with no stand (a non-station demand stop on an Auto line) now also ramps to zero speed and away at once.
