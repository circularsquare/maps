## 1. Today: every click mode and the options it reads

The `tool` signal (`game/ui.ts`) has ten values; the passage pick (`linking`, `game/links.ts`) is an
eleventh state outside it. Options are all in the Build tab today, shown whatever the tool.

| Mode | How it starts | What a click does | Options it reads | On the map today |
|---|---|---|---|---|
| Selecting (`select`, the default) | Esc, or the active tool's button again | opens the inspector of what is under it | none | nothing |
| Track (`track`) | 1, Build tab | starts or places a segment | level (Shift+1..7), ramp switch, Double / Quad / High speed, keep placing, snap to real, snap beside, target max speed | ghost and its tag |
| Station (`station`) | 2 | places a station on track | platform length (and the track type, only for the station's own piece: never on open ground since T-1820) | ghost, 1 and 2 km rings |
| Delete (`delete`) | 3 | removes what is red | none | red highlight |
| Select tool (`blueprint`) | 4 | picks pieces, box drag | none from the Build tab; its own bar | the selection bar, top centre |
| Bus (`bus`) | U, Build tab, Lines tab | adds a point | none | "New bus line: 3 points", Cancel, Make line, bottom left |
| Ferry (`ferry`) | O | adds a port | none | "New ferry line: 2 ports", bottom left |
| Line stops (`line`) | Edit stops, New line, Copy line, S, N | adds or removes a stop | none | "Editing stops on Z: 22 stops", Done, bottom left; the line hint |
| Trip explorer (`trip`) | T | sets a trip's start, then its end | none | the hint "Click where a trip starts, or a station." |
| Station building (`building`) | the station panel's building icon | places or moves a corner | none | "New station building: 4 corners", Cancel, Construct |
| Passage (`linking`) | the station panel's passage icon | links the next station clicked | none | a crosshair cursor only |

So only the track and station tools read the Build tab's options, and the level buttons there do
nothing in any other mode: the confusion Anita describes. The selection bar (`BlueprintBar`) already
is an on-map panel for one tool, top centre, which she points to ("like when we select track and are
editing its properties").

## 2. What other games do (short; sources in research/)

- One fixed spot for the active tool's options, shown only while that tool is on: Photoshop's options
  bar, Blender's tool settings strip, NIMBY Rails' level and track type menus beside its tools (shown
  "only for tools that need them").
- Level is always on keys too (Page Up/Down in Cities: Skylines and Subway Builder) and also on a
  visible control, which a touch screen needs.
- The mode is best said as what the next click does, in a line of text (Blender's status bar,
  AutoCAD's "Specify next point"). A coloured frame round the view is the strongest cue and the most
  annoying when overdone: Blender's red auto-key frame drew "red should be reserved for errors" and
  became optional; keep it thin, still, and paired with text.
- Subway Builder removed a duplicate mode toggle: one place for the mode's name, one for its options.

## 3. The design

### 3.1 One tool bar on the map

The map gets one tool bar at a time, in the selection bar's place: **top centre** of the map on a
desktop (the same rows down as the selection bar on narrower maps, `.blueprint-bar` rules), **the
map's bottom edge** on a phone. Which bar shows follows the mode:

| Mode | The bar shows |
|---|---|
| Track | level, ramp switch, price; Regular / High speed, keep placing, snap to real, snap beside, target max speed |
| Station | platform length |
| Select tool with a pick, or a blueprint piece picked by a plain click (3.4) | the selection bar, as now |
| anything else | no bar |

The bar is the selection bar's box (`--bg`, 1 px rule, the same padding), so the three read as one
thing. Each bar keeps its own spot at the top centre; the pointer and ghost are rarely there, and the
bar sits no lower than the selection bar does today, which nobody has found in the way. The map can be
panned under it as always.

### 3.2 The track bar

[track-light.png](../../artifacts/trainworld/t2267/track-light.png)

Two rows, about 600 by 90 px:

1. **Level** (a muted label), the seven level buttons, then the ramp switch, then the price
   "$75M per km (1.0x cost)". The level buttons grow from 32 by 28 to 38 by 32 px with 15 px numbers:
   this is "more prominent". The tinting and the chosen one's outline stay (T-478, T-692).
2. **Regular** / **High speed**, then keep placing, snap to real and snap beside (the three icon
   switches as now), then **Target max speed** and its stepper.

The hovers stay as they are today, except the level buttons' and the price's, which T-2271 changes:
the mockup draws T-2271's level hover under the +1 button ("Viaduct (Shift+3)", "1.0x cost, $75M per
km", "Upkeep $20k per km per day") and the 1x multiplier on light yellow, as she asked. T-2271 and the
stage that builds this bar (T-2282) touch the same lines of `BuildTab.tsx`: whichever lands second
carries the other's change over.

The **terrain switch** leaves the Build tab. Settings > Show > Terrain is already the same switch
(T-1394), so nothing is added to Settings.

**Quad goes** from the choice: it becomes **Regular** / **High speed**, the selection bar's words
(T-1898), one word per thing. Saves need nothing: quad track has always been two ordinary double-track
pieces side by side (track-and-service.md 6.1 "Quad track"), so old quad shows, runs and is edited as
it is now, two pairs. A browser that remembers Quad (`build.tracks === 4`) starts on Regular. **Double
up** stays (the track inspector's and the selection bar's button): it adds the pair beside a run
that already exists, which snap beside does not do in one step. The hovers' and price's quad cases
(`pairs` in `BuildTab.tsx`, "both pairs on Quad") go with it. `trackCount` can go once nothing reads
it; `TrackType` becomes `2 | "hsr"`.

### 3.3 The station bar

One row: **Platform length** and its stepper, in the same spot. Nothing else: the station tool reads
no other option (its own piece of track takes the track type only on open ground, which T-1820 ended).

### 3.4 A blueprint piece picked by a plain click

The bar is today's, `raw/select-light.png`; the inspector under it is `raw/inspector-light.png` without
its Level row.

Today a plain click on blueprint track opens the track inspector, whose Level row is seven plain
buttons at the panel's foot. The design: the click also makes that piece the pick (`bpPicked`, one
piece, as the select tool's click does), so **the selection bar shows on the map** with the tinted
level buttons, Regular / High speed, Disable / Enable, Double up, Remove and Clear: the select tool's
control, which is what she asked for. The track inspector stays open in the dock as now, without its
Level row. A click on anything else, Esc, or another selection clears the pick. Built track clicked
this way gets no bar (it has no level to set; its inspector has Double up and Remove).

Rules kept from the select tool: the bar acts on the pick; the pick's squares show so the piece can be
dragged. Not added: Shift+click and double click keep their plain-select meanings (none on track).

### 3.5 The Build tab after

Tools (track, station, delete, select, bus, ferry), "N disabled", the blueprint total, undo and redo,
Construct blueprints, and the cost breakdown (which T-2269 is moving and collapsing). The Level and
Track headings, both price rows, the toggles, Target max speed and Platform length all leave it. The
pane gets much shorter, so the inspector under it gains room.

### 3.6 Phone

Today's phone layout: `raw/phone-track.png`. The bar sits on the map's bottom edge, as the selection bar does on a phone (T-1263), one row of
36 px buttons that fits 390 px: the chosen level (one button showing "+1" in its colour; a tap opens
the seven above the bar, the selection bar's phone pattern), the track type (a button showing
"Regular", a tap opens the two), the ramp switch, the three switches, and the target speed (a button
showing "160", a tap opens the four). The descriptor (3.7) sits right above it. The touch control bar
(confirm, take back, stop) stays beside the point being placed.

### 3.7 T-2270: a colour and a descriptor per mode

[modes-light.png](../../artifacts/trainworld/t2267/modes-light.png),
[modes-dark.png](../../artifacts/trainworld/t2267/modes-dark.png)

- **The frame**: a 3 px line in the mode's colour round the inside of the map, still (no pulse or
  fade), taking no pointer events. None while selecting (the default): a frame means a click does
  something other than open an inspector.
- **The descriptor**: the first line of the bottom-left notes (`#tool-notes`), a 10 px square in the
  mode's colour then what the player is doing, with the mode's own buttons after it. The bus, ferry,
  stop editing and station building bars that are there today become their modes' descriptors (same
  words and buttons, plus the square). The notices (what an edit did, refusals) stay under it. The
  notes box takes the mode's colour on its top and right edges, so it joins the frame.
- **Optional, beyond her ask**: a small cross after the simple descriptors (track, station, delete,
  select tool, trip, passage) to leave the mode, hover "Stop (Esc)"; a phone has no Esc, and leaving a
  tool there now means finding its button in the dock. Also optional: the track and station bars'
  3 px top edge in the mode's colour (drawn in the mockups).

The colours, checked against every colour the game draws (the 16 line colours, the seven level colours,
the speed and crowding ramps, the demand mode colours, the build ghosts, the three accents and the
warning colours in both shades, and the map's land, water and parks), by CIEDE2000
(`colours.py`, `pairs.py` in the scratchpad):

| Mode | Colour | Nearest game colour (dE) | Nearest other mode (dE) |
|---|---|---|---|
| Track | `#0a819d` petrol | Blue accent `#4f8ac6` (13.7) | Ferry (15.3) |
| Station | `#8d71b1` violet | 320 km/h speed `#a03fc2` (13.9) | Line stops (15.6) |
| Delete | `#d63f73` raspberry | Magenta line `#e62aa6` (11.1) | Station building (11.2) |
| Select tool | `#9c7b31` bronze | Warning yellow `#c9a01c` (14.2) | Passage (12.4) |
| Bus | `#a09e2d` olive | Green accent `#7f9f4f` (11.0) | Select tool (14.9) |
| Ferry | `#16716f` deep teal | Trip (12.8) | Trip (12.8) |
| Line stops | `#d777ed` orchid | Lavender line `#a9a0e8` (15.5) | Station (15.6) |
| Trip explorer | `#268769` pine | 120 km/h speed `#55a886` (11.8) | Ferry (12.8) |
| Station building | `#a15b7b` plum | Magenta line `#e62aa6` (14.6) | Delete (11.2) |
| Passage | `#b0866a` tan | Warning orange `#c0661c` (14.1) | Select tool (12.4) |

What the numbers mean: the game already uses nearly every hue (16 line colours round the wheel, the
level and speed ramps, red/green/blue demand), so no new colour can be far from all of them. The
search over every in-gamut colour of medium lightness found none more than about 15.5 from the game's
set; these ten are 11 to 15.6 from it and 11 to 23 from each other. 11 is plainly a different colour
side by side; from memory two of them can be mixed up. So the words carry the mode and the colour is
the reminder, and the frame's place (the map's edge, never on the network) is what keeps it from
reading as a line. Red, green and blue are avoided (demand's colours, and red reads as an error), and
each colour is at least 29 from the land in both shades so the frame shows. In the dark shade, ferry
and trip are the dimmest; the same colours are used in both shades, like line and level colours.
