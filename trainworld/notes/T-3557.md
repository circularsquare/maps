# T-3557: weekend headway stepper runs the headway stepped (agent weekendstep, 2026-11-17)

Not archived: it changes scheduling numbers, so a fresh checker tries to break it first.

## The bug

On a headway line the Weekends rows of the timetables window show a count and a headway stepper. A step set the
weekend counts by hand (`autoTrainsFor(trip, h)`, whole trains) and a hand count runs as a count line: the line then
ran round trip / count, shorter than the stepped headway whenever the round trip is not a whole number of headways.
Weekday headway lines keep the cap because `line_auto` holds the headway (`running_trains` takes min(count, trip / h)).

## The fix

- `Weekend` (net.rs) gets `headways: [u32; 3]` (seconds, 0 none). Set only by a headway step, beside `counts`.
- `TrackWorld::weekend_auto` (world.rs): a line with hand counts and headways has those headways in `line_auto`
  while the weekends settle, so `running_trains`, `Service::spare` and `pattern_tph` cap the trains at the headway as
  on weekdays. A level with 0 runs as a count line, as before. Nothing else in the settle changed.
- New wasm call `set_line_weekend_headways(id, h, m, l, hh, hm, hl)` (counts and headways in one undoable edit);
  `set_line_weekend_counts` keeps a headway only at levels whose count did not change; a percent drops them all.
  `line_weekend(id)` has 8 numbers now (the last three: headways in seconds, one pair's x k like the counts).
- Quad twins: `halve`/`double` (twin.rs) carry headways x2 / /2 as `auto`.
- Save: LWE1's counts flag is 2 where headways follow the counts (1 as before otherwise), so every save without
  weekend headways is byte for byte as before and an old save loads.
- App: `weekendCounts` op takes optional `headways` (protocol.ts, clock.worker.ts case "weekendCounts", one line);
  `stepWeekendHeadway` calls new `setWeekendHeadway` (game/world.ts); `weekendOf` (stateRows.ts) reads 8 numbers.

No in-game strings added or changed.

## The line_pace lie

"Weekend departures run at the weekday round trip and the weekday pacing (`line_pace`)": NOT removed. `line_pace` is
solved once, from the weekday service, in `pace_merges`; the weekend settle reads it as it stands. Removing the lie
means running `pace_merges` on the weekend service too (own `line_pace_rest`, saved or recomputed, swapped in beside
`line_auto`). That is a separate piece (about an hour plus the checker) and touches net.rs and world.rs hot paths
other trees edit. Left written down in notes/T-3521.md "Lies".

## Check

`checks/t3557-weekend-headway.mjs` (about 4 minutes, own Vite on 6154, passes): a new game, a 3-stop line built
through lib/play.mjs, the schedule window opened, Headway picked, then the Weekends High headway stepper pressed
longer x3 and shorter x5. After each press: stepped (the stored weekend headway, `lineStats.weekend[5]`) against
measured (median gap between the line's drawn High departures on the next Saturday, `lineTrips`; the clock stays
before the Saturday so each edit is in force). Results: 5/6/9/8/5 min stepped = 5/6/9/8/5 measured; 3 min stepped
(below the track's 4 min) measured 4 (the track holds it). Medium and Low gaps (4 and 5 min) and the weekday
rates did not move. Control in the same fixture: the same counts sent without the headway (a percent first drops
it) ran every 4.1 min against 5.0 stepped: the bug. Sim test `t3557_a_stepped_weekend_headway_is_run`
(wasm/t1071_tests.rs; also that stepping High alone leaves Medium and Low at their rates, a count edit drops only
its level's headway, a save round-trips, a percent drops them). Both cargo suites pass (606 / 797);
t3521-weekends.mjs: see the report.

## Repro for the checker

Before the fix (any commit without `Weekend::headways`): build a headway line whose round trip is not a whole number
of headways (a 6 km line, 8/6/4 trains, Headway picked), open its schedule window, step the Weekends High headway to
5 min and read the Saturday's High departures in the Marey chart or `lineTrips`: they leave about every 4.1 min. The
check's control reproduces that on this tree (counts only, no headway).

Things worth attacking: a loop line (paired counts, even); a quad-track line on both pairs (headways x2 per pair);
a weekday headway changed after the weekend step (the hand counts and headway stay put, by design); undo/redo of the
step; save and load after a step (LWE1 flag 2); stepping Medium or Low only; a step to none (count 0); a headway
longer than the round trip; a merge with other lines (the settle can run the line slower than stepped where track is
full; the row then shows the settled rate, as weekdays).

## Left as it is

- `restHeadwayStep` still skips a headway that needs the same count as now (a weekday headway stepper does not).
  With the headway stored, 12 and 13 min are different services, so the skip could go (follow-up).
- Stored headways stay when the weekdays switch to counts (they are then ignored) and apply again on a switch back to
  headways.
