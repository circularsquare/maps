# T-3588: default headways switch lines to headway; none for new players (agent defaulthw, 2026-11-17)

Anita, 2026-11-17: setting a line to use default should switch it from train counts to headway; a completely new player has no default set; "Apply to all lines" for weekends should cover new lines and the popup should say so; "Default not set" instead of "Game default"; the lone "Simple" button at the top is silly.

## What it is now

- **Set as default** (`makeDefaultHeadway`, game/newHeadway.ts): a line on counts is switched to Headway first through `setAutoTrains`, at the headways its trains give (`headwaysOfTrains`, split out of `setAutoTrains` in game/world.ts), so it runs the same trains; those headways become the default. The switch is the line's own edit (one undo step); the default is outside undo, as before. Always on except while the line's headways already are the default.
- **No default in a new game**: the worker's `newLineHeadway` is null at a new game (`newGameHeader` clears `newHeadway`, the reset at the game start sets null) and is read only from the save header. Nothing in local storage, no browser-wide value. A first line runs on counts (checked).
- **Wording**: value "Default not set"; button "Clear default", drawn only while a default exists; the "Switch this line to Headway first" hover is gone.
- **Weekends**: "Apply to all lines" also stores the percent in the worker (`newLineWeekendShare`, save header `newWeekendShare`, validated in sharedSave.ts, cleared by a new game); `addLine` then calls the existing `set_line_weekend_share` on each new line when it is not 100. No sim or save-level change (a header field only, like `newHeadway`), so no cargo suites or checker. It is not undone with the apply-all edit, and Clear default does not touch it (a percent of 100 sets nothing special; applying 100 again resets it).
- **"Simple" button**: the schedule panel heading's mode choice had one option. It is drawn only when more than one mode exists (`scheduleModes` in SchedulePanel.tsx). Detailed and Exact are planned (T-3346 stages 3 and 6), not close, so it is hidden for now.

## Later asks (same day)

- **Per kind**: the default is kept for regular, tram and high-speed lines (`SaveHeader.newHeadway` is now {rail, tram, fast}, read by `cleanNewHeadways`; unpublished, so no migration). The worker's `addLine` decides the kind after the high-speed step (tram by the first node, high speed by `set_line_fast`), then applies that kind's headways, then the weekend percent. The row and "Set as default" use the selected line's kind (`lineKind` in game/newHeadway.ts); a bus or ferry line shows no row and keeps what it did.
- **"Game default" numbers**: with no player default a new line gets NEW_LINE.train counts (whole trains), not headways, so no headway numbers exist to show; the "7 min, 10 min and 18 min" she saw was the default she had set. "Default not set" stays for that case.
- **Weekend stepping**: `setWeekendHeadway` stored 0 for levels it left alone, so the sim fell back to count over round trip (10.75 min). It now stores each other level's displayed headway to the whole minute (`shownRestHeadway`). App side only; the sim op and save fields are T-3557's. No cargo run needed, no checker.
- **Chart button** is 24 px like the schedule button (`.sched-copy .btn.icon.mini`; the old rule lost to `.btn.icon.mini`).
- **Row text** is 12 px like the table; the values use the table's `headwayText` ("13 min", not "13.0 min").
- Tree rebased onto master (T-3557, T-3574) with a stash; wasm rebuilt.
