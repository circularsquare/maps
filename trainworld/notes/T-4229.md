# T-4229: Station names stay after zooming in

Player report 11-20 (board g170, feedback thread 1795190085-b98661d9, v0.4.4, Safari 27.2, Japanese): "一度マップを拡大すると、駅の名前が画面に残ったままになる" (once I zoom in, station names stay left on the screen). Picture: artifacts/trainworld/feedback/1795190085-b98661d9-1.jpg, three copies of 久屋大通 (Hisaya-odori, central Nagoya) over Tsushima with no network nearby.

## Cause

The names left behind were station buildings' names (T-2219), which show from FLOOR_ZOOM (13) in. `StationLabels.placeBuildings` rebuilt its labels whenever the buildings' key changed (zooming out past 13, a draw-anchor move, a building redrawn or renamed) and set the old ones aside in a `Map` keyed by their text, one label per key. Buildings that show the same name (the usual case: an unnamed building shows its complex's name, and one complex can have a building per line) overwrote each other in that map, so only one per name was found again or removed. The others stayed in the DOM, visible, at the spot they were last placed, and more were left on every zoom in and out.

The bus stops' names (T-4080) set theirs aside the same way, keyed by name and position: two named stops with the same name at the same spot would leave one behind. The station names themselves already kept a list per key.

## Fix (app/src/map/stationLabels.ts)

- One pool, `Spares`, for all three: a list of spare labels per key, and `drop()` removes every one not taken.
- A reused station label is the same object, updated in place (it was a copy): `shownLabels` and `follow` no longer move an element through a stale copy whose cached position and visibility differ from the label in use.
- The pan shortcut in `place` (translate the whole plane) is skipped when the draw anchor moved since the last full placement: a state built at a new anchor arriving mid-pan made every name jump by the anchor shift for up to 100 ms. capacityMarkers has no such shortcut; nothing else needed it.
