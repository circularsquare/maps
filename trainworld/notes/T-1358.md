# T-1358: `followTrack` on a game's first network

2026-11-05, agent followtrack (tree `tw/followtrack`). Follows notes/T-1357.md.

## What changed

All in `game/trackZones.ts`, plus `cellsSayInside` (`workers/cityReach.ts`) and `inOutlineBox`
(`map/coarseOutlines.ts`): true when every place in a box lies in cells of an outline's grid wholly
inside it, so `inOutline` is true at each.

- **Whole lines by their box.** A line's zones are worked out as before (a point every km, the zone
  last found kept while it holds the next point) unless its box, padded 1e-7 degrees, lies in cells
  wholly inside one zone that is the first holding its first point: then every point tested holds
  that zone and the walk would find it alone. That zone is either the one last found (`hint`), when
  the box lies in its own box and meets the box of no zone before it in registry order, or the first
  point's own.
- **A tree of boxes.** The lines to work out go through `zonesOfLines` together: one pass over all
  their points (a first network's 109,000) for their boxes in local units, a tree of the boxes'
  unions, and the test above on whole nodes, opened down to four lines where it fails.
- **Early exit on a walk.** When a walk enters a zone and the rest of the line from that stretch lies
  in cells wholly inside it, nothing more can be found.
- **`firstHolding`**: the first zone in registry order holding a point, as the scan of `zonesTouching`
  found it, trying the last one found first against only the zones before it whose boxes meet its own.
- Bookkeeping: the edge cache rebuilt as a new map each state (no `seen` set), the length compared as
  a number before `toFixed`, indexed loops, the walk's `%` taken only when the remainder can differ.

Nothing is approximated: the points tested, where they are tested, are the old ones (the walk's
arithmetic is unchanged); a line skips the walk only where each of its points would find the same zone.

## Zones: identical

- `trackZones` sets, the real save and a new game with three New York lines (`harness.mjs zones`):
  before and after both `{nhv, nyc}` built on the real save, `{nyc}` on the new game; set hashes
  1d30b53ed5972b16 and 2e4e42783f1e7b1c before and after.
- Per edge, the served module against the old walk (`probe3.js`): every edge of the real save both ways
  (3,294 lines, shuffled so the hint meets other zones first), 0 differ.
- Synthetic lines where many zones meet (`probe4.js`): 10,500 random lines of 2-60 points in the US
  Northeast, the Pearl River Delta, Kanto, the Low Countries, Delhi, the Rhine-Ruhr and Seoul (129
  zones), one at a time and in batches as `followTrack` makes them: 0 differ; `firstHolding` against
  the scan at 210,000 wandering points: 0 differ.

On the real save 1,617 of 1,647 edges are settled by their box; 30 (359 km, 7,418 points) still walk.

## Measurements

The profile's inclusive `followTrack` (T-1357's method) proved too noisy to use: two runs of the old
code gave 170 and 28 ms. Instead, `harness.mjs wall`: 6x throttling, one demand worker, the real save
imported into a new game, the wall time of the task main.ts sets for `followTrack` on the first network,
and inside it (temporary timestamps, since removed) its own work before the zones are set, apart from
the zones' effects (the realms, demand's `openCrossed`, the opened list: other modules' code, the same
both ways). Old and new were served by one Vite (the old code under a temporary `?t1358old` switch) and
run in turn, 5 pairs a set, 4 sets (the first before the last two bookkeeping changes). The machine had 15 of 16 cores claimed throughout, and runs swing
between two modes: when V8's compiler threads get time, both codes run at a fraction of the usual cost.

| at 6x, ms | old | new |
|---|---|---|
| own work, median of 20 | 99.4 | 54.3 |
| own work, set medians | 106.5, 91.6, 101.4, 101.2 | 50.0, 58.6, 53.8, 59.3 |
| the task (own work and the zones' effects), median of 20 | 108 | 69.5 |
| the zones' effects, median of 20 | 14 | 15 |

Unthrottled and warm, the old walk takes 7-8 ms over every edge and the new code 1.5-2.5 ms.

Where the new 50-60 ms goes, from timestamps on single runs: the edge loop 2-10, the pass over the
points 6-13, the tree 3-5, the nodes' tests and the 30 walks 6-54 (most of the swing). The walks' cost
is mostly first-time work the old code did too (each zone's band and cell grids, `bandsOf`,
`zeroGrid`, `fillRow`) and the walk's own arithmetic in code the JIT has not reached.

**Short of the target**: own work is about 0.55 of before, not 0.5; the task with the effects about
0.64. What is left would need either the walks gone (they decide where the 30 lines' points fall, so
skipping them changes which points are tested) or the per-edge bookkeeping, which is no longer the
sampling the task named.

## `toWorld` per edit

Not changed: `workers/clockClient.ts` is cleana4's file in this round. Profiled over three train-count
edits at 6x: 40 and 27 ms (13 and 9 ms an edit). About half is `s.edges.map` (1,647 `TrackEdge`
objects rebuilt every state) and a quarter the edge-to-lines map built from every line's path. A cut:
keep each edge's view per worker row, as T-1380 does for stations and lines, rebuilding it only when
its row or its lines change.
