# T-3611: autosave lands after another tab took the slot

Agent autolease, 2026-11-18. From T-3397 row 9 (MDN: a stolen lock's old holder keeps running).

## Change

- `workers/clock.worker.ts` `autosave()`: captures the lease at its start and checks it again right before the
  slot write. `writeSlot` gets a fourth argument, the tab's `seenEdit`.
- `workers/saveFile.ts` `writeSlot(key, v, lastName, seenEdit?)`: inside its readwrite transaction, if the stored
  record's `editOf` is newer than `seenEdit`, nothing is written and `SlotTakenError` is thrown. This covers a
  lost-lease message that has not reached the old tab yet, which the lease check alone cannot.
- A refused autosave leaves the change dirty, sets the tab as "another tab saved" (`activeLease` null,
  `leaseTaken`), shows no save-failure message, and does not retry through `makeRoom`. A save by hand takes the slot
  back as before.
- `keepOtherTabs` now sets `seenEdit` to the record it moved aside, since the save that follows is meant to replace it.
  Without that the stealing tab's own first write would have been refused.
- No save format change. Only `autosave` passes `seenEdit`; other writers (copy, cloud pull, keepAsLoaded) are as before.

## Probe (scratch, `probe.mjs` in the agent scratchpad; one Chrome profile, two pages, same slot)

Tab A loads, saves; tab B opens the same slot (read-only: A has the lease). A edits (fares) and saves; a route
patch on A's worker pauses its autosave just before the slot write (BroadcastChannel hold/release). B edits and saves
by hand (steals the lease). A is released.

| run | slot after B's save | slot at the end | B's save kept |
|---|---|---|---|
| before (master code), pause then B saves | 6e7d9a63 (edit ...414725) | 862d3a92 (A's, edit ...410907) | no, lost |
| after, `lease` (A's lost-lease message arrives while paused) | 6e7d9a63 | 6e7d9a63 | yes |
| after, `tx` (lease check switched off in the patch, as if the message were late) | 6e7d9a63 | 6e7d9a63 | yes, refused inside the transaction |
| after, `single` (one tab) | manual save changed the slot; the minute autosave changed it again | | writes still land |

Note the before run: A's lost write had an older edit than B's, so the check on `edit` is the right one.

## Residual

  nothing newer than A's last write) is not refused; then A's write carries newer or equal changes anyway.
- The backup write after a landed write is a separate key and is not guarded.
