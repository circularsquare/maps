# T-105: four track display modes

`DisplaySettings.trackColour` now selects Line, Traffic, Height or Speed. Traffic is the fresh
default, and is the sole mode enabling ridership-weighted line widths. The separate line-width
checkbox is removed. Existing Line + checkbox preferences migrate while new plain-Line choices
persist unchanged. Four buttons in a two-column grid fit the narrow dock.

The clock worker caches authoritative `edge_render_speeds` arrays with edge polylines, refreshing
only dirty edges. Those speed values align with rendered segments and become a single float
attribute on track strokes. The shader interpolates warm red / ochre / green / blue at
40 / 80 / 120 / 160 km/h. Speed and Height draw bare track at uniform width, without the coloured
line bundles over it, and train colours stay unchanged. Speeds describe geometry limits rather
than current train motion or average journey speed.

Browser verification in `notes/t105-check.mjs`: fresh default, all four controls and actual
uploaded widths, narrow layout, colour-mode bundle offsets, WebGL errors, plain-mode persistence,
old-checkbox migration and a 100 m radius curve fixture with straight/curve speed limits.
All pass: plain/height/speed upload uniform widths, traffic uploads varied widths; 303 px pane
has no horizontal overflow. Curve fixture: 43 speed values for 43 segments, 37.757 km/h on
the curve and 160 km/h on straights. No page or WebGL errors. Typecheck and Vite build pass.
Results: `T-105-check.json`; screenshot: `../../artifacts/trainworld/T-105-speed.png`. The screenshot also reveals a
