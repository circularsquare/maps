# T-3923 Trips to an unsearched station vanish silently

## What changed

- `Loads::dropped` (kernel/assign.rs): trips taken towards a destination whose `Skims::slot` is `NONE`, summed per
  solve. `DestAssign::take` now remembers the riders it took (`taken`); `assign_inner` adds them when it skips the
  destination. The `debug_assert` there is gone (it was off in release; the counter and the test gate replace it).
- Same in `assign_lanes` (everyday.rs): `LaneLoads::dropped` per purpose lane, `lane(k)` hands it on, `add_loads`
  sums it. `intercity/logsum.rs`'s load add carries it too.
- Read-outs: `DemandApi::dropped(q)` and `EverydayApi::dropped(q)` (wasm-bound, f64, 0 if the period has no solve).
  Not added to `summary()`: its tail is summed and merged by position in demand.worker.ts, and the worker is
  editrestart's. A caller wanting it in the app adds the call there.
- Crowding rounds average it like the other loads (`avg.dropped` in `crowd_with_external`).
- Tests: in a test build `kernel::note_dropped` logs every drop (`DROP_LOG`) and panics unless the test set
  `KNOWN_DROPS`, so every existing demand fixture (api, everyday, kernel, intercity's kernel walks, lanes) fails on a
  drop. Named checks: `no_trips_are_dropped_on_the_small_city` (api/tests.rs), `no_everyday_trips_are_dropped`
  (everyday/tests.rs), `trips_towards_an_unsearched_station_are_counted` (forces a drop with `want`, checks the
  count and log).

## Results

- Nothing is dropped on master by any fixture: `agent_cargo.py test` is green (712 + 926) with the panic on.
  No known-case marks were needed.
- The ignored real-NYC tests (`transfers_real_network`, `left_behind_real_network`, `complexes_real_network`,
  `everyday_real_network`, run with `--ignored`; pack data/packs/nyc.json and nyc_real_track.json) pass with the panic
  on, so the real network drops nothing in them. `intercity_real_network_outputs` also passed. `trip_real_network`
  fails its tolerance check (origin subzone 3406: 1657.389 against the solve's 1662.064, 2.8e-3 off, limit 1e-4,
  tests.rs:497); not a drop and not touched by this change (nothing it computes depends on the counter), noted for
  the orchestrator to file or ignore. No save file (.save) is loaded by any Rust test; the real network is the
  json route above.
- Bit-identical proof: a scratch hash over summary (minus the ms field), board, seg, entries and exits of all
  periods of the small-city fixture was 7a2dcee22f8000a0 on master (changes stashed) and 7a2dcee22f8000a0 with them.

## Not covered

- Intercity's own `pass_window` (intercity/pass.rs) skips a destination whose `Columns::strategy` is `None` with a
  bare `continue` and does not go through `assign_inner`; its trips are in `all.take` before that. Not counted here:
  a different path (strategy comes from a table or a fresh search) and a bigger change. Worth a task if wanted.
- The count is trips, not the station; the test log (`DROP_LOG`) has (station, trips) in test builds. If a real
  game solve shows a nonzero `dropped(q)`, find the station by `slot == NONE` with a nonzero OD column.
