## Findings, most severe first

### 1. A lost graphics context that comes back still leaves the game stopped, on desktop too (medium)
`app/src/game/loading.ts:160-174` (`watchGraphics`), wired at `map/mapView.ts` and `map/overlay.ts`, not gated by `smallDevice()`.

The 6 s timer starts on `webglcontextlost` and does not look at page visibility. The `webglcontextrestored` handler only clears
a timer still pending; it never clears `demandStopped`.

Scenario: a phone player switches apps, or a desktop has a GPU reset or sleeps, and the context stays lost more than 6 s. The
timer sets `demandStopped = "graphics"` and pauses the clock. The player returns, the context is restored and the map draws
normally (`overlay.ts` rebuilds the renderer), but "The map stopped drawing, so the game is paused. Reload the page" stays, with
Reload as its only button. Until a reload, `demandStopped` being set also means `demandCapped` is false and every pending line
is settled while demand is still solving (`game/lineFigures.ts:53,121`), the status tag goes quiet (`ui/StatusTag.tsx:172-173`),
and a real demand failure later cannot report itself (`loading.ts:205` only sets it when empty).

The notice exists for a context that never returns, which is the case the restore handler should separate out. DECISIONS says
"Desktop is unchanged", which this is not.

Fix: in the restored handler, when no canvas is still lost and `demandStopped` is `"graphics"`, set it back to null and restart
the clock if this code paused it. Count the 6 s only while `document.visibilityState === "visible"`.

### 2. The phone-only cuts reach desktops with 4 GB (medium, may be accepted)
`app/src/workers/deviceMemory.ts:26-29`, used by `workers/demandClient.ts:920,1112` (no market), `:766` (no demand cache),
`map/coarseOutlines.ts:114`, `map/cityBoundaries.ts:183`, `map/realmOverlay.ts:206`, `main.ts:174`.

`smallDevice()` is true for `gb <= 4` on any device. That threshold was only about worker counts until 309ff65b gave it the market.

Scenario: Chrome or Edge on a Windows laptop or Chromebook with 4 GB reports `navigator.deviceMemory === 4`. That player gets no
trips between zones (T-2802 measured 2.8% fewer rail trips on the real New York save, so income to match), no demand cache, and
the notice "Intercity trips cannot be computed on mobile", on a laptop. A game moved between that laptop and a bigger machine
reads differently on each. T-2802's and T-2794's DECISIONS entries argue from phones, and T-2794 says "Desktop is unchanged".

Fix: use `mobileDevice()` for the market, the demand cache and the note, leaving `smallDevice()` for worker counts; or keep it and
reword the note. Her call which; one condition in `marketZones` and one at `:920`.

### 3. A running line that truly loses its riders keeps its old figures until reload (low)
`app/src/game/today.ts:300`. c18d2fa1 removed the `!lineFiguresIn(demandView, ...)` condition.

A line with no riders has no demand entry (`profitKnown`'s comment, `today.ts:194`), so no boarding account
(`boarding.rs:559-562`), so no row in `past_day`. `!t && p && running` is then true forever.

Scenario: a line's edit or a new parallel line leaves it with zero riders. After the solve lands, `linesPending` clears, and the
line panel and Lines tab keep the last riders, stop counts and fares for the rest of the session, so its profit reads as if it
still earns. Real money is right (it comes from `incomeFor`), so this is display only.

Fix: keep the old figures only while they can still be replaced:
`else if (!t && p && running && (pend.has(l.id) || dv?.lines.has(l.id)))` (T-2793's "solved and not yet counted" has a demand entry;
the zero-rider line has neither).

### 4. A new line that reuses a deleted line's id shows the deleted line's figures while pending (low)
`app/src/game/today.ts:216,307-310`, with `sim/src/track/net.rs:879` (`alloc_line` reuses freed ids).

`settled` is pruned only inside `ask`, which runs only while a panel using `useToday` is mounted, and is otherwise cleared only on
a game load.

Scenario: delete line 7 and let its panel close (no `useToday` panel open), build a new line, which takes id 7, and open it. It is
pending "build"; once a local solve gives it an account, `pend.has(id) && s` shows the deleted line's riders, fares and (if the stop
count matches) stop counts, until the final result. Display only, seconds on a small game, longer on a big one.

Fix: hold only `pend.get(id) === "change"`, since a line just built has nothing settled to keep.

### 5. Phone: coarse outlines can stay undrawn after they arrive or after a zoom past the threshold (low, visual)
`app/src/map/cityBoundaries.ts:185-193,222`, phone path only.

`fillAround` changes `edges`, but only a change of the `around` set asks for a redraw. The desktop path calls `redraw()` after
filling (`:210`).

Scenario: `coarseOutlines()` resolves after a `follow()` already set `around`, or a zoom crosses `OUTLINE_MIN_ZOOM` with the same
zones around. The outlines stay missing (or stale) until something else redraws.

Fix: have `fillAround` report whether it changed anything and call `redrawSoon()` if so.

## Checked and found fine
- Currency never reaches the sim or saves: `display.currency` is a display setting, and `format.ts` converts on the way to the screen and back only.
- Fare steps, typing and drags in USD are numerically as before; `fromRows`, `stepRate`, `setRate` and the drag snap reduce to the old expressions at rate 1.
- Non-USD fare edits: `tidyNodes` and `tidyTransfer` keep 4 decimals, so yen, won and fen steps do not round to US cents and do not drift. An edit snaps nodes once to the currency's grain (at most half a grain), and it is stable after that.
- `moneyCash`/`moneyShort` T and Q units, `compactOf` in other languages, `millionsRange` (one caller): fine.
- `isCurrency` guards an unknown stored currency, falling back to USD.
- T-2773/T-2793 money: `today` holds are display only. The one hold that feeds real income is `incomeFor`'s `old` (`money.ts:181-187`): it needs a running line whose loads do not fit its stops, ends when the solve lands, and a deleted line is skipped because it is no longer in `save.lines`.
- `today()` hold (`clock.worker.ts:2039`): `boarding_step(0)` does no work (`ensure_some` returns before computing), `todayLast` resets on load, and stepping continues whether or not the clock runs.
- 967be7b6 removal is complete: `lineDays`, `LineMoney.tsx`, the `id` field on fares, `kinds` and `trip_lengths_kinds_day` are gone from source; `git diff b167196a~1 967be7b6` on the tripkinds files is empty; no messages are left without a receiver. A save written by the dev builds between c18d2fa1 and 967be7b6 would read as "from a newer build" (`headerUnread`); production never had that field.
- Tighter radius: `MIN_RADIUS` is read only by `geom.rs:341` (a refusal, now looser) and the quad ease at `wasm.rs:1033` (new express track only), so existing saves' geometry and speeds do not change on load.
- Snapped routes: every tracer entry uses `TRACE_MIN_RADIUS`, `ease` iterates on it, and `design_radii` only widens, so a traced line cannot get a 50-100 m corner.
- Station-end deletion: `holds_station` matches `keep_under_stations`' lay-back (a stub up to reach + 10 m comes back unchanged), matches `stationStub`, and a stub has one station at one end so the wrong one cannot be taken; `check_station` keeps a terminus's and a neighbour's reach from overlapping.
- Delete and Backspace: `keyIsTheirs` covers text fields, the conditions match the panels' Remove buttons, and `removeThing` keeps the confirmation.
- Update notice: expiry, per-version dismissal and the lazy `useState(updateToShow)` are right; hidden on the new-game sheet by design; no held feature in its list.
- Shade worker per cut: fetch then cut are ordered through `ready`, the worker is ended after its answer, failure falls back to the main thread, and `dataUrl` is absolute so a worker can fetch it.
- `CompactOutlines`, the pixel-ratio cap, `lite.ts` (unchanged where `normal` is null), `NoMarketNote` and the NaN guards in `demandSums.ts`: fine.
