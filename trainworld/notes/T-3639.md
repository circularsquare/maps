# T-3639: leaderboard score swings with no edit

Agent scoreswing, 2026-11-18. Tree `.tw-trees/scoreswing`, Vite 6190, headless Chrome, 3 cores (`TW_CORES=3`, two
demand workers). Scratch scripts and logs: the session scratchpad's `scoreswing/` folder (`probe.mjs` to `probe5.mjs`,
`*.log`, `p2/` to `p5new/`, each with `puts.json`). Probes 2-5 mock the account server (`?acct=local`, Playwright
`ctx.route` on 127.0.0.1:8083: config, refresh, `/trainworld/me`, and every score PUT recorded with its time).

The report (Anita's pad, from Discord): "leaderboard position fluctuated from 450m to 550m and back. after updating
to 0.4". The boards rank `points`, a game's last PUT (shonei-server `trainworld.go`: last PUT per game, best game per
person; nothing to change there). The real NYC save's forecast weekday score is 442,914,240.

## Cause

`sendScores` (game/account.ts) sent whatever `pointsScore` held at the next 15 s tick, with no look at the solve, and
after a send holds the next for 2 wall minutes (`SEND_GAP_MS`). So a figure from before the whole final went up and
stayed on the board about 2 minutes, then the final replaced it: the score dipped or rose and came back, with no edit.

The big one is a page reload (or any load) on a game whose clock stands on a weekend or holiday. Until the load's
first figures land, `pointsScore` falls back to the past 24 game hours from the ledger (T-3465's stand-in), and those
hours are a weekend's. Real PUTs on the old code (`probe5.mjs`, `p5old`), the real save played to a late Sunday
(hour 189), saved, page reloaded with the cache missed (as after an update):

| PUT | points | what it was |
|---|---|---|
| reload +17.7 s | 370,629,536 | the past 24 hours, a Sunday's: 0.84 of the weekday |
| reload +152.6 s | 444,512,016 | the load's crowding round 2, still mid-solve |

The report's two values, 450/550 = 0.82, are the same ratio: Sunday's forecast on NYC is 0.81 of the weekday's. A
player who reloads on game weekends sees their board figure drop by about a fifth for two minutes each time.
T-3465 made the score the forecast weekday but left this stand-in feeding the send.

The other early figures the old send took, smaller on NYC:

| shown during a load | real NYC save |
|---|---|
| the focus pool (zone in view alone) | 455,427,871 (+2.8%), sent at +26.6 s and +66 s in two runs |
| round 0 (no crowding) | 464,418,717 (+4.9%) |
| rounds 1-2 | 443.8M, 444.5M (444.5M sent, above) |

Bigger saves add more: several clusters, and an edit's local result 7-16% low on lines (notes/T-3600.md).

Not ruled out, and not fixable in the page: a tab or device still on the pre-0.4 build posting its own figure under
the same game id (T-988 games share one id across devices; the server keeps the last PUT). It ends as old tabs reload.

## Fix (game/account.ts)

`figures()` gives nothing until `settled()`: no solve running (`demandUpdating`) or held while paused (`demandHeld`),
no load in progress (`loadProgress`), the newest network's whole final in (`finalWorld >= networkWorld >= 0`), the
weekday view final, and every running line in that view on its stops as they are (editNote's `solvedForNow`, plus none
missing). With nothing running it sends what it has ("idle"). The points are the weekday row of `pointsPerDay`, never
`pointsScore`'s past-24-hours fallback, and a 0 goes up only for an idle network. The gate is in `figures()`, so the
hidden-tab send and `gameForShare`'s send pass through it too (a share made mid-solve copies the figures already on
the server).

The line check covers a game opened in a running page: for about a second after the import (`probe4.mjs`) the last
game's view is still shown, final, with nothing updating and the last game's `networkWorld`/`finalWorld` pair, while
all 109 running lines are missing from it (`loadProgress` is up then too).

The load's focus pool is not in the gate: it shows only while the load's whole solve runs, except the pool T-2533
keeps after it, 443,054,644 against 442,914,240 in the one case seen (the same network imported again).

Left as is: the score on screen (`pointsScore`) still shows the past-24-hours stand-in for the first seconds of a
load, then the load's estimates. Whether to show nothing there instead is T-3465's choice.

A side effect: the board waits for a whole final, so on a big save edited every few minutes it updates only once the
player pauses long enough for one.
