Measured 2026-11-16 (agent b9). Nothing was changed in the repo. There is no CI at all today (no .github folder), so "CI time" below means a local check command or a pre-commit step.

- Python (pipeline, tools, checks, about 160 files): nothing. No ruff in the venv.
- Docs: `checks/doc_lint.py` already exists and works.

## Recommendation, in order
1. **tsc flags (do now).** Add `noUnusedLocals`, `noUnusedParameters`, `noImplicitReturns`, `noFallthroughCasesInSwitch` to app/tsconfig.json. Cost: zero extra time, no new tool. Today it reports 22 errors (17 unused locals, 2 unused imports/params, 3 missing returns), about 20 minutes to clear. Catches dead variables left after a refactor and a function path that falls off the end without returning. `noUncheckedIndexedAccess` gives 98 errors (arr[i] possibly undefined). That is the real bug class (undefined from an index, as in the stale-id and empty-list crashes), but it is a few hours of fix-up. Do it per folder later, not now.
2. **clippy on sim (do now, in a relaxed form).** Installed already (0.1.99). Full run on all targets took 35 s from cold with 2 cores, 78 distinct warnings and 3 hard errors (two "this loop never actually loops" in transition_tests.rs, which are real test bugs: the loop body runs once and the test checks one case, not all). Most of the rest is style: 21 chunks_exact suggestions, 9 index loops, 5 complex types, 5 needless casts. Plan: fix the 3 errors, then add `#![allow(clippy::too_many_arguments, clippy::type_complexity, clippy::needless_range_loop)]` to the crate and run `cargo clippy --all-targets -- -D warnings`. About an hour for the rest. Clippy's useful catches here: never-looping loops, float comparisons (partial_cmp on f64, NaN), unsafe fn missing docs, redundant casts that hide a wrong type.
3. **ruff for Python (do soon, errors only).** One `pip install ruff` in the venv; runs in under a second over the whole tree. Use only `select = ["F", "E9"]` (undefined names, unused imports/variables, syntax errors). It catches typos in a rarely run pipeline script that today only fail hours into a world build. Expect a few dozen unused-import hits, mostly auto-fixable. Do not turn on the style rules: the checks/ files are throwaway one-offs and would be pure noise.
4. **eslint: skip for now.** tsc strict already covers most of what matters. The two eslint rules that would add something (no-floating-promises, no-misused-promises: a forgotten await on a worker or save call) need typescript-eslint with type information. That is a new dependency, extra minutes of lint time, and uncertain support for TypeScript 7. Revisit if a forgotten-await bug shows up again.

## For pull requests
All three are a single command each, so a future GitHub Action is three short steps (tsc, clippy, ruff), a few minutes in total with caching. Not worth setting up until there are outside PRs. Meanwhile one script, checks/lint.cmd, running the three commands, would do for us.

## Noise
Risk is low if the relaxed clippy allow-list and ruff's two rule groups are kept. The way this goes wrong is turning on the default-everything profiles, which gives hundreds of style warnings nobody fixes, after which people ignore the output.
