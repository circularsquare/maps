# T-3429 line creator refuses the next station after a one-way single station (bugs3, 2026-11-16)

Not reproduced as a bug. What I found (about 45 minutes, Rust tests in a scratch copy, removed again):

- The player's refusal is `add_stop` returning `Issue::LinePath` ("No track joins these stations in this order."). It comes from
  `check_route` (net.rs): the line's return run must exist (`back_path_of`, T-3094), and a one-track stop must be stopped at by a run
  (`check_one_track`, OneTrackStop).
- Ring of two one-way single tracks (east and west), stations A and B on them: every order of A, B and a third ring station is accepted.
- Refused: a stop whose way back does not exist. A fully one-way run with no return track refuses the second stop (LinePath). A two-way
  spur that leaves a one-way track in the direction of travel (a facing turnout) refuses its station: A to C works, the way back from C
  would have to run against the one-way track. Same for any order. That is the rules working.
- So the likely cause in her save: the next station lies on track a train cannot come back from (a spur or a continuation whose way back
  is one-way against it, or tracks not joined at the far end). The message is the poor part: LinePath says nothing about the way back.
- Her screenshot (artifacts/trainworld/feedback/1794770049-2d10e331-1.webp) shows pink eastbound and blue westbound tracks meeting at the
  bottom right; the picture is too small to see which station she tried.

Update 2026-11-16 (bug-a): the refusal for a return run with no way back is now its own issue, NoWayBack ("No way back from this station on one-way track."), in place of LinePath; check checks/t3429-noway.mjs, test a_stop_with_no_way_back_says_so. Still not reproduced as a bug with her save.
