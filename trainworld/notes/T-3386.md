# T-3386 inferred one-way lost at a station (bugs1, 2026-11-16)

Fixed. Cause: `derive_ways` (sim/src/track/lanes.rs) treated "a station anywhere on the run" and "a station at a run's end"
as a vote for both ways. A station in the middle splits the piece in two but the run goes through it, and the vote made the whole run two-way.
Now a station inside a run, or at a join end that counts (`join_away`), says nothing; a station at a bare end (one port) still says both
(a terminus branch stays two-way, test t3137_terminus_branch_stays_two_way). The run keeps the way its joins give.
This is a rule change in a small way: stations on inferred one-way single track no longer make it two-way (her TODO calls it a bug). docs/track-and-service.md updated.
Test: `t3386_a_station_inside_the_run_keeps_its_way` (lanes_tests.rs); check: checks/t3379-single-fixes.mjs.
The t3137 lanes parity baseline still matches (no digest change). Saves with a station on such a run will change way on load.
