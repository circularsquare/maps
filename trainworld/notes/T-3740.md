## The charging rule

Since T-3758 (below), the zones a trip passes: a ride on a zone line (each line is set to zones, the default, or
distance) that boards and alights at stations of one area is a zone ride; zone rides one after another in one area
are a run, counting the zones from the lowest to the highest of that area's stations they stop at or pass (2 -> 1
-> 2 is 2 zones). Every other ride is a distance ride.

    fare = base x M + (curve(distance rides' km) - base) x their multiplier
           + sum over runs of (zone price - base) x the run's multiplier + transfer fares

## Save shape

- Track model: `StationData::fare` (u32; 0 none, else area id << 8 | zone 1-255), set by `Op::Station`, so painting
  undoes with Ctrl+Z and a deleted station takes its zone with it. Trailing block `LFZ1` after `LHR1`, written only
  when a station has a zone.
- Header `fares.zones`: the fare areas, `[{ id, name, prices }]`, prices in curve units (the reference country's
  fares, times a country's scale where charged), one per zone count; plus `fares.zoneNext`, the next area id, so an
  id is never reused (a station still holding a deleted area's id never joins a new area).
- `save::LEVEL` 26 (both).
- T-3758: `LineData::fare_dist` in a trailing block `LFD1` after `LSN1` (T-3759's, itself after `LFZ1`; count, then
  line indexes), written only when some line pays distance; `LEVEL` 28 (T-3759 took 27).

### The shonei-server save check (read, not edited)

The check reads only four header fields, so `fares.zones` needs nothing there. The change: `twSaveLevel = 26`;
append `"LFZ1"` to `twTrackBlocks`; a `twWalkTrack` step for LFZ1: a count u, then per station a node index u (below
the node count) and a code u (any value; the game drops codes on nodes that are no station, so keep the walk
structural and a later zone cap needs no deploy); truncation cases like LHR1's (cut inside the count, between an
index and its code). `TestTwSaveCheckFollowsTheGame` fails once save.rs says 26. Until deployed, a save from this
build reads "unverified" and is never pinned as the recovery copy (as T-3542's).
