## The charging rule

Rule i of the design, start and end zones: a trip whose first boarding station and destination station are both in
one fare area counts the zones from the lower number to the higher, both included (zone 1 to zone 3 is 3 zones, 2 to
2 is 1, zone 2 north to zone 2 south through zone 1 is 1). It pays that area's price for that many zones (the last
price for any more) in the distance curve's place:

    fare = base x M + (zone price - base) x (km-weighted kind and own multiplier) + transfer fares

Any other trip (one end outside, unpainted, or two areas) pays the distance curve for the whole trip. Recorded in
DECISIONS 2026-11-19 (T-3740). Picked as the design recommends: what the sim already prices per station pair, and a
player can predict it from the two stations alone.

## Save shape

- Track model: `StationData::fare` (u32; 0 none, else area id << 8 | zone 1-255), set by `Op::Station`, so painting
  undoes with Ctrl+Z and a deleted station takes its zone with it. Trailing block `LFZ1` after `LHR1`, written only
  when a station has a zone.
- Header `fares.zones`: the fare areas, `[{ id, name, prices }]`, prices in curve units (the reference country's
  fares, times a country's scale where charged), one per zone count; plus `fares.zoneNext`, the next area id, so an
  id is never reused (a station still holding a deleted area's id never joins a new area).
- `save::LEVEL` 26 (both).

### The shonei-server save check (read, not edited)

The check reads only four header fields, so `fares.zones` needs nothing there. The change: `twSaveLevel = 26`;
append `"LFZ1"` to `twTrackBlocks`; a `twWalkTrack` step for LFZ1: a count u, then per station a node index u (below
the node count) and a code u (any value; the game drops codes on nodes that are no station, so keep the walk
structural and a later zone cap needs no deploy); truncation cases like LHR1's (cut inside the count, between an
index and its code). `TestTwSaveCheckFollowsTheGame` fails once save.rs says 26. Until deployed, a save from this
build reads "unverified" and is never pinned as the recovery copy (as T-3542's).

## Stage Z1: built (2026-11-19)

Nothing a player can see or set: the tool is Z2. A game with no fare areas runs every old path untouched.

### What changed

- sim `demand/kernel/search.rs`: `FareZones` (per demand station 0 or (area index + 1) << 8 | zone; prices per
  area) inside `FareCurve`, so the skim cache key, mem count and every curve reader carry it; `FareCurve::flat`
  (no curve and no zones) gates the fare-km work; `pair_extra(src, dst, km)` is the zone price over the base and
  rate where both stations are in one area, else the curve's extra. Used at every curve site: `DestSearch::run_by`
  (route costs), `board_extra` (income's `rn_fare_x`), `IntercityApi::fare_col` (the market's income groups),
  `trip::routes` (the trip explorer, from the station boarded at after a start walk, as `run_by`), the gates in
  `assign.rs` and `everyday.rs`.
- sim `demand/api.rs`: `put_fare_curve` and `put_fares` take the zones; on a straight curve with zones they set the
  base and rate and fill `rn_km`; prices go to minutes at the population's `fare_w`, each held to its base.
  `set_fare_zones(st, off, usd)` on DemandApi, EverydayApi and IntercityApi (`check_fare_zones`, `demand_fare_zones`:
  a merged demand station takes the first zone among the stations merged into it).
- sim track: `StationData::fare`, `Network::node_fare`, `LFZ1`, `LEVEL` 26; wasm `station_fares()` and
  `set_station_fares(nodes, codes)` (one edit, free, undoable; 1 when nothing changes).
- app: `game/fareZones.ts` (codes, `tidyPrices`, `tidyAreas`, `zonesOf`, `startPrices`, `chargedPrices`,
  `demandZones`); `Fares.zones`, `Fares.zoneNext`; edits `fareZones` (the areas as a whole, a setting) and
  `stationFares` (stations' codes, undoable); the snapshot's stations carry `fare` (only while the fares have
  areas) and `stationsKey` reads the codes so a lone paint sends a network; `DemandNetwork.fz`, sliced per view and
  cluster and in their signatures with the areas' charged prices; the demand worker sets each population's zones
  (a city's prices times its country's rate multiple, the market's as set).
- docs/track-and-service.md "Fares and the ledgers": the zone rule. Wiki waits for Z2 (nothing to see yet).
