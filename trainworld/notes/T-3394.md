## The shape

One head line per task, so `grep T-####` still finds it, then indented fields:

    - T-3264 [P2] {L:trains-drawn} {waits:Anita} One fix for trains drawn through each other
      - Need from Anita: one sentence: exactly what to decide or do
      - Context: 1-3 sentences: her words, where we are, why
      - Goal: what done is, with the numbers
      - Other: anything else worth keeping on the board; the notes link last

## Rules (as refined by the pilot)

Head line
- `- T-#### [P#] {tags} Title`: id, priority and tags exactly as before; only the title text changes.
- Title: 2-10 words, sentence case, no full stop, no colon. It names the thing ("Long rays across the map",
  "UBC demand looks low"), in words she'd use; it may repeat the line's name only when the task is the whole line.
- A `taking, <date>, <agent>` mark stays in the head line, after the title in brackets:
  `Saves elsewhere open New York first (taking, 2026-11-16, agent x)`. The board matches `taking,` anywhere there.

Fields (two spaces, `- `, the label, `: `, one line each, in this order)
- **Need from Anita:** there exactly when the head has `{waits:Anita}`. One sentence she can act on without
  opening anything; a question is fine. Say the recommended answer when there is one ("recommended no, which closes
  this"). Never "review the proposal": name what she says yes or no to, and point at the field that holds it ("Say
  yes to the plan in Goal").
- **Context:** her words first, quoted exactly, typos kept, dated ("Your TODO 2026-11-12: ..."); then where things
  stand today, with dates and commit or tree names; then why, if it isn't plain. 1-3 sentences. Written to her:
  "you", "your".
- **Goal:** what done is, with the deciding numbers from the line or the notes' "done when". When the next step
  differs from the end, the end first, then "Next: ...". An umbrella or survey task says what closes it.
- **Other:** estimates, related ids, findings, mocks and screenshots by path, and the notes link last (with the
  section name when one section matters). Leave Other out only when there is nothing, not even a notes file.
- An id in any field gets a few words beside it ("T-3215, Canada's census jobs") unless the sentence already says
  what it is. She shouldn't have to look an id up.
- Someday tasks: the same fields, Context and Goal one sentence each, Other usually the notes link alone.
- Her writing rules apply (global CLAUDE.md, "User-facing text"): plain words, no em dashes, no "not X but Y",
  no summing-up line.

True now, not reshuffled
- Read the task's notes (the sections the line names, plus any "For Anita", "as built" or "Next" section) and grep
  ARCHIVE.md and git log for the ids the line names. Context and Need say what is true today.
- A stale `{waits:Anita}` (nothing is waiting on her any more, or the wait is for a later stage) is dropped in the
  block and the id passed to `--retag`; the agent lists every retag in its report so the orchestrator sees them.
  Other tags never change in this job.
- Nothing factual is lost. A fact the notes already hold can leave the line. Anything else goes in a field or into
  the notes: append `## From the task line, 2026-11-16` with the old line verbatim (simpler and safer than picking
  facts), and point Other at it. As a backstop the tool's `--keep-old` file keeps every replaced entry verbatim.

## The apply tool

`trainworld/tools/restructure_tasks.py` (stdlib, Python 3.9):

    venv\Scripts\python.exe trainworld/tools/restructure_tasks.py --check --snapshot <snap> blocks\*.md
    venv\Scripts\python.exe trainworld/tools/restructure_tasks.py --snapshot <snap> --retag T-1,T-2 ^
        --keep-old trainworld/notes/tasks-before-T-3394.md blocks\*.md

- Reads one or more block files (blank lines, `#` headings and ``` fences between blocks are skipped; any other
  stray line is an error).
- Refuses: a head whose id is not in TASKS.md (or is there twice) or appears twice across the files; a different
  priority; different tags unless the id is in `--retag`; an unknown field label, fields out of order or twice,
  Context or Goal missing, Need present without `{waits:Anita}` or missing with it; a dropped `taking,` mark; with
  `--snapshot`, a task whose entry has changed since the snapshot the blocks were written from.
- Warns: a title outside 2-10 words or ending in a full stop, an em or en dash, a Need of more than one sentence.
- Replaces each task's head line and any indented lines under it in place; every other line stays byte for byte,
  with the file's own line ending (TASKS.md has been LF since 2026-11-16, though the brief said CRLF; the tool
  keeps whichever it finds and writes through a temp file and `os.replace`). Nothing is written if any block has an
  error, or if TASKS.md changed while it ran. A second run on the same blocks changes nothing.

Tested in the scratchpad (`shape/test_tool.py`, 19 of 19 pass): the 14 pilot blocks on a copy of TASKS.md (14
entries replaced, 46 field lines added, every other line identical, then a rerun with 0 to change); the same on a
CRLF copy (all CRLF, identical to the LF result but for endings); each refusal above on its own bad block, file left
untouched; `--check` writes nothing; a re-apply replaces old fields instead of doubling them.

The snapshot check earned its place during the pilot itself: agent lines changed 5 of my 14 tasks' lines in the
hour I worked (T-3390 archived, T-3150, T-3245, T-3264, T-3346 updated), and T-2164 was archived after I wrote its
block. A `--check` against the live file refuses T-2164 as not in TASKS.md.

## For the rollout

- **Sizing.** The pilot took about 5 minutes a task on average, tool aside: 8-12 minutes for a long active task
  (T-3264, T-3346, T-3348, T-3345, T-3245, T-2887, mostly reading notes to find what is true now), 1-3 minutes for a
  short P3 or Someday line. TASKS.md has 422 open tasks: about 100 lines over 400 characters, 96 Someday. At about
  3.5 minutes on average that is roughly 25 agent hours, about 3 hours of wall time with eight agents. By area:
  demand 133 tasks (25 long), performance 74 (14), track 66 (21), ops 42 (7), interface 40 (6), schematic 28 (9),
  schedule 20 (7), community 19 (11). Demand is two or three agents' worth (split by line), performance two; the
  others one each, schedule with schematic and community with interface.
- **How.** Each agent takes a snapshot copy of TASKS.md when it starts, writes its blocks to its own block file in
  its scratchpad, runs `--check --snapshot`, and hands the file back; the orchestrator applies all files in one run
  with `--keep-old trainworld/notes/tasks-before-T-3394.md`, and retags only what the agents listed. A refused task
  (changed since the snapshot) goes back to its agent.
- **After the rollout, other files need the new shape** (not edited here): trainworld/CLAUDE.md's Tasks rule
  (`- T-012 [P2] short title. State, owner if taken, notes link.`), TASKS.md's header ("one line a task") and the
  Someday header ("Short lines; the full context is in each task's notes file"), and docs/orchestrator.md wherever it
  says how to file a task. New tasks get the fields from then on.
- **The board** reads head lines only (`board/build.py`, `parse_tasks`): it needs to read the four fields, and its
  notes link finder (`task_notes`, `NOTES_MENTION`) must look in Other, since the head line no longer carries the
  notes path. Its `taking,` match should stay on the head line, so a quoted "taking," in a field doesn't count.
