# T-145: solid track placement ghost

Implemented 2026-10-11 by UI subagent. The live new-track placement preview is solid and opaque with a dark casing. Height mode uses the existing level palette per segment; Max speed mode uses the exact geometry-speed palette and per-segment limits; Line and Traffic modes use a white body. Invalid previews stay red in every display mode (the bad flag is handled before either display-colour branch). Snapping, curve labels, quotes, issues and route editing are unchanged. Placement retains the blueprint flag plus a transient placement-style bit; once placed, normal blueprint track remains dashed/faded until constructed. Ordinary edge/node edit and delete previews keep their previous rendering behavior.

Speed contract: TrackApi.preview_render_speeds returns one authoritative fitted-geometry speed per consecutive pair of route/edge preview points. The new cached array uses the same render chainages and piece-speed helper as edge_render_speeds. Route/edge preview clears stale speeds before early refusal; preview_out fills them without changing the stable preview point/vertex layout or creating track. The clock worker checks array length, transfers speeds with the preview, and clockClient forwards them to the placement stroke buffer. The main thread does not infer curve speeds from display points. Generated track WASM must be rebuilt with this source before browser use. The worker uses a narrow intersection type for the new method so the source can typecheck before generated WASM declarations refresh.

Changing the active track display immediately recolours the existing preview through renderer uniforms. Changing build height or single/double track requests a fresh preview even before pointer movement. Segment heights still come from the authoritative preview geometry; slopes preserve existing rounding into discrete height colours.
