  running line's service run (`svc.lines[l].runs`, live runs) naming a derived edge whose track id is no longer

- The colour edits that "kept reverting" fit the same state: a colour change re-applies the line (`Op::Line`), whose

## Found and fixed (tw/track)

- **`run_polyline` on a one-way loop's return run** (Vienna, `removeStation 2623`, one op): `derived.rs:398` index
  out of bounds in `d_window`. A line run one way (`live_runs` 1) keeps a run 1 that no edit rebuilds, so its
  entries can name track that is gone. `run_polyline` now gives nothing for a run past `live_runs` or with no
  entries (wasm/service.rs). Test: `wasm/t4116_tests.rs` `a_one_way_loops_return_run_reads_nothing`. In the game the
  app asks run 1 only for a line with a routed return (`drawnBack`), so a player may never have met it. Master has
  the same unguarded read (its run_polyline is identical); whether master's stale run 1 can panic was not tried.

## The replay tool

`sim/src/bin/edit_fuzz.rs` (Cargo bin `edit_fuzz`): loads a save's track bytes (cut by the scratch `cut.mjs`: gunzip,
`TWG1`, u32 header length, header, network), runs random edits, undos and previews (draw track, stations on track,
free stations, remove stations and pieces, Add a track, delete a track, rebuild, construct, lines, stops, colour,
one-way, levels, kinds, crossovers, moves) each followed by the reads the game makes (state rows, trips, markers,
per changed line its reads; every line every 25 ops; a save and reload every 10), with two invariants
(`TrackApi::stale_runs`, `bad_paths`: native only, not in the WASM interface). Modes `run`, `replay`, `shrink`;
a watchdog writes an op that runs past `TW_HANG_S` as a hang. `TW_BT=1` prints a backtrace (build with
`CARGO_PROFILE_AGENT_DEBUG=line-tables-only` for file and line). Big saves are slow (NYC and North America:
over 5 minutes an episode of 60 ops with every read), so stop_tiers is left out of the reads.
