## 2. finish / land

- Rebase conflict in `trainworld/DECISIONS.md`, `ARCHIVE.md`, `notes/*.md`, `research/*.md` (status AA or UU): both sides kept,
  master's first; if one side already contains the other (case a), that side is kept; then `rebase --continue`, repeated per commit.
  Logged as "rebase conflict in X: kept both sides, master's first". Any other conflict, or a delete/modify one, stops as before and now names the files.
- Fast-forward refused: the message names the main tree's uncommitted files the commit also changes, with
  `git -C <maps> commit -m "<one sentence>" -- <files>` and the command to land again. Nothing is committed for the orchestrator.
  Without a blocker it says master moved or see the log.
- Extra: an item reworded inside a tree moves to the main changelog with its new wording.

## 3. remove / finish

- `remove` and finish step 4 share `removeTree`. It refuses before touching anything when this process's cwd (inherited from the shell) is inside
  the tree; `finish` checks that first, before step 1, so nothing is half done.
- When git cannot remove the tree: junctions are put back, then it lists processes whose command line mentions the tree path
  (PowerShell Get-CimInstance Win32_Process) and says a shell's cwd cannot be read from outside. Never kills.
- A leftover folder without `.git` (what a failed removal leaves) is rmdir-ed and `git worktree prune` run, by `remove` or the retry.
- Tested with a hidden powershell sleeping inside the tree: named by pid, failed, stopped it, `remove` cleaned up the empty folder.

## 4. changelog.py

In a tree (script path under `.tw-trees/<name>/`) new items get `<name>-1`, `<name>-2`; in the main tree `c###` as before (ignores other ids).
`list`, `reword`, `hide`, `set`, `highlight` work on both (tested). finish moves them and prints the new c###.
Note: tree-side `hide` and `set --area` do not carry over at finish (only text, area, fix, task, by); `reword` does.

## Replacement text for docs/orchestrator.md Traps (replace the "Landing a tree fails while..." bullet)

- `finish` keeps both sides of a rebase conflict in DECISIONS.md, ARCHIVE.md, notes/ and research/ (master's first); a
  conflict anywhere else stops it. If master will not fast-forward because the main tree has uncommitted edits in a file
  the commit changes, the message names the files and the commit command: commit them (they are yours), then run
  finish again. The patch-and-reapply recipe is only for edits that are not yours to commit; write the patch with
  `cmd /c "git diff -- <files> > x.patch"` (PowerShell's Out-File adds a BOM and CRLFs). An agent still editing those files may write them meanwhile: tell it to pause first.
- Never run `remove` or `finish` from a shell whose cwd is inside the tree: it refuses. If git still cannot remove a tree,
  the message names the processes that mention it; close them (it never kills anything) and run `remove` again, which also clears an empty leftover folder.
