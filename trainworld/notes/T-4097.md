## 3. Design: show at once, catch up after

### What a player would see differently
- Every build click shows its result on the map in the next frame. That covers track pieces, stations, Construct (the dashed blueprint goes solid and the money drops), stop circles, the line's path after a stop click, the stop order in the panel, and undo.
- Numbers (riders, trips, profit) still update a moment later, as "calculating trips" says now.
- Rarely, something placed vanishes again with the red refusal flash and a notice saying why. Today the same refusal shows before anything appears.
- Quick clicks never wait for each other: ten stop clicks in two seconds all show at once and go to the worker as fast as they come.

### The pieces
1. **One pending list on the page** (generalising today's three stand-ins: the track ghost kept, `pendingSt` for stations, the stop guesses). Each entry is an edit's seq, what it draws (strokes, a station box, a stop circle, a recoloured edge, a path), and what it says in panels (rows, cost). The renderer draws the pending entries over the network. An entry is dropped when a state whose version holds that edit has been drawn, or at once on a refusal. No track model on the page: the page loads no WASM, so a prediction comes only from what the page already has (a preview answered for this exact request, the network's edges and line paths).
2. **Track**: keep the ghost as the piece at the click when the preview answered for this exact request was ok, without waiting for the answer (saves the apply, 0.06-0.47 s here). The next piece's start is the pending piece's end: the op names it as "the end node of edit seq N", which the worker resolves (`a.node` today).
3. **Stations**: already shown at the click. The station's platform drawn from the ghost box as built track would be, not only the marker.
4. **Construct**: blueprint strokes recoloured as built at the click (the renderer already hides edges by a uniform, T-2763; a "built" flag the same way), and the quote taken from the cash shown. Refusals (cash, ground data not in) put them back.
5. **Stop clicks**: the circle already flips. Also draw the line's new path: for a removal, the same track between the neighbours (most removals keep the path); for an insertion, the path through the station's platform from the route the page already has. Where the page cannot tell, the path waits and the circle shows pending. And stop sending one click at a time (today each waits for the last answer, post +0.5-2.7 s): send `dropStop` by station as `insertStop` is sent, so the worker resolves every click against the stops it holds, applies a burst back to back and sends one rows state for all of them.
6. **Reorder and undo**: the panel's list in its new order at once; an undo drops the newest pending entry or redraws the last state it holds (the page keeps the world before each edit for its charge split already).

### Queue, merge, nothing dropped
- The worker keeps doing edits one at a time in arrival order (its message queue), each its own undo step, and a state may cover several edits (T-3803's joined follow-ups). Nothing is merged inside the track model.
- Money: `chargeShares` reads the world before and after each edit to split a charge by region. With one state for several edits, each paid edit's answer has to name what it paid for (its line, station or pieces, T-3844), or charges land in the wrong region.
- A pending entry is kept until a drawn state holds it, so a slow state never shows an edit vanishing and coming back (the T-1407 rule today).

### Refused edits
- The worker refuses as now. The page drops the entry, flashes the refused strokes red (`setRefused`) and shows the reason. Money refusals are checked on the page first from the preview's cost and the cash shown, so most never get that far.
- Edits that depended on a refused one (a piece chained from a refused piece's end, a stop on a refused station) are refused by the worker, since the node or station never existed, and dropped by the page with the first one's notice.

### Undo
- Undo goes in the same queue, so it undoes the newest applied edit. If that edit is still pending and is then refused, a plain undo would undo the one before it. So undo names the seq it undoes; the worker undoes only when that edit is on top of its stack, and answers "nothing to undo" otherwise.

### Not measured, needed before building
- What `add_route` spends its 0.06-0.33 s on (Asia), which decides whether the track change alone is enough.
- Whether a removal's line path can be predicted without the worker's routing often enough to be worth drawing (count over the Asia save's lines).

### Size
- Pending list, track and Construct parts: 4-6 h. Stop clicks sent by station with one rows state per burst: 3-4 h. Undo by seq and named charges: 2-3 h. Each can land on its own, track first.

## 4. Redo only what an edit touches (Anita 11-23: "are there ways we could chunk the world?")

**Summary for Anita**
- Yes. Each edit can carry a list of what it touched: the pieces of track, the stations, and the lines whose path or timing changed, plus the lines sharing track with them. Each step then redoes only those records and keeps the rest from last time. A grid of 2 km squares covers the few things that depend on what is nearby, like parallel lines drawn side by side.
- Zones are too coarse to bound an edit: most of the Asia save's network is in the Tokyo zone, and lines cross zone edges.
- Some things stay whole-line or whole-game: a line's timing and capacity (only for the lines touched), money totals and the issues list (kept as running sums, patched by each edit), and what trip calculation reads.
- Expected on the Asia save (estimates, not measured): a station drawn as built in about 0.3 s (now 1.0-1.6 s), Construct about 0.2 s (now 0.7-1.0), a stop click's panel about 0.2 s and its path about 0.3 s (now 0.5-1.3 and 1.5-3.5), reorder about 0.35 s (now 1.8), undo about 0.3 s (now 1.2). The track model's own part (0.06-0.33 s) stays until it is profiled and bounded too.
- It doesn't replace show-at-click; do both. Show-at-click makes the first frame instant. Chunking makes the checked version land quickly, stops quick clicks piling up, and leaves more of the machine for calculating trips.
- About 25-40 h in six parts. The drawn-network part overlaps the track rework's stage 5 (T-3444), so that part goes into the rework. The risk is a record left out of date. It is caught by building everything from scratch beside the patched version and comparing, in tests and in a check mode the game already has for the drawn network.

### What bounds an edit's reach

1. **Touched records, from the track model.** Every edit already knows what it changed: `take_changed_lines` lists the lines whose rows or timing changed, `take_name_changes` the names, and T-1863 settles only the lines sharing capacity with the edit. Add the edges and nodes added, removed or changed, and send the set with each state (or "everything" for a load, an anchor move or a fallback).
2. **Lines through the touched records.** Any line using a touched piece or stopping at a touched station is redone whole: its stroke, its train samples, its profile and its stop rows. A line is the unit for anything along it (timing, capacity, crowding), so a stop click on the 42-stop Tokaido line redoes that line and the lines sharing its track, never the other 200.
3. **A spatial grid for neighbour effects only.** Several drawn things depend on what lies near a piece, not on what is joined to it: parallel lines' side-by-side order (`lineBands`, corridors, `besideSamples`, `legShifts` at shared nodes), flat crossings, waiting room and car park placement (already kept per complex, T-3803), quad pairs, capacity tags. A grid of 2 km cells: an edit dirties the cells its touched records cover plus one cell of margin, and those passes redo only items in dirty cells. Where a neighbour effect reaches farther than a cell (a corridor of parallel lines), the reach goes by the corridor's lines (rule 2), not by distance.
4. **Not zones.** One Tokyo zone holds most of this save's network and lines cross zone edges, so a zone bound would redo almost everything. Zones stay what they are for trip calculation, which already solves only the clusters an edit touched (T-326).

### How it fits with show-at-click

Both, and they help each other. Show-at-click covers the first frame for what the page can predict (pieces, stations, stop circles, Construct's colour). Chunking covers what it can't: the line's new path, refusals, the money split, the next edit's wait. Today a burst of stop clicks piles up because each click costs the worker and the page 0.3-0.9 s. With both done, the pending list rarely holds anything for more than a few hundred milliseconds, which also makes a refusal's flash land close to the click. Chunking also frees cores the trip calculation now shares with edits (the 2-5x slowdown in section 1).

### Risk: a record left out of date, and how checks catch it

- **What can go wrong.** An edit changes something the touched set leaves out: a line rerouted around a removed piece (T-4000), a complex split by a station delete, a neighbour's side-by-side order, a name bound to a complex. The patched state then keeps an old row, stroke or figure until something else touches it.
- **Full build beside the patch.** Every bounded step keeps a "check" path that also builds the whole thing from scratch and compares: rows field by field, drawn buffers byte for byte, the page's world against a fresh one, panel totals against a recount. The drawn network already has this (`?patch=check`, T-1029, which caught real slips in T-3803). Extend it to every step.
- **Fuzzing on real saves.** A Node test applies random edits (track, stations, stop clicks, reorders, Construct, deletes, undo and redo chains) to the Asia, North America and New York saves, and compares the patched state with a full rebuild after each edit, as T-3803's placement fuzz did (1,600 steps, 0 differences).
- **In play.** The batch checker runs its games with the check mode on. In normal play, a quiet full rebuild every few minutes of idle time compares itself with the patched state. On a difference it takes the full one and records the edit kind in diagnostics, so a slip heals itself and gets reported.
- **Fallback by design.** Anything the touched set can't bound (a load, an anchor move, a fare-zone change, the cluster split) asks for "everything", which is today's path.
